## 实现契约

- 检测策略按 `severity_mapping`、`correlation`、`risk_score` 分别版本化：不可原地修改；`draft → pending → active/rejected`；本人可撤回 draft/pending 为 retired，审批人可退役 active（之后检测显式失败，须先批准替代版本）。类型互斥锁保证批准/退役串行；批准同事务退役旧版，每次迁移追加内容哈希审计。预置旧策略保留；不伪造人工审批。
- 新的 severity 策略必须包含 `modelSignal: {enabled, countThreshold, highScore}`，计数阈值 2～10000、高分阈值 (0,1]；关联时间窗复用 correlation 策略。`enabled=false` 显式恢复单模型命中直接告警。旧版本缺此块时保持历史行为；启用分层须正式起草、他人批准新策略。
- 分层新增 `detection_alert.alert_layer`（signal/alert，历史默认 alert）、`correlation_policy_version` 与 `promoted_at`。信号 severity=low、不创建事件、默认告警列表与人工队列不含信号；使用 `GET /alerts?layer=signal` 查看。模型概率、阈值和权重不变。
- 同资产、同契约、同分级/关联策略版本的模型信号，在事件时间窗口中达到计数阈值、关联规则命中或高分阈值时升级；后到达的规则/记录会复核附近信号。升级只追加依据、记录升级时间并关联事件，不重复创建告警。已有历史告警不回写、旧策略信号不套用新参数。资产升序加锁、窗口当前读、有界查询，超限整批失败。
- 检测规则新增详情、从旧版复制并覆盖字段起草新版本、active 退役；仍使用原有独立审批，不原地修改版本。
- 处置申请只允许本人撤回 pending，保存理由与撤回审计；同审批共用行锁，已批准/已拒绝不可撤回。
- 事件指派要求操作者与受指派人都具有该事件所有关联资产、来源与研判权限；受指派人必须 active，支持取消指派。时间线记录前后处理人及理由。
- 模型退役只允许非 active、无 pending 发布申请的版本；不删除审批与制品。回退指定当前模型 ID 做并发保护，选择同模型键最近一次 inactive 且仍获批准的部署，再复核制品并走同一激活流程；不自动降级、不跨模型键、不激活已退役版本。
- 离线采集读取器增加经典 pcap/pcapng 自动识别，并逐包检查 Ethernet 接口，混合链路/后续 section 非以太网/截断文件拒绝；不改冻结特征。
- V18 只在独立测试 schema 验证；不在本轮部署开发库。执行器仍不可用，不执行防火墙动作。
