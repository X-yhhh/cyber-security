# 验证与验收

更新于 2026-10-07，评价版本 `host-guard-evaluation/2026-10-07.1`。本文统一 P3—P8 的验收口径：**3 道硬门槛（G1—G3）+ 类别自动资格 + 报告指标**。硬门槛之外的指标只报告、不一票否决；某一类达不到自动资格只降为“只告警”，不使整个项目失败。阶段状态以 [开发路线](开发路线.md) 为准。

2026-10-06 之前的 `host-guard-evaluation/2026-10-05.2`（分角色完整策略回放、E5 收益区间、自动处置期/人工移交期等）随旧 prefix 慢速路线一起停用，不再作为任何阶段门槛。

## 1. 验证层次

| ID | 环境/输入 | 证明内容与边界 |
|---|---|---|
| V1 数据与特征 | PCAP、标签账本、golden | 提取可复算、无未来信息、切分无泄漏；不证明模型准确 |
| V2 离线模型 | L1/L2/L3 数据集（见第 2 节） | 分类与检出能力；不代表任意网络 |
| V3 决策回放 | 冻结 PCAP 经传感器、模型和策略 | 来源汇总、告警/封禁候选和时延；不含真实防火墙 |
| V4 动作与恢复 | 网络隔离的无害 canary | OS 规则范围、到期、撤销、故障恢复 |
| V5 联合闭环 | 传感器 → 模型 → 决策 → 执行器 | 1 倍速实时链路与真实规则；不宣称承受真实漏洞攻击 |

PCAP 由传感器以文件方式读取，不向网卡注入攻击报文；不运行攻击工具、漏洞利用或恶意软件。lab 环境的隔离要有接口/路由/防火墙证据，回放隔离与时钟规则见 [契约第 11 节](检测与处置契约.md#11-回放隔离与版本升级)。

## 2. 评估数据层

| 层 | 数据 | 用途 | 是否门槛 |
|---|---|---|---|
| L1 | CIC-IDS2017，按 [数据与模型方案](数据与模型方案.md#4-切分与泄漏控制) 切出 train / validation / test | train 拟合，validation 选型和定阈值，test 只在 P6 使用 | G1、G2 |
| L2 | CSE-CIC-IDS2018 中与 5 类对应的日期 | 跨数据集泛化，只测试 | 只报告 |
| L3 | P3-B 受控采集的慢速攻击与困难良性 | 本机环境下 `dos_slow` 与正常流量的表现 | 只报告 |

L1 同一数据集内切分，攻击工具和攻击机在各集合之间相同，成绩偏乐观；L2 才是泛化参考，下降幅度必须如实报告。

## 3. 统计单位与判定规则

- **连接**：一个 parentConnection（含其全部 prefix/final 快照和续段）计 1 个样本，不按快照计数。
- **连接判定**：按时间顺序取该连接第一个 `attack_score ≥ alertThreshold` 的快照，类别为该快照 `family_scores` 最大的攻击类；没有快照过阈值则判为 `normal`。这与在线“首次过阈值即告警”的行为一致。
- **攻击检出率**：先算 4 个攻击类各自的连接检出率（判为任一攻击类即算检出），再取等权平均，避免洪泛类的海量连接掩盖其他类。
- **误报率（FPR）**：分别计算内部正常连接与网页补充正常连接（见 [数据与模型方案 3.1](数据与模型方案.md#31-提取视角)）各自的“被判为攻击数 / 该来源正常连接数”，再取二者等权平均。网页补充占正常样本七成以上且有客户端视角偏差，合并计算会让误报率主要反映网页补充；两个分项同时报告。
- **macro-F1**：5 类（含 normal）按连接判定计算各类 F1 后取平均。
- **活动**：一次有标签依据的连续攻击（同一攻击来源、同一类别、同一时段）。时延按活动的原始起点计算。

阈值 `alertThreshold`、各类 `autoThreshold` 与 `minDistinctFlows` 只在 validation 上选择并冻结，P6 读取 test 前不得再改。

## 4. 硬门槛

| 门槛 | 数据/环境 | 指标 | 标准 | 阶段 |
|---|---|---|---|---|
| **G1** | L1 test | 攻击检出率（4 类等权平均） / 误报率 | **≥ 90% / ≤ 2%** | P6 |
| **G2** | L1 test | 5 类 macro-F1 | **≥ 0.80** | P6 |
| **G3** | lab 联合闭环 | 见下 | 全部满足 | P7 |

G3 要求，在网络隔离的 lab 中以 1 倍速完成：

1. 4 个攻击类各至少 1 段冻结 PCAP 场景经“传感器 → 推理 → 决策 → 执行器”产生告警；具备自动资格的类别产生真实封禁，且只作用于映射的 canary 来源。
2. 每条真实规则在 TTL 到期或撤销后被清理，并由执行器核验不存在。
3. 同时回放的正常场景累计 ≥ 30 分钟，误封禁 ≤ 1 次/小时，且每次误封禁都能按 TTL 自动恢复。
4. 记录每段攻击的“原始起点 → 首次告警 → 规则生效”时延（数值只报告，不设门槛）。
5. 在实际部署平台（Mac 实时抓包）上，记录洪泛与慢速 DoS 场景中质量合格快照的比例。若服务器响应被网卡合并为大包导致快照大量为 `offloadSuspected`、类别无法判定，该类别不能在该平台取得自动资格，并在报告中说明；是否调整契约中的 offload 规则另行评估，不在 G3 中临时放宽。

G1/G2 未通过时回 P3 按第 7 节处理；G3 未通过时按失败环节回 P4 或 P5。

## 5. 类别自动资格

自动封禁按类别授予，**不是项目门槛**：

| 等级 | 条件（L1 test，连接判定） |
|---|---|
| 可自动封禁 | 该类召回率 ≥ 80% 且精确率 ≥ 90%，并在 G3 中完成真实封禁与恢复 |
| 只告警 | 未满足上一行任一条件 |

某类只告警不影响 G1—G3 的通过；报告写明降级原因。L2 成绩不影响自动资格，但下降超过 20 个百分点的类别必须在报告中单独说明局限。

## 6. 报告指标（不设门槛）

| 指标 | 参考目标 | 数据 |
|---|---|---|
| 各类召回率、精确率、混淆矩阵 | 主要类别召回 ≥ 80% | L1 validation/test |
| 跨数据集检出率 / 误报率 | 约 70% / 5% | L2 |
| 受控慢速攻击检出、困难良性误报 | 如实报告 | L3 |
| 规则对比 | 列出“仅规则 / 仅模型 / 二者并用”的检出率与误报率，以及模型补充检出、纠正规则误报的连接数 | L1 test、L2 |
| 可判定覆盖率 | 各类、各原始场景中至少有一个质量合格快照的连接比例；G1 成绩只代表可判定连接 | P3-A 冻结清单、P6 |
| 检测与封禁时延 | 扫描、洪泛 ≤ 10 秒；暴力破解、慢速 DoS ≤ 20 秒（攻击起点到告警） | V3、G3 |
| 证据到规则生效 | P95 ≤ 2 秒 | G3 |
| 运行开销 | 推理吞吐、端到端处理延迟、丢包/队列积压 | V3、G3 |
| ONNX 一致性 | 与训练框架最大分差 ≤ 1e-4，类别翻转数 | P3/P6 |

ONNX 一致性超限属于导出缺陷，必须修复后才能进入 P6，但它不是模型能力指标。

## 7. 失败处理与测试集使用

- test 只在 P6 读取。每次读取记入访问日志；**P6 最多评估 3 次**，第 2、3 次须先登记改动内容和原因，改动不得针对 test 的单条样本或单个时段调参。报告写明 test 被读取的次数。
- 3 次后仍未通过 G1/G2：可收窄支持类别（把不达标类别改为只告警或移出范围）后重新登记，或按 [开发路线](开发路线.md) 申请新的切分；不得删除 test 中的困难样本来制造通过。
- 数据或标签问题回 P3；后端接入问题回 P4；执行或恢复问题回 P5。

## 8. 动作与恢复场景

P5 先在 V4 中逐项验证，G3 前必须完成“必需”项；“补充”项未完成时在报告中列为未验证，并保持对应风险的保护（例如不在生产资产启用自动能力）。

| 场景 | 级别 |
|---|---|
| 目标正确且窄范围封禁；正常目标不触发 | 必需 |
| 未登记/跨资产目标、错误执行器或 boot 拒绝 | 必需 |
| 过期/撤销授权、过期命令、签名或参数篡改拒绝 | 必需 |
| 管理通道、网关、DNS 等保护对象不受影响 | 必需 |
| 同幂等键只产生一条规则且不延长 TTL | 必需 |
| TTL 到期与人工撤销后规则被清理并核验不存在 | 必需 |
| 写账本前后、安装后回执前进程崩溃，恢复后规则与账本一致 | 必需 |
| 不覆盖、不删除用户已有规则 | 必需 |
| 控制面断连或回执丢失时记 uncertain 并核对，不换 ID 重发 | 必需 |
| 并发命令、续封、撤销不突破目标与资产预算 | 必需 |
| 时钟回退、不可信时间不延长规则 | 补充 |
| 主机重启后先清理再接受新命令 | 补充 |
| 已建连接与新建连接的效果分别验证 | 补充 |
| 身份/策略轮换下预算连续 | 补充 |

每项保留期望/实际、平台/程序/配置、规则摘要和恢复证据。P1 探针通过不等于 P5 执行器已验证；Mac 与 Windows 分别记录，未验证的平台不开放自动能力。

## 9. 报告要求

报告输出到受控 run 目录，docs 只更新状态。每份报告绑定数据集、切分、标签规则、代码、模型、策略和评价版本的哈希，给出各类样本量、排除量及原因、门槛结果和未验证项。点估计不等于保证；样本局限与 L1 偏乐观的事实须写明。
