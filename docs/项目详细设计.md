# 项目详细设计

## 1. 建设目标

建设一个面向授权主机/网络的持续流量检测与分级防御系统。软件传感器从本机可见流量生成流记录/时间窗特征，版本明确的自训练分类模型和确定性规则共同产生告警；平台关联资产与安全事件，再经授权策略执行限时主机防火墙动作，支持审批、撤销和审计。首期部署在现有 Mac 与 Windows 上，不要求新增专用传感器硬件。项目不调用外部大模型 API，也不训练大语言模型。

## 2. 现状与能力边界

当前仓库已建立 `backend/` Spring Boot 3.5 / Java 25 Maven 工程，已交付身份会话与权限、Flyway V1-V12、资产/授权生命周期、数据源/映射、审计范围查询、connector 与 sensor 专用机器身份及幂等批次、告警/事件范围研判、模型候选制品校验/发布审查/本机激活台账和响应申请/审批台账。sensor 批次在服务端复核配置、序号、映射和 v3.1 raw fields；Java 侧另有只读 UNSW CSV 回放、事件时间窗口、需显式 `ct_state_ttl` codebook 的 Feature Builder、模板驱动 NetFlow v9/IPFIX 解码器和默认关闭的有界 outbox relay。RabbitMQ publisher 已实现 durable topic exchange、持久化消息、publisher confirm/return 检查；M2 已增加批次消费者、手动 ack、`consumed_message` 幂等台账、5 次 TTL 重试和死信拓扑。应用 relay/consumer 仍默认关闭；M3 本机推理端口已接入消费事务，按激活模型推理并写 `inference_request`，端口关闭时消费者 fail-closed，尚不生成告警。当前不执行来源单位猜测、ONNX 图外派生/插补/类别编码；本机开发库尚未激活在线模型；实际抓包、collector 服务和影子运行仍未验证。使用 JDK 25 与独立 `DB_TEST_*` MySQL schema 的后端测试未迁移本机业务库。本阶段未启用 Redis，也未将 RabbitMQ 用于生产业务。模型制品仅按 manifest 进行受控本机校验和离线回放，真实流量在线推理仍未开放。响应策略领域的纯匹配、授权范围、快照和审批状态机已独立为可单测组件；模型领域按 `artifact`、`validation`、`runtime`、`replay`、`release` 子包隔离制品校验、稳定契约异常、运行时会话、回放和发布台账职责；模型制品错误使用稳定异常码，ONNX 活动会话切换受读写锁保护。

| 能力 | 首期定义 | 依赖与限制 |
| --- | --- | --- |
| 基准流量分类 | 公开数据/预制输入的正常与攻击分类，可选数据支持的攻击类别 | 以已评估模型和严格特征契约为准 |
| 主机实时/近实时检测 | Mac/Windows 软件传感器生成流记录并执行冻结模型推理 | 流记录可能需等连接结束/时间窗形成；不承诺逐包即时检测 |
| 授权网络观测 | 监测安装传感器主机，或接收经授权的交换机流量镜像/流记录 | 两台终端默认只能看到各自可见流量；全网可见依赖现有网络设备能力和授权配置 |
| 终端/安全日志 | 作为独立证据接入并与事件关联 | 不代表当前流量模型理解终端行为 |
| 风险排序 | 结合模型输出、资产重要性、事件频度、证据完整度及规则 | 评分规则可解释；不等同于预测未来攻击 |
| DoS 风险检测 | 识别数据集标签支持的 DoS 流量类别并叠加速率/连接数规则 | 不等于检测所有 DDoS；大流量饱和上游链路需外部清洗能力 |
| 自动响应 | 通过主机防火墙适配器执行已验证的限时阻断；不支持安全限速时不伪称限速能力 | 精确资产授权、动作白名单、时限、幂等、回滚和审计均为前置条件 |
| 漂移监测与再训练 | 在线监测输入分布/人工反馈；Windows 离线训练候选版本后审批发布 | 生产模型权重冻结；无未经审核的在线自训练/自动替换 |

## 3. 总体架构

首期采用单体控制面、分布式主机传感器的轻量架构，不引入微服务治理成本。Mac 与 Windows 上的软件传感器只采集本机授权范围可见的流量元数据，在线执行流重组/时间窗特征提取、规则检查和必要的本机推理，再向控制面发送规范流记录/告警。系统也支持公开基准和预制记录回放。特征经版本映射及质量门禁后进入冻结模型推理；原始逐包数据不经 RabbitMQ，也默认不传到业务服务器。

```text
Mac 软件传感器 ─┐
Windows 传感器 ─┼→ 流/时间窗特征 → 本机规则+冻结模型 → 告警/最小遥测上报
授权镜像流量 ───┘                                      ↓
预制回放 ─────────────→ 接入/质量门禁 → 事件关联与风险研判
安全/终端日志 ────────────────────────────────┘       ↓
                                            策略校验/审批
                                                   ↓
                                     主机防火墙适配器/可选联动
                                                   ↓
                                          执行审计与回滚

Vue 3 控制台 → Spring Boot 模块化单体
                         ├─ MySQL 8：业务事实、配置、审计
                         ├─ Redis：缓存、短期状态、幂等辅助
                         ├─ RabbitMQ：接入/分析/响应异步任务
                         ├─ 推理端口 → 本机运行时 或 远端推理服务
                         └─ 漂移/反馈 → Windows 离线再训练 → 候选审批发布
```

### 3.1 逻辑分层

- **接入层：** 当前开放 connector 与 sensor 机器身份的已授权规范化批次提交；文件导入和模型推理尚未开放。sensor 还提供心跳、批准配置读取和健康窗口路由；M2 已接入 outbox 批次消费者和有界重试/死信，但真实抓包进程、collector/UDP 接入和 M3 推理实现尚未接入。接入身份、来源、采集时间及机器主体的数据源—资产配对由服务端校验。映射版本只校验审批状态，完整字段转换/单位校验暂未实现。
- **传感器层：** 分别安装于获授权的 Mac/Windows 主机，提供采集状态、心跳、版本、流量窗口、丢弃计数和本机资源指标。采集能力限于操作系统/接口实际可见内容；需评估 macOS 抓包权限和 Windows 抓包驱动等软件依赖，但不需要专用采集硬件。
- **在线检测层：** 传感器或本机检测服务生成有界流特征；确定性策略负责基础方向/服务放行规则，分类器只为符合契约的流提供异常信号。规则和模型结果均进入告警关联。
- **领域层：** 资产、数据源、模型版本、告警、事件、响应策略、审批与审计等业务模块。控制器不得直接访问 Mapper 执行业务流程。
- **当前后端交付：** 已实现 connector 批次接入、告警/事件范围读取与研判、模型候选登记、受控 ONNX 制品验证、Java 离线回放、独立发布审查和显式本机激活台账、响应申请幂等台账与职责分离审批。真实流量推理 API、响应策略写入和动作执行仍关闭，详见接口与功能模块设计。
- **分析层：** 特征契约校验、推理路由、结果归一化、规则关联和风险评估。推理适配器不拥有处置权限。
- **执行层：** 只接受策略引擎签发的结构化动作，适配器仅对登记资产执行明确白名单动作，并返回可校验结果及回滚句柄。
- **基础设施层：** MyBatis、MySQL、Redis、RabbitMQ、对象/文件存储接口、密钥引用及运行监控。当前后端使用 MySQL 配置通过环境变量注入、关闭自动 baseline，并提供存活/就绪探针、受权限保护的运行摘要和与应用共享本机绑定地址的 Actuator 指标端点；指标包括发件箱状态/年龄/平均发布延迟、outbox publisher Timer histogram、传感器心跳、接入拒绝率和登录节流摘要，RabbitMQ 仅在 outbox relay 启用时纳入健康判断。控制台日志使用 Spring Boot ECS 结构化格式，`RequestIdFilter` 将请求关联 ID 放入 MDC 并在请求结束时清理；不记录凭据、原始载荷或连接详情。

### 3.2 部署边界

- Web 控制台经 HTTPS 访问 Spring Boot API。首期由本地/受控服务器部署，不暴露未经认证的公网入口。
- Mac 承载控制面及 Mac 主机传感器；Windows 同时承担 CUDA 离线训练和可选 Windows 主机传感器。Windows 训练任务流量需标记/隔离，避免污染其日常基线。若控制面部署在 Mac，Windows 训练端仅上传审核后的模型制品和报告。
- 本机终端传感器通常只能观测其主机可见的接口流量。要集中观测多个设备，需使用现有交换机/路由器的镜像端口、NetFlow/IPFIX 等既有能力及授权配置；没有该能力时不得宣称全网监控。无需购买专用网络 TAP/NDR 设备作为首期前提。
- Java 运行目标为 JDK 25。模型训练保留在独立 Windows CUDA 训练环境；训练原始数据、实验输出和模型权重不进入业务 Git 仓库。
- 本机推理模式将经审查的制品安装到受控模型目录，由本机推理运行时加载；远端模式通过认证加密的推理 API 调用。二者实现同一 `InferencePort` 契约。
- MySQL 为持久事实源；Redis 丢失后可以重建缓存/短期状态；RabbitMQ 至少一次投递，业务消费者必须幂等。关键业务提交与消息发布采用事务发件箱或等价的可靠发布方案。
- 原始遥测若需留存，应进入有访问控制和保留期的受控存储；数据库仅存检索元数据、必要规范化字段及受保护引用，避免无限膨胀和敏感信息扩散。

## 4. 关键业务流程

### 4.1 数据接入与检测

1. 管理员登记数据源、来源类型、授权范围和可用字段；导入请求携带来源标识、批次号和幂等键。
2. 接入服务校验身份、数据格式、时间范围、资产引用和授权状态，记录批次及拒绝原因。
3. 规范化层按版本化映射把来源字段转换为规范流量记录；Java Feature Builder 只在事件时间窗口达到 100 条时计算窗口字段（v4 契约已移除 `ct_state_ttl`；v3.1 的 codebook 仅用于离线回放），模型图外不执行训练侧派生、插补或类别编码；同时检查模型必需字段、类型、单位、取值范围及来源可信度。
4. 不符合模型输入契约的记录标记为 `rejected` 或 `manual_review`，保留校验问题；不得静默补造特征。
5. 合格记录按管理员激活的模型部署调用本机或远端推理。记录模型版本、映射版本、阈值策略、耗时和结果。
6. 结果根据关联规则形成告警；与资产、身份、终端/安全日志证据在时间窗内归并成事件。

### 4.2 持续流量采集与实时路径

1. 传感器启动时以设备身份向控制面登记，下载签名/校验过的采集配置；配置包含允许接口、过滤范围、特征版本、采样率、留存限制和授权资产范围。
2. 传感器只处理其有权限且操作系统允许采集的流量元数据；默认不保存完整载荷。按五元组/超时规则维护有界流状态并计算训练契约要求的特征。
3. 传感器先做数据质量、确定性白名单/规则及速率检测，再对符合契约的流调用本机已批准模型；若模型部署为远端推理，传输最小必要规范特征并测量链路时延，不上传原始包。
4. 采集速率超过处理能力时执行有界队列、采样/背压和显式丢弃计数；过载/传感器失联必须显示为保护降级，不得显示“安全”。
5. 告警和必要摘要异步上报；本机策略动作不依赖 RabbitMQ 往返完成。与控制面断连时只能继续既有安全策略和获准的本机防护规则，不接受过期/新下发的动作。

“实时”验收以流形成时间、窗口长度、特征计算、推理和上报端到端延迟定义；连接结束型特征必须标注其检测延后，不等同逐包 IPS。

### 4.3 研判与风险排序

事件页汇总告警、原始证据引用、模型输出、模型版本、数据质量、受影响资产和事件时间线。初期风险等级由可解释规则计算，例如攻击分数区间、资产关键性、重复频度、独立证据数和数据可信度；低数据质量不得抬高模型置信度。分析员可以标记误报、确认事件、补充结论和关闭事件，所有判断保留操作者和时间。

“攻击趋势”首期只表示告警量、攻击类别和受影响资产的历史趋势。“未来攻击概率/攻击阶段预测”不作为首期已实现功能，除非后续训练数据、标签、回测方法和误报成本单独通过评审。

### 4.4 分级防御与回滚

1. 模型只产生分类结果和候选建议，不直接发起网络/终端操作。
2. 响应策略按动作类型、资产标签/范围、风险阈值、有效时长、频率限制和审批要求匹配。
3. 基础方向/服务放行由主机现有防火墙和确定性资产/网络策略控制；分类模型只贡献异常证据，禁止“模型判正常即无条件放行”。项目首期不接管或重写操作系统的默认放行策略。
4. 对模型高分、规则命中或 DoS 速率异常，策略可生成告警、临时阻断/限速建议或动作。主机防火墙适配器首期只追加目标明确、范围最窄、带 TTL 的阻断规则；不得刷新默认策略、清空现有规则或改写全局入站/出站默认行为。限速只有在操作系统适配器明确支持且实测通过后才开放，不支持时仅告警、阻断或转审批。
5. 策略引擎重新校验资产当前授权、执行适配器健康、参数、持续时间和幂等键。范围未知、目标不明确、授权过期或策略冲突时 fail-closed。高影响动作进入审批队列。
6. 执行前校验带外/本机恢复途径、管理连接和保护资产清单，禁止封禁控制面自身、当前管理会话关键端点或默认网关等可能造成失联的目标，除非专门靶场策略明确授权。执行前后状态、适配器回执、模型/策略/授权快照、操作者、过期时间、回滚句柄与结果入审计。动作必须有超时或可撤销机制；无法证明安全回滚的动作不得自动执行。

主机侧阻断无法解决已在上游链路饱和的大规模 DDoS。项目可监测本机/已观测链路并应用经该操作系统适配器验证的主机动作；主机限速仅在适配器明确支持且实测通过后启用，否则提供告警和受控阻断。上游清洗联动需目标环境实际存在且有授权，不作为无条件能力承诺。

### 4.5 漂移监测与受控再训练

运行中的模型权重保持只读冻结。系统在滑动时间窗统计特征分布、契约拒绝率、模型分数/类别比例、传感器丢弃率和人工误报/确认情况，发现异常时生成漂移告警，不在线更新模型。

分析员确认的样本及其标签来源进入隔离反馈集。管理员按数据版本在 Windows CUDA 训练环境触发离线再训练；候选模型须经数据/标签审查、训练/验证/锁定测试、DoS 类别和正常流误报评估、影子运行及审批后发布。发布失败保持当前批准版本，不自动回退到未审查制品。

### 4.6 数据回放与隔离靶场

基准数据回放使用离线样本，不连接外部目标、不生成攻击流量。隔离靶场仅运行组织自有服务和预置场景，网络层阻断外联；系统中的“回放”驱动记录和处置工作流，不主动向真实网站或服务器发送攻击请求。靶场自动动作与授权实网动作使用不同策略、适配器身份和审计标签。

## 5. 模型制品与推理契约

模型候选必须包含：制品 SHA-256、manifest 版本、模型/算法版本、数据集及切分指纹、训练代码/环境标识、准确特征顺序、数据类型/单位、预处理、标签映射、阈值策略、评估指标、运行时/算子需求、导出格式和审批状态。

- 默认禁止加载来源不可信的 Python pickle/joblib。优先使用可审查的 ONNX 等受限格式；若目标算法不能可靠导出，则必须为其定义受控运行时并进行安全与兼容评审。
- 在线生产推理不做 SGD/增量拟合，不自动用伪标签更新权重；反馈只进入隔离的再训练候选集。
- 激活前执行哈希、manifest schema、特征契约、运行时支持和冒烟推理检查。候选与生产/演示活动版本分离，切换有审计且支持回退到已批准版本。
- 本机和远端是同一抽象接口的两种部署模式。远端请求只发送完成推理所必需的规范化特征，不发送原始包或多余身份数据；明确远端数据驻留、传输保护和留存策略。
- 同一模型版本的本机与远端结果需通过一致性测试；远端不可用、版本不匹配、超时或契约校验失败时返回明确失败状态，不自动切换到未声明模型。
- 推理结果至少包含 requestId、modelVersion、inputContractVersion、binaryLabel、可选 attackCategory、score/probabilities、thresholdPolicyVersion、qualityStatus、latency 和产生时间。概率只有在校准评估通过后才称为概率；否则称为模型分数。

## 6. 安全、权限与隐私

- 所有数据源、资产和执行目标均需登记；授权范围使用明确资产 ID/标签，不允许用任意 URL、CIDR 或命令作为未经审核的执行参数。
- 使用 RBAC 与资源范围授权；敏感操作二次校验权限。处置适配器采用最小权限独立身份，凭据由受控密钥系统提供，数据库只保留引用。
- 对原始日志、用户标识、IP、进程和模型输入实施最小收集、访问审计、传输加密、保留期限和脱敏导出。
- 所有写接口采用认证、授权、参数校验、速率限制和请求关联 ID。导入/响应 API 支持幂等处理和重放保护。
- 任何无法证明授权、目标、动作、时效或回滚条件的执行请求一律拒绝，并记录拒绝理由。

### 6.1 身份认证与授权执行

- 控制台使用 Spring Security 服务端会话。浏览器会话采用 HttpOnly Cookie；HTTPS 环境设置 Secure/SameSite，写请求执行 CSRF 校验。注销、冻结用户、修改密码或变更角色/范围时，服务端撤销相关会话。
- 人工用户使用 permission catalog + role-permission 模板；连接器、传感器和响应适配器使用独立认证主体及匹配路径，不允许回退成人工会话或复用管理员角色。
- 过滤器链建立身份、校验 CSRF、限速并设置 request ID；方法级安全检查权限点；应用服务复核状态迁移、职责分离和授权时效；MyBatis 查询强制追加 asset/data-source scope 条件。任何授权信息缺失均 fail-closed。
- 内置角色为 `platform_admin`、`asset_source_admin`、`security_analyst`、`response_approver`、`model_operator`、`model_releaser` 和 `auditor`。平台管理员可分配预定义角色，但不能修改权限模板；其对告警、事件、运行状态和审计为全局只读，不含响应审批/执行或模型发布。
- 资产/网络授权必须有受控证明引用和有效期。`asset_source_admin` 仅能提交待审批记录，`platform_admin` 由独立权限批准，申请人与批准人不能相同；没有第二名合格审批人时授权不生效，接入/响应 fail-closed。
- 聚合事件只有在所有关联资产、数据源和将返回的证据均属于主体范围时才返回。无归属或范围外单资源请求统一按 404 隐藏存在性；列表先在数据库按范围过滤再分页。
- `admin/admin` 保留为本机开发/验收用户并绑定 `platform_admin`，Flyway 不改变其密码哈希或删除账号；不得作为非本机部署默认凭据。

### 6.2 本阶段明确停用项

- 本阶段不训练、不在线更新权重，也不开放真实流量推理 API。当前已实现受控模型制品校验、Java 离线回放、模型候选登记和发布申请审查；审查不等同激活，必须由具备权限的操作员显式激活本机部署。推理端口未配置时返回明确错误，不得模拟推理成功。
- 本阶段不执行实际防火墙/网络命令。动作申请/审批台账可落库；策略不存在、不匹配、资产授权无效时 fail-closed。执行端点固定返回 `503 ACTION_EXECUTION_UNAVAILABLE`，记录拒绝审计但不调用适配器、不插入 `action_execution`。

## 7. 可靠性与可观测性

- 所有异步任务有状态、重试次数、超时、死信与人工重放机制；处置动作不得因消息重投重复执行。
- 展示数据源最近成功时间、接入拒绝率、队列积压、推理延迟/失败率、模型激活版本、适配器健康、待审批量和处置失败量。
- 日志使用 request/correlation ID，不记录密码、令牌、原始敏感载荷或模型制品内容。
- MySQL 备份、审计保留和恢复演练作为部署验收项；Redis/RabbitMQ 不能替代业务事实持久化。

## 8. 验收指标与阶段

上线阈值由实际测得的基线和误报成本确定，不在尚无结果时写死。需要评估：分类宏平均/每类召回、PR-AUC、FPR/FNR、DoS 类精确率/召回、正常流误拦率、特征覆盖率、漂移检测信号、传感器丢弃/延迟、端到端检测延迟、CPU/内存、事件关联准确性、幂等性、审批合规、回滚成功率和审计完整性。

1. **设计与契约阶段：** 完成模块、数据库、接口、特征映射、权限动作矩阵和安全边界评审。
2. **离线模型阶段：** Windows 训练并发布首个冻结模型；Mac/Windows 传感器回放/影子输入，验证契约、延迟和本机 CPU 推理能力。
3. **两机实时阶段：** 对 Mac 与 Windows 本机授权接口持续监测，先 shadow/观察运行；测量覆盖、采集丢弃、资源占用、正常流误报和 DoS 分类表现。
4. **受限自动响应阶段：** 在隔离靶场及登记的自有测试主机上验证限时阻断、到期恢复、审批、回滚和故障降级。
5. **漂移与迭代阶段：** 监测漂移、收集人工标注、Windows 离线再训练并审核发布；不做自动在线学习。

## 9. 后端与数据库首期实施顺序

1. 先统一角色权限矩阵、会话、资源范围、混合事件可见性和 Flyway 基线文档，并完成设计/计划评审。
2. 建立 Maven/JDK 25 工程骨架、统一错误与 request ID、MyBatis、Flyway profile 和 MySQL 8 集成测试。
3. 实现登录/注销/me、服务端会话撤销、内置权限 seed、用户角色分配、机器身份隔离、scope 授权及审计。
4. 实现资产/授权、数据源/映射、批次/记录、传感器健康、告警/事件读取和合法状态迁移。
5. 实现模型注册元数据和发布申请/审批台账、响应审批/执行台账、outbox 和运维健康接口；响应策略只读，策略写入/启用、模型推理和真实外部动作保持禁用。
6. 在隔离数据库验证空库和现存 schema 两种迁移路径；现有本机数据库须先比对完整结构并备份。空库 local profile 的 `admin/admin` 仅作为登录验收夹具；本机现存 `admin` 的密码哈希不重置，实际改密/登录验收须另行授权。

## 10. 明确不做

首期不做通用 SIEM/SOAR 全量替代、不做完整终端代理/EDR、不做未经评估的原始载荷 DPI、不做无标签支撑的攻击预测、不训练大语言模型、不提供在线自训练/自动换权重、不允许模型自由调用 shell 或任意 API、不攻击第三方或扫描未授权网络，也不承诺主机传感器可见整个内网或可单独抵御任意规模 DDoS。
