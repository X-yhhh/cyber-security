# 前端设计文档

版本：host-guard v5，视觉基线 v2，更新于 2026-10-14（决策 Q10：菜单收敛为 6 组 12 项、视觉基线改版、新增实时态势与待办中心，见第 3、4、10 节）。本文是前端的基本设计文档之一，描述**当前已实现的界面**（第 4.2 节标为“迁移前”的部分将由 F1R、F2—F5 替换）与**目标界面**（第 10 节）的区别，
组件库、接入层与交互约定。实施路线见[开发路线](开发路线.md)，后端接口语义以[接口设计](接口设计.md)为准，
模块职责见[功能模块设计](功能模块设计.md)，角色、权限与菜单可见性见[权限设计](权限设计.md)。本文不重复后端契约，只固定前端的表达方式与落位规则。

代码位置：`frontend/`。本文与代码冲突时以代码为准，并修正本文。

## 1. 定位与边界

前端是**本地自用控制台**，用于查看、审核和驱动后端已经实现的事实，不承担检测、判定或执行职责。

| 项 | 约定 |
|---|---|
| 数据来源 | 全部来自后端 API；**不内置演示数据**，数据库无记录时如实显示空态 |
| 授权 | 前端权限判断**只用于隐藏入口**；一切授权、状态迁移、幂等与职责分离由后端重新判定 |
| 动作 | 不提供任意目标地址、命令或 shell 的输入；处置只能引用已登记的决策与稳定预算目标 |
| 阶段声明 | 候选设计、未验收能力不得在界面写成已实现；能力等级按后端返回值原样展示 |
| 敏感值 | 不持久化机器凭据；凭据只在签发响应中出现一次并提示立即保存，不写入本地存储 |

界面上的每一条口径说明都对应一条后端硬约束（例如「批复不等于规则已清理」「202 不代表检测完成」），
改写文案时不得弱化这些含义。

## 3. 视觉基线（v2）

2026-10-14 决定 Q10：界面仍是白底、单色的控制台，以白色面板（细边框 + 8px 圆角）分组，加入克制的圆角、按钮与线性图标。同日 U0 实施时经用户确认两点修订：**页面底色保持白色**（不用浅灰画布，避免色差）；**交互色用墨色**，主按钮、选中菜单、焦点框、悬停与文字选中都不用钴蓝。目标是**信息密度不变、视觉噪音下降**：面板负责分组，线只用于表内分隔。首屏（`LandingView`）保持原样，是本节风格的来源。

### 3.1 色彩

单一强调色；语义靠文字与小圆点，不用彩色底徽章。

| 用途 | Token | 值 |
|---|---|---|
| 页面底色 | `paper` | `#FFFFFF`（与面板同色，面板靠边框区分；2026-10-14 取消原定的 `canvas #F6F6F4`） |
| 面板 / 表面 | `paper` | `#FFFFFF` |
| 面板内次级表面（表头、hover 行） | `paper.soft` | `#F2F1EE` |
| 主要文字 | `ink` | `#14161A` |
| 次级 / 三级 / 四级文字 | `ink-2` `ink-3` `ink-4` | `#3A3D44` `#6B6E75` `#9A9CA1` |
| 面板边框 | `ink-line` | `#E2E0DA` |
| 表内分隔线 / 发丝线 | `ink-hair` | `#EDEBE6` |
| 强分隔（表格表头下、时间线轴） | `ink` | `#14161A` |
| 交互与选中 | `ink` | `#14161A`（主按钮、选中菜单项、焦点框、选中文字；悬停提亮为 `ink-2`） |
| 强调（品牌） | `signal` `signal-soft` | `#2438E8` `#E6E8FB`（只用于品牌标识小方点与“进行中”状态语义，不作交互色） |
| 威胁 / 警示 / 正常 | `threat` `warn` `ok`（各带 `soft`） | `#E0482A` `#B7791F` `#2F7D5B` |

### 3.2 形状与层级

- **面板**：一级区块放在白色面板中，`1px` 边框（`border-ink-line`）、圆角 `8px`、不加阴影。每页面板数控制在 2—4 块；**不允许面板嵌套**，面板内的分组用标题与间距表达。
- **表格**：面板内表格只用行间发丝线；表头用 `paper.soft` 底、不加竖线。宽表允许横向滚动，不压缩列。
- **圆角**：面板 `8px`、按钮与输入框 `6px`、状态胶囊 `9999px`、徽标 `4px`。列表行与表格单元格不加圆角。
- **阴影**：只用于抽屉与弹层（`shadow-panel`）；页面内任何区块都不加阴影。
- 侧栏为白色，与内容区用 `1px` 发丝线分隔；每个二级项带线性图标（lucide，线宽 1.5），当前项用墨色实心底 + 白字（与登录按钮一致）。

### 3.3 排版

- 字体：正文 Inter（300/400/500/600），标识符与数值 JetBrains Mono（400/500）。
- 规律：**字号越小越粗、越大越细**。页面标题 `1.5rem font-medium`（比 v1 收敛，避免与面板标题脱节），面板标题 `15px font-medium`，正文与表格 `13.5px`，辅助说明 `12px`。
- `.num`（等宽 + `tabular-nums`）只用于时间、ID、IP、端口、哈希、分数、计数、TTL、版本号；**中文标签、按钮与表头用常规字体，不再使用等宽大写与宽字距**。
- 页面编号（如 `D-03`）保留但缩小为 `11px` 常规字体，放在页面标题左侧同一行。

### 3.4 动效

统一使用 `cubic-bezier(0.22, 1, 0.36, 1)`；页面切换 320ms，抽屉 420ms，淡入淡出 240ms，面板进入时轻微上移（`4px`）。
`prefers-reduced-motion: reduce` 下全部压缩为 0.01ms，`.reveal` 直接显形。

### 3.5 标识符与文案

1. **ID 不铺满**：UUID 默认显示前 8 位并跟复制按钮，悬停显示完整值；表格列宽固定，超长内容省略号截断。
2. **能显示名称就显示名称**：资产、模型、策略、组合、用户、角色一律显示名称，UUID 收进「技术细节」。
3. **技术细节折叠**：哈希、修订号、内部键、`manifestRef`、签名与报告原文放在页面底部的「技术细节」区块，默认折叠；业务字段在前。
4. **文案**：页面说明不超过一句白话（≤40 字）；后端约束写在**相关字段或按钮旁边**（字段下方 `12px` 说明或按钮 `title`），不再集中堆在页面顶部。含义不得弱化，例如「批复不等于规则已清理」仍须保留，只改变位置与措辞。
5. **内部代号**：界面不出现 `S5`、`r6`、`G3`、`T2` 这类项目内部编号；确需保留时写中文全称（如「来源等级」「现场只告警组合」），原文放进技术细节。
6. **时间线合并**：同类型、同主体、连续 5 分钟内的系统记录合并为一条，右侧显示 `×N`，展开可看逐条。
7. **状态与空态**：状态用文字 + 小圆点；空态写明范围（如「你可见范围内暂无未结事件」），不用「暂无数据」。
8. **操作命名**：按钮用动词 + 对象（「批准授权」「停用传感器」）；危险操作（停用、退役、撤销、删除）需二次确认，并在确认框写明影响。

### 3.6 图表

- 只用于实时态势与统计：折线（入站、告警、拦截）、按类别分色的分线或堆叠、横向排行条。
- 调色板固定为 `signal` + `threat` + `warn` + `ok` + 中性灰，按类别稳定分配，不随筛选换色；同图不超过 5 条线。
- 坐标轴、网格与图例用 `ink-hair`/`ink-3`，不加背景色块；无数据的时间点留空并标注「该时段无数据」，不画平线。
- 图表必须带悬浮读数，并提供数值表或 CSV 导出，供答辩与论文引用。

## 4. 信息架构

2026-10-14 决定（Q7）：控制台只保留 v2 页面，侧栏改为**按权限过滤的两级菜单**，v1 重复页面直接删除。同日决定 Q10：菜单由 7 组 18 项收敛为 **6 组 12 项**，工作台改为待办中心，新增实时态势。菜单清单、每项的可见条件（`anyOf` 权限）与六个角色的可见性矩阵以[权限设计第 7 节](权限设计.md#7-控制台菜单两级)为准，本节只固定前端落位规则。FE-9（任务单 F0）已实现两级菜单外壳与守卫，F1 已完成事件研判与误报反馈；U0.9 切换菜单骨架后、F1R、F2—F6 完成前，未完成的二级项要么复用第 4.2 节的旧视图，要么以 `legacy: true` 过渡行保留旧入口，v1 页面地址仍保留但不进菜单。

### 4.1 目标结构（Q10，6 组 12 项）

| 一级 | 二级 |
|---|---|
| 态势 | 实时态势 · 待办中心 |
| 威胁检测 | 事件研判 · 检测记录 · 误报反馈 |
| 响应处置 | 处置记录 |
| 模型与发布 | 模型与数据集 · 发布管理 |
| 资产与接入 | 资产 · 传感器与执行器 |
| 系统管理 | 用户管理 · 角色管理 · 审计日志 |

“12 项”不含登录即可见的待办中心（取代原工作台），`nav.ts` 共 13 行；菜单骨架由任务单 U0.9 一次切换，F1R、F2—F6 只改各自的行。

- 菜单配置单一来源 `src/router/nav.ts`（FE-9 已实现）：`{group, key, title, en, path, anyOf, component, ready, segment?}`，路由由其生成；编号不再硬编码在页面里。`ready=false` 的项既不显示也不注册路由（直达显示 404），各卡片完成页面后只改自己那一行。`segment` 只在复用旧视图期间指定初始分段，F1R 合并完成后删除。
- 一级组只是分组标题，可折叠（折叠状态存 `localStorage` 键 `sentinel.nav.collapsed`），当前路由所在组自动展开；二级项是独立路由 `/console/<group>/<item>`，路由名为 `<group>-<item>`（待办中心为 `workbench`）。顶栏面包屑为“一级 / 二级 / 详情 ID”。
- 宽度小于 768（Tailwind `md`）时侧栏改为左侧抽屉，由顶栏菜单按钮打开；抽屉内 Tab 焦点循环、Escape 或点遮罩关闭，关闭后焦点回到菜单按钮，跳转后自动关闭。
- 详情：事件详情 `/console/detect/events/:id`、lab 会话详情 `/console/release/lab/:id` 为整页，其余用抽屉。详情页随所属二级项注册并沿用其 `anyOf`。
- 登录后：持有 `detection.read` 或 `ops.read` 的用户进入实时态势，其余进入待办中心；未知地址显示 404 页，无权限地址在原地址显示 403 页（守卫在加载目标组件之前改道，目标页面不挂载、不发请求）。
- 被合并的旧地址保留重定向一个版本（清单见[权限设计 7.2 节](权限设计.md#72-菜单清单)）；v1 页面地址直接删除。

### 4.3 子视图落位规则

业务归类由两级菜单承担，每个二级项是独立路由。页内分段（`Segmented`）只用于**同一条流程的不同对象或同一对象的不同视图**（检测记录中的判定/推理/观察/批次；发布管理中的组合/策略/能力/验证记录；资产详情中的概况/授权/接入设备/活动发布），分段选项按权限动态展开；一个分段都不可见的用户看不到该页。分段选择同步到 URL 查询参数，便于跳转与刷新。

### 4.4 v2 链路的归属

v2 对象按因果顺序归组，而不是并入同名的旧页面：观察链路是一条连续证据链（批次 → 观察 → 推理 → 判定），与 v1 的同名对象语义不同，混排会误导读数。Q10 后仍遵守这条边界，只是把链路放进「检测记录」一页的四个分段，证据组只在事件详情中出现。

- 威胁检测承载检测链路，除研判、标注、复核外只读。
- 模型与发布承载「策略与发布组合」的冻结与审批，是能力等级的唯一来源；策略、能力与验证记录作为该页分段，仍不与其他模块混排。
- 响应处置承载动作、回执与预算占用，是唯一涉及真实执行意图的分组；预算不再单独成页，只在动作详情中显示占用与恢复条件。

## 5. 组件库

通用组件位于 `src/components/`。新增页面必须复用这些组件，不另造同类控件。

| 组件 | 用途 | 关键 props / 约定 |
|---|---|---|
| `PageHead` | 页头：图标方块 + 标题 + 一句说明 | `title` `desc` `icon`（缺省取当前菜单项图标）；右侧 slot 放操作 |
| `Panel` | 面板：标题 + 右上角操作 + 筛选条 + 内容 + 页脚 | `title` `desc` `icon` `flush`；插槽 `actions` `toolbar` `foot`；白底、`8px` 圆角、`1px` 边框、不加阴影；**不嵌套** |
| `StatBand` | 读数带：一行 2—4 个关键计数 | `stats[]`；`undefined` 不渲染（无权限不补 0），字符串值（时间）用小字号；`hint` 写明统计范围 |
| `DistBar` | 构成条：分段横条 + 图例（条数、占比） | `segments[]`（颜色取自 `tones.ts`），超出 `max` 并入“其他” |
| `ChainNav` | 因果链导航：有先后的分段画成相连节点 | 与 `Segmented` 同一无障碍约定；用于检测记录 |
| `PipelineSteps` | 阶段流水线：生命周期各阶段计数 | 只用于本身有顺序的流程（发布组合）；点击阶段发出 `select` |
| `Segmented` | 页内分段（`role="tablist"`） | `defineModel` 双向绑定；分段按权限展开，无可显示分段时整页隐藏 |
| `Tag` | 状态标记 | `tone` + `label`；圆点 + 文字，可选 `pill` 变体（浅底色胶囊，只用于状态列） |
| `Metric` | 大指标 | 进场计数动画，尊重 `prefers-reduced-motion`；`tone` 只影响数字颜色 |
| `TrendChart` | 折线与排行 | `series`（名称、颜色、点位）、`range`；无数据点为 `null` 留空；带悬浮读数与 CSV 导出回调 |
| `IdText` | 标识符 | `value`；默认显示前 8 位 + 复制按钮，悬停显示完整值 |

### 5.1 操作控件阶梯

每个页面只应有一个实心主操作，按语义递降：

1. `.act` — 实心主操作（批准、提交、激活），每页唯一，墨色（`ink`）底、白字、悬停提亮为 `ink-2`，高 32px、圆角 6px（2026-10-14 用户确认：沿用登录页的墨色按钮，控制台不用钴蓝做交互色）；
2. `.act-ghost` — 边框次操作（起草、停用、编辑）；
3. `.act-danger` — 危险操作（退役、删除、撤销），`threat` 描边，需二次确认；
4. `.link` — 行内文字操作（查看、复制、展开）；
5. 无样式 `<button>` + 下划线切换 — 筛选器。

输入统一用 `.field`（`1px` 边框的框式输入框，圆角 6px、高 32px，聚焦时边框变墨色）；多行输入同款、高度自适应。
列表页的筛选条固定为「搜索框 + 状态下拉 + 时间范围 + 排序」，全部同步到 URL 查询参数；筛选器放在面板标题下方一行（`.toolbar`，字段标签在控件左侧、同高对齐），不单独占一块面板。离散状态筛选用胶囊组（`.chips` / `.chip`，选中为墨色实心）。

## 6. 接入层

### 6.1 两套协议

`src/api/client.ts` 同时支持 v1 与 v2，区别只有信封与错误判定：

| 项 | `/api/v1` | `/api/v2`（P4） |
|---|---|---|
| 信封 | `{success, data, error, requestId}` | `{requestId, data, error}` |
| 成功判定 | `success === true` | HTTP 2xx 且 `error == null` |
| 分页 | `page` + `size`，返回 `totalElements` | `cursor` + `limit`（1—200），返回 `nextCursor` |
| 主键 | 内部数字 ID | 外部 UUID |
| 幂等 | 部分写操作 | **全部写操作**必带 `Idempotency-Key`（UUID 形态） |
| 并发 | 无 | 审批/激活/停用类需 `If-Match: <revision>` |

路径以 `/api/` 开头时视为已含版本前缀，否则自动补 `/api/v1`（F5 切换到 v2 会话后改为补 `/api/v2`），因此既有调用点无需改动。

### 6.2 v2 封装

`guard` 对象提供 `list` / `get` / `child` / `create` / `op` 五个方法，只封装后端路由中真实存在的组合，
不在前端做兜底猜测；未知组合由后端返回 404。

- 写入的幂等键默认由 `idempotencyKey()` 生成 UUID；
- `op` 的 `revision` 参数生成 `If-Match`。注意同一幂等键配不同 `If-Match` 会被后端视为不同请求，
  因此键必须随每次提交生成，不能跨提交复用。

### 6.3 会话与错误

- 会话状态只来自 `GET /auth/me`（Q10 后为 `/api/v2/auth/me`）；`can(permission)` 用于隐藏入口。
- CSRF 头名由后端 `/auth/csrf` 下发，前端不硬编码；写请求 403 时自动作废本地令牌，下次重取。
- 401 自动跳登录页（`/auth/*` 自身的失败除外）。
- 错误文案统一由 `errText` 生成并附带 `request-id`，页面不得自行拼接错误信息。

## 7. 权限与职责分离

权限与菜单的完整定义见[权限设计](权限设计.md)；前端遵守以下规则。

- **导航按权限过滤**：二级项的 `anyOf` 与会话 `permissions` 无交集即不显示，一级组无可见项则整组隐藏。路由守卫复用同一 `anyOf`，直达无权限地址显示 403 页且不发数据请求（FE-9 已实现，`nav.test.ts` 与 `guards.test.ts` 锁定）。
- 页内过滤仍发生在分段选项、操作按钮与请求三处；按钮与权限的对应见权限设计第 8 节。
- 审批类入口在无权限时不显示原因文案（避免泄露他人对象的处理状态）。
- 后端职责分离规则在前端只做提示：自批返回 403 `APPROVAL_SEPARATION_REQUIRED`，本人起草或申请的对象不显示审批按钮，`If-Match` 不匹配返回 409 `REVISION_CONFLICT`。
- 权限只在登录与刷新时从 `auth/me` 读取；角色变更后由后端撤销会话，前端回到登录页，不做本地增量更新。
- 页面不得依据前端推断「已批准」「已清理」等终态；终态一律读自后端返回值。

## 8. 状态与语义

后端状态值到颜色的映射**集中在 `src/data/tones.ts`**，用 `Proxy` 对未知值回退为中性 `mute`，
页面不各自判色。新增集合必须在此登记，不允许在页面里内联三元表达式选颜色。

要点：

- `signal`（钴蓝）表示「进行中 / 需关注但非威胁」，不是装饰色；
- 威胁语义只用 `threat`，且「模型分数」与「展示风险」分开着色，不合并为一个高亮；
- **期望状态与观测状态分开显示**：动作的 desired 与 observed 各自成列，制定不等于执行；
- 不成功的推理不带分数，`null` 显示为 `—` 而不是 `0`。

## 9. 交互与实现约定

1. **不本地推断终态**：写操作成功后 `await reload()` 重新读取；不做乐观更新。
2. **竞态防护**：切换实体或翻页时用请求序号作废旧响应（`let seq` + `mine !== seq` 早退）。
3. **分页**：v1 用 `Pager`（页码从 0 开始）；v2 用 `CursorPager`（游标栈支持回退，栈空时禁用「上一页」），读取逻辑统一用 `composables/cursor.ts` 的 `useCursor`。lab 会话事实按追加序号 `after` 翻页，是例外。
4. **可点击行**：`tr.row-link` 必须配 `tabindex="0"` 与 `@keydown.enter`。
5. **空态文案**：带范围限定的句子（如「数据库中暂无你审计范围内的记录。」），不使用「暂无数据」。
6. **表单**：字段名集中在常量对象中定义，避免同一请求体在两处写字面量。
7. **无障碍**：抽屉焦点循环与 Escape 由 `Drawer` 统一处理；错误区 `role="alert"`；
   切换类控件 `role="tab"` + `aria-selected`，分页区 `aria-label`。

### 10.10 各页版式（U0 落地，2026-10-14）

视觉基线统一（第 3 节），但每页按自身功能单独设计一个主视觉，不再“一个页面一张表格”。统计类读数只按后端返回值或当前已加载数据计算，并在旁边写明范围（如“按当前页 50 条统计”）；全量计数只来自 `GET /summary`。

| 页面 | 主视觉与版式 |
|---|---|
| 待办中心 | 问候式页头，右侧待处理合计与构成条；“优先处理”行动条（数量最多且可进入的一项，唯一主按钮；无待办时写明）；主栏“需要你处理”卡片带卡片合计与比例条，侧栏“运行与审计”带状态标记与相对时间；底部“常用入口”按权限列出可进入的页面。F2 接入 `GET /todos` 后在优先处理下方加入逐条待办（`TodoList`） |
| 事件研判 | 生命周期状态条（待处理 → 研判中 → 已遏制 → 已解决，误报 / 已关闭为旁路终态，点选即筛选）；研判队列行首按严重度着色；右侧栏为严重度构成、类别排行与未指派数 |
| 事件详情 | 案卷页头（事件键、标题、属性行、操作）+ 生命周期进度条；主栏时间线、证据组、关联动作（期望 → 观测同列）；侧栏处置资格；标识符收进技术细节 |

## 11. 测试

## 12. 待办与约束

- 视觉基线 v2（第 3 节）由任务单 U0 落地（`tailwind.config.js`、`src/styles/index.css`、通用组件与第 10.10 节各页版式）；F1R、F2—F6 在此基础上合并页面，首屏 `LandingView` 不改。修改视觉基线必须同时更新本文、`tailwind.config.js` 与 README。
- 面板与圆角是**限量**手段：面板只用于一级区块、每页 2—4 块、不允许嵌套；行内操作仍是文字链接，不把每个操作都做成按钮。
- 图表只用于实时态势与统计页，不引入图表库以外的新前端依赖（`TrendChart` 用轻量 SVG 实现）。
- 后台任务未接入 `event-sources` / `heartbeats` / `health-windows` / `target-bindings` / `command-claims` /
  `reconciliations` 等**机器侧**路由：这些由采集器与执行器以机器凭据调用，浏览器会话不可用
  （机器路由会清空会话上下文，且要求 `Bearer mch_*` 身份），因此不属于控制台前端范围。
- 稳定目标预算的「未核验标识冲突」「跨 boot 续期」等异常分支只按后端返回值展示，
  前端不自行推断连续性。
- 回放与真实执行器仍按后端能力开放；前端不提供绕过签名、TTL 与范围约束的入口。
