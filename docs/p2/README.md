## 交接内容

| 项目 | 后续使用约定 |
|---|---|
| 观测格式 | `host-guard/5.0.0-rc.2`；prefix/final、质量、上下文和目标引用语义见 [契约](../检测与处置契约.md) |
| 特征输入 | [feature-profile](../contracts/feature-profile.json) 的 43 个数值及 3 个类别输入；缺失 mask 独立 |
| 提取路径 | `sensor/internal/hostguard`，PCAP 与现场共用因果引擎；跨平台复算、golden 和结构验证已交接 |
| 研究入口 | `guardextract`、`guardjoin`、`guardgolden`；实时采集入口和依赖见 [传感器说明](../../sensor/README.md) |
| 目标引用 | 易失、鉴权的本机 IPC 原型；生产命令和持久恢复由 P5 接续 |

观测字段、单位、顺序、prefix 调度、同 parent 去重等保持交接语义。P3 改行为分组、评估时钟和预算判定时，使用单独的计划与决策规则版本；不因此重新开启 P2。确需改变观测字段或计算公式时，按 [版本升级规则](../检测与处置契约.md#11-回放隔离与版本升级) 产生新的兼容性变更和对拍证据。

## 当前使用与追溯

当前 P3 数据入口及哈希只在 [P3 执行文档](../p3/README.md) 登记。旧 final 数据快照、历史分区和 P2 生成报告已从 docs 清理，不能再充当新 prefix 实验的默认输入。

原冻结包与源码历史保留各自的文件和哈希，不改写它们来吸收新文档。`scripts/p2/freeze.py`、旧打包和报告命令用于对应历史版本的复现；当前 docs 不再承诺为这些闭阶段命令提供旧输入。新的 P3 run 必须绑定实际使用的 schema/profile、提取器、数据、切分、计划与决策规则哈希。

当前结构校验可运行 `python3 -B scripts/p2/validate_contracts.py`（需既有 Python 环境具备 jsonschema 及日期检查器）；这项校验不等于模型或自动处置验收。后端活动路径仍为 v4，相关兼容资源的替换在 P4/P8 处理。
