# 模型整改与分阶段开发计划

日期：2026-10-03。状态：**当前唯一的跨仓库实施计划；阶段 0、1 已完成，阶段 2 的 IoT-23 有界试点已收口，但该子集未通过数据准入，返回阶段 1 寻找合适来源。Windows 原生提取未验证。数据 readiness 与 S3 仍为 `BLOCKED`，未授权开始训练或真实处置。**

本文连接本地应用仓库 `main` 与 Windows 训练仓库 `training/windows-cuda`。它给出下一阶段先后顺序和每一步的停走条件；整体架构、接口、数据库、数据接入和冻结特征契约仍以本文末尾所列设计文档为准。远端训练实施细节见 Windows 仓库 `docs/model-readiness-roadmap.md`。本计划中的拟新增接口在实现前必须先同步《接口设计》和《接口实现核对矩阵》，不能按已存在接口开发页面。

## 1. 当前判断

**当前主要问题不是缺少一次调参，而是训练和验收数据无法证明模型对真实良性流量有足够低的误报，同时现有模型跨数据源泛化不足。应先暂停 S3，先解决数据、标签和传感器特征是否同源的问题；只有这些门禁通过后才重新训练。**

| 证据 | 已核实结果 | 决策含义 |
|---|---|---|
| UNSW v4 锁定测试 | Macro-F1 `0.9456`、FNR `4.94%`、FPR `0.77%`、PR-AUC `0.9741`、ROC-AUC `0.9988` | 只证明该历史切分内通过；FNR 仅比 `5%` 门槛低 `0.06` 个百分点，不证明跨域可用，也不能用于新权重的验收 |
| UNSW → D2 泛化 | Macro-F1 约 `0.510`、ROC-AUC `0.681` | 现有特征和模型对异域流量没有足够证据；不能只靠继续优化 UNSW 验证集解决 |
| CIC-IDS2017 Windows validation | 41,820 条；Normal 1,572、Attack 40,248；FPR `1.2723%`、Recall `38.0367%`、Macro-F1 `0.33076`、PR-AUC `0.99656`、ROC-AUC `0.93147` | Recall 和 Macro-F1 明确不达标；高攻击占比抬高 PR-AUC，不能据此认定模型可用 |
| 旧 CSE-CIC-IDS2018 标签 | 旧版将未匹配攻击规则的背景流当作 Normal，按该不可信口径算出的 FPR 为 `72.24%`；新审查的可信 Normal 仍为 `0` | 旧 FPR 仅作标签问题诊断，不是正式良性误报估计；不能用于训练或放行 |
| 阶段三数据 readiness v4 / S3 preflight | `BLOCKED`；L2 可信 Normal/Attack 为 `0/0`，独立规则场景 `0/10`，S3 `trainingAuthorized=false` | 不开始训练、不读取 holdout、不生成预测。登记的实验预算不是运行授权 |
| Monday 良性候选人工复核 | 1,674 条均保持 `Unknown`，可训练行数为 `0` | 不得因完成了人工复核就改成 Normal |
| 新来源试点 | IoT-23 80.5 MiB 子集的完整关联与 Go 同源提取审查已完成：Somfy 两个单主机窗口仅 77/7 条，ready Normal=0；Muhstik 有 2,964 条完整关联且 v4 合格的攻击切段，全为 initiator；当前模型范围内候选为 0。Windows 新 EXE 被应用控制以 4551 阻止；Windows 完成了对来源哈希绑定的 Mac 结果审计 | 当前子集不进入阶段 3，不降低 100 流窗口、不拼主机、不改 responder 范围；返回阶段 1 寻找独立良性/目标攻击证据。可训练标签仍为 0，Windows 原生平台 parity 未验证 |

机器证据保留在 `docs/phase1/evidence/`、`docs/phase2-evidence/` 和 `docs/phase3-optimization-evidence/`。本机开发库曾登记并激活 `unsw-binary-2026.10.2`，不等于生产批准。Mac 传感器的既有对拍/影子证据仅覆盖已授权主机可见范围；Windows 传感器尚未形成同等验收证据。后端 `/api/v1/actions/{id}/execute` 仍固定返回 `503 ACTION_EXECUTION_UNAVAILABLE`，不调用防火墙适配器。因此目前既不能宣称模型达门禁，也不能宣称已实现模型命中后自动阻断。

准确率不单独作为放行指标。类别不平衡时必须同时看每来源 FPR、FNR、Recall、Macro-F1、PR-AUC、ROC-AUC、混淆矩阵、置信区间及每小时误报告警量；合并均值不能掩盖单一来源失败。

## 2. 固定门禁

以下沿用模型训练计划和阶段二已冻结的范围。对纳入验收的每个来源都报告独立指标，再报告合并指标；如果要改变来源范围或指标，必须在训练前版本化并重新审批。

| 层级 | 门槛 | 使用条件 |
|---|---|---|
| L1-P 离线模型门禁 | Macro-F1 ≥ `0.92`；FNR ≤ `5%`；FPR ≤ `1.5%`；PR-AUC ≥ `0.93`；ROC-AUC ≥ `0.99` | 仅在新建、冻结的独立 holdout 上做最终判定一次；验证集可用于开发和选阈值，但不能替代 holdout |
| L2 独立操作效果门禁 | FPR ≤ `3%`；Recall ≥ `80%`；可信 Normal ≥ `1,000`；可信 Attack ≥ `100` | 标签须有独立来源证据和复核；任何 Unknown 不计入任一类 |
| L3 授权资产影子门禁 | FPR ≤ `2%`；至少两个独立时段、累计 `8` 个资产小时、可信 Normal ≥ `1,000` | 还须继续满足 L2 Recall 要求；只证明已观测的授权主机/接口与时段 |
| 自动处置独立门禁 | 规则/动作验证场景须先冻结并全数通过（当前 `0/10`）；动作需证明授权、幂等、TTL、审计和回滚 | 模型分数不能越过策略引擎直接调用执行器；L1/L2/L3 通过不自动授权阻断 |

holdout 只用于已经冻结模型、阈值、来源范围和报告模板的最终验收。失败后不能针对同一 holdout 调阈值或重训；要继续实验，须使用开发/验证分区，必要时另建未暴露的新 holdout。

## 3. 实施阶段

阶段按依赖顺序推进。阶段未达到出口时停止在该阶段，保留失败证据并修复上游问题，不跳过门禁进入训练、集成或阻断。

### 阶段 0：冻结当前状态并解除错误预期

**目标：** 明确目前没有满足自动处置条件的模型，也没有可用于重训的可信新数据。

- **远端训练仓库：** 只保留已登记矩阵和当前 readiness/preflight 证据；将 S3 维持 `trainingAuthorized=false`。本阶段不运行训练、预测、Optuna、holdout 读取或模型导出。
- **数据集：** 不把 CIC-IDS2017 的未确认良性背景、CSE 的旧 Normal、Monday 的 `Unknown` 改成训练标签。保留既有 UNSW/CIC/CSE 审计和历史切分指纹。
- **本地后端：** 当前模型作为历史/开发候选看待；不把活动部署状态等同生产批准，不开放执行器，不降低 L1/L2/L3 门槛。
- **传感器：** 继续遵守 v4 严格校验和 fail-closed；不把模型标签直接映射为封禁命令，不扩张采集到未授权接口。
- **前端：** 不新增训练启动或自动封禁控件。现有模型、告警、事件和影子报告只展示其 API 实际提供的状态。
- **出口：** 本文的当前状态、门槛、证据路径和“不得开始 S3”在本地与训练仓库文档中一致。此出口不代表数据 readiness 已通过。

**执行记录（2026-10-03）：** 阶段 0 已完成，验收及验证边界见[阶段 0 状态冻结记录](phase0/README.md)，机器摘要见 `docs/phase0/evidence/freeze-20261003.json`。训练仓库已同步同一记录、最新 readiness/preflight、Monday 复核摘要和原始 S3 矩阵；其阶段 0 出口已改为两仓库状态一致，候选来源 pilot 仍属于阶段 1～2。S3 保持 `trainingAuthorized=false`，没有进行新训练、预测、holdout 读取、模型导出或真实处置。现有矩阵 SHA-256 保持 `14c71d367d3ae584ba235c74802c9500f584f93a6235e1e6b4ab368c1c3048e7`；其中 FNR≤`4%` 是更严格的开发停止条件，与 §2 的 L1-P 最终验收 FNR≤`5%` 分别记录，均未放宽。下一阶段是小体量候选来源初筛，须按阶段 1 的范围另行推进。

### 阶段 1：小体量候选数据源初筛

**目标：** 在投入全量下载、特征工程或训练前，快速淘汰过大、许可不清、无可信良性标签或无法与流量关联的数据源。现阶段不预先指定任何 Kaggle 候选为合格来源。

- **远端训练仓库：** 增加只读候选清单/审计流程：记录 Kaggle owner/slug/version（或官方项目标识）、官方说明与许可、文件列表和字节数、PCAP/flow/日志构成、标签来源、样本时间范围、内容哈希及审核结论。对 ToN-IoT 先解决下载授权/访问，再做样本级时间与端点关联；IoT-23 先解决条款冲突；CICIoT2023 因缺少独立事件日志证据不优先。只允许有界元数据读取和小样本 pilot；不自动下载整个大归档。
- **数据集：** 首轮每个候选完整下载上限建议为 `2 GiB`；若只需合法、可复算的官方场景子集，pilot 原始成员总量控制在 `1 GiB` 内。候选至少要能证明逐流标签对应依据（时间、协议、双向端点或发布者提供的稳定连接 ID）以及 Normal 的独立良性证据。单有攻击日程、未匹配攻击标签或“背景流”不等于 Normal。
- **本地后端：** 不改数据库和在线 API；候选审查仍在离线训练环境完成。
- **传感器：** 不改在线采集代码；只准备已授权/公开小型 PCAP 的离线回放夹具。
- **前端：** 无页面工作；数据源候选审查是训练/数据治理流程，不误放进生产数据源管理页面。
- **出口：** 至少一个体量合适、许可可接受、标签可追溯且可取得代表性良性流的候选进入阶段 2。没有候选满足时停止，先调整检测任务或寻找数据，不以现有标签质量不足的数据硬训。

**执行记录（2026-10-03）：** 阶段 1 已完成，见[候选初筛与有界 pilot 记录](phase1/README.md)。10 项来源/镜像已登记；IoT-23 按要求引用的官方子集通过本阶段出口，4 个成员共 `84,415,438` 字节。29 条良性候选（TCP 10、UDP 19）与 151,567 条攻击候选具有精确双向端点、协议和微秒起始包对应，4,637 条仍为 Unknown。Windows 标准库审计工具及 24 项门禁测试已完成。当前报告为 `source-screening-pilot-v2.json`；完整连接/独立活动日志、v4 特征、人工标签复核和独立分区尚未验证，`trainingEligibleRows=0`、S3 `trainingAuthorized=false`。下一步按阶段 2 核验该有界子集，不能直接进入训练。

### 阶段 2：传感器特征兼容性与标签关联试点

**目标：** 尽早判定候选数据能否通过本项目传感器的特征语义，而不是到模型训练后才发现字段对不上。

- **远端训练仓库：** 对候选小样本建立可重复的 PCAP/流读取器和标签关联器，输出逐流 join 成功率、未知标签率、丢包/截断、方向、时间单位、重复连接、冲突标签和各字段缺失分布。特征提取须复用或逐字段对拍传感器同一实现，不以不同工具生成的 CSV 直接冒充同契约输入。
- **数据集：** 把无法唯一关联或标签证据不足的行标为 `Unknown` 并排除训练；仅保留有明确证据的 Normal/Attack。按场景、日期、主机、连接分组审查近重复和跨分区泄漏。
- **本地后端：** 若候选能严格产生冻结 `unsw-nb15-flow-v4` 的 19 个输入字段，则继续复用 v4。若任一必需字段不可观测、单位或语义无法对齐，立即停止这条候选路线；需要新字段或计算语义时先设计并冻结新的契约版本（例如 v5），同步后端 validator、API 文档、manifest 与传感器，绝不原位改写 v4。
- **传感器：** 建立 PCAP replay/golden fixtures，对双向合并、方向、流结束、水位线、超时、单位及类别值逐字段对拍；对于不可观测字段要明确拒绝或按契约允许的缺失语义处理，禁止默认补零。
- **前端：** 无页面工作。
- **出口：** 每个被接受的样本要么满足冻结字段/单位/标签契约，要么带明确排除原因；已接受样本的流关联与特征差异都可复算，Unknown 不进入训练。契约不能成立就退回阶段 1 换数据源或先修订版本化契约。

**执行记录（2026-10-03）：** 本次阶段 2 有界试点已收口，见[完整流关联与特征兼容性记录](phase2-pilot/README.md)。Mac 对四个已冻结官方成员使用 Go 同源提取；Somfy 两个单主机窗口只有 77/7 条入窗流，全部未暖机，ready Normal=0。Muhstik 的 85,803 条 ready 流字段审查均通过，其中 2,964 条同时具有完整连接标签证据，但全部为 initiator，当前模型范围内候选为 0。公开 10,000 帧 golden 的 1,868 条流（ready 1,769）与 Java 独立参考实现完全一致。Windows 原生 Go EXE 被系统应用控制以 `4551` 拒绝，平台 parity 未验证；Windows 标准库审计工具消费源哈希绑定的 Mac 提取包，完成逐流决定账本、精确/近重复候选及连接/日期分组审查，51 项门禁测试通过。当前子集不进入阶段 3；Unknown、缺字段、区间/方向/计数不符及地址排除均有记录。独立活动证据、第二人复核、足量 Normal 和分区尚未接受，`trainingEligibleRows=0`；未创建分区，不声称跨分区零泄漏。下一步返回阶段 1，保持 readiness/S3 阻断，不训练、不读 holdout、不改 v4 或活动模型。

### 阶段 3：数据审查、分区冻结与 readiness

**目标：** 在训练前证明数据足量、标签可信、分区独立并可支持所有目标门禁。

- **远端训练仓库：** 实现数据登记 manifest、文件哈希、标签证据账本、字段/质量报告、去重/近重复审计、按 capture/day/host/scenario/activity group 的确定性切分和 holdout guard。训练/验证/锁定测试的来源、标签映射、过滤条件、样本 ID 与分区指纹必须可重建。
- **数据集：** 所有来源和许可固定；至少达到 L2 的可信 Normal `1,000` / Attack `100` 数量门槛。若要声称跨域泛化，则每个独立来源必须有自己的合格 holdout 和逐源报告。标签范围、攻击家族缺失和明确不可评估类别须在训练前写入范围，不得事后把缺失类描述为已覆盖。
- **本地后端：** 确认将接收的契约版本、标签语义、manifest schema、阈值来源和特征单位；如需变更，先更新《特征规格》《接口设计》《数据接入设计》，再实现后端对应校验。
- **传感器：** 对照冻结特征规格确认在线字段可观测性与质量标记，记录接口可见边界、丢包、截断和流超时；不以仿真结果代替传感器实测。
- **前端：** 暂无业务页面；如后续要求项目内查看训练 readiness，先新增具备只读范围控制的后端报告接口，再由 Claude 实现只读 readiness 报告页。
- **出口：** readiness 为 `PASS`；许可、来源、标签、样本量、分区、零泄漏和数据哈希齐全；L1/L2/L3 与动作场景的可评估范围事先明确。任何一项不足就保持 `BLOCKED`，不得只改 JSON 计数或跳过 gate。

### 阶段 4：受限开发训练与验证集选型

**目标：** 只在阶段 3 通过后，用开发集做有限的模型/预处理/阈值比较，尽早发现效果不达标。

- **远端训练仓库：** 先修正并测试数据加载、训练/验证划分、阈值选择、逐来源指标、运行配置/日志和失败恢复；然后按冻结的 S3 矩阵在 Windows CUDA 运行 XGBoost、LightGBM 等有限基线。当前矩阵登记的 P1、seed `20261003`、每来源最多 `100,000` 行、合计最多 `200,000` 行、最多两轮、`30` 分钟预算仅作为规划；若数据或契约变了，先生成新矩阵。无 `trainingAuthorized=true` 时不可开跑。
- **数据集：** 本阶段只读 train/validation；holdout 文件访问控制应在代码和测试中实际拒绝，不只靠操作约定。插补、编码、缩放、特征选择、阈值等只在 train 拟合或 validation 选择。
- **本地后端：** 不升级活动模型，不调生产阈值；继续严格使用已登记 manifest 的字段顺序和阈值快照。
- **传感器：** 只运行离线 replay/golden 测试，不接授权实网，不执行防火墙动作。
- **前端：** 不增加“开始训练”按钮。训练在独立 Windows 仓库离线执行；需要查看时只读访问已持久化的 `GET /api/v1/training-jobs`，且不得暗示后端能编排/启动训练。
- **出口：** 在所有预登记来源分别达到 L1-P 开发/验证门槛；多种子稳定性、阈值和失败类别可说明；无训练/验证泄漏；holdout 未读。如果没通过，只能回到数据或开发配置，不进入最终验收。

### 阶段 5：锁定验收、模型导出和候选封存

**目标：** 形成可审查的候选模型；训练效果与交付工程质量同时合格。

- **远端训练仓库：** 冻结代码 SHA、数据与 split fingerprint、完整特征顺序/单位、预处理、标签映射、来源范围、阈值策略和运行时；仅在 validation 通过并冻结报告后解锁新 holdout 一次。输出逐来源及类别混淆矩阵、FPR/FNR/Recall、Macro-F1、PR/ROC、置信区间、样本数、性能、ONNX parity、文件 SHA-256 和 `model_manifest.json`。所有制品保持 `candidate_only=true`、`production_approved=false`。
- **数据集：** holdout 只用于这次最终判定。若失败，记录失败并封存该 holdout；不能针对它改阈值、过滤样本或选择另一模型。
- **本地后端：** 复用候选登记和 `POST /api/v1/models/{id}/validate`，补足 manifest 对新数据来源、split 指纹、逐源指标及未知/排除样本的校验。计划新增只读 `GET /api/v1/models/{id}/validation-report`，返回不可变评估报告及逐来源门禁结果；实现前同步接口设计、权限范围和矩阵。
- **传感器：** 暂不更新线上活动模型；验证导出的字段、单位、阈值和 ONNX runtime 与冻结合同一致。
- **前端：** Claude 实现“候选评估详情”只读视图，对接 `GET /api/v1/models`、`GET /api/v1/models/{id}`、`GET /api/v1/models/{id}/validation-report`（拟新增）和现有模型验证/发布接口；页面逐来源呈现数据与指标范围、门禁结果、缺项和 candidate-only 状态，不提供训练控制。
- **出口：** 每个验收来源均通过 L1-P，导出哈希与 manifest 一致，ONNX/训练框架概率差满足训练契约（当前目标最大绝对误差 ≤ `1e-4`），运行时/性能门槛通过，锁定评估无泄漏。任一失败则候选拒绝登记/发布。

### 阶段 6：后端、Mac/Windows 传感器离线端到端对拍

**目标：** 验证候选从 PCAP/采集到在线特征、后端校验、ONNX 推理的真实输入输出一致。

- **远端训练仓库：** 提供固定、可分发的 golden PCAP/规范流/期望特征及期望概率样本；报告来自训练程序和导出 ONNX 的逐条 parity。数据量仅够复算，不把原始大数据或权重提交到 Git。
- **数据集：** 使用训练、validation 之外公开且许可允许的回放夹具；不能复用锁定 holdout 做集成调参。
- **本地后端：** 完成模型候选导入、契约/hash 校验、dry-run 和推理台账追溯；模型故障、字段不符、未知版本和超时都明确失败，不静默退回旧模型。若支持多版本契约，按版本路由并保证 v4 不变。
- **传感器：** 将 Go/macOS 已有流构造路径和 Windows 传感器分别对拍；覆盖反向流、短流、迟到/重复包、分片/截断、超时、类别缺失、单位转换、缓冲上限和丢包计数。失败记录必须留在拒绝/规则研判路径，不伪造完整流。
- **前端：** Claude 实现“离线回放/推理核验”结果页，对接已有 `POST /api/v1/inference/dry-run` 与 `GET /api/v1/inference-requests`（后者仅显示持久化记录）；明确 dry-run 不落推理台账，显示状态/错误码而不是只显示模型分数。
- **出口：** Golden fixtures 的特征、模型概率和标签符合逐字段容差；后端和两端传感器的契约/版本/哈希一致；Windows 路径未完成时只允许标记平台范围不支持，不得宣传跨平台可用。

### 阶段 7：L2/L3 授权流量影子验证

**目标：** 用与训练/holdout 独立、来源明确的观测确认实际良性误报率和攻击召回，并观察传感器工程质量；仍不自动阻断。

- **远端训练仓库：** 只消费经过独立人工审核并批准进入候选集的标签；建立新数据版本，不回填或改写已锁定评估。漂移仅触发复核/新候选，不触发在线学习。
- **数据集：** L2 收集至少 `1,000` 条可信 Normal 和 `100` 条可信 Attack，并逐来源报 FPR≤`3%`、Recall≥`80%`；L3 还要覆盖两个独立时段、累计 `8` 个授权资产小时、可信 Normal≥`1,000`，FPR≤`2%` 且保留 L2 Recall 门槛。每条真值保留来源、时间、判据和第二人复核链。
- **本地后端：** 完成审计范围内的影子统计、反馈双人复核、模型/数据源/特征契约/策略版本关联。现有只读接口包括 `GET /api/v1/data-sources/{id}/shadow-report`、`GET /api/v1/model-drift-windows`、`GET /api/v1/inference-requests`、`GET /api/v1/feedback-samples`；人工标注与复核使用告警 feedback/review 接口。若现有报告不包含分时段可信标签分母，先设计新增 shadow-evaluation report API。
- **传感器：** 仅在书面/可审计授权的资产和接口上被动采集；报告运行时长、观测流量、丢包/截断/过载、CPU/内存和契约拒绝率。传感器不执行模型输出的动作。
- **前端：** Claude 实现“数据源影子报告”“模型漂移/推理台账”和“告警标注/第二人复核”页面；对接上列已有 shadow-report、drift、inference、feedback/review 接口。新 shadow-evaluation API 若未实现则不制作伪数据视图。
- **出口：** L2/L3 各指标、可信样本数、时段/资产覆盖和采集质量同时通过；任何指标失败或样本不足就保持 shadow-only，回到数据/模型迭代，不启用自动动作。

### 阶段 8：受控响应能力实现与小范围自动处置验收

**目标：** 在模型、数据、影子门禁都通过后，单独验证防火墙动作安全性。它是新的业务实现与授权阶段，不包含在文档整改授权中。

- **远端训练仓库：** 维持冻结推理/离线训练；不新增网络探测、攻击流生成、在线学习或模型直连系统命令。
- **数据集：** 完成至少 `10/10` 个独立规则/动作安全场景，覆盖正常放行、攻击命中、未知/越权资产、授权过期、重复动作、执行超时、适配器故障、TTL 到期及回滚/管理连接保护。当前 readiness 中此项为 `0/10`。
- **本地后端：** 实现经过目标操作系统验证的窄范围执行适配器与可证明回滚；动作仍由策略引擎校验登记资产、执行时有效授权、白名单、参数、TTL、幂等、超时、管理连接保护及审计。模型只能提供信号；符合策略的明确规则/审批流程才可产生执行请求。建立全局 kill switch、失败关闭、撤销/回滚与双人发布审批。当前 `execute` 是 503，`rollback` 未实现，不能把它们写成已完成。
- **传感器：** 若执行器需要驻留端，采用最小权限代理，只接受后端签名且目标/动作/TTL 明确的请求；本机规则设置幂等和到期清理，不能持有模型权重之外的任意凭据或执行任意命令。分别验证 macOS/Windows 防火墙和保护管理链路。
- **前端：** Claude 实现“响应策略版本审批”“动作申请/审批/执行状态/撤销回滚/审计”页面。使用已有 `GET/POST /api/v1/response-policies`、submit/decision/retire、`POST /api/v1/events/{eventId}/actions`、`GET /api/v1/actions/mine`、`GET /api/v1/approvals/ledger`；`execute`、`rollback` 接口只有后端实现和测试通过后才开放为可操作状态。
- **出口：** 10/10 安全场景通过、真实回滚已实测、授权和审批边界通过，先从显式授权的一台/一组资产、短 TTL、人工可撤销的窄范围 pilot 开始。模型指标通过不替代动作审批，动作通过也不扩大模型能力声明。

## 4. 决策树与禁止捷径

| 阶段发现的问题 | 正确决策 |
|---|---|
| Kaggle 候选体量大、许可不适用、标签无法对应逐流或没有可信 Normal | 淘汰或仅保留为攻击覆盖研究；不全量下载、不训练 |
| 数据标签可靠，但 PCAP 无法产生 v4 的准确字段/单位/语义 | 停止该数据源；或先冻结新契约版本并同步训练、后端、传感器，不能强行映射 |
| 有可信数据但分区/活动独立性不足或样本门槛不够 | readiness 继续 `BLOCKED`；增加合法独立数据或缩小项目能力范围 |
| 新数据通过，开发验证门禁失败 | 仅用开发/验证数据分析标签、特征和工作点；修订后新版本再评估，不能窥看锁定集 |
| L1-P 通过而 L2/L3 失败 | 模型保持候选或 shadow-only；报告分布边界，不启用自动阻断 |
| L1/L2/L3 都通过但动作适配器/回滚失败 | 禁止自动处置，只提供告警和人工审批 |

**不要走的捷径：** 在旧 holdout 上反复挑阈值；按文件名认定 split；把 unknown/background 自动变正常；把 accuracy/PR-AUC 的单个好数字当门禁通过；将 CICFlowMeter 或其他工具导出的字段未经对拍当作 Go 传感器特征；修改冻结 v4；模型输出绕过后端策略直接执行；将“自动处置权限”当作模型发布的附带结果。
