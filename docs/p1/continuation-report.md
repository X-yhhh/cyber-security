# P1 定向补证报告

本文保留先前数据补证及PersistentStore平台试验的历史事实。随后完成的WFP动态会话、六项非重启场景和一次另获明确授权的重启，见[动态恢复补证](wfp-dynamic-probe.md)；当前出口以[阶段裁决](stage-exit.json)为准。历史失败、旧版本及时效记录不覆盖。

本轮从首次 P1 的真实失败继续，于 2026-10-04 完成后续数据补证。任务候选收敛为 **单个 HTTP 服务入站慢请求/连接滥用**，执行范围为 Windows / IPv4 / TCP / 同一对端与本机服务端口。数据可行性出口通过；**P1 整体仍为 `blocked`**，因为 Windows 跨重启 TTL 截止时效未通过，Mac 自动能力也未实测。[阶段裁决](stage-exit.json)分别记录数据和平台结果。未获得生产自动资格。

## 平台实测

[可复算平台报告](continuation-platform.json)绑定连接结果、实际规则删除事件、环境、源码、契约和证据哈希。

| 项目 | 结果与限制 |
|---|---|
| Windows 程序启动 | 原 unsigned canary 的相同 SHA-256 实际启动成功；历史 4551 未再现，原因未知，不能声称修复了 SAC |
| 抓包依赖 | 官方 Npcap 1.89 安装，签名有效，admin-only；实际抓到 Tailscale 接口的 Raw IP（DLT 12），不能当 Ethernet 解码 |
| 网络隔离 | 专用 canary 程序禁止主动外联；入站仅允许授权 peer 和两个专用高端口；第三端口监听期间连接超时；保护 SSH/Tailscale |
| 窄阻断 | 独立命名空间，对端 + 本机服务 + TCP + 入站；既有和新目标连接被阻断，控制端口维持正常 |
| 30 秒到期 | 实际删除事件相对到期点为 +0.286 秒；恢复后新目标连接成功 |
| 进程退出 | 终止专用探针 PowerShell 后独立清理有效；删除比到期早 0.700 秒，体现任务计划的秒级精度；不是生产检测器崩溃验收 |
| 控制连接断开 | 首次试验有一条 1.5 秒控制回显超时，保留失败；3 秒超时的复试全部连接检查通过，删除比到期晚 0.317 秒；首次超时原因未证明 |
| 重启恢复 | 首次合并 Once/Boot 任务清理延迟约 593 秒，时效失败；拆分任务后，第二次启动后 25.897—25.911 秒自动删除 5 条规则 |
| 重启时 TTL | 第二次阻断规则仍比原定到期晚约 19.654 秒删除。只证明启动清理可行，**严格跨重启 TTL 未通过**；不能给生产自动资格 |
| 结束清理 | 6 个本任务命名空间全部核验：规则 0、任务 0、专用试验进程 0；sshd/Tailscale/MpsSvc/Npcap 运行 |
| 系统边界 | SAC 仍为 1，未修改执行策略；三个防火墙 profile 开启、默认入站 Block/出站 Allow。首次重启前后非本任务规则快照有 10 条新增/14 条消失，不能声称整个防火墙完全不变 |
| Mac | 仅首次只读预检；未验证 PF 阻断与恢复，不能授予 Mac auto 能力。Windows 授权不延伸为 Mac 提权授权 |

两次重启均已结束。后续按用户补充要求优先采用进程级故障试验，不再主动安排重启。杀进程可测试崩溃/通道中断，无法代替真正的开机触发与持久规则重载验证。

平台结论是 `feasibility_demonstrated_with_limits`：Windows 有窄规则与独立恢复的真实可行性证据，P5 仍须实现账本、可信时钟、恢复状态机和接受新命令前的清理门禁，并满足严格时效。未验证的 IPv6、出站动作、限速或全网防护不能随之启用。

## 数据与正常任务

IoT-23 已有 5 个完整捕获及 196,146 条发布者标签，150 条抽查包括失败。原 Mirai 的 12 条零包 DDoS 记录，在精确起点和 ±1 微秒窗口内各找到 1 包；±1 毫秒会混入 4—11 包。无 SYN、连接 epoch 与攻击起点仍不明，未改原计数、未授予监督资格。Torii 两次捕获的 60 条补充抽查分别有 2/1 条不一致；C&C 不能因此改名为已验证的入站连接滥用。

CIC 两个完整工作日已获取并核验，共 22,260,098,668 字节（约 20.73 GiB），没有重下已确认分段。末尾停滞分段在保留账本后重新连接完成。周三 MD5 与用户登记后取得的官方文件一致；周五 MD5 与镜像文件一致，官方独立核验仍未完成。两者均记录全文件 SHA-256，注册资料、Cookie、原始地址和原始数据不进入 Git。

两份 `.pcap` 实际都是单接口 PCAPNG。初次解析明确拒绝，补齐块首尾长度、接口、时间精度和容器校验后，完整读到周三 13,788,878 帧、周五 9,997,874 帧；无 snap 截断，分别有 12,654/7,094 次文件时间回退。P2 必须按同一有界水位处理，不能离线全局排序后冒充在线能力。

预先固定的周三 76 条、周五 35 条抽查 **111/111 关联匹配**，包含 50 条攻击、51 条 BENIGN、10 条 Attempted。匹配指五元组时间窗口、双向包数及 TCP 载荷量一致，不代表全量标签或自动资格通过。周三/周五的 BENIGN 抽查中，只有 11/13 条同时满足起始单 SYN epoch、无卸载大包和无连接内时间回退；同攻击目标正常连接对应 4/7 条。失败质量不被删除，避免用其他主机的大流量正常连接掩盖目标服务样本不足。

20 条 Slowloris 起点样本全部可关联。初版错误地套用 2018 的数字头值模式，得到 0 个候选；去敏载荷形状核对及 2017 发布者说明证明应匹配字面 `X-a: b`。保持同一组样本和标签修正探针后，**5 条满足结构起点条件，15 条保留未通过**。起点相对首包为 0.200、1.033、27.043、44.078、46.424 秒；其中 3 条可在发布者观察窗口内对应后续 1s、5s、50s 时刻。另 2 条候选调度时刻超过标签窗口最后包，不能把最终流时长当实时结束真值，须由 P2 的 Tick/FIN/RST/idle 与续段规则判定。旧报告、旧代码和形状诊断均保留。

这证明存在可解释的因果起点方案，**未批准整类或全量 prefix 标签**。Attempted 单独保留；普通 GET 和最终攻击标签均不能向过去传播。匹配字符串只在标签旁路，不能输入模型或用于声称模型收益。详细规则见[补充标签策略](continuation-label-policy.md)，预算见[预算决策](continuation-budget.md)。

修正表共有周三 496,641 行、周五 547,557 行，均无整行重复、空字段、负时长或零包行。周三一个零时长行的两个速率字段为非有限值；不导入这些旧表特征做训练。五元组标识重复分别有 49,603/52,015 个，可能是新 epoch 或 120s 续段，P2 不能把它们直接当独立连接或重复删除。

独立活动方面，仅核验了 CSE-CIC-IDS2018 2018-02-15 活动的官方/修正说明及公共归档可获取性，约 41.28 GB 原件未下载、未审包、未分配 final_test。所有已查看的 CICIDS2017 活动保持开发暴露。第一轮 P2 预算最多 100,000 个 parentConnection，先建立活动/连接/重复分组；来源混淆、跨活动泛化和模型相对规则收益留给 P2/P3/P6 实测。

授权 Windows 良性 HTTP 任务使用固定内存夹具，执行顺序下载、四路并发、中断后 Range 续传与控制端口下载。第二轮 8 项有 7 项内容 SHA-256 核验通过，1 项并发超时保留为合法任务失败；共验证 1,835,008 字节。抓包 2,958 帧、9 个 TCP 五元组，原始 IP 字节 2,275,807，授权端点/端口范围全部通过，原生丢包和接口丢包均为 0。

第一次尝试整段 4 MiB 下载未在有界期限内完成；其 Windows 抓包统计 ABI 使用了错误的 4 字段布局，未采纳该轮丢包统计。按官方头文件改为 6 字段后第二轮才取得有效统计。后续修正 Python 参考统计中 SYN/SYN-ACK 混计的问题，并用相同抓包重新计算，9 个连接未见卸载大包。所有失败原件和旧审计保留。这些小规模任务只补充正常并发、慢传输与恢复边界，不能代表所有桌面更新和生产误伤水平。
