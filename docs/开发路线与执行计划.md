## 0. 摘要

- 项目拆为两条线，只通过“模型交付包”对接：
  - **模型线**（`training/windows-cuda`）：完成毕设模型训练，并证明模型能接入后端使用。
  - **功能线**（`main`）：前后端功能尽量完整，每个实体该有的增删改查都要有。
- 没有持续接收入站流量的服务器，真实主机影子运行回答不了“模型能不能用”。因此：
  - 模型好坏由离线三层评估判定（§3.5）；
  - 本机影子运行只看工程指标（延迟、死信、契约拒绝率、告警量）；
  - 原 G3 指标仍按原口径计算，只作报告，不作放行门槛。
- M7 处置与模型解耦：处置只由规则告警触发，一律人工审批。模型告警只作研判证据。
- 以上调整都做成可恢复的开关（§2.3）。恢复条件在读取 holdout 之前写定，满足后按计划恢复模型触发。
- 不改的东西：v4 契约、冻结规格与字段集；在线权重冻结；不在线调阈值；评估数据只用一次。

## 3. 模型线（`training/windows-cuda`）

### 3.1 目标与范围

- 目标：交付一个新的 v4 契约模型版本，在离线三层评估上达标，并在后端完成接入验收（§3.6）。
- 评估范围：`responder` + IPv4 + TCP + `handshakeSeen=true`，与 `2026.10.2` 一致。UDP、ICMP、无握手片段记为 `not_in_model_scope`，由规则引擎覆盖。
- 扫描、爆破、路径探测、UDP 突发属于多流现象，由功能线的时间窗聚合规则覆盖（§4.2），不作为模型的验收目标。
- 不变：契约 `unsw-nb15-flow-v4`、冻结规格、字段顺序、类别识别规则。新模型只换权重与 manifest。

### 3.2 数据集审核

审核标准：① 有原始 pcap，能用本项目传感器按 v4 重新提特征；② 有入站攻击，与 `responder` 视角一致；③ 有干净的正常流量；④ 许可允许学术使用。

| 数据集 | 结论 | 用途 | 依据与待核实项 |
| --- | --- | --- | --- |
| UNSW-NB15（CSV 重算） | 保留 | 训练 + holdout | 现有流程；原始 pcap 约 100 GB，按路线 B 决策 D1 不引入 |
| CIC-IDS2017 | 采用 | 训练 + holdout | UNB 页面说明面向研究者公开、要求引用 Sharafaldin 等 ICISSP 2018；提供 pcap；周一全为正常流量；受害网段 192.168.10.0/24，攻击者在 205.174.165.x，符合入站视角 |
| CSE-CIC-IDS2018 | 采用 | 只做跨数据集测试 | AWS Open Data（`s3://cse-cic-ids2018/`，`ca-central-1`，免账号）；许可条款在 UNB 页面，**使用前核实**；pcap 格式与总大小下载前确认 |
| Bot-IoT、TON_IoT | 不采用 | — | IoT 场景，与单主机传感器差异大 |
| CTU-13、MAWI | 不采用 | — | CTU-13 以出站僵尸网络为主；MAWI 无标签 |

CIC-IDS2017 的注意事项：

- 原始 CSV 标签不可直接使用。已有研究指出其存在标注错误、包乱序与重复（Engelen 等 2021；Lanvin 等 2022）。本项目按官方攻击时间表 + 攻击者/受害者 IP 自行打标签（§3.3）。
- pcap 含完整载荷，但传感器只解析到传输层头部（决策 D8），载荷不被读取、不落盘。
- `sensor extract` 目前只接受以太网链路的 pcap，使用前检查链路类型；不符时在 `internal/capture` 增加对应链路层解析并补单测，不改特征计算。

每个数据集登记：来源 URL、获取日期、许可与引用、文件大小、SHA-256、行数、标签规则版本、切分指纹。原始数据与提取结果不进 Git。

### 3.3 特征提取与标签

- 提取：pcap 经 `sensor extract -pcap … -local-addr <受害主机>` 生成 v4 记录。`ct_*` 窗口按主机计算，因此每台受害主机分别运行一次，`viewpoint` 由 `-local-addr` 决定。
- 与线上同源：训练特征与线上特征出自同一份 Go 代码，消除“CSV 口径 ≠ 传感器口径”的偏差。
- 标签规则 `label-rules-<数据集>-vN`：按（时间窗、攻击者 IP、受害者 IP、端口）判定 `Attack`，其余为 `Normal`；边界时段（攻击开始前后若干秒）的流标为 `excluded`，不进训练也不进评估。规则先写成版本文件并提交到训练分支，再用于提取，之后不改。
- 反馈样本：只使用 `training_eligible=true`（经第二人复核）的误报标注，导出时带数据集版本与哈希（§4.5）。
- 排除：路线 B §13.7 受控实验时段的数据不参与训练，避免与评估混用。

### 3.4 训练与切分

- 算法与流程沿用《模型训练计划》第 5～10 步与 §12（预处理对比、多模型初筛与调优、多种子复现、阈值策略、锁定评估、导出）。只替换数据组成与切分种子。
- 训练数据：UNSW 训练切分 + CIC-IDS2017 训练切分 + 已复核的误报反馈样本。可按数据来源设样本权重，权重只在验证集上选。
- 切分：每个数据集各自按固定新种子切 train/validation/holdout，按连接/主机分组，避免同一会话跨分区。切分指纹写入 manifest。
- CSE-CIC-IDS2018 不参与任何拟合、调参或阈值选择。
- holdout 使用规则同《模型训练计划》§4.3：每个 holdout 只解锁一次，解锁次数写入审计日志；调参只看验证集。

### 3.5 三层评估与验收门槛

| 层 | 数据 | 回答的问题 | 门槛 |
| --- | --- | --- | --- |
| L1 分布内 | UNSW、CIC-IDS2017 各自的锁定 holdout | 在训练分布上是否可用 | 每个数据集分别满足《模型训练计划》§1：Macro-F1、FNR ≤ 5%、FPR ≤ 1.5%、PR-AUC；按数据集分别报告，不只报合并值 |
| L2 跨数据集 | CSE-CIC-IDS2018（同样经 `sensor extract` 与标签规则） | 换一个网络环境是否还能用 | 良性流 FPR 与攻击召回的底线，§5 阶段 2 按验证集基线定出 |
| L3 受控流量 | Intel Mac 新一轮受控实验（新时段、新生成，良性 + 轻微攻击特征） | 在本项目传感器实际抓到的流量上误报如何 | 良性时段、握手完整 TCP 的误报流比例上限，§5 阶段 2 定出 |

- 门槛与“恢复模型触发”的条件（§2.3）在读取任何 holdout 之前写入 §12，写入后不改。
- L1 未达标：按路线 B §19.3 的思路处理，只允许调参、类别权重和阈值策略，不允许恢复已删除字段或改契约。
- L2、L3 未达标：模型仍可交付为“只告警”的版本，能力边界中如实写明；不打开模型触发开关。
- 报告必须写明：各层样本量、标签规则版本、未覆盖的流量形态，以及“受控流量上的误报率不等于真实业务流量上的误报率”。

### 3.6 交付与接入验收

- 交付包内容与现有格式一致：`model.onnx`、`model_manifest.json`（含 `feature_contract`、评估范围、`feature_baseline_stats`、数据集与切分指纹、标签规则版本）、`preprocessing.json`、golden fixtures、`checksums.json`。
- 版本号另起（例如 `unsw-cic-binary-2026.10.x`，具体命名在阶段 3 定），不覆盖 `2026.10.x`。
- 接入验收（“模型可以接入使用”的出口条件）：
  1. 后端登记 → 制品校验（manifest、哈希、契约、基线块、冒烟推理）→ 发布申请 → 他人审批 → 显式激活；
  2. `ModelReplayCli` 用交付包的 golden fixtures 回放，与训练端输出误差 ≤ 1e-5；
  3. `SensorReplayCli` 回放一段 pcap 提取结果，跑通“接入 → 推理 → 告警 → 事件”；
  4. `POST /inference/dry-run` 对回放数据源返回与离线一致的结果；
  5. 本机影子运行切换到新模型后，工程指标（延迟 P95 ≤ 50 ms、死信 0、契约拒绝率 ≤ 1%）保持通过。

### 4.2 时间窗聚合规则

阶段 1 已实现 `all` 过滤 + `window` 的受限 `count`/`sum` 聚合，按同资产事件时间 `(t-seconds,t]` 计算，窗口内抑制重复告警。窗口 10～3600 秒；仅匹配当前批次同契约记录；超出 100,000 条上下文时显式回滚并重试/死信，不以截断数据确认消费。跨批次迟到记录不会回溯修正先前候选，离线排序回放与在线乱序消费不保证完全相同。

以下表格保留需求意图。实际 v4 不含端口或载荷：当前扫描规则统计 SYN 可见但握手计时缺失的 TCP 流，不能计不同端口；SSH 规则只确认短连接突发；Web 规则为非 SSH TCP 短连接突发代理，也会覆盖其他非标准服务。`handshakeSeen` 按实现表示首包 SYN 可见，不等于三次握手完成；不得把这些规则告警直接写成已确认扫描、登录失败或 Web 路径探测。定义见 `backend/src/main/resources/detection-rules/window-rules-v1.json`，只提供待登记规则，不自动激活。


逐流模型看不出短时间内大量重复的攻击，由规则引擎按时间窗聚合覆盖。

| 规则 | 聚合口径 | 验证数据 |
| --- | --- | --- |
| 端口扫描 | 同资产、窗口内被连接的不同目的端口数 / 失败握手数超过阈值 | 路线 B §13.7 端口扫描场景 |
| SSH 登录失败 | 同资产 22 端口、窗口内短连接数超过阈值 | §13.7 SSH 登录失败场景 |
| Web 路径探测 | 同资产 HTTP/HTTPS 端口、窗口内短请求流数超过阈值 | §13.7 路径探测、HTTP 高频场景 |
| UDP 突发 | 同资产、窗口内 UDP 包数或流数超过阈值 | §13.7 UDP 突发场景 |

- 规则只用 v4 已有字段与元数据（`ct_*`、`service`、`proto`、`handshakeSeen` 等），不引入对端地址，不改契约。
- 规则条件扩展仍为受限结构，不允许脚本；新增聚合类型需要扩展 `RuleCondition` 并补单测。
- 规则经登记、他人批准后生效，阈值变更一律发新版本。
- 出口条件：每条规则在对应攻击场景时段有检出；在良性时段的误报逐条列出并可解释。这是 M7 的前置条件（§2.2）。

### 4.3 检测策略管理与告警分层

- 检测策略（`detection_policy`：分级映射、关联时间窗、风险评分参数）目前只有迁移预置数据，没有管理接口。按 M6 的做法补齐：`draft → pending → active | rejected`，起草人≠审批人，批准即生效并在同一事务退役旧 active 版本，每次迁移写带 `after_hash` 的审计。
- 告警分层：单条模型命中记为“模型信号”（低等级，不进人工队列）。满足以下任一条件才升级为告警：
  - 同一记录或同一资产窗口内规则也命中；
  - 同一资产在关联时间窗内的模型信号数超过设定值；
  - 分数高于更高一档阈值（只在 `detection_policy` 中配置，模型阈值本身不变）。
- 分层参数属于 `detection_policy` 版本，告警与事件记录所用版本；不在线调模型阈值，不改权重。
- 需要的迁移：告警等级或信号标记列（具体结构在实现前设计并同步《数据库设计》）。已有告警不回写。

### 4.4 M7 处置执行器与主机防火墙适配器

前置条件：§4.2 规则出口条件满足（§2.2）。不再等待模型 G3。

**执行流程**

1. 规则告警 → 分析员基于事件发起处置申请 → 他人审批。
2. 审批通过后写 `action_execution`（`idempotency_key` 唯一，`status=queued`）并经 outbox 下发。
3. 执行前再次校验：资产登记、授权未过期、策略仍为 active、策略 `alertSources` 与触发告警来源一致、目标不在保护名单（管理地址、网关、后端地址、DNS、本机开发 Mac 的管理连接）。任一失败 fail-closed 并写原因。
4. 传感器侧适配器执行，结果与回滚句柄写回；到期自动撤销，撤销后再次核对规则已不存在。

**适配器接口**

```java
interface HostFirewallAdapter {
    Capability capability();               // 已验证的动作与操作系统
    ExecutionResult apply(BlockSpec spec);  // 只追加窄范围、带 TTL 的阻断
    ExecutionResult revoke(String rollbackRef);
    VerifyResult verify(String rollbackRef);
}
```

- 适配器运行在传感器侧的独立最小权限进程，只接受后端签名下发的结构化任务；后端不持有主机凭据，模型不能直接调用。
- macOS：pf 独立 anchor 与 table（例如 `com.xyh.cyber/block`），只增删 table 条目，不修改主规则集、不改默认放行策略。
- Windows：`New-NetFirewallRule` 创建统一前缀 `CYBER-TTL-` 的规则，只作用于指定远端 IP。Windows 适配器在 Windows 传感器补测之后才做，可裁剪。
- TTL：适配器本地调度撤销，后端兜底扫描到期未撤销的执行记录。
- 状态：`queued → running → applied → revoking → revoked`；失败为 `failed`/`timed_out`，任何失败都触发撤销尝试并提示人工接管。
- 限速：不实现，capability 中明确标记不支持。
- 开关：`EXECUTION_ENABLED` 默认 `false`；`cyber.response.model-trigger.enabled` 默认 `false`（§2.3）；`auto_execute` 仍拒绝。

**策略匹配扩展**：`response-policy/schema/match.json` 新增 `alertSources`（枚举 `rule`、`model`，至少一项），当前服务层只接受 `["rule"]`；V15 前的策略按 `["rule"]` 解释。

**验证环境**

- 开发验证：局域网 Intel Mac（需新一轮授权），封禁目标只限本机开发 Mac 的地址，TTL ≤ 600 秒，验证 apply → verify → revoke → verify 与管理连接不受影响。
- 最终验收：网络层外联隔离的虚拟机靶场（§5 阶段 6），提供隔离证明。家庭局域网不能替代隔离证明。

**测试矩阵**：越权、过期授权、未知目标、保护名单命中、策略冲突、`alertSources` 不匹配、重复请求（幂等键）、执行超时、适配器故障、撤销失败、审批分离、TTL 到期自动撤销、后端兜底扫描、审计完整性。

### 4.5 M9 后端：训练任务台账与导出导入

后端不远程执行训练命令，只负责数据包导出和结果登记。

- 创建导出任务：管理员选择模型版本、时间范围、数据源范围；只导出 `training_eligible=true` 的反馈样本，按告警记录导出 v4 特征与元数据，不含地址、端口、时间序列明细。
- 数据包：`manifest.json`（数据集版本、样本数、标签分布、导出条件、SHA-256）+ 特征文件；写入受控目录，经人工或受控通道传到 win-dev。
- 导入结果：训练端交付包按既有候选登记流程进入（登记 → 校验 → 审批 → 激活），训练任务记录关联候选模型版本与评估摘要。
- 状态：`created → exported → training → delivered | failed | cancelled`，状态迁移写审计。
- 测试：未复核样本不导出；导出重复请求幂等；范围外数据源不可导出；导入的制品哈希与任务记录不一致时拒绝。

### 4.6 M12 回放场景与报告

**回放场景**

- `replay_scenario` 增删改查：登记公开数据集片段（来源、许可、引用、SHA-256、文件在受控目录中的相对路径、标签规则版本）。被运行过的场景不能物理删除，只能停用。
- `replay_run` 运行与控制：启动、暂停、继续、终止；在后端内部管道执行（复用 `SensorReplayCli` 的回放逻辑），只写入 `source_type='replay'` 的数据源，**不向网络发送任何流量**。
- 回放产生的告警与事件标记为演练数据，与授权实网数据分开展示与统计。
- 运行记录保存进度、处理记录数、推理/告警计数、错误；相同输入与模型版本可重复比较。

**报告任务**

- `report_job` 创建、查询、下载、删除：内容包括数据范围、模型与策略版本、检测指标（精确率、召回率、误报率、延迟，限回放数据）、告警与事件摘要、处置与审计摘要。
- 格式：HTML 与 CSV（PDF 可选）。导出时脱敏，不含凭据、原始载荷或未脱敏地址。
- 异步生成，状态 `queued → running → succeeded | failed`；报告文件存受控目录，删除只删文件和记录，写审计。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| CIC pcap 链路类型或规模与预期不符 | 阶段 2 延期 | 先抽一天的 pcap 试提取；链路层解析只加解析不改特征 |
| CIC-IDS2017 标签质量 | 训练与评估失真 | 自行打标签，边界时段排除，规则版本化 |
| 多数据集混训后 UNSW holdout 下降 | L1 不达标 | 样本权重在验证集上选；按数据来源分别报告；不恢复删除字段 |
| L2 跨数据集不达标 | 模型只能“只告警” | 能力边界如实写明；处置依赖规则，不受影响 |
| win-dev 不可用 | 阶段 3 阻塞 | 功能线继续推进；模型线准备工作在本机完成 |
| Intel Mac 授权过期或不可用 | L3 与 M7 验证延期 | 提前申请新授权；M7 核心逻辑先用单测与集成测试覆盖 |
| 规则阈值在真实流量上误报 | 告警量过大 | 阈值只在受控数据上定，良性误报逐条列出；阈值变更发新版本 |
| 时间不足 | 毕设进度 | 按 §4.7 顺序裁剪；R1 回放闭环仍是保底演示基线 |

## 10. 能力边界（最终报告须写明）

- 检测能力为基于 v4 可移植流特征的二分类，训练分布为 UNSW-NB15 与 CIC-IDS2017，评估范围为 `responder` + IPv4 + TCP + 握手完整。
- 模型只经过离线三层评估；没有在持续接收真实入站业务流量的服务器上验证。受控流量上的误报率不等于真实业务流量上的误报率。
- 扫描、爆破、探测等多流攻击由时间窗规则覆盖，不是模型能力。
- 不是原始包检测、终端行为识别或攻击阶段预测；传感器只覆盖部署主机上实际可见的流量。
- 处置只由规则告警触发、人工审批；DoS 类分类不等于 DDoS 防护，主机软件不能解决上游带宽饱和；限速未实现。
- 列出所有裁剪项与未验证项。
