## 1. 目标与架构

系统持续监测授权主机的入站流量，识别 4 类攻击（端口扫描、暴力破解、洪泛 DoS、慢速 DoS），并对确认的攻击来源实施限时、可撤销的本机防火墙封禁。

| 组件 | 只负责 | 主要阶段 |
|---|---|---|
| 传感器（Go） | 抓包、组流、计算特征并上报，不做判断 | P2、P7 |
| 检测（后端 ONNX 推理） | 对每个快照输出攻击概率与类别，不决定是否封禁 | P3、P4 |
| 规则引擎（后端） | 基于观察字段的阈值规则，作为第二条检测来源 | P3、P4 |
| 决策（后端） | 按来源汇总模型与规则结果，决定告警或封禁候选，检查白名单、授权与预算 | P4 |
| 执行器（Python） | 校验签名命令，安装/清理 PF 或 WFP 规则并回执 | P5 |

验收采用 3 道硬门槛：G1、G2 衡量模型，G3 衡量闭环；另有类别自动资格，定义见 [验证与验收](验证与验收.md)。

### P7 出口与 P8 内容

- **G3 / J3（M1 告警闭环）**：四类都经传感器 → 推理/规则 → 决策产生告警，正常场景误封 ≤ 1 次/小时。
- **G3 / J4（M2 自动封禁闭环）**：计划 M2 类别完成真实封禁、TTL 或撤销清理与执行器核验；通过的类别登记 `lab_auto`，未通过的降为只告警并写明原因。port_scan 依赖 `peer_inbound`。
- **P8**：把冻结模型与配置导入 Mac 后端，核对运行程序、模型/profile/policy/bundle 哈希、真实加载与拒绝行为；采集器、执行器、恢复器和控制面按最小权限配置起停、日志、健康与恢复路径；按 Q3（2026-10-14），真实主机（`authorized`）只激活只告警组合 r6，不产生封禁；自动封禁只在 lab 资产用 r5 演示（若冻结前另行开放 `authorized_auto`，还需目标平台短时良性任务与真实独立批准）；完成前验证启用/停用、授权撤销、模型不可用、断连、规则清理和回退。

## 5. 交付目标与保底线

| 层级 | 内容 |
|---|---|
| 目标 | G1/G2 通过；G3 中四类全部告警；port_scan、brute_force、dos_slow 三类取得 `lab_auto` 并完成真实封禁与恢复；dos_flood 只告警（2026-10-12 用户确认） |
| **保底线** | 1. 发布组合通过 G1/G2；2. **G3 通过**：四类都产生告警，正常场景误封 ≤ 1 次/小时；3. **至少 2 类取得 `lab_auto`**，在 Mac lab 完成真实封禁、TTL 或撤销清理、执行器核验，其中必须包括 brute_force；4. P5 的 Mac 必需场景全部通过；5. 未取得 `lab_auto` 的类别写明原因和后续路径 |

“四类只告警”不是可接受的交付结果。保底依据：第二轮候选单对端敏感性为零；brute_force 使用 `peer_service` 作用域，不依赖全入站豁免，其资格只取决于模型来源（离线 recall 99.33%、precision 100%）。

| 触发情况 | 保底处理 |
|---|---|
| G3 某类自动封禁未通过 | 按失败环节回 P4 或 P5 修复后重跑该类；修复不了的类别降为只告警（改策略即新 subject），剩余通过类别 ≥ 2 即达保底线 |
| 方案 B 预演或克隆 G3 中任一拟自动类别未通过 | 停下报告，由用户决定修代码或降级；不调阈值、不重跑挑结果 |
| port_scan 的 `peer_inbound` 出问题 | 先保 brute_force 与 dos_slow（`peer_service`）；port_scan 降为只告警 |
| dos_flood 质量覆盖不足 | 只告警，不放宽 `offloadSuspected` |
| brute_force 在 G3 不能封禁成功 | 保底线不可达，停止推进 P8，回报失败环节和证据，由用户决定 |

- 不训练或微调大语言模型；检测与处置不依赖外部大模型 API。
