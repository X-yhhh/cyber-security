### BE-1 健康协议 1.1.0 实现

口径（写入契约正文）：1.1.0 = 1.0.0 全部字段 + 必填 `captureSource ∈ {live, file_replay}`。`live` 与 1.0.0 判定相同；`file_replay` 要求 `kernelDrops` 必须为 null（不适用而非未知）、`packetsSeen` 与 `capacityDrops` 已知且前者不回退、后者不变，`captureGap=false`，其余时钟、窗口、哈希链与身份规则同 1.0.0，通过时 `verification_status="replay_healthy"`。T2（判定与领取复核）只有在组合 subject 的 health 为 1.1.0、观察 `environment=lab`、该 sensor/boot 归属 running 且 `evidenceKind=lab` 的会话时，才把 `replay_healthy` 视为健康；`proof()` 与预算恢复只认 `healthy`。

### BE-13 持续攻击下封禁维持时间（签发后保持）

根因（业务库 G3 审计核对）：命令在 `applyBy`（签发后 5 秒）前的每次领取都会重发，并重新执行领取复核；6 次撤销都发生在签发后 1.0—3.0 秒，此时执行器已回执 applied（签发后 0.2—0.4 秒），但后端还没完成 applied 核对。持续攻击产生的同 parent 新快照使选证不再是最新的，于是判为 `EVIDENCE_STALE` 并撤销。

2026-10-13 用户决定（Q1）：`GuardActions.claims` 与 `filterClaims` 对“执行器已回执 applied 或动作已核对为 applied”的命令不再重发、不再复核，也不因此撤销；规则保持到 TTL，期间撤销只经显式路径。尚无回执的命令保持原有复核。以[检测与处置契约](../检测与处置契约.md#81-判定次序与发布绑定) 8.1 的 BE-13 注登记，不升决策协议、不改 r5 subject，r5 的 `lab_auto` 不重新登记；以克隆 G3 复验非扫描规则保持到 TTL。单测 `GuardReplayClaimsTest` +4（已回执两种情形、无回执仍撤销、显式停止仍撤销），撤掉修复后其中 2 项失败。

复验中暴露的回执竞态（2026-10-14）：clone-p0-04 里 9 条规则全部保持到 TTL（59—60 秒）、撤销 0 次，但有 4 段的 expired 回执晚于核对到达，动作已被核对判为终态，回执不能投影，报告为 `unverified`。`GuardReceipts.project` 改为对同一终态的一致回执补记已核验（契约 8.1 回执补核验注），`GuardIntegrationTest` +1，撤掉修复后失败；`mvn verify` 571 项 0 失败、70 跳过（新增集成测试被两个按环境变量禁用的子类继承，跳过数 +2）。
