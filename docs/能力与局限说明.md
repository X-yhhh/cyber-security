## 1. 初版口径

- **真实主机只告警，自动封禁只在 lab 演示**。P8 按 Q3 使用 r6 的 `authorized/alert_only` 组合；r5 的三类 `lab_auto` 资格只适用于其绑定的 lab 环境、平台与来源，演示仍须满足执行时有效授权、资产绑定、质量、健康、预算及保护范围。历史通过不自动授权下一次运行。[依据：开发路线 Q3、Q4 与第 2.1 节](开发路线.md)，[E2、E4](#7-证据索引)。
- **现场观察为一次 30 分钟样本，相关指标只报告**。告警率、健康窗口占比、质量合格比例均须标注“30 分钟样本、只报告”；当前尚无此次观察结果。无完整真值的被动流量不能支持分类正确率或误报率结论，长期稳定性留待 BE-10。[依据：开发路线 Q8](开发路线.md)，[后端任务 BE-8、BE-10](任务/后端.md)。
- **初版只放宽模型容错，不改模型、阈值和冻结策略**。此处“放宽”是允许带着已披露的检测缺口交付，现场上述报告项不设通过门槛；链路、安全与健康判定正确性仍是硬条件。能力或阈值升级通过新的、经审查批准的发布组合接入，不改写既有权重的历史成绩。[依据：初版任务单第 0 节](任务/初版落地任务单.md)，[开发路线 Q8、Q9](开发路线.md)。
- **锁定测试集只剩 1 次使用机会**。L1 test 已用 2/3，第一轮拟合 33/33、第二轮 1/1 均已用尽；D1 不训练、不调阈值、不读取 test，不以编写说明消耗剩余额度。[依据：模型记录第 0、10 节](模型训练与评估记录.md)，[验证与验收第 7 节](验证与验收.md)。
- **模型分数、离线判定、实际 OS 动作分别报告**。概率不是已校准的现场攻击概率；离线 recall/precision 不等于动作资格；PF 执行及清理证据也不等于在攻击负载下维持服务可用的证据。[依据：数据与模型方案第 6 节](数据与模型方案.md)，[验证与验收第 3—6 节](验证与验收.md)，[E1—E3](#7-证据索引)。

## 3. 逐类能力与限制

表中“可自动”仅指已取得相应资格的**模型来源**，每次执行仍需完整门控。`peer_inbound` 为限定对端的入站范围；`peer_service` 还须限定授权服务端口，不接管默认放行策略、不覆盖既有规则，并保护管理/恢复路径。[依据：检测与处置契约](检测与处置契约.md)，[E6 资格门控](#7-证据索引)。

| 类别 | 能检测什么 | 能自动做什么、在哪个环境 | 证据 | 不能据此宣称什么 |
|---|---|---|---|---|
| `port_scan` | CIC-IDS2017 的端口扫描模式，包括 Friday PortScan / Thursday 内部扫描；L1 模型 recall 99.2550%、precision 100.0000% | r5 / Mac 回环 lab：模型来源可按 `peer_inbound` 签发窄范围 TTL 封禁并清理；真实主机 r6 只告警。`scan-ports` 规则仅离线合格，G3 只作诊断，不能自动 | E1、E2、E3；[类别定义](数据与模型方案.md) | 不证明对所有扫描工具、速率、协议、主机或全网有效；原始连接可判定覆盖 85.39%，也不授予主动扫描能力 |
| `brute_force` | FTP-Patator / SSH-Patator 对应的入站流行为；L1 模型 recall 99.3341%、precision 100.0000% | r5 / Mac 回环 lab：模型来源按 `peer_service` 限定对端及授权端口封禁；真实主机只告警；`brute-starts` 规则不能自动 | E1—E3；[类别定义与规则](数据与模型方案.md) | 不检查登录口令或认证成功，不证明其他协议/低速凭据攻击的覆盖；规则 test precision 仅 3.4813%，不能用规则高 recall 代替可靠阻断证据 |
| `dos_flood` | Hulk / GoldenEye / LOIC 对应的洪泛流模式；合格 L1 子集模型 recall/precision 均为 100.0000% | **仅告警**，r5 lab 与 r6 真实主机均不自动。正式 G3 首先被 offload 质量门 T2 `QUALITY_UNSUPPORTED` 拦截；冻结策略关闭自动门另由 D5 门测证明 | E1、E2；[系统记录第 6.7 节](系统实施记录.md) | 不证明全部洪泛连接均可判定：总覆盖 19.38%、Hulk 9.34%。不能声称抵御分布式洪泛、修复饱和带宽或已验证攻击期间服务可用 |
| `dos_slow` | 仅覆盖**单一来源多条并发慢连接占用 HTTP 服务**，来源为 slowloris / Slowhttptest；L1 模型 recall 99.5249%、precision 100.0000% | r5 / Mac 回环 lab：模型来源按 `peer_service` 限定服务端口封禁；真实主机只告警；`slow-starts` 规则不能自动 | E1—E3；[模型记录第 12 节](模型训练与评估记录.md) | **L3 受控慢速检出 0/29**；不支持单连接慢请求、一般慢客户端与正常长轮询的可靠区分，不证明跨对端或现场泛化；持续攻击超过 TTL 的续封未验证 |
| `normal`（正常对照） | L1 内部正常与网站正常对照；L3 困难良性 0/42 告警；两次 G3 各 49.7 分钟正常场景 0 误封 | 正常对照不应形成封禁；真实主机全部只告警，不会因模型 normal 分数获得额外动作权限 | E1—E3；[E6 动作入口](#7-证据索引) | 有限样本的 0 次不是零风险保证；网站正常为客户端视角，不能等同于服务器入站正常流量；两次复用场景不累计为独立长期观察 |

## 4. 离线成绩及其分母

### 4.1 L1 锁定测试成绩

P6 第二次评价 `p6-l1-02`（2026-10-10）使用 79,177 个快照、51,749 条连接；计数和去重遵守冻结评价计划，快照并非独立执行证据。G1 四攻击类等权检出率 **99.528524%**，正常来源等权 FPR **0%**；G2 五类 macro-F1 **0.996283**，均通过。FPR 的实际计数为内部正常 0/1,880、网站正常 0/9,631；不能把有限样本的 0% 外推为新环境保证。上述数值是离线模型判定成绩，逐类数值见第 3 节。[E1；统计定义：验证与验收第 3、4 节](验证与验收.md)。

## 6. 泛化、健康与真实主机边界

### 6.1 数据与泛化

- **L1 可能偏乐观**：CIC 同类工具跨训练/验证/test 出现，validation 已多次使用；网站正常补充为客户端视角，服务器入站正常 HTTP 的约束较弱。高 L1 分数不证明未知工具、新主机或不同正常负载的表现。[E1；模型记录第 5.4、10、12 节](模型训练与评估记录.md)。
- **单对端敏感性为零有特定含义**：第二轮候选删除主机上下文输入，对这些上下文字段的敏感性为零；不等于所有对端、并发和现场分布下性能相同，也不消除 CIC 同工具跨集合的影响。[模型记录第 9、12 节](模型训练与评估记录.md)，[E1](#7-证据索引)。
- **L3 检测失败必须披露**：571 个快照、71 条连接中，慢速攻击检出 0/29，困难良性告警 0/42。来源此前已检查，样本小、单对端且低并发；不是新的独立 holdout，既不能证明一般慢速能力，也不能通过 L1 高分掩盖漏检。训练中慢速攻击来源与内部正常 HTTP 样本也少，同一来源多个时间桶不等于独立来源。[E1；模型记录第 10、12 节](模型训练与评估记录.md)。
- **L2 未评估**：CSE-CIC-IDS2018 没有可交付成绩，不宣称跨数据集泛化。L3′ 新采集、后续离线候选和新组合均须各自评审与授权；不以新增数据静默修改冻结模型。[模型任务 ML-4、ML-5](任务/模型.md)，[开发路线](开发路线.md)。
- **双端数值一致性只证明推理对拍**：79,177 行 Mac/Windows ONNX 最大概率差 `6.556510925292969e-07`，类别/告警翻转均为 0；不能据此认定 Windows 抓包、现场健康或 WFP 自动执行可用。[E1；模型记录第 10 节](模型训练与评估记录.md)。

### 6.2 回放健康与现场健康

### 6.3 人工确认不能绕过只告警

当前 v2 人工路径是**已有合格候选 + 人工确认**，不是任意普通告警转封禁。代码依据如下（E6）；D1 仅检查实现，不新增动作能力。

1. [GuardDetection.java](../backend/src/main/java/com/xyh/cybersecurity/guard/GuardDetection.java) 仅在无拒绝原因且结果为 `block_candidate` 时进入动作路径。
2. [GuardActions.java](../backend/src/main/java/com/xyh/cybersecurity/guard/GuardActions.java) 的 `manual()` 要求已有判定为 `block_candidate`，普通 alert 触发 `ACTION_EVIDENCE_REQUIRED`；创建前仍调用 `recheck()` 重查证据、资格、授权与预算。
3. [GuardEligibility.java](../backend/src/main/java/com/xyh/cybersecurity/guard/GuardEligibility.java) 的 `authorized()` 在自动化关闭、策略 `alert_only` 或资产/组合/绑定/执行器/授权不满足时拒绝；`matchingCapability()` 在 authorized 环境只接受 `authorized_auto`，不能借用 lab 的 `lab_auto`。

因此现有路径不提供 r6 真实主机普通告警的封禁入口；控制台权限或人工确认不能替代发布资格与执行授权。[E6；检测与处置契约](检测与处置契约.md)，[开发路线 Q3](开发路线.md)。
