## 2. 任务说明

### DB-1 r5 业务库导入

1. 随机 schema 全流程演练，删除后核对业务库不变。
2. 整库备份 `backups/20261012-cyber-security-r5/` → 恢复演练逐表一致。
3. 后端（BE-1 合入后的 jar；默认 profile、自动化关闭、仅回环）登记 r5：复用既有模型、评价计划、4 条 lab_auto 能力与已审查策略 `6adcb0d0…`（不重新登记、不重新审查），`protocolVersions.health=1.1.0`。
4. `p6-evaluator/2026-10-10` 为 r5 subject 签发正式 final 后导入，停在 candidate；`e3_bootstrap.check_candidate(formal=True)` 只读通过。

**验收**：变动表只有 `guard_release_bundle` +1、`guard_bundle_capability` +4、`guard_evaluation_run` +1，以及 `guard_idempotency`、`audit_log`、会话表与登录字段；Flyway 仍为 25；r3/r4 行不变；记录 r5 bundleId 与 subject。

### DB-2 r5 封存与独立批准

参数化 `.cache/a6-20261012/run_seal.py`：演练 → 备份与恢复演练 → 导入 BE-3 产出的 platform/canary → 以 final+platform+canary 封存 → `guard-reviewer` 独立批准。**验收**：r5 approved、未激活、无资产绑定；变动表与 2026-10-12 A6 封存同口径。

### DB-3 正式 G3 的业务库写入
