# 项目详细设计

版本：host-guard v5，更新于 2026-10-06。P1/P2 已完成并收口；本文件描述 P3—P8 的目标系统，实现差距见[现状与迁移](现状与迁移.md)。观测格式沿用 rc.2，新决策、评价和健康证据版本见[统一契约](检测与处置契约.md)。

## 1. 产品目标与能力

系统持续监测授权主机的入站流量，由模型识别攻击类别，对确认的攻击来源实施限时、可撤销的本机防火墙封禁。首版完成标准：模型在离线评估中达到 G1、G2，并在 lab 中完成“传感器 → 模型 → 决策 → 执行器 → 自动恢复”的 G3 闭环，定义见[验证与验收](验证与验收.md)。模型与仅规则的对比作为量化报告，不作为通过门槛。

识别范围为入站 IPv4/TCP 的 5 类：`normal`、`port_scan`、`brute_force`、`dos_flood`、`dos_slow`（[类别映射](数据与模型方案.md#1-任务定义)）。Web 应用攻击、Bot 回连、UDP 攻击不在本版范围；DoS 类分类不意味着能解决上游链路饱和。新增类别另行版本化。

能力按 `(platform, adapterVersion, addressFamily, protocol, direction, attackFamily, featureProfile)` 注册，独立取得 `research / alert_only / lab_auto / authorized_auto / suspended` 等级；某一类只告警不阻塞其他已验证类别。当前 v5 全部为 research。

## 2. 根因与裁决

| 旧限制 | v5 裁决 |
|---|---|
| 围绕历史 UNSW 字段和响应端挑数据 | 按主机观测和攻击行为定义输入 |
| 100 条完成流暖机及约 61 秒释放等待 | 正在进行的流和因果时间窗；完整流用于复核 |
| 规范记录没有执行目标 | 统计特征与受保护目标引用分开 |
| 同资产不同对端合并、计数抬高风险 | 执行证据绑定对象；快照去重，排序和阻断资格分开 |
| 训练等待全部影子门禁 | 开发数据合格即可实验；发布再验收整链 |
| 最后才开发执行器 | P1 平台探针已收口；P4/P5 分别完成后端与生产适配器 |
| 改时长或身份后称为新独立样本 | 完整 parent、共同早期轨迹及来源上下文一起归组 |
| 活动结束就清空动作预算 | 稳定真实目标账本跨活动，持续健康与到期后冷却均证明后恢复 |
| 每个统计桶重置攻击起点 | 原始活动起点固定，时延从活动起点计算 |
| 单连接前缀二分类、只覆盖慢速攻击 | 多分类，按来源汇总多条连接的证据后再决定封禁 |
| 模型须在统计上证明优于规则才算通过 | G1—G3 硬门槛；规则对比只报告；不达标类别降为只告警 |

## 3. 总体架构

```mermaid
flowchart LR
  P[公开 PCAP 离线读取] --> X[Go 统一因果特征提取器]
  S[授权接口被动采集] --> X
  X --> O[观察记录与本地目标引用]
  O --> I[接入与有界检测队列]
  I --> M[Java ONNX 推理]
  M --> D[来源汇总与自动策略]
  O --> RE[规则引擎]
  RE --> D
  D --> A[签名短期命令]
  A --> E[主机最小权限执行器]
  E --> R[规则核验与到期恢复]
  D --> DB[(MySQL 事实与审计)]
  R --> DB
  H[连续采集健康旁证] --> B[稳定目标预算账本]
  R --> B
  B --> D
  T[Windows 离线训练] --> V[候选及独立验收]
  V --> M
```

控制面保持 Spring Boot 模块化单体。首版只支持本机 ONNX，远端推理不列交付依赖。RabbitMQ 承担已持久化观察/决策通知，MySQL outbox 保证可靠发布；队列拥堵不得使过期证据产生新阻断。Redis 不承担事实、唯一幂等或恢复。

部署目标是用户自有环境的可用系统。Windows负责离线训练，模型及配套配置导出到Mac的现有后端或本地推理入口；不要求对外发行、独立安装包或程序代码签名证书。后文“发布组合”用于内部版本登记和能力启用，命令签名用于验证处置来源，均不表示需要购买软件发行证书。

Go 采集/特征进程无防火墙权限。执行代理单独身份、进程和本地恢复账本，只允许白名单动作，不接受任意命令、URL 或模型调用 shell。执行代理通过受鉴权本地通信核验采集器建立的目标引用。

## 4. 三条数据路径

### 4.1 在线检测

1. 机器身份绑定资产、接口、环境、配置版本；下发配置只收窄本地授权。
2. 同一 Go 提取器生成 prefix/final 及时间窗，`asOf` 之后报文不能进入快照。
3. 后端去重、校验契约/质量；有效快照进入 ONNX，其他记录写拒绝/不适用原因。
4. 模型输出攻击分数、各类分数与适用性；规则引擎并行输出命中结果；两者都不输出防火墙命令。
5. 决策按来源汇总同类证据，结合目标新鲜度、发布能力和稳定预算账本判定 `observe / alert / block_candidate`；健康旁证与模型输入分开。
6. 有效授权和自动策略才可形成命令；执行时复核授权租约、签名、期限、保护目标和平台能力。
7. 保留 observation、model、policy、authorization、command、receipt 不可变引用及哈希。

### 4.2 离线研究

PCAP 作为文件输入，不通过网卡发送历史攻击报文。离线按原始事件时间推进；倍速只减少墙钟等待，不压缩窗口。标签只用于训练/评估，不进入特征/策略。完整测试集不参与开发选择。

研究队列、身份、部署、目标命名空间与真实执行路径隔离。离线结果不能解析到现实目标；联合测试使用另行登记且网络隔离的 canary 映射。离线评价以连接为单位计算 G1/G2，无观察或被排除的样本单列数量与原因。

### 4.3 动作验收

隔离环境普通 TCP 服务产生无害连接。冻结回放经过真实模型和同一策略形成测试命令，专用映射绑定 canary，不把 PCAP 地址写入现实规则。验证目标连接阻断、其他连接正常、TTL 后恢复。只证明链路和执行，不声称经历真实攻击利用。

## 5. 检测与动作时效

记录 `attackOnset`（仅评估真值）、`asOf`、`receivedAt`、`decisionAt`、`appliedAt`。分别报告攻击开始到检出、证据满足到规则生效，不能只报入库到 ONNX 耗时。

prefix 在连接持续 1 秒、5 秒及之后每 5 秒生成（必须有新增报文），结束生成 final；上下文按 1/5/30 秒。首版不承诺阻止第一包或瞬时利用。任何确认期均计入检测延迟。

证据距当前最多 10 秒、命令签发后应用期限最多 5 秒、目标引用最晚到 lastPacketAt+15 秒。这些新鲜度限制与攻击起点到告警/封禁的时延分别记录；时延按类别报告（扫描、洪泛参考 ≤ 10 秒，暴力破解、慢速 DoS 参考 ≤ 20 秒），不设门槛，见[报告指标](验证与验收.md#6-报告指标不设门槛)。时钟偏差不可测或超过 1 秒禁止新自动动作；断连时本地恢复器继续清理已有规则。

默认 TTL 30 秒、硬上限 60 秒，同一稳定真实目标累计最多 120 秒，所有能力共享每资产 10 个未终结动作/每分钟 5 个新动作额度。更换 boot/capture/keyEpoch/策略不能刷新额度。只有实际清零、从最后到期及最后合格证据起连续健康至少 120 秒均得到证明，才事务恢复预算；连续健康观察器接入前，额度用尽的目标只能经核对与人工批准恢复。

## 6. 策略与研判

告警阈值和自动阻断阈值独立。`riskScore` 用于排序，`attackScore` 是模型输出，`blockPrecision` 是评估结果，三者不可互换。同一连接的多个快照不能当作多条证据；规则与模型证据分别记录。各类阈值与 `minDistinctFlows` 在 validation 上选择并冻结。

自动模式由策略发布时授权，无须逐动作人工点击。策略外、高影响、范围外事件只告警/人工处理。人工批准不能覆盖目标不明、保护目标、过期授权和无回滚能力等硬约束。

## 7. 部署与治理

- Mac 控制面、双平台代理、Windows 离线训练职责分离。沿用 P1 已收口的平台结论；新制品在目标机核验，不能绕过系统策略。
- 默认不保存载荷。地址只用于关联和定位，原始目标映射保留在本机受控账本；控制面只持资产内假名标识和短期引用。
- 防火墙只作用于登记资产自身流量，不操作远端设备。共享出口、网关、DNS、管理链路默认保护，不把公网 IP 等同一个人或设备。
- 对已有连接的影响由平台实测；只能阻止后续新连接的适配器只能发布该能力。
- 审计追加，反馈经复核后进入离线候选数据；禁止伪标签在线训练。
- P3—P8 不包含前端；用 API、CLI 与受控 run 报告完成验收，docs 原位维护规范。
