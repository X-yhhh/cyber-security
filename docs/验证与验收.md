# 验证与验收

更新于 2026-10-05。P1/P2 已完成并收口；本文统一 P3—P8 的验收口径，采用 `host-guard-evaluation/2026-10-05.2`。当前 P3 新计划尚未完成实施、数据准入与拟合，尚无通过的新 prefix 最终评估或联合自动能力。阶段状态以 [开发路线](开发路线.md) 为准，不重复保留旧实验报告。

交付面向自用，不要求前端、持续入站影子运行、独立安装包或程序发行证书。内部命令鉴权、实际推理、目标范围、到期与恢复仍是必须验证的能力。

## 1. 验证层次

| ID | 环境/输入 | 证明内容与边界 |
|---|---|---|
| V1 数据与因果特征 | PCAP、标签、golden、完整时间线 | 可复算、无未来信息、角色/重复隔离；不能证明模型准确 |
| V2 独立模型/策略 | 未暴露 final_test、冻结 pipeline | 声明行为及来源上的候选覆盖、精确率和误伤；不能代表任意网络 |
| V3 连续时序回放 | 原事件时钟、稳定目标、健康旁证 | 证据/时效/TTL/累计预算与恢复；不能代替现场墙钟延迟 |
| V4 短时良性任务 | 授权主机/接口上的明确业务 | 采集可用、正常任务影响；未标注背景不自动算正常 |
| V5 动作与故障 | 网络层隔离的无害 canary | OS 规则范围、连接效果、到期、撤销、故障恢复 |
| V6 联合闭环 | 真模型/策略 → 映射目标 → 实际适配器 | 完整接线和真实时间；不宣称承受真实漏洞攻击 |

PCAP 由文件读取器消费，不向网卡注入攻击报文；V5/V6 不运行攻击工具、漏洞利用或恶意软件。隔离需接口/路由/防火墙证据。V6 固定 1 倍速和单次时间 offset，详见 [回放契约](检测与处置契约.md#11-回放隔离与版本升级)。

## 2. 预登记与阶段资格

每次评价锁定 evaluationPlanId/hash，包含机器/决策/评价/健康版本，scope/profile、behaviorScenario 与来源用途、角色/分组/标签时间线、模型/校准/策略、目标预算初值与健康旁证、时效、固定机会分母、动作去重、配比、指标/区间、停止条件和代码身份。报告逐项绑定，不能用名称相似的旧计划替代。

| 阶段 | 入口与通过要求 |
|---|---|
| P3-A/C 训练前 | 无拟合完成完整策略可达性；四开发角色都有正负与两行为；独立开发≥5攻击组/5良性组；新运行计划、角色和健康/预算核验通过 |
| P3-D/E 可行性 | train仅诊断；选型/校准/独立开发分别逐行为完整策略自动处置期及时覆盖≥80%、人工移交连续性≥80%，登记良性错误机会与错误候选均为0；支持来源分别达标；E5收益成立与ONNX对拍通过 |
| P6 独立最终评价 | P3完整组合锁定，另用未暴露活动，一次评价；满足第4节离线可验证指标和样本要求 |
| P7 联合自动资格 | P4、相应平台P5、相应能力P6通过；实际模型/策略/规则/恢复联合验收，不复制离线时延或另一平台结果 |

八次采集不是八个独立组；最低 5+5 只是 P3 起步条件，不证明统计充分。选型/校准结果注明参与过选择，不能称无偏；独立开发用于修正后登记暴露并换新组。P3 不需要先备齐 P6 的 100/3000 样本。

仅诊断来源须在拟合前登记，不计入支持格子或用来宣称通过；支持来源失败不能被同一行为的合并均值掩盖。若支持范围调整，重新登记角色和能力，不能看过最终成绩再剔除失败来源。

## 3. 统计单位、时钟与公式

### 3.1 分母与覆盖

- connection 是完整 parentConnection，多个 prefix/final/续段不能当独立连接或执行证据。
- activity 是有真值依据的原始行为活动。按其原始起点，将同目标的有效标签时间线切为 `[start+30k, min(start+30(k+1),end))`；末段不满30秒仍是一个机会。边界、目标和排除规则在评分前冻结。
- attack episode 是上述攻击机会，benign opportunity 是同口径正常机会。二者的 30 秒是统计分箱，不是新的攻击起点。同一活动的桶高度相关，不能当独立试验。
- 分母不依赖输出观察或高分。无观察、起点后证据迟现、冷启动、引用失效、预算拒绝或 pipeline 失败仍保留。ambiguous 等不适用区间只能按事前规则排除，单列数量/原因，不能评分后排除。
- action 合并幂等重试和同一目标 TTL 内重复触发；续封作为新的区间且受累计预算。已有有效阻断覆盖机会时不因重复触发被抑制而判漏阻断。

对活动 a，先计算其**原始起点到首次正确候选/有效动作**的延迟，并按第4.1节判定及时性。一个机会被覆盖，要求同目标有效阻断区间与该机会的攻击时间区间有正长度交集；这是机会级覆盖，另报实际被覆盖秒数/比例，不能称全时段防护。只有所属活动首个动作及时，且该机会被有效覆盖，才计及时覆盖；未及时的活动仍留全量分母。后发生的动作不能追溯覆盖已经结束的桶。

攻击机会在评分前按策略无关规则分为两期，全部保留在固定分母中：

- **自动处置期**：活动所在稳定目标具备完整额度时，为 `[原始起点, 原始起点+startToActionLimitMs+120秒)` 内开始的机会。具备额度指该目标的首个攻击活动，或认证健康完整覆盖上一攻击活动结束至本活动起点、且间隔不短于 120 秒冷却加 60 秒最大 TTL。不具备额度的活动整段属于人工移交期。划分只读标签时间线、登记时效与认证健康，不读分数或动作，三臂配对分母相同。
- **人工移交期**：其余攻击机会。有效阻断仍在，或该目标已输出 `escalate_manual` 且桶内有合格告警（满足 T1—T7 的高分新鲜证据），才计连续。

这一划分来自契约 120 秒连续阻断上限：持续数十分钟的单目标攻击在自动额度用尽后本应转人工，不能再要求自动阻断覆盖整段。它不放宽额度、不删除机会；整段阻断覆盖率继续作为描述指标报告，不设门槛，也不称全时段防护。

`blockPrecision = 正确攻击目标动作数 / 全部动作数`；`blockRecall = 自动处置期及时覆盖的支持范围攻击机会数 / 全部自动处置期支持范围攻击机会数`；`handoffContinuity = 连续的人工移交期攻击机会数 / 全部人工移交期攻击机会数`；`falseBlockRate = 被错误影响的正常机会数 / 全部正常机会数`。候选计算用模拟区间，P7用实际OS区间，分别报告。无动作时 precision 未定义，不能填100%。目标/真值不明的动作不能算正确；同一服务正常会话受到影响仍计误伤，不因对端同时有攻击就免计。

同时报告活动级首次响应成功率、首次响应延迟、每1000正常机会误伤数、每小时动作数、正常会话影响与误伤秒数。放宽起点截止也不能删除此前未覆盖的机会。

### 3.2 连续预算与因果性

先按稳定真实目标及原始时间顺序完整回放，再按角色、行为、来源汇总。不能逐活动/逐角色重新初始化 TargetBudget；逻辑特征隔离不重置安全预算。状态跨角色传递仅限未用于模型拟合的因果预算/健康事实，不传未来标签或评分结果。每个对照臂独立保存自己的决策/动作状态，共享相同外生输入与起始条件。

认证健康记录须覆盖最后阻断到期至冷却结束，真实清零/模拟区间明确区分。无合格新证据且连续健康≥120秒才按 [契约](检测与处置契约.md#92-连续健康与预算恢复) 恢复额度；未知计数、gap、停采、身份切换或低分不能清零。报告每次恢复/拒绝的时间、原因与证明哈希。

### 3.3 区间与模型贡献

按最终独立防泄漏组聚类，关联活动先并组；采用2000次 bootstrap、seed=20261004，默认双侧95%区间。组数不足明确区间不可靠，不用海量相关快照制造窄区间。独立伯努利假设成立时才补报 Wilson/Clopper-Pearson；零错误近似上界3/n注明该假设。

E5 的 rules、model、model_and_policy 在同一误伤、新鲜度、目标、时效与动作预算下，各自在登记预算内选择参数并锁定。当前主收益为**攻击独立组等权的自动处置期及时覆盖率差（模型+策略减仅规则）**，按同组配对重采样，95%区间下界>0才判收益成立；时效改善作为次指标，不能主指标失败后改用另一指标放行。良性误伤按良性组另报，不以攻击收益抵消。

Precision 随流量配比变化。报告原始连续场景及预登记10%、1%、0.1%攻击机会配比的敏感性；主配比在P6读取前冻结。只改变报告权重/抽样，不能拼接虚假时间流重算上下文或省略累计预算。

## 4. 首版联合门槛

| 项目 | 要求及证据归属 |
|---|---|
| 数据/范围 | 标签、因果、泄漏与来源用途合格；两个声明行为分别有未暴露独立证据（P6） |
| 动作精确率 | 主配比下候选/实际动作点估计≥99%，同时给区间与样本量（P6/P7分开） |
| 及时覆盖 | 两行为及各登记支持来源 blockRecall≥80%，且存在移交期机会时 handoffContinuity≥80%；不能用均值或几乎不执行获得通过（P3开发回归、P6最终分别计算） |
| 最终样本 | ≥100攻击episode、≥3000良性机会；逐行为/来源独立组数及统计局限另列（P6） |
| 困难良性 | 登记的长请求、下载、并发、长轮询、重试和连接恢复零误阻断；管理连接另验保护约束 |
| 动作边界 | 每资产最多10个未终结动作/滚动60秒5个新动作；TTL≤60秒、同目标累计≤120秒；恢复条件一致（P4/P5/P7） |
| 时效 | 按4.1节登记原始起点截止；证据满足到OS确认生效P95≤2秒（P7）；离线候选不能宣称已测OS延迟 |
| 平台与恢复 | 第6节适用的安全必需场景全部通过，新/已建连接范围、TTL、撤销与恢复有证据（P5/P7） |
| 模型贡献 | 公平E5主收益成立并给配对区间；仅规则能力不算模型自动成果 |

99%是试验点目标。若要声称真实精确率已被证明≥99%，需单侧95%下界≥99%且来源代表性成立；约100次零错误不证明这一强结论。不能把活动少、范围窄的研究结果写成普遍保证。

### 4.1 行为与来源时效登记

每个声明行为及来源记录 `evidenceAvailableP50Ms/P95Ms`、`evidenceToActionP95Ms`、`startToActionLimitMs`、研究/自动适用等级与批准引用。证据可用时间须满足真实因果特征、parent和上下文条件；不能只找第一条1秒prefix。研究登记在拟合前完成，最终计划在P6读取前锁定。

- 短窗口能力默认原始起点到首次有效动作≤10000ms；它不是所有慢行为在物理上都能达到的统一结论。
- 慢行为研究的默认可达登记为 `ceil((evidenceAvailableP95Ms+2000)/1000)*1000` 毫秒。该值从开发真值与无拟合诊断取得，不从最终测试调出。
- 离线候选须为真实执行保留2000ms链路预算，候选起点截止为 `startToActionLimitMs-2000`；报告起点到候选的结果。P7再测实际证据到OS≤2000ms及完整起点截止，不能把离线相减当实测。
- 超过10000ms的能力默认保持alert_only；真实自动资格须在capability中单独登记并批准该时效与理由。当前P3计划没有授予较长时效自动资格。
- 所有活动的原始起点固定不变，30秒桶、连接续段、新boot不重置它。晚于登记截止或始终无正确候选/动作的活动记失败，其机会不计及时覆盖；同时报告失败比例，P95必须伴随无响应量，不能仅对成功样本宣布时效达标。
- 行为/来源标签只在评价旁路选择预登记统计口径，不能进入在线策略选择阈值、预算或有利的时钟。相同在线适用条件使用同一冻结策略；离线来源名不充当真实网络的适用性判据。

P3-A 无拟合诊断（旧输入，仅诊断）登记的研究截止为：CIC2018 与 TAARA 慢头部 10000ms，受控慢头部 23000ms，受控慢请求体 18000ms，均为 alert_only；CIC2017 慢请求体证据约 111 秒才出现，且公共角色固定为 train，登记为仅 train 诊断来源，不作支持来源。新采集冻结后须按实际文件重测。不能改起点、放宽10秒证据新鲜度或移除早期失败桶让短时效通过。

P6证明独立离线候选指标，P5/P7证明真实生效/恢复，两者不循环等待。authorized_auto另需实际资产/接口/服务授权、至少两个不同任务时段的V4、版本一致的V5及独立批准；没有持续入站或等待若干天的要求。

## 6. 动作与恢复必需场景

1. 目标正确且窄范围阻断；正常目标不触发，模型候选与实际目标一致。
2. 未登记/跨资产目标、错误executor、boot、captureScope均拒绝。
3. 过期/撤销授权、旧revision、失效目标、过期证据与命令均拒绝。
4. 未知/撤销密钥、签名或参数篡改均拒绝。
5. 管理通道、网关、DNS、受保护peer/service按保护清单不受影响。
6. 同键同内容只产生一条规则且不延长TTL；不同内容拒绝。
7. 写账本前后、安装后回执前等位置崩溃，恢复后实际规则与账本可核对。
8. 控制面/消息队列/代理断连或回执丢失时记uncertain、核对实态，不换ID盲重发。
9. 到期、人工撤销、策略暂停按需清理自身规则；健康状态下截止后1秒内核验不存在。失败记recovery_failed并停自动，不能只依据墙钟写expired。
10. 时钟回退、不可信时间、主机重启不延长规则；启动先恢复再接新命令。
11. 不覆盖/删除用户已有规则，未知归属不擅自处理。
12. 已建/新建连接分别验证效果，能力仅覆盖实测支持路径。
13. 并发命令、续封、撤销、身份/策略轮换不突破稳定目标与资产总预算；冷却恢复原子且可审计。
14. research/lab/authorized目标、身份及队列隔离，研究结果不能改标签变真实命令。
15. 多peer不串目标，同parent多快照/续段不增加独立证据，恢复账本不被活动边界清空。

每项保留expected/actual、平台/程序/配置、规则摘要、前后连接和恢复证据。P1探针已收口，但生产P5仍须验证这些适用场景；探针通过不等于执行器已经实现。

### 6.1 最小交付与可延后项

声明自动能力必须完成上述相关安全场景，没有“先做正常路径、以后再验授权和崩溃”的豁免。某项确实不适用时，限定capability范围并说明依据，不能仅标记跳过。

可以延后非必要的自动修复重试、运维便利功能及尚未声明的平台/协议能力。recovery_failed可由告警、停自动和经核验的人工清理收敛，不强制自动重试；但真实清理状态、审计与可执行的恢复路径必须具备。lab_auto同样不能省略授权、环境隔离、TTL和预算硬约束。

## 7. 报告与失败处理

报告输出到受控run目录，docs只原位维护规范与当前状态。报告绑定数据/计划/代码/模型/策略/健康/能力哈希，逐角色、行为、来源给分母、失败原因、首次时效、机会覆盖、误伤、区间及未验证项。

统计/模型失败返回P3对应问题；接入/预算持久化失败修P4，执行/恢复失败修P5。需要改观测公式时创建新的兼容性版本，不重写已收口P1/P2。旧shadow报告与历史final候选不授予新能力；漂移只能触发暂停/离线复核，不能自动调阈值或换权重。
