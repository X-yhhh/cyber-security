# 前端设计文档

版本：host-guard v5，更新于 2026-10-14（新增 rbac-v2 目标信息架构，见第 4、7 节；FE-9 两级菜单外壳已实现，见第 4.1 节）。本文是前端的基本设计文档之一，描述**当前已实现的界面**（第 4.2 节标为“迁移前”的部分将由 FE-10—FE-12 替换）、
组件库、接入层与交互约定。实施路线见[开发路线](开发路线.md)，后端接口语义以[接口设计](接口设计.md)为准，
模块职责见[功能模块设计](功能模块设计.md)，角色、权限与菜单可见性见[权限设计](权限设计.md)。本文不重复后端契约，只固定前端的表达方式与落位规则。

代码位置：`frontend/`。本文与代码冲突时以代码为准，并修正本文。

## 1. 定位与边界

前端是**本地自用控制台**，用于查看、审核和驱动后端已经实现的事实，不承担检测、判定或执行职责。

| 项 | 约定 |
|---|---|
| 数据来源 | 全部来自后端 API；**不内置演示数据**，数据库无记录时如实显示空态 |
| 授权 | 前端权限判断**只用于隐藏入口**；一切授权、状态迁移、幂等与职责分离由后端重新判定 |
| 动作 | 不提供任意目标地址、命令或 shell 的输入；处置只能引用已登记的决策与稳定预算目标 |
| 阶段声明 | 候选设计、未验收能力不得在界面写成已实现；能力等级按后端返回值原样展示 |
| 敏感值 | 不持久化机器凭据；凭据只在签发响应中出现一次并提示立即保存，不写入本地存储 |

界面上的每一条口径说明都对应一条后端硬约束（例如「批复不等于规则已清理」「202 不代表检测完成」），
改写文案时不得弱化这些含义。

## 3. 视觉基线

### 3.1 色彩

单一强调色，不用彩色底徽章；语义靠圆点与文字着色。

| 用途 | Token | 值 |
|---|---|---|
| 页面底色 / 表面 | `paper` | `#FFFFFF` |
| 次级表面（hover 行） | `paper.soft` | `#EFEEE9` |
| 强分隔线（区块顶线） | `ink` | `#14161A` |
| 主要文字 | `ink` | `#14161A` |
| 次级 / 三级 / 四级文字 | `ink-2` `ink-3` `ink-4` | `#3A3D44` `#6B6E75` `#9A9CA1` |
| 分隔线 / 发丝线 | `ink-line` `ink-hair` | `#D9D7D0` `#E4E2DB` |
| 强调（品牌） | `signal` `signal-soft` | `#2438E8` `#E6E8FB` |
| 威胁 / 警示 / 正常 | `threat` `warn` `ok` | `#E0482A` `#B7791F` `#2F7D5B` |

三级线宽体系（`border-ink` / `border-ink-line` / `border-ink-hair`）是版面组织的核心手段。

### 3.2 形状与层级

- **无阴影**。层级只用细线、留白与 `z` 轴（遮罩 `bg-ink/10`）表达。
- **小圆角**：`rounded` = 2px，`rounded-sm` = 1px；`rounded-md/lg/xl` 已从主题移除，写了不产生样式。
  `rounded-full` 仅用于状态圆点 `.dot`。

### 3.3 排版

- 字体：正文 Inter（300/400/500/600），标识符与数值 JetBrains Mono（400/500）。
- 规律：**字号越小越粗、越大越细**。页面标题 `2.25rem font-light`，大指标 `2.5rem font-light`，
  表格单元格 `13.5px`，小标签 `11px`。
- `.num`（等宽 + `tabular-nums`）用于时间、ID、IP、端口、哈希、分数、计数、TTL、版本号。
- `.label`（等宽、大写、`tracking-label`）用于章节号、字段名与表头。

### 3.4 动效

统一使用 `cubic-bezier(0.22, 1, 0.36, 1)`；页面切换 450ms，抽屉 500ms，淡入淡出 300ms。
`prefers-reduced-motion: reduce` 下全部压缩为 0.01ms，`.reveal` 直接显形。

## 4. 信息架构

2026-10-14 决定（Q7）：控制台只保留 v2 页面，侧栏改为**按权限过滤的两级菜单**，v1 重复页面直接删除。菜单清单、每项的可见条件（`anyOf` 权限）与六个角色的可见性矩阵以[权限设计第 7 节](权限设计.md#7-控制台菜单两级)为准，本节只固定前端落位规则。FE-9（任务单 F0）已实现两级菜单外壳、守卫与工作台框架；FE-10—FE-12 完成前，部分二级项仍复用第 4.2 节的旧视图，v1 页面地址仍保留但不进菜单。

### 4.1 目标结构（rbac-v2）

| 一级 | 二级 |
|---|---|
| 工作台 | —（按权限组合卡片） |
| 威胁检测 | 观测与推理 · 判定与来源 · 事件研判 · 反馈与复核 |
| 受控响应 | 处置动作 · 目标预算 |
| 模型与发布 | 数据集与模型 · 评价与回放 · 决策策略 · 能力与发布组合 · lab 验证与 G3 |
| 资产与采集 | 资产 · 资产授权 · 传感器与执行器 |
| 运行与审计 | 运行健康 · 审计日志 |
| 系统管理 | 用户与角色绑定 · 角色与权限目录 |

- 菜单配置单一来源 `src/router/nav.ts`（FE-9 已实现）：`{group, key, title, en, path, anyOf, component, ready, segment?}`，路由由其生成；编号不再硬编码在页面里。`ready=false` 的项既不显示也不注册路由（直达显示 404），F1—F5 完成页面后只改自己那一行。`segment` 只在复用旧视图期间指定初始分段，F1—F4 拆分后删除。
- 一级组只是分组标题，可折叠（折叠状态存 `localStorage` 键 `sentinel.nav.collapsed`），当前路由所在组自动展开；二级项是独立路由 `/console/<group>/<item>`，路由名为 `<group>-<item>`（工作台为 `workbench`）。顶栏面包屑为“一级 / 二级 / 详情 ID”。
- 宽度小于 768（Tailwind `md`）时侧栏改为左侧抽屉，由顶栏菜单按钮打开；抽屉内 Tab 焦点循环、Escape 或点遮罩关闭，关闭后焦点回到菜单按钮，跳转后自动关闭。
- 详情：事件详情 `/console/detect/events/:id`、lab 会话详情 `/console/release/lab/:id` 为整页，其余用抽屉。详情页随所属二级项注册并沿用其 `anyOf`。
- 登录后统一进入工作台（`/console/workbench`）；未知地址显示 404 页，无权限地址在原地址显示 403 页（守卫在加载目标组件之前改道，目标页面不挂载、不发请求）。
- 迁入新位置的 v2 页面（09—14）旧地址保留重定向一个版本；v1 页面地址直接删除。

### 4.3 子视图落位规则

业务归类由两级菜单承担，每个二级项是独立路由。页内分段（`Segmented`）只用于**同一对象的不同视图**（如观测与推理中的批次、观察、推理、证据迹），分段选项按权限动态展开，可见分段数与顺序随身份变化。

### 4.4 v2 链路的归属

v2 对象按因果顺序归组，而不是并入同名的旧页面：观察链路是一条连续证据链（批次 → 观察 → 推理 → 证据迹），与 v1 的同名对象语义不同，混排会误导读数。

- 威胁检测承载检测链路，除研判、标注、复核外只读。
- 模型与发布承载「策略与发布组合」的冻结与审批，是能力等级的唯一来源。
- 受控响应承载动作、回执与预算账本，是唯一涉及真实执行意图的分组。

## 5. 组件库

通用组件位于 `src/components/`。新增页面必须复用这些组件，不另造同类控件。

| 组件 | 用途 | 关键 props / 约定 |
|---|---|---|
| `PageHead` | 页头：编号 + 标题 + 一句口径说明 | `no` `title` `desc`；右侧 slot 放主操作；`#kicker` 放英文名 |
| `Segmented` | 子视图切换（`role="tablist"`） | `defineModel` 双向绑定；指示线用 DOM 实测定位，选项数变化自动重测 |
| `Tag` | 状态标记 | `tone` + `label`；**圆点 + 文字**，不做彩色底 |
| `Metric` | 大指标 | 进场计数动画，尊重 `prefers-reduced-motion`；`tone` 仅影响数字颜色 |
| `Pager` | **页码**分页条 | 用于 v1 的 `page/size` 接口；单页时整条隐藏 |
| `CursorPager` | **游标**分页条 | 用于 v2；后端不返回总数，故只显示「本页 N 条」与进退 |
| `Drawer` | 详情面板 | `Teleport` 到 body；Escape 关闭、Tab 焦点循环、打开时自动聚焦标题、关闭后归还焦点 |
| `LoadState` | 四态占位 | 顺序 `loading → error → empty → slot`；错误带 `role="alert"`；`empty` 由父组件计算 |
| `ToastHost` | 操作结果提示 | 全局唯一，挂载于 `App.vue` |

### 5.1 操作控件阶梯

每个页面只应有一个实心主操作，按语义递降：

1. `.act` — 实心主操作（提交、批准、激活），每页唯一；
2. `.act-ghost` — 边框次操作（起草、停用）；
3. `.link` — 行内文字操作（查看、撤回、取消）；
4. 无样式 `<button>` + 下划线切换 — 筛选器。

输入统一用 `.field`（下划线式，无边框盒）；多行输入追加 `h-auto resize-none py-2`。

## 6. 接入层

### 6.1 两套协议

`src/api/client.ts` 同时支持 v1 与 v2，区别只有信封与错误判定：

| 项 | `/api/v1` | `/api/v2`（P4） |
|---|---|---|
| 信封 | `{success, data, error, requestId}` | `{requestId, data, error}` |
| 成功判定 | `success === true` | HTTP 2xx 且 `error == null` |
| 分页 | `page` + `size`，返回 `totalElements` | `cursor` + `limit`（1—200），返回 `nextCursor` |
| 主键 | 内部数字 ID | 外部 UUID |
| 幂等 | 部分写操作 | **全部写操作**必带 `Idempotency-Key`（UUID 形态） |
| 并发 | 无 | 审批/激活/停用类需 `If-Match: <revision>` |

路径以 `/api/` 开头时视为已含版本前缀，否则自动补 `/api/v1`，因此既有调用点无需改动。

### 6.2 v2 封装

`guard` 对象提供 `list` / `get` / `child` / `create` / `op` 五个方法，只封装后端路由中真实存在的组合，
不在前端做兜底猜测；未知组合由后端返回 404。

- 写入的幂等键默认由 `idempotencyKey()` 生成 UUID；
- `op` 的 `revision` 参数生成 `If-Match`。注意同一幂等键配不同 `If-Match` 会被后端视为不同请求，
  因此键必须随每次提交生成，不能跨提交复用。

### 6.3 会话与错误

- 会话状态只来自 `GET /auth/me`；`can(permission)` 用于隐藏入口。
- CSRF 头名由后端 `/auth/csrf` 下发，前端不硬编码；写请求 403 时自动作废本地令牌，下次重取。
- 401 自动跳登录页（`/auth/*` 自身的失败除外）。
- 错误文案统一由 `errText` 生成并附带 `request-id`，页面不得自行拼接错误信息。

## 7. 权限与职责分离

权限与菜单的完整定义见[权限设计](权限设计.md)；前端遵守以下规则。

- **导航按权限过滤**：二级项的 `anyOf` 与会话 `permissions` 无交集即不显示，一级组无可见项则整组隐藏。路由守卫复用同一 `anyOf`，直达无权限地址显示 403 页且不发数据请求（FE-9 已实现，`nav.test.ts` 与 `guards.test.ts` 锁定）。
- 页内过滤仍发生在分段选项、操作按钮与请求三处；按钮与权限的对应见权限设计第 8 节。
- 审批类入口在无权限时不显示原因文案（避免泄露他人对象的处理状态）。
- 后端职责分离规则在前端只做提示：自批返回 403 `APPROVAL_SEPARATION_REQUIRED`，本人起草或申请的对象不显示审批按钮，`If-Match` 不匹配返回 409 `REVISION_CONFLICT`。
- 权限只在登录与刷新时从 `auth/me` 读取；角色变更后由后端撤销会话，前端回到登录页，不做本地增量更新。
- 页面不得依据前端推断「已批准」「已清理」等终态；终态一律读自后端返回值。

## 8. 状态与语义

后端状态值到颜色的映射**集中在 `src/data/tones.ts`**，用 `Proxy` 对未知值回退为中性 `mute`，
页面不各自判色。新增集合必须在此登记，不允许在页面里内联三元表达式选颜色。

要点：

- `signal`（钴蓝）表示「进行中 / 需关注但非威胁」，不是装饰色；
- 威胁语义只用 `threat`，且「模型分数」与「展示风险」分开着色，不合并为一个高亮；
- **期望状态与观测状态分开显示**：动作的 desired 与 observed 各自成列，制定不等于执行；
- 不成功的推理不带分数，`null` 显示为 `—` 而不是 `0`。

## 9. 交互与实现约定

1. **不本地推断终态**：写操作成功后 `await reload()` 重新读取；不做乐观更新。
2. **竞态防护**：切换实体或翻页时用请求序号作废旧响应（`let seq` + `mine !== seq` 早退）。
3. **分页**：v1 用 `Pager`（页码从 0 开始）；v2 用 `CursorPager`（游标栈支持回退，栈空时禁用「上一页」），读取逻辑统一用 `composables/cursor.ts` 的 `useCursor`。lab 会话事实按追加序号 `after` 翻页，是例外。
4. **可点击行**：`tr.row-link` 必须配 `tabindex="0"` 与 `@keydown.enter`。
5. **空态文案**：带范围限定的句子（如「数据库中暂无你审计范围内的记录。」），不使用「暂无数据」。
6. **表单**：字段名集中在常量对象中定义，避免同一请求体在两处写字面量。
7. **无障碍**：抽屉焦点循环与 Escape 由 `Drawer` 统一处理；错误区 `role="alert"`；
   切换类控件 `role="tab"` + `aria-selected`，分页区 `aria-label`。

### 10.1 既有页面（01—08）

v1 接口为主，明细见 `frontend/README.md` 第 2 节的接口对照表。按 Q7 全部在 FE-12 删除，不再维护或扩展；替代页面见第 4.2 节“去向”列。

以下 10.2—10.7 为保留的 v2 页面，标题括号内为 rbac-v2 的新位置（FE-10 迁移）。FE-9 期间这些视图已挂到新地址：Release 按 `segment` 分别服务评价与回放、决策策略、能力与发布组合；Execution 服务处置动作、目标预算；Health 服务运行健康、审计日志。

### 10.0 外壳页面（FE-9）

| 页面 | 路由 | 说明 |
|---|---|---|
| 工作台 | `/console/workbench` | `WorkbenchView` 按 `views/workbench/cards.ts` 渲染权限设计第 7.4 节的卡片；卡片 `anyOf` 无交集不渲染，没有可见卡片时不请求；数字取自 `GET /api/v2/summary`（B2.5 契约，B2 合入前由 msw 模拟），后端未返回的字段不显示、不补 0；卡片行带 `?status=` 跳到已上线且有权访问的列表，否则只显示数字。F2 完善内容与定时刷新 |

### 10.2 观测与推理（09 → 威胁检测 / 观测与推理，`views/detect/ObservationsView.vue`）

| 分段 | 数据 | 读权限 | 写操作 |
|---|---|---|---|
| 观察批次 | `observation-batches` | `detection.read` | 无 |
| 观察记录 | `observations` | `detection.read` | 标注反馈（`feedback.label`，`POST /api/v2/feedback`） |
| 推理结论 | `detections` | `detection.read` | 标注关联观察（`feedback.label`） |
| 证据迹 | `evidence-episodes` + `evidence` 子资源 | `detection.read` | 标注证据明细中的观察（`feedback.label`） |

表达重点：支持按资产（`assetId`）筛选并同步 URL 查询参数；批次受理是局部接收（接受/拒绝/去重三态并存）；202 只表示持久化受理；
快照只含 `asOf` 之前的报文；证据迹按 30 秒桶归并并按父流去重；人工标注提交后状态为 `pending` 待复核，不自动进入在线训练。

### 10.3 策略与发布（10 → 模型与发布 / 决策策略、能力与发布组合、评价与回放）

| 分段 | 数据 | 读权限 | 写操作 |
|---|---|---|---|
| 决策策略 | `decision-policies` | `resource.read` | 复核（`policy.approve`，需 `If-Match`） |
| 发布组合 | `release-bundles` | `resource.read` | 登记报告 / 封存 / 审批 / 激活 / 停用 |
| 能力登记 | `capabilities` | `resource.read` | 无（只读） |
| 评价运行 | `evaluations` | `evaluation.read` | 无（只读） |

表达重点：策略复核不等于激活；封存必须含一次 `final` 运行；报告不反向写入被评估的 subject；
能力等级按平台分别取得，不复制另一平台成绩。

### 10.4 执行与预算（11 → 受控响应 / 处置动作、目标预算）

| 分段 | 数据 | 读权限 | 写操作 |
|---|---|---|---|
| 动作台账 | `actions` + `receipts` 子资源 | `action.read` | 申请（`action.request`）、审批（`authorization.approve`）、撤销（`action.revoke`） |
| 预算目标 | `budget-targets` | `action.read` | 无（只读） |

页头另有「停用自动化」（`automation.stop`，202 受理）。

表达重点：期望与观测状态分列；无回执时显示「命令未下发」，不显示「执行成功」；
预算账本只读，界面不提供任何清零入口，额度恢复条件如实写出；
人工申请必须引用决策绑定的稳定预算目标，不接受原始地址。

### 10.5 判定与来源（12，FE-1 → 威胁检测 / 判定与来源）

| 内容 | 数据 | 读权限 |
|---|---|---|
| 来源 × 类别矩阵、判定列表、判定详情抽屉 | `decisions`（游标，每次 200 条，可追加） | `detection.read` |

表达重点：后端不提供聚合，矩阵只统计**已加载样本**，页面写明条数与时间范围，不外推比例；
模型与每条规则分列计数，不合并；「告警 + 原因码」表示已告警但在该自动门被拒绝；
本页不推断来源能否自动，等级以 13 页登记为准。09 页推理结论同时显示四类分数（`FamilyScores`），证据迹显示来源与作用域。

### 10.6 lab 验证与 G3（13，FE-2 → 模型与发布 / lab 验证与 G3）

| 内容 | 数据 | 读权限 |
|---|---|---|
| 会话列表（按运行状态筛选） | `lab-validation-runs` | `evaluation.read` |
| 会话详情 | `lab-validation-runs/{id}`、`/qualifications`、`/events?after=` | `evaluation.read` |
| G3 报告 | `evaluations/{evaluationId}` 的 `payload`（签名报告原文） | `evaluation.read` |

报告定位：先取来源等级记录里的 `evaluationId`；未登记等级时在评价运行中按 `payload.sessionId` 查找最新一份。
表达重点：资格状态与运行状态分列；会话不授予执行权限；**等级只来自已登记来源，`lab_auto` 一律标「lab 自动（仅 lab）」，未登记的来源标「只告警」**，并写明不适用于真实主机；
时延只报告不设门槛；报告 `limitations` 原文列出，不改写；报告导入事实本身不带 `kind`，按 `evaluationId` 识别。

### 10.7 健康与审计（14，FE-3 → 运行与审计 / 运行健康、审计日志）

| 分段 | 数据 | 读权限 |
|---|---|---|
| 运行概况 | `ops/status` | `ops.read` |
| 采集健康窗口（按服务端判定筛选） | `health-windows` | `ops.read` |
| 采集心跳 / 执行心跳 | `sensor-heartbeats` / `executor-heartbeats` | `ops.read` |
| 审计（按动作精确筛选） | `audit` | `audit.read` |

表达重点：服务端判定（`verificationStatus`）与当前状态（`healthState`，叠加 10 秒新鲜度）分两列；
`replay_healthy` 显示为「文件回放健康」并注明「不代表现场采集健康」，用 `signal` 色而非 `ok`；
文件回放的内核丢包显示「不适用」而不是 0；心跳只表示存活，不代表采集健康。分段在切到时才首次请求。

### 10.8 事件研判与反馈复核（FE-11 / F1 → 威胁检测 / 事件研判、反馈与复核）

| 页面 | 路由 | 数据 | 读权限 | 写操作 |
|---|---|---|---|---|
| 事件研判列表 | `/console/detect/events` | `events`（按 `status`、`assetId` 游标分页） | `detection.read` | 无（点击行进入整页详情） |
| 事件研判详情 | `/console/detect/events/:id` | `events/{id}`（含 B2.7 扩展字段）、`timeline`、`episodes`（含 `evidence` 子资源）、`actions`（需 `action.read`）、`assignable-users`（需 `event.manage`） | `detection.read` | 状态迁移（`event.manage`，需 `If-Match`）、指派负责人（`event.manage`，`PUT /events/{id}/assignee`，需 `If-Match`）、追加研判记录（`event.manage`）、申请人工处置（`action.request`）、标注证据观察（`feedback.label`） |
| 反馈与复核 | `/console/detect/feedback` | `feedback`（按 `status`、`assetId` 游标分页）、`observations/{id}` | `feedback.label` 或 `feedback.review`（后端读校验 `detection.read`） | 新建标注（`feedback.label`）、独立复核（`feedback.review`，`POST /feedback/{id}/reviews`，需 `If-Match`） |

表达重点：
- 事件详情中的「申请处置」按钮只在 `actionable=true` 时可用，只读引用后端返回的 `actionEpisodeId`、`budgetTargetId`、`targetRef` 与 `policyId`，不提供任何 IP、端口或命令输入框；`actionable=false` 时按钮灰显并写出后端返回的不可申请原因码（`actionableReasonCode`）。
- 反馈与复核的「待复核」列表默认排除本人标注；详情抽屉对本人标注的对象隐藏复核按钮并说明职责分离（S6），复核通过只登记为 `reviewed`，不自动触发模型在线重训。

## 11. 测试

- 单元与组件测试位于 `src/**/*.test.ts`，用 msw 拦截请求，断言落到可见文案与 `role`。
- 页面级测试覆盖权限门控（无权限不显示入口）与四态渲染。
- 菜单快照测试：按[权限设计第 7.3 节](权限设计.md#73-角色可见性矩阵)对六个角色逐一断言可见菜单；直达无权限地址显示 403 且无数据请求。
- 公共夹具：`src/test/roles.ts` 提供六个单角色和一个合法组合（`platform_admin` + `model_operator`）的 `auth/me`，权限逐格取自权限设计第 5 节；msw 处理器放在 `src/test/handlers/<分组>.ts`，由 `handlers/index.ts` 汇总，并记录请求供“无数据请求”断言。
- `npm run lint` 警告即失败；`npm run typecheck` 与 `npm run build` 必须通过。
- 覆盖率阈值由 `vite.config.ts` 强制，新增页面应同步补测试，不通过降低阈值来达标。

## 12. 待办与约束

- 现有 README 的历史描述曾与实际实现不一致（浅色调色板、彩色徽章、多层阴影），已按代码修正；
  后续修改视觉基线必须同时更新本文、`tailwind.config.js` 与 README。
- 后台任务未接入 `event-sources` / `heartbeats` / `health-windows` / `target-bindings` / `command-claims` /
  `reconciliations` 等**机器侧**路由：这些由采集器与执行器以机器凭据调用，浏览器会话不可用
  （机器路由会清空会话上下文，且要求 `Bearer mch_*` 身份），因此不属于控制台前端范围。
- 稳定目标预算的「未核验标识冲突」「跨 boot 续期」等异常分支只按后端返回值展示，
  前端不自行推断连续性。
- 回放与真实执行器仍按后端能力开放；前端不提供绕过签名、TTL 与范围约束的入口。
