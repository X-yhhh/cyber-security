## 0. 初版口径

**只放宽模型容错**：
- 模型、阈值、冻结策略不改，r6（真实主机只告警）与 r5（lab 自动封禁）按现状使用。
- 现场准确性指标（告警率、健康占比、质量比例）只报告、不设门槛（Q8）。

**其余一律按完整初版交付**：
- 前后端每个功能模块都要具备完整的增删改查和审批闭环、权限门控、错误与空态处理，并有自动化测试。
- 增删改查的范围（Q10）：用户、角色（含自定义角色）、资产、传感器、执行器、采集配置、数据集、模型、决策策略、发布组合、资产授权；支持启用/停用；列表统一支持搜索、状态、时间筛选与排序（[权限设计第 10.5 节](../权限设计.md#105-后端与数据库q10-控制台重设计与增删改查补全)）。内置 6 个角色的权限矩阵不变。
- “删除”只用于草稿与未使用的对象；已产生业务事实的对象只能停用、退役或撤销。
- 控制台按[前端设计文档](../前端设计文档.md)第 3—5、10 节重做视觉与信息架构：菜单为 6 个一级组、12 个二级页，加上登录即可见的待办中心（共 13 行，[权限设计第 7 节](../权限设计.md#7-控制台菜单两级)）；新增实时态势与待办中心；删除「目标预算」等只读账本页，约束改到动作详情中显示；首屏 `LandingView` 不改。
- 部署要求常驻服务运行、真实传感器接入、可回退。
- 不接受“页面能打开但功能缺失”、“建设中”、“只读占位”等形态。需要签名证据或由 runner 驱动的操作（能力报告生成、lab 会话推进、研究回放开始/完成）仍由脚本执行，页面只读展示结果并注明“由 runner 执行”，这不算“只读占位”。

**“完成”的统一定义**（所有卡片都适用）：
1. 代码、测试、文档三项齐全，PR 已合入 main；
2. 与卡片相关的检查全部通过，包括 `mvn test`、Go 测试、`pytest`、`npm run lint/typecheck/test/build`；
3. 新接口在[接口设计](../接口设计.md)登记，新页面在[前端设计文档](../前端设计文档.md)登记，新权限点在[权限设计](../权限设计.md)登记；设计文档中标为“待实现”的条目改为“已实现（提交号）”；
4. 系统实施记录追加一条：提交、验证命令与结果、未验证项。
5. 第 2 节总览表中本卡片的“状态”列改为“已完成（PR 链接）”，与代码在同一个 PR 中合入 main。PR 未合入前保持“待开始”或写“进行中”，不提前标完成；部分完成时写明剩余项。

## 1. 协作规则

- **分支与目录**：每张卡片使用独立 worktree 与分支 `Xyhhh/v1-<卡片号小写>`，只改卡片“位置”列出的路径。确实需要改动别的路径时，在 PR 描述中说明原因。
- **合入方式**：PR 用 merge commit 合入并删除分支。同一波次内谁先完成谁先合入；后合入的一方负责 rebase 并解决冲突，不得改写他人的逻辑。
- **业务库保护**：W4 之前，任何人不得用 main 构建的新 JAR 启动业务库 `cyber_security`。原因是 Flyway 在启动时会自动执行 V26（以及 B4 合入后的 V27）。开发和预演只使用隔离 schema（`DB_TEST_*`）、预览副本或业务库克隆。
- **提交规范**：
  - 提交信息用中文；只暂存本卡片的文件。
  - 提交前运行 `git diff --check`，并检查是否混入秘密、权重、数据或本机绝对路径。
  - 机器凭据、口令、私钥不得进入 Git、日志或测试快照。
- **禁止改动**：模型、阈值、冻结策略、冻结场景、`docs/验证与验收.md` 正文、已执行过的迁移、admin 行与口令哈希。
- **前端约定**：
  - 只调用 `/api/v2`。写操作带 `Idempotency-Key`（每次提交重新生成）；审批类和状态变更类操作带 `If-Match`。
  - 错误统一用 `errText` 展示，并附上 request-id。
  - 每页都要处理加载、空、错误、正常四种状态。
  - 读写之后重新拉取数据，不做乐观更新。
  - 按钮显隐按[权限设计第 8 节](../权限设计.md#8-页面操作--权限)；本人起草或申请的对象不显示审批按钮。
  - 视觉与文案按[前端设计文档第 3.5 节](../前端设计文档.md#35-标识符与文案)：ID 用 `IdText`，能显示名称的地方不显示 UUID，界面不出现 `S5`、`r6`、`G3` 等内部编号。
- **前端并行约定**：减少冲突的做法如下。
  - 接口封装放在 `frontend/src/api/v2/<分组>.ts`，msw 处理器放在 `frontend/src/test/handlers/<分组>.ts`，页面放在 `frontend/src/views/<分组>/`。
  - **菜单骨架由 U0.9 一次切换到 6 组 13 行**，并把 `nav.test.ts` 的矩阵期望值改为[权限设计第 7.3 节](../权限设计.md#73-角色可见性矩阵)。之后各页面卡片不得改矩阵期望值，只做三件事：把自己负责的行设为 `ready: true` 并指向新页面；删除自己承接的过渡行（`legacy: true`）；在 `router/index.ts` 为被合并的旧地址加重定向。
  - `nav.ts` 每个菜单项只占一行，各卡片只改自己的行。态势组的两行：待办中心归 F2，实时态势与“登录后默认落地页”归 F6。

## 4. W2 卡片（页面）

各页面卡片的通用要求：
- **列表**：游标分页（`CursorPager`）；筛选条件统一用 `composables/query.ts` 的 `useQueryState` 同步到 URL 查询参数（F0R 已落地并迁移已有页面）；行可点击，并支持键盘 Enter；空态文案要写明范围，例如“你可见范围内暂无……”。
- **列表筛选**：统一为“搜索框（`q`）+ 状态 + 时间范围 + 排序”，放在面板标题下方一行。B4 已合入，按集合白名单接入真实筛选契约，见[接口设计第 3.2 节](../接口设计.md#32-控制台增删改查补全q10)。
- **详情**：默认用抽屉；内容多的对象（事件、lab 会话、资产）用整页加 `SectionTabs`。
- **视觉**：页面一级区块用 `Panel`（每页 2—4 块、不嵌套）；ID 用 `IdText`；能显示名称的地方不显示 UUID；哈希与内部键收进“技术细节”折叠区；页面说明不超过一句，约束写在相关字段或按钮旁，含义不弱化；界面不出现 `S5`、`r6`、`G3` 等内部编号。
- **表单**：字段名集中在常量里定义；先做客户端校验（必填项、UUID、SHA-256 格式），服务端返回 400/422 时把原因码显示在对应字段旁；危险操作（停用、退役、撤销、删除）二次确认并写明影响。
- **测试**：每页覆盖四种状态，至少 1 个写操作成功，以及 403 和 409 的错误展示；每个按钮测试“有权限才显示”；审批按钮测试“本人对象不显示”；列表测试覆盖筛选与游标翻页。
- **菜单与重定向**：按各卡片的“菜单”一行改 `nav.ts`（见第 1 节前端并行约定），旧地址重定向清单以[权限设计 7.2 节](../权限设计.md#72-菜单清单)为准；F0 已有的旧 v2 地址（`/console/observation` 等）同步改指到最终地址。
