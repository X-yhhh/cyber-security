## 起点审查：保持 Unknown，停止对应 prefix 训练

两个来源分别固定样本后读取完整原件/已登记派生件，包含活动前后边界、成功标签及Attempted失败样本。初轮2017仅19条观察到关闭，故另行登记扩大为24条正标签候选＋4条Attempted；原初轮记录保留。最终每场景审查28条，2017有23条、2018有24条观察到完整连接关闭。逐连接材料位于忽略目录，公开[摘要](onset-review-summary.json)绑定样本登记、原件、发布者文档和审查结果哈希。

- **2017 Slowhttptest：** 修正文档给出final标签、时间窗和伪影排除，但没有可直接批准的因果工具模式/起点规则。本轮完整连接形态检查未建立该规则；12条样本存在抓包质量问题。不能照搬Slowloris的未完成头规则，prefix继续Unknown。
- **2018 Slowloris：** 修正文档描述GET后续为值1—5000的数字型 `X-a`；原件抽查实际出现128个字面值 `X-a: b` 后续片段。该差异不证明攻击标签错误，也不证明不能提早检测，但不能在未解释差异前把文档模式视作已核验。保留来源冲突，未把字面值规则静默扩大为已批准标签。
- 判断仅使用因果前缀；起点前、等于起点及证据不明时刻均为Unknown，不转成正常。既有2017 Slowloris训练侧669条/124个parent候选不变，不提升为独立选型或校准证据。

因此没有生成新的合格prefix数据冻结，也没有为未通过的数据接入口编写可绕过闸门的训练路径。后续应先解释实际工具模式和原件差异，再版本化来源规则并重新审查；当前结果不能推出“模型永久无处置能力”。

## 对后期处置授权的影响

当前候选只能保留 `candidateOnly=true / alert_only`，且没有接入活动运行时。P3完整策略覆盖和独立早期证据未通过，阻止P6最终验收准入；即便后续模型通过，Windows严格TTL/恢复缺口及Mac无自动能力还会阻止对应P7联合自动资格。发布批准也不能替代执行时的登记资产与有效授权。

恢复路线依次为：解释并核验来源起点规则 → 在有界来源计划中取得可追溯的独立活动及长期良性任务 → 冻结新prefix数据与实验计划 → 有界训练并完成完整策略的逐场景/独立评价 → P6一次性评估 → 对应平台P5/P7动作与恢复联合验收 → P8限定资产授权。若来源和可观察证据仍不能支持任务，应返回任务范围可行性审查；不能通过降低门槛或修改授权配置补足证据。
