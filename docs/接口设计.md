# 接口设计

实现状态以 [接口实现核对矩阵](接口实现核对矩阵.md) 为准；本文定义目标契约，未在矩阵标为“已实现”的路径不得视为已开放能力。

## 1. 约定

- 基础路径 `/api/v1`，JSON UTF-8，时间使用 ISO-8601 UTC；前端不直接访问 MySQL、Redis 或 RabbitMQ。
- 浏览器用户接口使用 Spring Security 服务端会话和 CSRF 保护；连接器/传感器使用与人工用户隔离的机器身份认证链。角色仅授予功能权限，资源读写还须按资产/数据源范围二次授权。
- 每个请求支持/返回 `X-Request-Id`；可重试写请求使用 `Idempotency-Key`。异步操作返回 `202 Accepted` 和任务 ID。
- 统一错误结构：`code`、`message`、`requestId`、`details`。不得在错误中泄露密钥、内部堆栈或敏感载荷。
- 分页采用 `page`、`size`，限制最大页长；列表过滤和排序字段采用服务端白名单。
- 所有时间、分数和模型概率的语义在响应中明确；未经校准的输出标为 `score`，不标为概率。

## 2. 统一响应

基础探针为 `GET /api/v1/health/live` 和 `GET /api/v1/health/ready`，响应使用统一 envelope 并回显 `X-Request-Id`。存活探针仅表示进程运行；就绪探针检查 MySQL，依赖不可用返回 `503` 且不泄露连接信息。匿名访问只允许健康探针及登录/CSRF 引导接口；健康端点仅返回状态枚举。另提供受 `ops.status.read` 保护的 `GET /api/v1/ops/status` 运行摘要，以及与应用共享本机绑定地址的 Actuator `health`、`metrics`、`prometheus` 端点；默认应用地址为 `127.0.0.1`，metrics/prometheus 复用登录会话并要求 `ops.status.read`，指标不包含原始载荷、凭据或连接信息。

成功响应：

```json
{
  "success": true,
  "data": {},
  "error": null,
  "requestId": "req_01..."
}
```

错误响应：

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "MODEL_CONTRACT_MISMATCH",
    "message": "输入数据不满足活动模型的特征契约"
  },
  "requestId": "req_01..."
}
```

主要状态码：`400` 参数错误，`401` 未认证，`403` 无权限/超范围，`404` 不存在，`409` 幂等冲突/状态冲突，`422` 数据或模型契约不满足，`429` 限流，`503` 推理端/队列/适配器不可用。

### 3.1 首期后端范围

- 当前已实现健康探针、用户登录/注销/me/CSRF 引导、用户列表与创建、内置角色查询及用户角色/范围整体替换、资产列表/详情/登记/范围内更新/授权申请及独立审批、数据源列表/登记/范围内更新/映射版本列表与登记、审计列表，以及 connector 客户端和 sensor 主体签发、传感器心跳/配置/健康窗口/规范化流批次提交。
- 用户创建只保存 BCrypt 哈希且不隐式分配角色；角色替换只允许 7 个内置角色，拒绝不存在的资产/数据源/模型范围、未知类型和非管理员全局范围；平台 API 不提供编辑内置角色权限模板的接口。角色或范围变化会撤销目标用户所有 JDBC 会话。
- 资产列表在 SQL 内先应用 `asset.read` 与当前角色对应的资产范围，再排序和分页；跨范围单项查询统一返回 `404`。审计列表在 SQL 内要求所有资源关联范围可见；无范围或含任一范围外资源的记录对范围型审计员隐藏。
- 资产创建需全局 `platform_admin`；更新、授权申请须同时匹配 asset 权限和角色绑定的资产范围。授权先写入 `pending` 并记录 `requested_by`，仅独立 `asset.authorization.approve` 主体可在有效期包含当前 UTC 时间时批准；所有变更审计关联资产范围。
- 数据源创建仅允许全局平台管理员；列表先按 `source.read` 和显式数据源范围在 SQL 过滤再分页，更新与映射写入还需对应范围内 `source.manage`。映射版本按数据源唯一，创建后状态为 `draft`，本阶段尚无映射审批/激活端点。
- connector 凭据仅在平台管理员创建响应返回一次，服务端只持久化 SHA-256 验证摘要；机器路由采用无状态独立过滤器链，浏览器会话和 CSRF token 均不能作为机器凭据。签发时须提供资源范围和明确的 `sourceAssetBindings` 数据源—资产配对；每条记录必须带 `assetId`，且配对有效。原始请求体在 JSON 解析前限制为 1 MiB，批次最多 500 条、单条规范化 payload 最多 64 KiB。当前只接收连接器已规范化 JSON，检查数据源、凭据/权限、配对和映射版本审批状态，不执行字段转换或完整字段/单位 schema 校验。
- 暂未实现用户更新/冻结、自助改密、通用导入和推理 API。传感器登记及机器主体的心跳、配置读取、健康窗口和流批次路由已实现，但不代表真实抓包进程、collector/UDP 接入或在线检测消费者已接入；不得据规划清单推断其他端点已可用，未注册路由返回通用 `404 NOT_FOUND`。
- 已实现按授权范围过滤的告警/事件读取、事件研判状态迁移/备注，以及候选模型元数据/发布申请审查、响应申请/审批台账。
- 模型 API 登记不可变候选元数据；本轮增加受控 ONNX 制品校验、Java CPU 推理、交付 CSV 离线回放和显式本机激活。候选校验、独立审批和部署激活是三个分离状态步骤。
- 响应策略按版本管理（M6，V15）：起草人登记 draft 并提交，他人批准后成为 active，同一策略键的旧 active 版本同事务退役；版本不可原地修改。首期只允许 `temporary_block`，TTL 上限 3600 秒，没有经验证的回滚证据时拒绝 `autoExecute=true`。已退役版本不能再被动作申请引用，引用它的待审批动作也不能被批准。动作申请必须引用已批准且 active 的策略、匹配资产环境、策略允许目标/动作/TTL，并有当前有效的资产授权；无匹配策略或授权时拒绝且不建审批单。审批通过只更新台账；执行路由对获准申请返回 `503 ACTION_EXECUTION_UNAVAILABLE`，不调用适配器且不插入 `action_execution`。
- 真实流量在线推理 API、漂移自动化、离线训练任务执行、一般场景回放控制、报告服务和真实防火墙动作仍暂缓；本轮只开放受控模型制品校验/本机激活及交付 CSV 离线回放。

`PUT /model-deployments/active`、审批、策略发布和响应执行属于敏感操作，应要求专门权限并生成审计事件。
传感器 API 使用独立机器身份和资产范围授权；心跳或流记录接口不能调用策略、审批或防火墙动作。传感器只能上报流级记录、命中摘要、质量/健康信息，不上传原始载荷，除非另有明确设计、授权和留存审查。

浏览器认证使用 HttpOnly 服务端会话 Cookie；生产 HTTPS 部署通过 `SESSION_COOKIE_SECURE=true` 设置 Secure 与 SameSite，并对非安全方法执行 CSRF 校验。匿名接口目前仅限 live/ready、登录和 CSRF 引导。注销和角色/范围整体替换会撤销服务端会话；用户冻结与密码修改流程尚未开放。当前 connector 与 sensor 均使用独立机器身份和范围绑定；响应适配器机器路由未实现，且任何机器路由都不能回退到浏览器会话。

## 4. 传感器与在线检测契约

传感器注册请求绑定 `agentKey`、`assetId`、`dataSourceId`、平台/版本和能力摘要；资产与数据源范围校验通过后才签发一次性设备凭据。传感器到控制面的连接使用 TLS 和独立机器身份；注册凭据需轮换/撤销，传感器 API 按 sensor 到 asset/data-source 的绑定授权，不能复用用户会话凭据。配置响应包含配置版本、批准接口/过滤范围、流超时/窗口、`featureContractVersion`、模型版本引用、上报目的地及配置过期时间。配置不得包含可自由执行的命令或凭据明文。

流量上报采用有界批次，包含 `configVersion`、`sequence`、`observedAt`、`sourceMappingVersion`、`featureContractVersion` 和流记录数组；传感器/资产身份只能由机器主体绑定解析。服务核对授权、配置、来源映射、契约字段、时间偏差、幂等键和配置版本内序号，并将拒绝原因按字段留痕。在线契约为 `unsw-nb15-flow-v4`（17 数值 + 2 类别，规格 `docs/特征规格-unsw-nb15-flow-v4.md`）；`unsw-nb15-flow-v3.1` 只用于离线回放，在线批次一律记 `FEATURE_CONTRACT_MISMATCH` 且不发布 outbox。v4 记录体必须携带非特征元数据 `viewpoint`（`responder`/`initiator`）、`addressFamily`（`ipv4`/`ipv6`）和 `handshakeSeen`，缺失或取值非法记 `RECORD_METADATA_INVALID`；三项为空时不计入幂等摘要，v3.1 客户端重试摘要不变。传感器配置与来源映射登记契约版本和契约文件 SHA-256（V11，服务端按注册表写入，不接受客户端传入）：配置哈希与当前注册契约不符返回 `409 CONFIG_VERSION_STALE`；批次使用在线契约时，映射未绑定该契约或哈希不符返回 `409 MAPPING_NOT_APPROVED`。`POST /api/v1/data-sources/{id}/mappings` 增加可选 `featureContractVersion`，版本须已注册。

非阻断遥测随记录落库、不改变接收结论：`CATEGORY_OUT_OF_VOCABULARY`（类别不在激活模型词表内，只记字段名，不回显取值）、`VOCABULARY_UNAVAILABLE`（没有绑定该契约的激活模型）、`NOT_IN_MODEL_SCOPE`（视角或地址族不在模型 `supported_viewpoints`/`supported_address_families` 内）。推理入口须满足“记录契约 = 传感器配置契约 = 激活模型 manifest 契约”，且配置契约哈希等于注册表哈希、契约 `onlineEnabled`，否则返回稳定错误码 `FEATURE_CONTRACT_MODEL_MISMATCH`，不切换模型；契约一致但不在模型评估范围时记 `not_in_model_scope`，不推理也不算拒绝。门禁组件已实现（`FeatureContractModelGate`），由阶段 4 推理提交调用。健康窗口仅接受有限的错误码到计数摘要，不持久化任意日志文本。

传感器离线时，控制面显示覆盖降级。设备可在有效的签名配置期限内继续既有本机检测/已批准规则，但不得接受过期动作或自行更改模型。恢复连接后补报摘要时仍进行幂等和时间范围校验。

## 5. 关键接口契约

### 5.1 目标批次导入契约

`POST /api/v1/ingest/batches` 是目标导入契约，目前尚未开放。当前 connector 路由为 `POST /api/v1/machine/ingest/batches`；sensor 路由为 `POST /api/v1/machine/sensors/{sensorId}/flow-batches`，另提供 heartbeat/config/health-windows。两条机器链路均使用 `dataSourceId`、配置/映射/契约版本和含显式 `assetId` 的规范化 JSON 记录，并要求机器主体配置了相同的数据源—资产配对。

目标导入服务应返回 `202` 任务引用并提供字段级错误。当前 connector 与 sensor 路由在同一 MySQL 事务内保存批次、记录、资源范围审计和 outbox；首次写入返回 `201`，同内容幂等重放返回 `200`，同键异内容返回 `409`。M2 已提供默认关闭的异步消费者：`ingest.batch.received` 事件进入 durable 批次队列后按 `eventKey` 写消费台账，事务提交后手动 ack；可重试故障最多经过 5 次 TTL 退避，不可恢复故障进入死信。M3 本机推理提交端口已接入（`cyber.inference.local.enabled`，默认开启）：消费事务内对 accepted 记录执行契约门禁与本机推理并写 `inference_request`，与消费台账同一事务提交；关闭该开关时消费者仍按端口不可用 fail-closed。不执行 mapping 转换，sensor 记录仅执行已实现的 raw feature 契约门禁；契约在线开关关闭时记录会 fail-closed 并留痕为拒绝。

### 5.2 推理

当前实现（路线 B 阶段 4）：在线推理只由 M2 消费链路触发，不开放任意记录的同步推理入口。每条 accepted 记录写一行 `inference_request`（`request_key = local:record:<ingest_record_id>`，重复投递不重复推理），结果带模型版本、契约版本与契约文件哈希、`attackProbability`、`binaryLabel`、`decisionThreshold`、`thresholdPolicyVersion`（阈值固定时为 `fixed:<model_version>`）与 `latencyMs`。稳定错误码：

| 状态 | 错误码 | 含义 |
|---|---|---|
| `rejected` | `FEATURE_CONTRACT_MODEL_MISMATCH` | 记录契约、传感器配置契约（须 `active`）、激活模型 manifest 契约或契约哈希不一致；`rejectReason` 给出细分原因（如 `record_contract_missing`、`config_not_active`、`record_model_mismatch`） |
| `rejected` | `ACTIVE_MODEL_UNAVAILABLE` | 没有本机激活模型；不回退、不给默认分数 |
| `rejected` | `MODEL_INPUT_CONTRACT_MISMATCH` | 字段缺失、类型不符或非有限值（`rejectReason` 如 `feature_missing:dur`） |
| `not_in_model_scope` | — | 视角或地址族不在模型评估范围，不推理、不算拒绝 |
| `timed_out` | `INFERENCE_TIMEOUT` | 单批超时（默认 2000 ms，`cyber.inference.local.batch-timeout-ms`） |
| `failed` | `MODEL_RUNTIME_FAILED`、`MODEL_OUTPUT_CONTRACT_MISMATCH` | 会话错误；输出数量或标签与阈值不一致 |

工作线程容量耗尽（`INFERENCE_CAPACITY_EXHAUSTED`）、门禁判定后激活版本切换（`ACTIVE_MODEL_CHANGED`）和激活不变量被破坏（`ACTIVE_MODEL_AMBIGUOUS`）不落行，整批回滚并按 M2 策略重试直至死信。

`GET /api/v1/inference-requests`（`inference.request.read`，按数据源范围过滤）支持 `dataSourceId`、`assetId`、`status`、`modelVersionId`、`from`/`to`（ISO-8601 UTC，默认最近 24 小时，最长 7 天）、`page`、`size`（≤ 100）；参数格式错误返回 `400 INVALID_REQUEST`。

`POST /api/v1/inference/dry-run`（`model.replay.run`，需在该数据源范围内）请求体 `{"dataSourceId":…, "batchId":…}`，只允许 `source_type='replay'` 的活动数据源，否则 `409 DRY_RUN_REPLAY_SOURCE_REQUIRED`；批次不存在、不属于该数据源或不在调用者范围内返回 `404`。走与在线相同的门禁与推理路径，返回逐条结果，不写 `inference_request`、不产生告警，只写审计 `inference.dry_run`；推理暂不可用返回 `503`。

以下为目标同步推理契约，尚未开放。`POST /api/v1/inference` 请求引用一个已接入记录，或提交符合模型契约的规范化流记录，并指定 `inputContractVersion`。调用方不得指定未激活的任意模型；影子对比需单独权限和显式模型列表。

```json
{
  "inputContractVersion": "unsw-nb15-flow-v3.1",
  "records": [{
    "recordKey": "flow_01...",
    "features": {"dur": 0.42, "proto": "tcp"}
  }]
}
```

响应可能为同步结果或 `202` 任务引用。每个结果含：`recordKey`、`status`、`modelKey`、`modelVersion`、`deploymentMode`、`binaryLabel`、可选 `attackCategory`、`score` 或经校准的 `probabilities`、`thresholdPolicyVersion`、`qualityStatus`、`latencyMs`、`createdAt`。字段不全/单位或版本不符返回 `422 MODEL_CONTRACT_MISMATCH`，不对该记录静默推理。

### 5.3 模型校验与激活

模型登记使用受控 `artifactRef`，不通过浏览器上传任意可执行文件。制品解析限制在配置的制品根目录内，并拒绝路径穿越和越界符号链接。校验端点检查模型 SHA-256、已登记 manifest 快照、二分类标签/特征契约、opset、ONNX Runtime Java 版本及图输入输出，并执行有限冒烟推理；失败保持候选状态。校验成功只将候选设为 `validated`，不会批准或激活。

发布申请只允许已验证候选；`model_releaser` 必须由不同于申请人的用户独立批准/拒绝。批准同时更新模型审批状态和发布审查台账，但不激活。随后 `model_operator` 可显式激活本机部署；服务再次核对制品哈希/契约，事务性停用旧部署、登记新部署并审计。ONNX Java 固定使用 ONNX Runtime 1.23.2 CPU provider；远端部署不属于本轮范围。

离线 Java 回放命令读取交付目录内的 `replay-sample.csv`，要求恰好 10,000 条且字段齐全，逐行比较 ONNX Runtime 与远端概率/标签；最大概率差不得超过 `1e-5`（路线 B §10.2，严于训练端 1e-4），标签必须全部一致。命令生成逐行结果和摘要报告，写入交付目录之外的独立输出目录（交付包文件均登记在 `checksums.json`，原地写入会破坏制品校验），不覆盖既有报告。缺少样本或制品时不生成通过报告，也不能激活模型。

### 5.4 创建响应动作

分析员/策略流程提交 `eventId`、`assetId`、白名单 `actionType`、有限参数、`reason` 和 `Idempotency-Key`。服务端返回动作状态 `rejected|pending_approval|queued`。

请求中的目标必须已登记、授权有效且属于策略范围；客户端不能提交 shell 命令或任意 URL。动作参数只能表达窄范围、带 TTL 的阻断，不允许覆盖主机默认防火墙策略；服务端校验保护资产和管理连接。风险等级、自动执行与审批由服务端策略决定，不能由调用者用参数绕过。超范围或授权过期返回 `403`，策略冲突返回 `409`，并产生审计记录。

### 5.5 审批与回滚

审批请求包含 `decision` (`approve`/`reject`) 和理由；审批人不能是策略禁止的发起者。审批只授权具体动作快照，不授予后续任意操作。动作状态端点提供适配器结果和回滚能力标志；回滚使用专用 `POST /actions/{id}/rollback`，再次进行范围和权限校验，返回异步状态。

## 6. 数据源/推理/响应适配器内部端口

以下是服务内部契约，不直接暴露为任意远程管理 API：

- `FlowNormalizer`: 来源记录 + mapping version → 规范记录 + 质量问题。
- `InferencePort`: 模型版本 + 合格规范特征 → 版本明确的分类结果或可分类错误。
- `ResponseExecutor`: 策略签名的动作 + 授权资产快照 + 幂等键 → 主机防火墙执行回执/到期或回滚引用。
- `SensorConfigPort`: 传感器身份 + 当前授权 → 最小权限签名配置；不得返回任意命令。

每种实现需要健康检查、超时、限流、错误分类和审计字段。响应实现只能由管理员配置的适配器注册，不允许用户动态指定类、脚本或任意 endpoint。

## 7. 漂移、反馈与离线训练契约

- 漂移接口只读取固定时间窗统计及状态，不提供任何更新活动权重的 API。漂移窗口由后台任务按 UTC 整点小时写入（`cyber.drift.enabled`，默认关闭），基线来自 manifest `feature_baseline_stats`（`baseline-v1`）；缺基线记 `baseline_unavailable`，结构不合规时模型校验以 `MODEL_BASELINE_STATS_INVALID` 失败。
- 告警级反馈由研判员标注、第二人复核（见 §3.2）；只有复核批准的标注 `training_eligible=true`，可进入离线训练候选。标注与复核不改阈值、不换模型、不触发处置。
- 反馈样本必须引用原始流/告警、人工标签、标签依据、审核人和时间。系统不得将模型预测自动复制为真实标签。
- 创建离线训练任务需指定经批准的数据集版本、标签清单、算法候选和 Windows 训练环境。任务运行在训练环境，与在线传感器推理隔离。
- 训练任务完成只登记候选制品和评估报告；候选须通过哈希/manifest、锁定测试、类别召回/正常误报、特征兼容、推理性能和影子观察，再由有权限人员发布。
- 发布接口需记录旧/新模型版本、批准人、部署目标、校验结果和回退版本；任何门禁失败都保持现有活动版本。
- 本项目不提供大语言模型训练/微调或在线自学习接口。
- 限速动作只有在目标平台适配器能力清单和运行时健康检查均确认支持后才允许提交；不支持时 API 返回 `ACTION_NOT_SUPPORTED`，不得降级成语义不同的阻断。

## 8. 异步任务和安全控制

- 导入、批量推理、回放、处置、报告均有可查询任务 ID、状态、进度、失败原因和重试策略。
- 消费者按任务 ID/幂等键去重。响应动作重试前检查既有执行记录和适配器回执，不可盲目重放。
- 任务取消只在其状态和动作语义允许时成功；正在执行的外部动作须通过适配器补偿/撤销，不能仅更新数据库状态。
- API 访问按用户/客户端、资产范围、环境和动作类型授权；写入审计及请求关联 ID。外部错误消息脱敏。
- 授权是功能权限点与资源范围的交集。scope 条件必须进入数据库查询后再分页；禁止先取出全量或按 ID 取对象后仅在控制器鉴权。范围外单资源读取返回 `404`，越权写入返回 `403`。
- 多资产/多来源事件只有在所有关联对象和返回证据均属于调用者范围时才可见；归属不明时 fail-closed。审批接口仅暴露作出具体决定所需的范围内快照。
- `platform_admin` 对告警、事件、运行状态和审计的全局权限是只读，不包含响应审批/执行或模型发布。角色分配及敏感授权变更要审计操作者、范围、时间和 request ID。
- OpenAPI 文件应在实现阶段由本设计生成并纳入契约测试；当前文档定义语义，不代表接口已实现。


## 9. 阶段 1 已实现契约补充

生命周期接口的路径、权限与请求体统一见[接口实现核对矩阵](接口实现核对矩阵.md#阶段-1-增量接口2026-10-01)。用户冻结、改密与改角色撤销全部会话；口令受 BCrypt 72 字节限制。配置对象停用/退役保留历史事实，传感器配置须起草、独立审批、显式启用，不提供原地修改；已吊销凭据不可恢复。

检测规则的 condition 可包含 `window: {seconds, aggregate, field?, threshold, groupBy?}`：seconds 为 10～3600 整数，aggregate 为 count 或 sum（后者必需 features.* 求和字段），threshold 为 (0, 1e9] 数值，groupBy 只支持 asset；all 为 1～16 个受限字段比较。超限窗口抛 `DETECTION_WINDOW_CAPACITY_EXCEEDED`，消费整批回滚，不静默跳过告警。

模型 manifest 的 feature_contract 可新增 supported_protocols 与 requires_handshake_seen。缺省兼容旧包；显式类型错误、空列表或与词表不一致拒绝校验。requires_handshake_seen=true 要求协议仅 tcp。范围外推理结果为 not_in_model_scope，不写概率、不隐式换模型。该元数据条件不增加 ONNX 输入字段，也不修改冻结规格。
