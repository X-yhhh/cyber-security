# 功能模块设计

版本：host-guard v5，目标设计；无前端任务。阶段见[开发路线](开发路线.md)，对象见[数据库设计](数据库设计.md)。

## 1. 模块职责

| 模块 | 输入 / 输出与边界 | 阶段 |
|---|---|---|
| M01 身份与范围授权 | 人工/机器主体 → 权限与资源范围；采集身份不能领执行命令 | P4 |
| M02 资产与能力授权 | 资产/接口/环境 → 观察权与执行租约；撤销拒绝新动作并请求清理 | P1、P4 |
| M03 因果采集与特征 | PCAP/被动报文 → prefix/final、时间窗、质量；同实现 | P1、P2 |
| M04 数据与标签登记 | 来源/规则/哈希 → manifest；Unknown 不造标签 | P1、P3 |
| M05 训练与校准 | train/validation → 树模型/MLP/必要的时序候选；Windows 离线 | P3 |
| M06 模型登记与运行时 | ONNX/manifest/评估 → 冻结本机推理；激活不启用阻断 | P3、P4 |
| M07 接入与检测 | 观察 → 推理与结论；幂等、期限、容量保护 | P4 |
| M08 目标级关联 | 同对象推理/规则 → evidence episode；同连接快照不重复计数 | P4 |
| M09 策略与发布包 | 模型/策略/评估/能力 → 冻结发布组合；独立审批 | P3、P4、P7 |
| M10 执行与恢复 | 签名命令 → 规则/回执；TTL、幂等、断连重启恢复 | P1、P5 |
| M11 回放与评估 | 冻结场景 → 分类/动作/时效报告；不注入攻击报文 | P2、P6 |
| M12 研判反馈与审计 | 告警/人工证据 → 追加记录；反馈不自动成为真值 | P4、P7 |
| M13 运行健康与停用 | 丢包/积压/心跳/预算 → 观察或暂停；不自动换权重 | P4、P8 |

## 2. 角色与权限

下列是 v2 目标权限，P4 显式映射旧 IAM；当前不自动生效。角色同时受 asset/model/dataset/report 范围约束。所有人工角色共有范围内的 `resource.read`，只用于非敏感对象元数据；敏感查询仍需表列专门读权限，写权限不隐式授予全部读取。同一版本起草人与批准人必须不同；服务账号不能代替独立批准。

| 角色 | 目标权限 | 边界 |
|---|---|---|
| platform_admin | `iam.manage`, `asset.manage`, `sensor.manage`, `authorization.request`, `ops.read` | 不默认拥有模型/策略批准权限 |
| security_reviewer | `authorization.approve`, `bundle.approve`, `policy.approve`, `evaluation.read`, `detection.read`, `action.read`, `action.revoke`, `automation.stop` | 不自批，不越过执行硬约束 |
| model_operator | `dataset.manage`, `model.manage`, `model.validate`, `evaluation.run`, `evaluation.read`, `policy.draft`, `bundle.request` | 不操作防火墙、不在线训练 |
| security_analyst | `detection.read`, `event.manage`, `feedback.label`, `action.read`, `action.request` | 不指定任意地址或 shell |
| evidence_reviewer | `feedback.review`, `evaluation.read`, `detection.read` | 不复核自己标签 |
| auditor | `audit.read`, `evaluation.read`, `action.read` | 只读 |
| sensor_agent | `machine.observation.write`, `machine.sensor.read`, `machine.sensor.health` | 不能领命令 |
| executor_agent | `machine.command.claim`, `machine.receipt.write`, `machine.executor.health` | 不能提交观察或标签 |

单人开发可完成研究和测试身份隔离；测试身份只证明程序约束，不等于实际第二人发布审核。没有独立审批不能伪造 authorized_auto。

## 3. 状态与协作

### 3.1 观察和推理

观察为 `accepted / rejected / duplicate`，推理为 `succeeded / not_applicable / rejected / failed / expired`。不成功的推理不带攻击概率。接收成功不等于推理成功，两者分别查询。

上下文不足时记录覆盖时长，不因此丢弃合法单流；模型 manifest 决定是否适用。数据缺失不能伪装成低风险。

### 3.2 检测与事件

结论为 `observe / alert / block_candidate`。事件为 `open / investigating / contained / resolved / false_positive / closed`。只有确认规则生效才记录 contained；到期解除不自动宣称攻击已解决。

执行证据 episode 按 `(assetId, sensorId, bootId, peerKey, keyEpoch, direction, transport, servicePort, family, bundleId)` 和固定 30 秒桶归并，按 parentConnectionId 去重，续段也不能重复计数。同一主机其他 peer 不得升级本 episode。案件可以合并多个 episode，动作仍绑定单一证据与目标。

### 3.3 发布与动作

策略为 `draft → reviewed → retired`；发布包为 `candidate → evaluated → approved → active → suspended/retired`，审批与激活分开。模型、特征、策略、验收和平台能力按确切哈希绑定，仅改阈值也要新发布包。策略—能力的绑定唯一落在发布包（`guard_release_bundle` + `guard_bundle_capability` + `guard_asset_binding`），不在策略增加能力字段；禁止出现"能力已登记可自动、策略仍为 draft"的活动组合。细则见[rc.2 契约澄清](contracts/clarifications-rc2.md#c4-策略与能力的绑定落点)。

动作状态和失败后的实际核对见[检测与处置契约](检测与处置契约.md)。拒绝须提供稳定原因，不能以“高风险”覆盖超时或目标未知。

## 4. 保留、替换及非目标

- 复用 IAM、资产、会话、MyBatis、outbox、制品校验、审计和研判。
- 替换单一 v4 特征路线、资产级自动关联、影子 G3 放行和无执行器的响应流程。
- 不做前端、全网扫描、攻击生成、漏洞利用、恶意软件运行、通用清洗、在线自训练、任意脚本策略。
- 采集、模型、执行器分别验收再联合发布；未实现能力不能写成支持。

## 5. 完成标准

每个模块具备契约、实现、相关测试、可复算证据和局限。M03 通过不代表 M05 准确，M05 通过不代表 M10 安全，M10 通过不代表模型值得自动执行。最终以[验证与验收](验证与验收.md) 为准。
