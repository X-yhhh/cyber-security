# 接口设计

版本：host-guard v5 API，状态核对于 2026-10-15（C1）。P4 已实现 v2 控制面、机器接入、多分类推理、来源汇总、rc.3 后端范围校验、lab 验证会话与 B5 只读查询（见[系统实施记录](系统实施记录.md#3-p4-后端数据库与决策)）；健康协议 1.1.0（文件回放）已实现，只用于正式 lab 会话的 T2 与领取复核；P5 新范围执行和其他未实现端点不能因文档存在视为已实现。P1/P2 已收口，新协议统一 `/api/v2`。B1/B4 已提供 v2 身份与角色维护，F5 会话已切换，C1 已删除旧 v1 人工接口；旧机器契约保留至 BE-11，不静默改语义，公共健康探针使用 `/health/*`。

## 1. 通用约定

- HTTPS；本机回环开发可 HTTP，非回环不得明文。人工请求使用服务端 session，所有人工写入校验 CSRF；机器使用专用 bearer 凭据，不接受浏览器 session 冒充。
- 外部 ID 为 UUID，映射数据库内部 BIGINT。时间为 UTC RFC3339 Z。列表 `cursor` + `limit`（默认50，1—200），按 `(createdAt,id)` 稳定倒序；返回 nextCursor，不让跨范围记录影响可见分页。
- 所有资源先权限再范围校验；跨范围单对象返回404，功能权限不足403。请求 trace 使用服务器生成/校验的 `X-Request-Id`，日志脱敏。
- 人工/机器写入均需 `Idempotency-Key` UUID，范围为主体+方法+路由模板+资源+键；保存 JCS 请求 SHA-256。相同键内容不同409，相同内容返回原结果。幂等记录至少覆盖重试期，动作幂等事实永不按短缓存到期删除。
- JSON 未知字段拒绝；Content-Type固定 application/json，默认请求≤1MiB。观察批次最多512条且不得超过已批准 sensor 配置的上限；不接受原始 PCAP/权重/任意文件路径上传到通用接口。
- 人工更新需 `If-Match: revision`，并发冲突409；批准的不可变版本不能原位 PATCH。

统一响应：`{requestId, data, error}`；成功 error=null；失败 data=null，error 为 `{code,message,retryable,details}`。details 只含脱敏字段名/原因码。异步接收202意味着持久化受理，不代表检测、部署或阻断已完成。

P1R-2 的 v2 错误日志约定：`GuardApiErrors` 对 5xx 以 ERROR 记录经校验的 request-id、HTTP 状态、异常及原因类型；JDBC 故障可附合法的五位 SQLState 和数字错误码。原因链只做有界检查，不记录异常消息、Throwable 堆栈、SQL/参数、URL、请求头、Cookie 或请求体。4xx 沿用现有状态映射，不进入此服务器错误日志；响应信封与脱敏文案不变。

并发幂等写入：首次查询已提交结果使用非锁定读，避免 MySQL REPEATABLE READ 对缺失键加间隙锁；同键竞争由唯一索引串行化。插入冲突先回滚，再以新事务锁定读取已提交结果，重新验证当前权限与请求摘要后重放，不自动重复业务副作用。不同载荷仍返回 409 `IDEMPOTENCY_CONFLICT`。

## 2. 权限与资源映射

人工共同查询需要 `resource.read` 和该资源范围；报告另需 evaluation.read，安全数据另需 detection.read，动作另需 action.read。写权限见下表；角色、权限键、范围类型（只认 global/asset）、角色互斥与职责分离以[权限设计](权限设计.md)为唯一基线。v2 身份与访问接口（`/api/v2/auth/*`、users、role-bindings、roles、machine-clients 列表，BE-16/B4）已实现，见权限设计第 10.1 节。C1（BE-17）已删除所有 v1 人工控制器和专用依赖；浏览器及 P7 登录只使用 v2。`/api/v1/machine/*` 保留至 BE-11，数据库旧表退役归 DB-8。公共探针为 `GET /health/live`（存活）和 `GET /health/ready`（数据库就绪）；均无需登录，返回包含 requestId 的兼容信封，依赖故障为脱敏 503 `DEPENDENCY_UNAVAILABLE`，不提供旧 v1 健康别名。机器权限精确绑定 sensor/executor→asset，不接受独立范围笛卡尔积。人工管理员不能用普通业务请求指定机器已批准标志。

### 3.1 身份与访问（B1，rbac-v2）

已实现并通过隔离验证，验证与交付记录见[初版落地任务单 B1](任务/初版落地任务单.md#b1-身份与访问-v2--v26-权限迁移be-16db-10)。所有路径以 `/api/v2` 为前缀；人工 session、CSRF、登录限速与口令策略沿用现有组件。口令至少 12 字符、至多 128 字符且 UTF-8 不超过 BCrypt 的 72 字节上限。

| 方法/路径 | 请求与返回 | 权限与失败边界 |
|---|---|---|
| GET /auth/csrf | `{headerName,parameterName,token}` | 允许匿名；先取得 CSRF 和会话再登录 |
| POST /auth/login | `{username,password}`；返回与 me 相同的身份摘要 | 轮换会话；401 AUTHENTICATION_FAILED，429 LOGIN_RATE_LIMITED |
| GET /auth/me | `{id,username,displayName,roles,bindings:[{id,roleKey,scopeType,scopeId}],permissions}` | 每次读取当前有效用户、角色和权限；不返回口令哈希、会话编号 |
| POST /auth/logout | `{}`；`{status:logged_out}` | 登录用户；注销当前会话 |

| GET /users | `cursor,limit=50,status,q`；`{items,nextCursor}` | 全局 `iam.manage`；status=active/disabled/locked；q 为用户名/显示名前缀，筛选先于 LIMIT |
| GET /users/{id} | `{id,username,displayName,status,revision}` | 全局 `iam.manage`；不存在或范围不覆盖均 404 |

| PATCH /users/{id} | `{username?,displayName?}`；200 用户 | 全局 `iam.manage`；必须 If-Match |
| POST /users/{id}/status-changes | `{status,reason}`；200 用户 | active/disabled；必须 If-Match；撤销目标全部会话 |

| POST /role-bindings/{id}/revocations | `{reason}`；200 `{id,status:revoked}` | 撤销指定绑定并保留追加审计；撤销目标全部会话 |

用户与绑定 ID 为正整数，绑定 ID 由 V26 为既有绑定补齐；用户 revision 从 1 起，资料、状态、口令、绑定变更递增。新绑定不接受 v1 的 data_source/model_registry 范围，auth/me 也不从这些范围计算权限。角色目录纳入停用自定义角色，不重新暴露 v1 旧角色；返回数组而非游标页（B4）。

所有写请求必须带 UUID `Idempotency-Key`，未知字段拒绝。同主体、路由、键和内容重试返回原结果；不同内容或 If-Match 不同返回 409 `IDEMPOTENCY_CONFLICT`。含口令请求只持久化带密钥的内容摘要，不保存原文或可离线猜解的普通口令摘要。登录幂等绑定 CSRF 引导会话，不允许用缓存恢复已失效会话；退出/改密/管理撤权后的旧会话须重新登录，重试同样先过当前认证和授权。

用户管理仅限全局范围；具备功能权限但仅绑定资产的主体查询/变更单个用户时返回 404，集合访问返回 403。本人管理返回 403 `SELF_ADMINISTRATION_FORBIDDEN`（本人改密走 auth/password）；互斥角色 409 `ROLE_CONFLICT`；失去最后有效全局管理员 409 `LAST_ADMIN_REQUIRED`；停用角色 422 `ROLE_DISABLED`；修订不符 409 `REVISION_CONFLICT`。审核职责分离规则仍见[权限设计第 6 节](权限设计.md#6-职责分离)。写审计使用 `iam.user.*`、`iam.binding.*`、`auth.*`，记录 global/asset 资源范围，口令不进入审计。

`GET /feedback` 与 `/feedback/{id}` 返回 `createdBy`（整数，与 `/auth/me.id` 同口径），供现有页面识别本人标注及隐藏本人复核入口；不附带用户资料或复核人信息。列表仍按 `detection.read` 和资产范围裁剪，支持 `status,assetId,from,until,sort,cursor,limit`，不支持 `q` 或按任意用户查询。当前页面的“我的标注”与“排除本人”只筛选已加载的当前页；服务端独立强制 S6，客户端的本人识别不授予复核资格。

`displayName`、`notes` 可显式传 `null` 清空，上限分别为 128、1000 字符。状态变更、退役、撤回的 `reason` 必填。新写接口先校验功能权限（不足为 403 `SCOPE_DENIED`），再校验对象范围（越界为 404 `RESOURCE_NOT_FOUND`）；缓存重放也复核当前权限，草稿删除后的资产归属和组合退役前状态从服务器缓存读取。角色目录保留数组形式，增加 `status`、`builtin`、`revision` 并纳入停用自定义角色；成员与用户列表使用加密游标。`q` 只在登记了搜索列的集合可用，未知、重复或空查询参数均拒绝，筛选变化后旧游标返回 400 `INVALID_CURSOR`。

#### B5.1 待办响应与跳转契约

`GET /api/v2/todos` 的 `data` 为 `{groups:[{kind,count,items:[{kind,id,title,assetId,createdAt,route}]}],truncated}`。组 `kind` 固定依次为 `approve`（需要批准）、`triage`（需要研判）、`other`；条目 `kind` 为下表的机器键。`id`、`assetId` 只使用公开 UUID，全局对象的 `assetId=null`；`createdAt` 是对象创建时间，UTC RFC3339；`title` 是中文事项名称。接口只查询 MySQL，不写审计或业务状态，无需 CSRF、幂等键或修订号。

- 每个类别使用自己的权限键与资产范围计算，权限和范围须来自同一个有效角色绑定。策略、模型、发布组合是全局对象，必须持有相应全局权限；资产范围角色不能查看这些全局对象。
- 没有任何可见类别的组不返回；可见但当前无事项的组允许 `count=0,items=[]`。没有任何可见类别时为 `{groups:[],truncated:false}`。
- 只读 REPEATABLE READ 事务内计算完整计数与列表。先按分组优先级，再按组内 `createdAt DESC,kind ASC,id DESC` 排序，**所有组共用 100 条上限**；同组各类别归并后再截断。`count` 不受上限影响；后续组可能计数大于 0、列表为空。可见总数超过 100 才有 `truncated=true`，恰好 100 为 false。
- 未登录或仅带机器 bearer 返回 401；服务层拒绝非人工身份（403 `HUMAN_IDENTITY_REQUIRED`）。任何查询参数，包括空参数、`limit`、`assetId`，均为 400 `INVALID_QUERY`，错误沿用统一信封及 `requestId`。

## 4. 机器观察与健康

### 4.1 提交观察

`POST /machine/sensors/{id}/observation-batches`，权限 machine.observation.write。

请求 `{batchId,bootId,sequence,configId,contractVersion,profileSha256,observations}`，observations 中每条遵循 [Observation Schema](contracts/observation.schema.json)。最大512条，具体受已批准配置 `limits.maxBatchSize`（1—512）限制；原有100条配置继续有效，不自动变更。请求体仍最多1MiB，传感器在下一条将超出字节上限时先封口，单条已超限则显式失败。batchId固定，sequence按boot从1单调递增；重试同键复用原序号。允许接收乱序到达批次但记录缺口，缺口未恢复期间相应上下文不得用于自动动作。

服务端从身份读取asset/sensor/environment，不信任请求扩大范围；逐条核对boot/config/profileSha256和结构，整批身份/版本/幂等冲突拒绝。业务记录可部分接收，202返回 `{batchId,status,acceptedCount,rejectedCount,duplicateCount,rejections:[{observationId,code}]}`。拒绝明细逐条返回，不超过本批记录数（最多512条）。

同事务写观察/拒绝事实和outbox；随后返回。查询 `GET /observation-batches/{id}`、`GET /observations/{id}` 返回接入与推理独立状态，不把202当作执行成功。查询需要 detection.read 与全部来源/资产范围。

### 4.2 配置和健康

| 方法/路径 | 机器权限 | 请求 / 响应 |
|---|---|---|
| GET /machine/sensors/{id}/config | machine.sensor.read | 批准配置、契约/profile/健康版本、采集范围、资源上限、serverTime |
| POST /machine/sensors/{id}/heartbeats | machine.sensor.health | bootId,version,configHash,lastSequence,clockSkewMs；返回serverTime，不下发秘密 |
| POST /machine/sensors/{id}/health-windows | machine.sensor.health | healthVersion,healthWindowId,assetId,sensorId,observerSessionId,captureScopeId,sequence,intervalStart/End,previousSha256,counterStart/End,captureGap,clockSkewMs,configSha256,buildSha256；可附metrics |
| POST /machine/executors/{id}/heartbeats | machine.executor.health | bootId,adapterVersion,capabilityHash,pendingRecovery,activeRuleCount,clockSkewMs；capabilityHash 为能力集合摘要，定义见领取说明 |

healthVersion 接受 `host-guard-capture-health/1.0.0` 和 `host-guard-capture-health/1.1.0`，默认现场版本仍为 1.0.0。1.1.0 必填 captureSource=live/file_replay，1.0.0 拒绝此字段。live 沿用旧计数校验；file_replay 必须 kernelDrops=null，packetsSeen 已知且不回退、capacityDrops 已知且不变，通过为 replay_healthy，仅在绑定 1.1.0 subject 的 running 正式 lab 会话中用于 T2，不用于预算恢复。assetId/sensorId必须与机器身份及路由一致。counterStart/End 的键固定为packetsSeen、kernelDrops、capacityDrops，均为非负累计整数或null；未知不填0。可选metrics仅包含lateCount、queueMax、memoryBytes、cpuPercent、qualityCounts。窗口最多5秒，实时接收延迟不超过10秒。按机器身份+observerSessionId+sequence及healthWindowId去重，同键不同哈希拒绝；校验认证身份、区间连续、前序摘要、计数单调和配置/程序身份。采集器不能自行上报healthy=true或budgetReset=true使额度恢复。

逻辑特征引擎重置不停止健康观察器；物理捕获域/观察器中断或变化必须显式留痕，不能用连续序号掩盖缺口。健康窗口与观察分开持久化，合格与否由服务端按[契约第9节](检测与处置契约.md#92-连续健康与预算恢复)推导。缺口、未知计数或时钟不可信不能作为冷却证明；恢复额度还须匹配真实规则清零事实与最后合格证据。心跳中的serverTime用于新鲜偏差计算，旧偏差不无限缓存。

### 4.3 稳定目标绑定

`POST /machine/executors/{id}/target-bindings`，权限 `machine.target.bind`。可信本机解析器先核验targetRef，再提交 `{bindingId,executorBootId,sensorId,collectorBootId,captureScopeId,targetRef,peerKey,keyEpoch,scope?,direction,transport,servicePort,addressFamily,stableTargetToken,scopeDigest,expiresAt}`；身份限定asset/environment。可选scope省略时兼容peer_service，servicePort必须为1—65535整数；peer_inbound须显式登记scope、direction=inbound且servicePort=null，未知或null的scope拒绝。stableTargetToken为本机持久预算密钥对规范真实目标作用域生成的不可反查HMAC，不是peerKey；密钥不随boot、capture或keyEpoch轮换，不离开本机安全存储。

授权的executionScopes每项为 `{capabilityId,scope?,direction,transport,servicePort,addressFamily}`，采用同样的scope/端口约束。类别策略、授权和目标作用域必须一致；扫描观察本身仍保存实际访问端口，不能据观察端口推定全入站执行授权。

服务端核验授权、采集/执行身份、现有绑定与保护范围，按 `(asset,environment,stableTargetToken)` 取得稳定budgetTargetId，返回201 `{bindingId,budgetTargetId,revision}`。同targetRef变绑定、旧身份重新登记不同token或状态无法关联时拒绝并核对，不能自动创建空额度；预算密钥迁移须证明旧新身份连续性并审计。原始地址不上送。此接口只登记目标映射，不创建或续期规则，也不授予命令资格。

`GET /budget-targets/{id}` 需action.read及资产范围，只返回预算占用、revision、最后证据/清零时刻、健康证明引用和拒绝原因，不返回token或真实端点。没有客户端直接清零预算接口；人工恢复仍须暂停自动能力、核对实态并留下批准与审计。

**F3 前端消费与现状边界（2026-10-15）**

`frontend/src/api/v2/release.ts` 已按 `GuardController`、`GuardQueries` 与 `GuardLabController` 的真实路由封装（实现 `e6aad6d`，分支 `Xyhhh/v1-f3`，本次先通过 PR 合入 main），没有新增后端路由。九类集合均可列表与详情读取；bindings 仅通过 `GET /release-bundles/{id}/bindings` 读取，不存在独立 `/bindings` 集合。模型的候选标记取 manifest，不把校验通过解释为已取得发布资格。

- 全局目录不传 `assetId`；models、datasets、decision-policies、release-bundles 支持 `q/status/from/until/sort`，capabilities、evaluation-plans 支持 `q/from/until/sort`；evaluations、replay-runs 不支持 `q`，lab 列表只传 `status/cursor/limit`，事件子资源使用 `after/limit`。
- 已通过的导入评价返回 `status=passed`，当前通用列表筛选白名单仍只有 `pending/running/completed/failed`，前端不得发送 `status=passed`。这个限制不改变报告原有结论。
- 策略起草先按仓库 Schema 和数值特征白名单预校验，服务端仍核验模型/计划归属、能力及独立审核。资料编辑与草稿删除带 `If-Match`；runner 推进回放/lab 的方法不作为页面执行入口。
- 策略、组合查询隐藏 `createdBy/requestedBy`，当前 DTO 不能完整支持“刷新后隐藏本人审批按钮”。页面接续需明确本人识别字段或等价服务端标记并补测试；mock 内部归属不属于真实响应契约，后端职责分离拒绝继续生效。

candidate 的模型/策略/契约/能力声明形成不可变 subjectSha256，评估报告引用该 subject；报告完成后另封存发布 manifest（含 subject 和报告哈希），再进入 evaluated/approved。报告不反向写入被评估的 subject，避免哈希循环。评估失败保留candidate及失败报告，不伪造evaluated。

## 8. 执行机器协议

`POST /machine/executors/{id}/command-claims`，machine.command.claim，body为 `{bootId,capabilityHash,maxItems,waitSeconds}`，maxItems为1—10、waitSeconds为0—5。控制面复核当下授权和目标新鲜度，返回200 `{commands:[SignedActionCommand],revocations:[RevocationRequest],serverTime}`，无任务相应数组为空。总任务数不超过maxItems，撤销优先。领取有副作用，不能用GET实现。capabilityHash 须等于最近心跳上报值，否则 422；它还须等于控制面重算的能力集合摘要：取该执行器资产 active 绑定且组合 active、平台相同、等级适配环境的能力，每项 `{capabilityId,scope,protectionSetSha256,protectedPortsSha256}`（全入站项的端口摘要仅在能力保护集等于当前保护文件时给出，否则为 null），按 capabilityId 升序取 JCS SHA-256。不一致时只返回撤销、不签发或重放命令。签发全入站命令时另记审计 `guard.command.inbound_ranges`。

命令包结构见 [ActionCommand](contracts/action-command.schema.json)，签名算法和所有绑定见[检测与处置契约](检测与处置契约.md)。rc.3 已新增 `peer_inbound` 范围及入站/空端口约束；P5 在支持与验证前须拒绝该scope。领取逐条复核所选parent的最新观察、内容哈希、模型/规则事实及目标/健康/授权；新观察尚未消费也使旧命令依据失效。同一命令重领不更新TTL；应用期限过后不再返回可执行命令；从未领取可证明未执行的记expired，已领取但无终结证明的记uncertain并核对，不能仅按时间写已清理。命令payload的bootId绑定采集器，executorBootId绑定当前领取代理；两者分别核验。

RevocationRequest固定字段为 `{revocationId,actionId,commandId,executorId,assetId,environment,desiredRevision,issuedAt,reasonCode}`；ID均UUID，desiredRevision为正整数，issuedAt为UTC时间，未知字段拒绝。控制面仅返回该executor名下任务，HTTPS校验服务端身份；恢复撤销不依赖已经过期的执行授权。pending从未签发命令的撤销由控制面锁行终止并审计，不生成代理任务；已签发才生成绑定commandId的RevocationRequest。代理先匹配自己的命令账本或已持久化领取记录，未知绑定拒绝并启动核对，不能执行任意规则删除。相同revocationId重领内容不变，旧revision不能覆盖新意图；代理先持久化撤销墓碑，再取消待应用命令、删除自身规则并回执revocationId。未收到清理证明会持续返回该任务，不以已领取代表成功。此通道没有任意ruleHandle/地址输入；撤销消息不另作离线签名，不能脱离受认证通道受理。

`POST /machine/executors/{id}/receipts`，machine.receipt.write，body遵循 [ActionReceipt](contracts/action-receipt.schema.json)。200表示回执已追加持久化；迟到回执不能逆转终态。同一receiptId不同哈希409。

`POST /machine/executors/{id}/reconciliations`，machine.receipt.write，body为 `{executorBootId,observedAt,digestVersion,stateDigest,ownedRules:[{actionId,commandId,ruleHandle,effectiveBlockUntil,normalizedScopeSha256}],pendingRevocations:[{revocationId,actionId,desiredRevision}],recoveryErrors}`；上限1000条规则/1MiB。服务端从认证主体取得assetId/executorId，按guard-state/1重组规范对象核验摘要；ownedRules对应其中的rules数组。只核对本系统规则；不一致先暂停、追加证据，不按控制面旧状态盲目覆盖系统。

回执stateDigest采用契约的guard-state/1，证据摘要采用guard-evidence/1；P4/P5必须按规范化对象重算。真实清零记录只更新规则事实，不能直接恢复目标累计预算；领域服务同时校验连续健康和120秒冷却后事务恢复，记录proof哈希和revision。过期、重复或来自其他executor的回执不能反复释放额度。

P5新增两个执行器专用操作，均复用机器身份、资源范围、Idempotency-Key及标准响应信封，不另增命令/回执字段（当前命令rc.3、回执rc.2）：

- `POST /machine/executors/{id}/budget-proofs`：machine.target.bind；输入 `{stableTargetToken}`，只返回所属资产/执行器的 `{stableTargetToken,budgetTargetId,revision,chargedMs,cycleStartedAt,healthProofSha256}`。查询不恢复额度。执行器仅在零额度、非空健康证明、冷却时点与本地真实清零均匹配时同步本地预算周期。
- `POST /machine/executors/{id}/clearance-proofs`：machine.receipt.write；输入 `{commandId,clearedAt,stateDigest}`，核验命令归属及时间后追加审计。历史清零报告不替代当前实态核对，不直接投影动作终态或恢复预算。

本机IPC新增 `/v1/targets/resolve-lease`，输入与旧resolve相同，返回 `{endpoints,expiresAt,lastPacketAt}`。严格复用原mTLS身份/boot/目标绑定，解析不延长引用；旧resolve响应不变。地址只在本机IPC存在。

### 11.2 参数、范围与分页

- 列表支持 `limit`（默认 50，1—200）与 `cursor`，不使用 offset。未知、重复或空值参数 400 `INVALID_QUERY`；limit 越界 `INVALID_PAGE_SIZE`；UUID 须小写标准格式（`INVALID_UUID`）；时间为 UTC RFC3339 Z、最多微秒，区间 `[from,until)` 且 from 早于 until（`INVALID_TIME_RANGE`）。status 筛选存储状态，不把已过期但未改状态的授权自动改为 expired。审计无独立 correlation 列，只按 requestId 精确筛选，历史空 requestId 保持 null。
- 无功能权限 403 `SCOPE_DENIED`；未登录由安全链返回 401（同样带 requestId）。详情、assetId/sensorId/executorId/captureScopeId 筛选和游标锚点超出范围统一 404 `RESOURCE_NOT_FOUND`，不泄露存在性。范围条件与筛选写在 SQL WHERE 中、先于 LIMIT 执行，不取页后再过滤。
- 审计（T1-R3）：v2 全局 `audit.read` 可查看全部已登记范围的记录；局部授权须覆盖每条 `audit_resource_scope`，部分覆盖不放行。历史无范围记录仍仅持 `audit.read` 的全局 `platform_admin` 可见；旧 `AuditMapper` 的精确范围规则不变，不恢复已退役的 v1 人工接口。新的 guard 目录审计显式登记 `global/*`，资产审计登记所属资产；不回填历史行。
- 审计补齐（T1-R2）：研判追加记录为 `guard.event.noted`，策略起草为 `guard.policy.drafted`，报告导入为 `guard.report.imported`；与业务写入共用事务与幂等键，审计只保存摘要，不复制研判自由文本或报告正文。
- 排序为（排序时间,内部 id）倒序，内部 id 不返回。游标是进程内随机密钥 AES-GCM 认证加密的不透明值，绑定主体、集合与全部规范化筛选（limit 可变），内含首屏可见最大 id 上界、锚点和 asOf。后续页排除上界之后追加的记录，并每页重新核验当前权限与锚点范围。篡改、截断、换筛选/主体/集合及进程重启后的旧游标返回 400 `INVALID_CURSOR`，需重读首屏；锚点已移出范围返回 404。多实例部署需共享密钥或会话粘滞，当前未实现。只读 REPEATABLE READ 事务保证单页一致，多页不是长期快照。
- 恰好满页时 nextCursor 为 null，不产生空尾页；空集返回 `items=[]`、nextCursor=null。
- P1R-2 的大行读取约定：AUTHORIZATIONS、CONFIGS、HEALTH、SENSORS 在权限、资产范围、筛选与游标条件内，先按原排序时间和主键选取有界键页，再按主键延迟关联完整行；SENSORS 的当前 active 配置仅在键页选定后读取。排序不携带 scope/config/health 大 JSON，仍保持详情、字段白名单、读取上界和 `(时间,id)` 倒序语义；不调整全局排序缓冲区、不新增迁移。

### 11.3 返回字段白名单与健康四态

- 授权：id、assetId、status、revision、createdAt、requestedBy、validFrom、validUntil、validity（not_yet_valid/valid/expired，仅按 asOf 展示时间）、scope。scope 只含 interfaces、observationAllowed、executionScopes（scope/direction/transport/servicePort/addressFamily/capabilityId）；不返回 evidenceRef、authorization_ref、地址、稳定目标 token、审批人或理由原文。
- 采集配置：id、assetId、sensorId、status、revision、createdAt、requestedBy、configVersion、featureContractVersion、activatedAt、contentSha256、definition（contractVersion/profileSha256/captureHealthVersion/interfaceIds/limits.maxBatchSize/captureScopeId/addressFamily/buildSha256）。旧 v1 配置 definition=null；配置无有效期字段，不杜撰；不返回过滤规则及其他原始 JSON。
- **F4 本人识别已实现**：上述两个集合及详情的 `requestedBy` 为申请人/起草人的用户 ID，与 `GET /api/v2/auth/me` 的 `id` 同口径；历史无归属时为 null，不伪造本人。字段只服务于入口显隐，不扩大可见范围、不授予审批权；自批、代他人撤回/删除等仍由后端写服务独立校验。契约及隔离 MySQL 回归见[实施记录 6.32](系统实施记录.md#632-初版-f4非页面实现与自动化验收2026-10-15)。
- 审计：id（稳定派生 UUID 引用）、occurredAt、actorType、action、resourceType、resourceId、requestId、outcome。合法 UUID 的 resourceId 原样返回，其他历史值以带类型的派生 UUID 呈现，不可解引用、不授予权限；不输出 actor_id、reason、metadata 和快照哈希。
- 健康窗口：id、assetId、sensorId、captureScopeId、observerSessionId、sequence、intervalStart/End、receivedAt、verificationStatus、serverVerifiedHealthy、failureReason、freshness、healthState、healthBasis=server_verified_window、healthVersion、configSha256、buildSha256、counterStart/End（packetsSeen/kernelDrops/capacityDrops）、captureGap、clockSkewMs。类型不符或未知为 null，不输出原始 payload、摘要链及自由格式 metrics。
- 传感器心跳：id、assetId、status、revision、receivedAt、bootId、agentVersion、freshness、healthState、healthBasis=heartbeat_and_status、projection=latest、serverVerifiedHealthy=null、reportedConfigSha256/lastSequence/clockSkewMs=null（当前投影未保存这些上报值）、currentConfig（当前 active 配置的 id/configVersion/contentSha256/buildSha256，无则 null）。不返回 credential_ref。
- 执行器心跳：id、assetId、status、revision、receivedAt、bootId、adapterVersion、capabilityHash、freshness、healthState、healthBasis、projection=latest、serverVerifiedHealthy=null、reported（pendingRecovery/activeRuleCount/clockSkewMs）。不返回 api_client 或凭据引用。
- 运维每项：id（assetId）、status、sensorCount、executorCount、lastSensorHeartbeatAt、lastExecutorHeartbeatAt、healthWindowCount、lastHealthReceivedAt、budgetTargetCount、budgetResetCount、lastBudgetResetAt；只统计已持久化事实，空为 0/null，无全局 healthy 标志，不调用预算恢复。

freshness 为 no_record / unknown（时间晚于 asOf）/ fresh（不超过 10 秒）/ stale。healthState 只取 `unknown`、`stale`、`unhealthy`、`healthy` 四值，是对已存储事实的展示映射，不重新判定健康、不用于预算恢复或自动处置资格：

| 对象 | unknown | stale | unhealthy | healthy |
|---|---|---|---|---|
| 健康窗口 | 判定缺失、COUNTER_UNKNOWN、CLOCK_UNTRUSTED；intervalEnd 晚于 asOf；HEALTH_DELAY_EXCEEDED 且 intervalEnd 晚于接收时间 | verification=healthy 但 intervalEnd 超过 10 秒；其余 HEALTH_DELAY_EXCEEDED | 其他非 healthy 判定（含未来新增码） | verification=healthy 且 intervalEnd 在 asOf 前 10 秒内（与 `GuardHealth.current` 同窗） |
| 心跳 | 从未收到、时间晚于 asOf，或新鲜但状态非 active（如 pending） | 超过 10 秒 | 状态为 offline、suspended 或 revoked | 新鲜且状态 active |

心跳 healthy 只表示机器存活且服务端状态为 active，不代表采集健康；采集健康以健康窗口为准。未知在任何对象上都不显示为 healthy。

### 11.4 验证与边界

测试覆盖每个路由的未登录 401、无权限 403、跨资产详情/筛选/游标 404 或 400、空集、恰好满页与最后一页、游标篡改/截断/换筛选/换主体/换集合、脱敏（凭据引用、证明引用、地址与嵌套伪装字段）、request ID、授权过期、旧配置、心跳无记录/过期/未来时间、未知计数和四态映射，以及查询前后业务表快照不变。上述测试尚待主会话在合并后统一运行；结果未出前不得写成已验证。

无需新增迁移。数据量增大后建议另行评估索引（如 `guard_capture_health_window(asset_id,received_at,id)`、`asset_authorization(asset_id,created_at,id)`、`audit_log(action,occurred_at,id)`），由主线统一分配迁移号并先在随机 schema 验证。
