保留当前P3原始输入、受控原件、现有运行资源与代码。docs中的删除不清空业务数据库，不触碰远端Windows训练工作区或改写历史制品包；旧运行结果不再作为当前规范入口。新的实验结果、候选和清单写入受控run目录，不能再把每轮产物堆进docs。

## 4. 版本与接入顺序

1. 沿用P1/P2交接的观测结构rc.2及提取能力，P3按新版计划完成数据/实验；旧P2包保持独立不可变，不用旧清单为新Markdown背书。
2. P3-A将行为映射、角色、共同早期轨迹、原始起点评价和连续预算/健康规则接到实际工具；训练前绑定当前数据/代码/计划哈希并通过运行计划检查。
3. P4 已完成后端/数据库代码和隔离迁移验证；P5 继续实现执行器。观测结构版本、决策/健康版本、policyVersion 与评估计划同时核验。稳定budgetTargetId跨活动/boot/keyEpoch/策略，只有实际清零与连续健康冷却都成立才恢复。
4. P6使用未暴露数据对完整冻结组合评价一次；P7汇合后端、真实模型及实际规则，记录真实起点/生效/恢复。计划能力不冒充已完成。
5. P8按具体资产和已验收能力切换。新路径失败显式暂停并核对本机规则；旧路径仅保留原已验证用途，不无提示接管v5自动动作。
