# 验证与验收

更新于 2026-10-08，第二轮候选评价版本 `host-guard-evaluation/2026-10-08.1`。本文统一 P3—P8 的验收口径：**3 道硬门槛（G1—G3）+ 类别自动资格 + 报告指标**。硬门槛之外的指标只报告、不一票否决；某一类达不到自动资格只降为“只告警”，不使整个项目失败。阶段状态以 [开发路线](开发路线.md) 为准。

T3.6 登记的新版本只绑定第二轮 `ablation-no-host-context` 候选：增加 validation 单对端敏感性冻结准入，并采纳 A11，分别计算模型及每条规则的资格。旧 `host-guard-evaluation/2026-10-07.1` 及 candidate-v2 原计划、报告和哈希保留，不追溯重算；G1—G3 数值标准及同一计划最多 3 次 test 额度不变。新计划及候选层在 `.cache/t35-t36-20261008/`，完整策略和封口仍待真实 T3.8 部署绑定；本次登记不等于 P6 访问登记、评价或平台数据库登记。

2026-10-06 之前的 `host-guard-evaluation/2026-10-05.2`（分角色完整策略回放、E5 收益区间、自动处置期/人工移交期等）随旧 prefix 慢速路线一起停用，不再作为任何阶段门槛。

## 1. 验证层次

| ID | 环境/输入 | 证明内容与边界 |
|---|---|---|
| V1 数据与特征 | PCAP、标签账本、golden | 提取可复算、无未来信息、切分无泄漏；不证明模型准确 |
| V2 离线模型 | L1/L2/L3 数据集（见第 2 节） | 分类与检出能力；不代表任意网络 |
| V3 决策回放 | 冻结 PCAP 经传感器、模型和策略 | 来源汇总、告警/封禁候选和时延；不含真实防火墙 |
| V4 动作与恢复 | 网络隔离的无害 canary | OS 规则范围、到期、撤销、故障恢复 |
| V5 联合闭环 | 传感器 → 模型 → 决策 → 执行器 | 1 倍速实时链路与真实规则；不宣称承受真实漏洞攻击 |

PCAP 由传感器以文件方式读取，不向网卡注入攻击报文；不运行攻击工具、漏洞利用或恶意软件。lab 环境的隔离要有接口/路由/防火墙证据，回放隔离与时钟规则见 [契约第 11 节](检测与处置契约.md#11-回放隔离与版本升级)。

## 3. 统计单位与判定规则

- **连接**：一个 parentConnection（含其全部 prefix/final 快照和续段）计 1 个样本，不按快照计数。
- **连接判定**：按时间顺序取该连接第一个 `attack_score ≥ alertThreshold` 的快照，类别为该快照 `family_scores` 最大的攻击类；没有快照过阈值则判为 `normal`。这与在线“首次过阈值即告警”的行为一致。
- **攻击检出率**：先算 4 个攻击类各自的连接检出率（判为任一攻击类即算检出），再取等权平均，避免洪泛类的海量连接掩盖其他类。
- **误报率（FPR）**：分别计算内部正常连接与网页补充正常连接（见 [数据与模型方案 3.1](数据与模型方案.md#31-提取视角)）各自的“被判为攻击数 / 该来源正常连接数”，再取二者等权平均。网页补充占正常样本七成以上且有客户端视角偏差，合并计算会让误报率主要反映网页补充；两个分项同时报告。
- **macro-F1**：5 类（含 normal）按连接判定计算各类 F1 后取平均。
- **活动**：一次有标签依据的连续攻击（同一攻击来源、同一类别、同一时段）。时延按活动的原始起点计算。

阈值 `alertThreshold`、各类 `autoThreshold` 与 `minDistinctFlows` 只在 validation 上选择并冻结，P6 读取 test 前不得再改。

### 3.1 T3 profile 口径登记（R3，2026-10-08）

T3 的 `policy-preview` 和 T3.3 选值统计包含 prefix/final；validation 共 106,129 条快照，其中 prefix 32,621 条、final 73,508 条，dos_slow 的 3,167 条中有 561 条 final。候选层绑定 `flow-prefix-v1`，P4 自动路径要求观察的 profile 与策略一致，因而这些离线统计不能直接解释为自动路径覆盖率；第 3 节的连接级告警口径仍包含全部 prefix/final。

当前代码在 `GuardEligibility.capability()` 中拒绝 profile 不一致，由 `GuardDetection` 对当前观察及每条汇总证据做 capability AND，`GuardDecisionEngine` 在 distinct parent 计数前拒绝整组；`GuardActions` 在领取时再次逐条核验。计数函数自身没有 profile 过滤，但未发现当前生产调用路径允许不匹配快照凑数放行。final 可以替换同 parent 的旧 prefix，或使混合证据组被拒；属于必须测量的覆盖差异，不能写成“只删 final 即等价于 P4”。代码行号和源码 SHA 见 `.cache/r3-profile-review-20261008/CODE-REVIEW.md` 及报告中的 `reviewedCodeSha256`。

只用 prefix 的报告位于 `.cache/r3-profile-review-20261008/prefix-only-report.json`（SHA-256 `683bc86a5aaf90d4f08fd5495fd79a712fbee694d42947e2272d0ff339e554b3`），只读取哈希绑定的 validation 与既有分数，先复算原混合口径，再固定现有阈值及连接下限统计四类来源机会和来源覆盖。dos_slow 在下限 5、既有 HTTP 范围内覆盖 `15/18` 个攻击机会，正常机会 FPR 为 `0/2553`（internal `0/5`、website `0/2548`）。这是来源身份 × 类别 × 30 秒机会的统计，不是 G1 连接级 FPR，也不是完整 P4 自动路径回放；删去 final 后保留的旧 prefix 没有模拟线上最新快照失效、到达顺序及目标、授权、健康和预算门槛。分母与混合口径不同，比例变化不能表述为能力改善。

差异已追加到 `.cache/t35-t36-20261008/registration.json` 的 `parameterDecisions.profile`；候选层、冻结参数及 `evaluation-plan.json` 原件不变。J1/G3 后续须实测纯 prefix、prefix/final 混组、同 parent 从 prefix 更新为 final，以及领取时快照更新，分别登记告警与候选拒绝原因及覆盖。本报告只作口径说明，不授予自动资格、不新增或调整阈值。registration 修订前原件和独立校验记录见 `.cache/r3-profile-review-20261008/`；T3.5/T3.6 原 `verification.json`、`acceptance.json` 保留为历史证据，不能当作修订后 registration 的校验。

## 4. 硬门槛

| 门槛 | 数据/环境 | 指标 | 标准 | 阶段 |
|---|---|---|---|---|
| **G1** | L1 test | 攻击检出率（4 类等权平均） / 误报率 | **≥ 90% / ≤ 2%** | P6 |
| **G2** | L1 test | 5 类 macro-F1 | **≥ 0.80** | P6 |
| **G3** | lab 联合闭环 | 见下 | 全部满足 | P7 |

G3 要求，在网络隔离的 lab 中以 1 倍速完成：

1. 4 个攻击类各至少 1 段冻结 PCAP 场景经“传感器 → 推理 → 决策 → 执行器”产生告警；具备自动资格的类别产生真实封禁，且只作用于映射的 canary 来源。
2. 每条真实规则在 TTL 到期或撤销后被清理，并由执行器核验不存在。
3. 同时回放的正常场景累计 ≥ 30 分钟，误封禁 ≤ 1 次/小时，且每次误封禁都能按 TTL 自动恢复。
4. 记录每段攻击的“原始起点 → 首次告警 → 规则生效”时延（数值只报告，不设门槛）。
5. 在实际部署平台（Mac 实时抓包）上，记录洪泛与慢速 DoS 场景中质量合格快照的比例。若服务器响应被网卡合并为大包导致快照大量为 `offloadSuspected`、类别无法判定，该类别不能在该平台取得自动资格，并在报告中说明；是否调整契约中的 offload 规则另行评估，不在 G3 中临时放宽。

G1/G2 未通过时回 P3 按第 7 节处理；G3 未通过时按失败环节回 P4 或 P5。

阶段 0 的 K5 方案 B 目标路径：P5 platform/canary 针对同一完整 subject 的真实联合证据先使 lab 组合封存、独立批准并绑定 lab 资产；G3 随后运行，报告追加到 approved/active 组合并逐类别、逐来源登记等级。synthetic 会话只验证工程链路，报告永不成为正式通过。

方案 B 中“E3 要求 r4 已 active、r4 激活先要 E3 platform 报告”的前置闭环，按 K9 引导克隆解除：同 subject 在业务库克隆中以引导报告激活，在其中运行真实 E3 与 canary，由 K6 产出正式报告后回业务库封存、批准、激活。K9 验收：① 无授权部分在隔离 schema 用替身执行器走通克隆 → 引导激活 → E3 rehearse → K6 报告（标 synthetic）→ 另一克隆中 r4 封存/批准/激活全链路；② 引导身份不在正式 report-trust 中，业务库导入引导或 synthetic 报告必须拒绝；③ 克隆 r4 的 bundleId/subject 与业务库逐位一致，执行器运行前核验 subject 绑定；④ E3 观察来自冻结片段经传感器回放，不手造特征；⑤ 业务库在克隆运行前后摘要一致。2026-10-12 状态：② ③ ⑤ 已由演练和测试满足；④ 已对 `peer_service` 验证；`peer_inbound` 因 port_scan 能力 profile 不匹配（K9-B1，见[后续实施计划](后续实施计划.md#k9-e3-引导克隆解除-r4e3-前置闭环2026-10-12-登记未实施)）无法形成动作，① 未完成，等待用户决定处理方案。真实 E3 仍需 A6 逐轮授权；业务库激活另行授权。K9 交付前隔离 synthetic 状态测试不能证明真实路径已解环，尚不开放 A6。

申请 A6 前的 K7-R 采用 18 段冻结 PCAP、1 倍速、v1.1 场景固定偏移和正常段全程并发。使用真实后端/传感器及内存防火墙，执行门关闭时按 J1 同一假想候选投影计数；扫描模型和 scan-ports 各段 ≤10 秒，brute_force 与 dos_slow 各段 ≤20 秒，dos_slow 至少 5 个独立 parent，正常 0 候选，关联完整、替身全程空规则、业务库快照一致。该门禁只决定是否申请 A6；任何 S/B 工程修复保留旧目录，T 模型问题须用户决策，brute_force 失败直接停止并报告。不得调阈值、换片段或把该演练写成 G3。

## 5. 类别自动资格

自动封禁按类别授予，**不是项目门槛**：

| 等级 | 条件（L1 test，连接判定） |
|---|---|
| 可自动封禁 | 该类召回率 ≥ 80% 且精确率 ≥ 90%，并在 G3 中完成真实封禁与恢复 |
| 只告警 | 未满足上一行任一条件 |

**按来源判定（`host-guard-evaluation/2026-10-08.1`）**：模型来源用该类“仅模型”成绩，每条规则用“仅规则”成绩，分别对照上表的召回率与精确率。某类只要有一个来源达标，该类可设为可自动，但策略只把达标来源标为可自动（模型来源 `modelAutoEligible`，规则来源 `rulePolicies[].autoEligible`），未达标来源的命中只产生告警。G3 中各来源分别完成真实封禁与恢复后才登记 `lab_auto`；规则来源单次命中即可形成候选，须在 G3 中单独核对误封。报告分来源列出成绩与资格。本条不追溯 `host-guard-evaluation/2026-10-07.1`，candidate-v2 的离线资格仍按原口径解释。

某类只告警不影响 G1—G3 的通过；报告写明降级原因。L2 成绩不影响自动资格，但下降超过 20 个百分点的类别必须在报告中单独说明局限。

## 6. 报告指标（不设门槛）

| 指标 | 参考目标 | 数据 |
|---|---|---|
| 各类召回率、精确率、混淆矩阵 | 主要类别召回 ≥ 80% | L1 validation/test |
| 跨数据集检出率 / 误报率 | 约 70% / 5% | L2 |
| 受控慢速攻击检出、困难良性误报 | 如实报告 | L3 |
| 单对端敏感性 | 在冻结候选上，把 validation 快照的主机侧上下文改为“1 个对端”（`hostDistinctPeers=1`，`hostFlowStarts` 取同源值）后，各类的连接检出率与正常误报；任一攻击类检出降幅超过 20 个百分点时，该候选不得冻结，回 P3 调整。只改字段的反事实只衡量敏感性，不替代 G3 实测 | L1 validation，P3-C 冻结前 |
| 规则对比 | 列出“仅规则 / 仅模型 / 二者并用”的检出率与误报率，以及模型补充检出、纠正规则误报的连接数 | L1 test、L2 |
| 可判定覆盖率 | 各类、各原始场景中至少有一个质量合格快照的连接比例；G1 成绩只代表可判定连接 | P3-A 冻结清单、P6 |
| 检测与封禁时延 | 扫描、洪泛 ≤ 10 秒；暴力破解、慢速 DoS ≤ 20 秒（攻击起点到告警） | V3、G3 |
| 证据到规则生效 | P95 ≤ 2 秒 | G3 |
| 运行开销 | 推理吞吐、端到端处理延迟、丢包/队列积压 | V3、G3 |
| ONNX 一致性 | 与训练框架最大分差 ≤ 1e-4，类别翻转数 | P3/P6 |

ONNX 一致性超限属于导出缺陷，必须修复后才能进入 P6，但它不是模型能力指标。

单对端敏感性自 2026-10-07 P6 评价后诊断起增设，只约束此后冻结的候选，现随 `host-guard-evaluation/2026-10-08.1` 与新评估计划登记生效（`host-guard-evaluation/2026-10-07.1` 仍只对应 candidate-v2）。它是冻结准入条件，不是 G1—G3 之外的新门槛，也不追溯改变已登记的 P6 成绩，背景见 [P6 诊断](p6/README.md)。G3 场景按 lab 的实际对端构成回放，不得为了通过而人为加入背景对端。

## 7. 失败处理与测试集使用

- test 只在 P6 读取。每次读取记入访问日志；**P6 最多评估 3 次**，第 2、3 次须先登记改动内容和原因，改动不得针对 test 的单条样本或单个时段调参。报告写明 test 被读取的次数。
- 3 次后仍未通过 G1/G2：可收窄支持类别（把不达标类别改为只告警或移出范围）后重新登记，或按 [开发路线](开发路线.md) 申请新的切分；不得删除 test 中的困难样本来制造通过。
- 数据或标签问题回 P3；后端接入问题回 P4；执行或恢复问题回 P5。

## 8. 动作与恢复场景

P5 先在 V4 中逐项验证，G3 前必须完成“必需”项；“补充”项未完成时在报告中列为未验证，并保持对应风险的保护（例如不在生产资产启用自动能力）。

| 场景 | 级别 |
|---|---|
| 目标正确且窄范围封禁；正常目标不触发 | 必需 |
| 未登记/跨资产目标、错误执行器或 boot 拒绝 | 必需 |
| 过期/撤销授权、过期命令、签名或参数篡改拒绝 | 必需 |
| 管理通道、网关、DNS 等保护对象不受影响 | 必需 |
| 同幂等键只产生一条规则且不延长 TTL | 必需 |
| TTL 到期与人工撤销后规则被清理并核验不存在 | 必需 |
| 写账本前后、安装后回执前进程崩溃，恢复后规则与账本一致 | 必需 |
| 不覆盖、不删除用户已有规则 | 必需 |
| 控制面断连或回执丢失时记 uncertain 并核对，不换 ID 重发 | 必需 |
| 并发命令、续封、撤销不突破目标与资产预算 | 必需 |
| 时钟回退、不可信时间不延长规则 | 补充 |
| 主机重启后先清理再接受新命令 | 补充 |
| 已建连接与新建连接的效果分别验证 | 补充 |
| 身份/策略轮换下预算连续 | 补充 |

每项保留期望/实际、平台/程序/配置、规则摘要和恢复证据。P1 探针通过不等于 P5 执行器已验证；Mac 与 Windows 分别记录，未验证的平台不开放自动能力。

## 9. 报告要求

报告输出到受控 run 目录，docs 只更新状态。每份报告绑定数据集、切分、标签规则、代码、模型、策略和评价版本的哈希，给出各类样本量、排除量及原因、门槛结果和未验证项。点估计不等于保证；样本局限与 L1 偏乐观的事实须写明。
