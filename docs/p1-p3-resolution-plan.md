## 1. 决策与缺口总表

**优先修正“标签—观察时机—完整策略”的不匹配，同时补齐真实可取得的数据；平台恢复沿独立支线完成。** 不重做已通过的 P2 提取器，不再训练 final 模型去追求早期动作，不靠延长旧证据寿命、降低覆盖目标或重命名失败场景推进。

## 2. G1：Windows 恢复与启动观察

### 已知根因和未知项

[WFP 报告](p1/wfp-dynamic-probe.md)证明动态过滤器在手动复查时已不存在，没有证明它们超时残留；旧 PersistentStore 超时则是另一个已证实的问题。任务退出 1 的具体原因没有 stderr/启动日志，不能武断归为权限或 Python 路径。

当前 `wfp_reboot_observer.py` 在进入 `main()` 前导入本地模块；启动入口若在导入、目录访问、解释器选择处失败，业务日志不会出现。普通观察进程即便设置较晚的 shutdown order，也不能可靠观察所有服务和 BFE 的结束过程。

### 改法

1. **先修启动入口，不先重启。** 固定现有获准解释器的绝对路径、模块目录、工作目录及 SYSTEM ACL；最外层启动器先创建日志，再进入 Python 导入。保存解释器版本、cwd、身份类别、异常栈和退出码，原始路径留私有证据。不得吞异常或只写 `ExitCode=1`。
2. 以同一 SYSTEM 身份按需执行与启动触发完全相同的入口，覆盖“网络尚未就绪/BFE 暂未就绪/目录不可用”的有限启动状态。BFE 未就绪可有界重试；`ready` 只能在成功枚举后发布，不能用捕获异常后的空数组代替清零。
3. **使用真正的服务停止生命周期。** 在现有获准解释器上实现最小 SCM 服务入口及 `PRESHUTDOWN/STOP` 处理（可使用 Windows API 绑定），复用 WFP owner/supervisor；新生产二进制再走 G11 签名。收到关机通知即停止新命令，撤销自身动态过滤器并核验，写入并刷新 `closed_before_shutdown`；不要等原 30 秒结束再关机。
4. 独立观察者与所有者分离。观察者记录真实枚举结果、boot、UTC 和本 boot 单调时间。所有者删除成功不等于观察成功；二者均成功才有旧 boot 的清零证据。
5. 新 boot 先枚举项目命名空间，无残留才发布执行器 ready；新的 executor/boot 拒绝旧命令，不重放旧租约。若发现归属本系统的残留，先记录，再精准清理，再复核；保留第一次异常，不能只报最终空状态。
6. 正常存活状态仍要求 `blockUntil + 1s` 内实际核验清零。正常重启通过关机前撤销满足原期限；断电/系统停机期间没有可运行观察者，必须分别记录“不可观测区间”和启动后首次真实检查，不把它补写成精确删除时刻。微软动态对象生命周期是设计依据，不能替代目标机实测。

**完成条件：** 同身份启动检查先通过；之后在必要的单次维护重启中记录“租约生效 → 关机通知 → 截止前独立清零 → 新 boot 自动首次枚举 → 旧命令拒绝 → 目标/控制连接恢复”。未改动的六项非重启场景复用原证据，修改影响到的场景才重跑。突然断电的保证范围独立声明，不用普通重启冒充断电试验。

**落点/成本：** `scripts/p1/wfp_reboot_observer.py`、`wfp_probe.py`、`run_wfp_reboot.py` 和启动入口；约 1—2 人日，计划重启最多一次，在同身份预检通过后才安排。P5 直接复用该恢复核心，避免另写第二套。

## 3. G2：Mac 的窄范围 PF 方案

本轮只读确认本机为 macOS 27.2 / Darwin 27.2.0；`pfctl(8)` 支持 anchor 和 PF enable token，但文档中的 `-k host` 是主机级状态删除，不能拿它实现“对端＋单服务”精确处置。当前 `/etc/pf.conf` 只有 Apple anchor 入口，没有项目 anchor。

**实现选择：** 最小 root helper 管 PF，普通执行器通过鉴权 IPC 提交结构化窄命令；不提供任意 shell。使用自有 `hostguard/*` 命名空间，按 peer、本机地址、TCP、入站、服务端口生成规则；拒绝管理连接及受保护目标。一次性接入自有 anchor 需备份并比较主规则和活动配置，确认插入位置实际可达，不借用 `com.apple/*` 冒充系统规则，也不能只加载一个未被引用的 anchor。

新增 block 可能不影响已有 state。因此必须在安装窄规则后枚举精确连接状态，并通过匹配当前 OS 的 PF 状态删除接口删除这些状态。Apple 公开 XNU 的 `pfioc_state_kill` 提供协议、源/目的地址条件结构；**必须核对目标版本的端口匹配字段、ABI 和计数语义**，不能把上游 main 的结构直接写进本机。当前 SDK 未找到公开 `pfvar.h`，实现应使用匹配系统版本的公开源/头定义并进行尺寸核对。若该版本无法安全提供所需精度，备选是具 Apple entitlement 的 Network Extension 过滤器；它涉及签名/部署成本，不能用宽泛 kill-state 充数。

规则租约由两个独立 launchd 进程监督，恢复器保留绝对截止时间与本 boot 单调截止时间，100ms 级检查；断连只停止新动作，既有规则仍到期删除。进程崩溃、睡眠唤醒、时钟变化和启动恢复统一走实际规则对账；PF 不提供本项目可依赖的原生规则 TTL。启动只清理自有 anchor；不全局 `pfctl -d`、不 flush 用户 rules/states，若本系统申请了 enable token，仅释放自己的 token。

**最小实机证据：** 同 peer 上目标端口的已有/新连接均被阻断，控制端口不受影响；期限/撤销后恢复；杀死执行进程仍由恢复器清零。睡眠与重启恢复可和维护窗口合并，Mac 阻塞不拖住 Windows 数据/模型工作。端到端测试前保持原有“暂缓 Mac 实测”安排；本节先把实现路径与成本备好，不把暂缓当永久解决方案。

**成本：** PF 路径预计 2—4 人日；Network Extension 是更高成本备选。验收精度或恢复不够就修适配器，不能把双平台目标静默缩成 Windows。

## 4. G3：补齐 P2 的真实输入路径

`hostguard/live.go` 受 `//go:build cgo` 限制，现有 `CGO_ENABLED=0` Windows 离线验收不覆盖它。`input.go` 只接受 Ethernet、RAW 12/101；P2 回环数据实际是 DLT_NULL，并经过外部去头转换。现状是可复用引擎加未验收 live 适配，不是已经部署的 v5 Windows 传感器。

**实施：**

- 增加一个有时限、接口白名单和显式资产配置的 live CLI，直接调用 `OpenPCAPLive → RunLive`，输出研究/验证观察。不要接入旧 v4 ingest 冒充 v5，不依赖后端新库表。
- 在同一个 `normalizeLink` 中显式支持实际 Npcap DLT_NULL 的 AF 头格式；若需要 DLT_LOOP，作为不同链路类型处理字节序。未知 AF 拒绝，保留原时间、IP 字节和线路长度。旧转换脚本只保留作为历史材料。
- Windows 用既有 Npcap 加匹配 SDK 构建 cgo 入口；Mac 用 libpcap。每端验证实际链接/加载的库与冻结 exe，而非仅交叉编译成功。SAC 身份按 G11 处理。
- 将 G6 的一轮正常任务同时作为 live 数据验收：保留同一捕获源送入引擎的头部事件序列、序号、drop/gap 和 Tick 轨迹，再用同一序列离线复算。只比较相同截止点和水位的观察；不要求另开抓包句柄后“碰巧抓到同一批包”逐字节一致，不用 EOF final 冒充实时 idle final。
- 比较方向、服务、parent、prefix、缺失/质量与字段误差，并核验实际 drop 统计。Windows 回环证据不外推物理网卡；目标物理/覆盖网接口各做一次短任务确认。

**版本与成本：** 仅适配输入、不改特征公式时发布新软件 build/冻结清单，模型 profile 不必改名；不得覆盖旧 45 文件冻结清单。若语义改变则新 rc。预计 1—2 人日，直接复用正常补数任务，不另造大型测试工程。

## 5. G4：让早期标签从具体证据产生

### 2018 Slowloris

实查 CNS2022 文档描述数字型 `X-a`，本仓库抽查出现 128 个 `X-a: b` 片段。两者在“未完成 GET 之后持续补充头字段”的结构上并不互斥；差异需要记录，不能要求所有真实变种必须字面匹配文档举例。

新规则必须同时绑定：原件哈希、修正标签、发布活动/端点范围、SYN epoch 和伪影排除。在这个来源限定范围内，按**已连续重组的 HTTP 字节流**确认请求仍未结束、之后到达了新的头部续传；`X-a` 的具体值只记录为变种，不作为唯一正例开关。完整、正常终结的 HTTP 请求和 Attempted 单列验证，不能仅见 `X-a` 就判攻击。是否有足够行为证据依赖来源与逐连接状态，不把该规则扩成通用现场签名。

### 2017 Slowhttptest

`approvedPattern=None` 加上只识别 GET/X-a 的审查器，无法发现其他模式。先用既有固定样本重组前向/反向 HTTP，判别：

| 实际可见模式 | 需要的因果证据 | 模型侧影响 |
|---|---|---|
| 慢头 | 完整请求行后请求头尚未终结，后续确有新头字节到达 | 可以先试 rc.2 prefix；不能复制别的活动窗口 |
| 慢 body | 已有合法声明长度/分块语义，body 尚未完成且缓慢推进 | 起点规则独立；只用已到达字节，不用最终长度推断早期状态 |
| 慢读取 | 完整请求已发出，响应流持续被接收窗口/ACK 行为约束 | rc.2 缺 TCP window 等直接信号，必要时走 G7 的新特征分支 |

模式不是从工具名称猜测。本轮核实 CNS2022 明确指出 **CIC2018 Slowhttptest 未成功实现且误指向 FTP/21**，因此不能把它当作 2017 Slowhttptest 的独立 HTTP 正例去补数。

### 共用审查改动

1. 当前 `novel` 单段的 regex 改成连接级有界状态机，容纳跨包字段、一个包多字段、TCP 重传及有界乱序。序号缺口、冲突重叠、头部超限显式记录；不把 ACK-only、重复报文当进展。
2. 区分 `connectionProvenance` 与 `prefixQuality(asOf)`：整连接用来核对来源和标签，但未来 FIN、未来截断/乱序不能反向改变已得到的早期可观察事实。全连接质量可另作保守队列，不能混入模型输入。
3. 分开 `attackStart`、`evidenceAvailableAt`、`asOf`。来源确认的真实起点不能为了满足 10 秒目标移动到第一条高分或第二次续传；不确定起点给区间和保守时延界。起点前与证据不充分处保持 Unknown，不能补成正常。
4. 生成新的 `labelRuleVersion`、来源差异记录、样本逐条依据与全量标签；不改旧 28 条审查及 475 条结果。基于发布者标签的可复算派生说明保持来源可追溯，不冒充已经完成人工第二人复核。

**完成条件：** 两个场景各自有可重算的模式/起点规则，旧失败样本保留；明确规则的适用范围与保留率，全量合格 prefix 能进入新数据版本。不能只将 `numeric_x_a` 改成“数字或 b”后宣布通过。

**落点/成本：** `scripts/p3/review_prefix_onsets.py`、`scripts/p2/data_readiness/adjudicate_prefix.py` 和构建入口；首轮 1—2 人日，复用已下载原件，0 次模型重训。

## 6. G5：具体的独立活动补齐路径

旧计划查过的 CIC DoS2017 官网当前仍写不可用；ISCX2012 的一个 HTTP DoS 日既不保证匹配慢请求，也不保证多次独立活动。继续在这两个入口等待没有收益。本任务启动**新一轮、最多两个原始数据包**的定向补数，不继承“旧两来源失败后永远停止”的结论；仍用 2GiB 原始下载预算，已找到的两个包合计约 0.72GiB。

### 路线 A：TAARA Slowloris 研究包

[Zenodo 15612669](https://zenodo.org/records/15612669)，CC BY 4.0。本轮完整取得 `Acquire.zip`，44,087,589 字节，MD5 与发布记录一致；ZIP 内 15 份 PCAP，配套 Apache/Suricata 日志。论文声明五类场景、每类三轮。本轮完整读取容器结构，确认 15 个原件哈希互异、Ethernet，14 份完整，1 份末条报文缺 28 字节；捕获日期为 2025-05-20/21。

**直接处理已发现的问题，而非弃源：**

- `Ringan 3` 的损坏限于最后一条：原件保留；新派生件只截到最后完整记录边界 1,941,450，删除原件末尾 54 字节。排除尾边界上下文和不完整 parent，单列损失；完整 14 份先进入资格审查，不等待这一份修复。
- 论文表 VI 写 6 月，而 PCAP 写 5 月；本轮进一步核对全部 15 组 Apache 日志，将其明确时区转换为 UTC 后，日期一致为 5 月 20/21 日，且至少一份 PCAP 与论文公布 SHA-256 一致。因此关联采用原件/日志的 5 月时间，单独登记论文月份差异，不移动源时间戳。逐连接标签仍须按请求状态核验，不能从月份一致直接推出标签全部正确。
- Suricata 告警基于连接数与 `X-a` 签名，不能当独立真值，更不能把 HTTP 408 一律标攻击。使用论文实验登记＋PCAP 请求状态＋日志关联；来源控制面描述和数据包共同支持正例，正常业务需单独对应完整请求与任务证据。

**活动独立性处理：** 以真正采集轮次、时间与连接谱系为单位，核对重启/重新发起信息、跨捕获 parent、去地址后的报文序列/相对时序重复和共享背景。相同捕获副本只算一次；相邻窗口不足 150 秒时隔离边界/整组归属，不能仅换 UUID。五种参数不是五个独立网络域；分别报告 session、scenario、day、source 的数量，区间按有共享依赖的较粗组聚类。

## 7. G6：困难良性必须长得像问题本身

六批旧任务的 1008 条连接最长约 2389.867ms，无法约束 30—60 秒慢请求。旧回环活动不作废，但不能再仅凭 `slow_download` 名称验收。

采用固定内存 HTTP 服务、最多四路并发、单次有界任务；同一正常服务覆盖：

| 任务 | 必须实测的内容 | 所约束的误伤 |
|---|---|---|
| 30/60/120 秒下载 | 真实连接时长、响应内容哈希、分段接收完成 | 长连接、低吞吐不等于攻击 |
| 合法慢上传/分段头 | 有界内容，明确完整结束且服务器确认成功 | 未完成请求的早期阶段可能正常 |
| 长轮询/等待响应 | 服务端按任务设计延迟并正常返回 | 静默与低频交互不能单独触发 |
| 四路并发＋重试/Range 恢复 | 独立 parent，失败原因、重试和完整性可关联 | 多连接、新建连接不能单独触发 |
| 同 peer 的正常/可疑并存离线对照 | 在原数据/任务中保留同 peer 同服务的正常连接 | 服务级封禁的附带误伤必须计入 |

这里的合法分段请求只按低并发、资源上限和确定结束任务执行，不生成耗尽服务的攻击。现场不注入公开攻击 PCAP。

分批分配职责：新增训练/选型/校准各至少一批，再为独立评价准备至少五批，分成两个不超过 30 分钟的任务窗口；每批之间至少 155 秒、新引擎，跨批 parent 整体处理。每批均包含长期连接及成功业务记录，不能按一次任务内的五个接口调用算五次独立活动。P6 良性另留新的时段与任务组合，不由八批复制出 3000 个机会。

**完成条件：** 从包而非 sleep 参数验证实际时长、业务完成、drop、时间/服务绑定和角色隔离；监听/专用进程释放。Windows 先做回环和登记目标接口；Mac 正常采集与 PF 动作资格分别验证。同源正负对照不足时，先利用 Rios/TAARA 中可确证的正常连接补齐，而非只增加 Windows 正常、CIC 攻击的来源混淆。

**成本：** 扩展 `p1httpcanary` 或独立受控任务器约 0.5—1 人日，实际任务最多两小时（含失败留档与整理），与 G3 共用捕获。

## 8. G7/G8：模型与完整策略一起解决时效和覆盖

### 8.1 先解除 final 的信息瓶颈

[原诊断](p3/continuation-plan.md)显示选型攻击 1236 条 final 中，999 条在 idle 关闭时末包已过去 30 秒，天然超过 15 秒新鲜度。理想分数也不能通过晚到的 final 修复全部覆盖。因此停止在这批 final 上反复换算法/调阈值；新候选必须用 G4 的因果 prefix 与 G6 困难良性。

先复用 rc.2 基础特征与已有 1s/5s prefix。统计每个攻击模式从真实起点到第一份合格快照的延迟，连同必要上下文预热和新证据数量得到**可观察时效下界**。如果 10 秒内没有能区分正常的证据，换分类器无助于证明该时效。

### 8.2 两类策略候选，硬保护共用

- **连接建立型：** 新建连接聚集可作为辅助条件，但不能替代模型证据。
- **连接维持型：** 以同目标当前仍新鲜的多个独立 parent 为证据，`minPeerFlowStarts=0` 是现有契约允许的候选；仍保留高分、新鲜度、上下文质量、授权、目标及动作预算。旧数据上取消新建条件仅到 13/28，不足以批准，因此必须与新 prefix 和长期良性共同评价。

`minDistinctFlows` 保留有限候选 `{2,3}`，首轮不增加单连接自动模式。证据跨多个 prefix 只替换同一 parent 的最新观察，不能累加独立连接。`minEvidenceSpanMs` 当前定义是不同合格观察 asOf 的跨度，**不是同一连接持续可疑时长**；首轮维持 0，不把所有 prefix 同时刷新的跨度误用成“长期证据消失”。若确需“持续可疑时长”，新增明确状态/策略版本，低分、缺口、超时或 close 即重置，不能保留失效历史高分。

首轮有限网格：校准分数阈值 `{0.95,0.975,0.99,0.999}` × parent `{2,3}` × 新建连接条件 `{0,3}`，TTL 固定 30 秒、跨度固定 0，共 16 组/模型组合；阈值是搜索点，不是已批准自动值。新鲜度 10 秒、末包 15 秒、保护范围和动作预算固定，不能作为提高覆盖的调参旋钮。

### 8.3 确有信息不足时，只补必要的因果特征

优先用 P2 已解析但未输出的头部事实形成小型新 profile：方向化的 payload 字节/包数、有效载荷进展、重传比例、初始 SYN 至当前的 parent 年龄、TCP 接收窗口/零窗计数、同 peer **同服务**仍有新鲜证据的连接数。每个字段须明确单位、方向、重传/窗口缩放和缺失规则；不能把“超过多久没看见包”当作确证连接仍占用服务器资源。

当前 `context.go` 的 peer 统计跨服务聚合，不能直接当同服务并发；新字段必须按资产/捕获域/peer/服务/方向分组，不混主机全局数。所有改变经新 rc、Go/Java 参考和新 ONNX 输入绑定，在 Windows/Mac 复算同一批数据；旧 rc.2 和旧权重保留。

如果差异只能由 HTTP 请求状态观察，候选是**注册明文 HTTP 服务的有界状态提取**，仅输出请求完成/进展等统计，载荷不落日志、不入模型；HTTPS 不推断明文状态。它需要独立 profile、采集权限/隐私和内存成本评审，不能悄悄让已有 header-only 采集器变成全载荷采集器。先在已经取得的离线数据证明净收益，再实现现场部分；若首轮 rc.2 已够用，则不做这一分支。

### 8.4 有界训练、校准和收益选择

维持后续总额 **≤10 次完整拟合、≤4 小时训练/选择墙钟、≤4 GPU 小时**，树模型优先 CPU，不因存在 GPU 就增加神经模型。用现有预算：4 个 LightGBM/XGBoost × 基础/对端上下文，2 次根因消融，2 次优胜者附加种子，2 次失败/分组复核预留；每折算一次。

选型角色比较完整策略覆盖/误伤，选定模型后在互斥校准角色拟合一个低复杂度校准器并选策略，冻结后回归所有开发场景；若需重新选择，明确登记为下一次开发选择，不能继续称先前结果无偏。优先一套全局校准，避免每个数据源各调一组阈值记住来源。校准需有多个活动的正负对照，活动/parent 有限权重；0.999 仅为校准分数，不是 99.9% 阻断正确率。

独立开发评价同时回放仅规则、仅模型、模型＋策略，共用时间轴、目标、预算、TTL、附带误伤口径。先报告每个声明场景，最后才汇总；模型收益区间跨零就不能宣称已确证收益。两轮修正没有净收益时，不继续搜索算法，而执行已定位的信息补充/标签修正；不删除失败场景追求绿色报告。

**成本：** prefix 数据构建约 1—2 人日；第一轮模型/策略实施及归档约 1—2 人日，机器实验受上述硬预算约束；新特征分支另约 1—2 人日，仅根因证据支持时投入。

## 9. G9：防止“覆盖提高”破坏动作安全

### 真实发现的续封漏洞

本地 continuation 训练源码副本中，`evaluation.py: Replay.run` 使用 `t > last_expiry + 1` 清零 `chain_start`，时间单位为毫秒。于是 30 秒阻断到期后晚 2ms 再下发，就会被视为全新一轮，可反复规避 120 秒限制。本轮核对该副本与公开清单全部 9 个文件哈希一致，并直接调用原 `Replay` 做一次最小复现：相同目标、三 parent、六轮间隔 2ms 的 30 秒租约全部获准，累计阻断 **180 秒**；没有训练、真实动作或新增测试文件。它不是当前 4/28 的已证明主因，但若优化长连接覆盖后忽略它，会产生新的安全缺口。

**修正设计：** 将 `episodeBudget` 与证据缓存分开，以稳定的真实处置目标记账；研究回放使用同语义的目标映射。boot、sensor、keyEpoch 改变使证据失效，但不能让同资产预算清零。租约到期、模型短时低分和毫秒级间隙均不自动重置预算。累计实际 block 区间（不重计重叠）达到 120 秒后转人工；只有预登记的恢复/冷却条件满足才新建预算轮次，首版候选为完整 120 秒无自动阻断且捕获健康、无有效攻击证据，人工解除另记审计。这个新增参数须进入新策略版本，先复算其覆盖代价，不原地修改旧策略/成绩。

如果一次攻击持续 20 分钟、同一目标只能自动封 120 秒，持续覆盖本就有限。需要明确同时报告“及时首次响应”“自动覆盖时段”“达到上限后等待人工时段”；后者仍计入原正式覆盖分母，不能偷偷排除来保持 80%。任何提高自动上限、加入其他处置动作的建议都是独立范围变更，不能用评估代码绕过。

### 机会与时效计算

- 攻击 episode 来自标签活动/起点时间线，不由“恰好有 final 输出/高分”决定分母；Unknown 与不可评估量单列，不无声删除。
- 30 秒桶保留原定义，每桶记录首次合格证据、候选动作、真实或模拟有效区间。已有 TTL 覆盖按区间算；正式动作效果和 1 倍速联调仍由 P5/P7 证明。
- 正常误伤用正常连接在整个租约区间的交集，而不仅看其 final 时间是否落进 TTL；同 peer 同服务的正常流必须计附带误伤。
- 攻击开始→合格证据、证据→动作确认分别计时；看不见早期起点不能通过把计时起点移到高分来满足 10 秒。
- 针对 0/18 正常误伤给出样本不足含义。即便暂按独立伯努利假设，单侧 95% 误伤率上界约 `1 - 0.05^(1/18) = 15.3%`；活动相关时还不能使用这一独立性结论。旧敏感性报告代入 FPR=0 得到 1.0，不是低攻击占比下精确率的证明。

**成本：** 修正回放与统一统计约 0.5—1 人日；P4/P5 使用同一预算语义。仅增加“121 秒累计不能经间隙逃逸”“TTL 内正常连接附带误伤”“无观察攻击桶保留”三类必要行为回归，可合并入已有测试。

## 10. G10/G11：交付与平台身份不再留下尾账

**完整包：** 模型、预处理、校准、策略、支持范围、label/data/software manifests 和评估代码清单生成同一只读包；Mac/Windows 接收同一个 package SHA-256。先核对全部文件，再只对新权重/新输入 profile 执行 ONNX 对拍；旧权重不变时不为包装变化重复数次大规模推理。收尾入口不拟合、不搜索阈值、不改参数。Mac “旧 69 文件”不能替代新 Windows “86 文件”，差异以实际清单为准，不固定数量作为新门槛。

**新构建获准执行：** 原冻结程序可用于未改动的离线提取；新 exe 在一次预检中记录 SHA-256、签名和 CodeIntegrity 事件。受 SAC 阻止时，使用受信任 CA 的组织代码签名及时间戳建立正式发布路径，按微软支持方式提交信誉检查；证书/签名服务会有外部成本，目前没有已核实可用证书。不能假定管理员权限、自签名、换文件名、反复重试或关闭防护能解决。已获准解释器可承载原有 Python 数据/恢复工作，但不通过偷偷重写提取器来绕开 Go 的跨平台一致性。

**版本耦合控制：**

| 改动 | 新建内容 | 可以复用 |
|---|---|---|
| 来源标签/起点改进 | labelRule 与 dataset 版本、逐条依据 | 公式不变的 rc.2 提取器 |
| 新 PCAP/正常活动 | source/activity/split/data freeze | 原始软件/golden |
| 新输入适配或启动修复 | 软件 build 与新的软件冻结 | 字段语义不变的 profile |
| 新特征/状态含义 | 新 rc、Schema/profile、Go/参考计算、训练与 ONNX 输入 | 原件及独立标签旁路 |
| 校准、阈值、策略预算改变 | 新策略/校准/评估组合 | 允许复用同权重，但不能复用旧组合成绩 |
| 发布和真实资产授权 | P6/P7/P8 独立 release bundle | 候选 manifest 始终 candidateOnly |

预计完整包收尾 0.5 人日；正式签名接入约 0.5—1 人日另加供应商办理时间，当前无报价，不虚构零成本或即时完成。
