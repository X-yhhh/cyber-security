# 数据与模型方案

更新于 2026-10-05。P1/P2 已完成并收口；本文规定 P3—P8 的数据、训练和交付规则。当前输入、数量及补齐配额集中在 [P3 执行文档](p3/README.md)，不在此累积历史实验快照。结构与决策版本以 [检测与处置契约](检测与处置契约.md) 为准。

## 1. 当前任务与来源

当前任务为 `flow-prefix-v1`、IPv4/TCP、入站 HTTP/80 的 `connection_abuse`，二分类 benign=0、attack=1。声明行为为 `slowloris`（慢头部）和 `slowhttptest`（慢请求体）；两个行为分别验收，不扩展为通用扫描、DDoS 或应用漏洞检测。

| 来源 | 当前用途 | 关联与限制 |
|---|---|---|
| CIC-IDS2017 修正标签及对应 PCAP | 慢请求体开发组，计划 train | 连接、起点和来源工具模式必须有据；证据迟现不能通过改起点伪装早期检测 |
| CIC-IDS2018 对应 PCAP/标签 | 慢头部开发组，计划 validation_selection | 续段共享真实 parent；流表导出段结束不等于 TCP 连接结束 |
| TAARA 对应原件与来源说明 | 慢头部开发组，计划 independent_development | 来源日、端点/活动、近重复一并归组；每条连接不是独立活动 |
| 预制回放及另行批准的有界受控任务 | 定向补行为/角色与困难良性 | 真实业务轨迹、任务完成、起点和持续健康记录可对应；改身份/时长不增加独立性 |
| UNSW、旧 final 候选及其他历史来源 | 兼容或外部诊断 | 不作为当前 prefix 默认训练/验收输入，不继承历史成绩 |

来源登记包含版本、许可/引用、原件路径引用、大小、SHA-256、采集域和暴露用途。官方来源说明示例：[CIC2017](https://www.unb.ca/cic/datasets/ids-2017.html)、[CIC2018](https://www.unb.ca/cic/datasets/ids-2018.html)、[CNS2022 修正研究](https://intrusion-detection.distrinet-research.be/CNS2022/index.html)。发布者说明和修正表格不等于已取得可关联原始 PCAP，许可与实际文件身份须随 run 绑定。

本轮不默认扩展来源或使用新的模型家族。若来源/行为在声明时效或预算下结构不可达，在拟合前登记为 alert_only/诊断或提出明确的能力时效变更；不能用删除失败来源制造通过。来源一旦只作诊断，不再充当对应支持角色的验收证据，配额重新计算。

## 2. 标签与场景旁路

标签账本至少包含 sourceVersion/sourceHash、labelRuleVersion/hash、connectionId、parentConnectionId、activityId、sourceDomainId、contextSourceId、cohortId、原始场景、behaviorScenario、plannedRole、start/end、label/family、evidenceTier、reviewStatus、exclusionReason。原始端点仅在受控离线账本保存，Git 不收原始地址/载荷。

| evidenceTier | 可用条件 |
|---|---|
| publisher_documented | 发布来源及标签定义可信，连接/活动/时段可追溯并复算；不一概要求额外主机日志 |
| controlled_task | 已批准任务的行为、完成条件、端点/时间和原件对应；只标注属于该任务的连接 |
| analyst_reviewed | 证据明确且完成独立复核，记录审查依据 |
| ambiguous | Unknown，只作诊断；排除量及原因必须报告 |

“未匹配攻击”“某主机曾攻击”“模型高分”均不构成标签。Attempted 按实际可观察行为裁决，不机械改成攻击或正常。旧 Unknown 获得新证据时发布新标签版本并绑定依据，不改旧 run 真值。

行为映射采用 `host-guard-behavior-map/1`，映射表在 [P3 计划](p3/cde-plan.json)；保留来源域，不把来源合并成不可见属性。health、角色、源标识、标签辅助列、地址/ID、文件名和绝对时间不得进入模型。

## 3. 因果样本与完整分母

1. 原件只读，登记实际提取器 build、配置和哈希。线上/离线采用同一因果 Go 引擎，前缀只读 asOf 之前已释放的包。
2. 关联完整 SYN epoch 与 parentConnection，分段/快照不制造独立连接。原始标签活动时间线与观察输出分别保存。
3. 每个 prefix 的监督标签必须有截至当时可用的行为证据；攻击起点前、证据不明或关联歧义保留 Unknown。完整流 Attack 标签不能反向灌给攻击尚未发生的早期前缀。
4. 结构性缺失按 mask 表示，质量故障单列，不造值。第三方 final 流表不能冒充因果 prefix。
5. 评估分母由合格原始活动/目标时间线生成，不由“有观察”“有高分”或“通过策略”反推。没有可用观察、迟现、冷启动和预算抑制保留为可解释失败。
6. 分来源/行为/角色报告原始连接、有效 prefix、独立组、排除量和时效；低保留率先定位关联或可观察性。

训练时每个 parent 的快照权重总和为 1，再按预登记活动/来源上限做有限平衡，避免超长连接或大来源支配损失。默认不使用 SMOTE；禁止跨角色拟合预处理或合成伪时间流。

## 4. 角色与泄漏控制

四个开发角色为 train、validation_selection、validation_calibration、independent_development。模型/预处理只拟合 train，选型只用 selection，校准及策略选择只用 calibration，完整 pipeline 锁定后查看 independent。P6 使用另一批未暴露 final_test。

- plannedRole 由预登记一路传到完成账本、索引、标签时间线和冻结分区；缺失/非法/冲突拒绝，没有默认角色。三个既有公共组也要显式登记，不能在新组加入后被贪心算法重新分配。
- 同一 parent、活动、重放/镜像副本、来源上下文及近重复整体分组；跨角色冲突先归并，再在拟合前重新登记，绝不拆组。
- 30 秒上下文与 120 秒流状态要求至少 150 秒加登记余量的隔离，本轮最低 155 秒；跨边界长连接整体归组或排除。特征引擎可以重新初始化，健康/预算域不能因此初始化。
- 保留完整 parent 量化序列近重复检查，增加共同早期窗口检查：10/30/45/60/75/90 秒。只截掉尾部会改变整序列哈希，不证明决策窗口独立。相同早期业务轨迹按相关组处理，不能靠地址/UUID/时长或微抖动规避。
- 四角色均须有合格正负与两种声明行为；独立开发至少 5 攻击组、5 良性组，并逐行为/来源披露。数字指审查后的独立防泄漏组，不是捕获次数、连接数或快照数。
- 受控域在各角色配同服务困难良性；不能把“公共来源=攻击、主机任务=正常”当可靠分类实验。保留来源可分性诊断和特征消融，高来源 AUC 表示混淆风险，不单凭它断言模型必然作弊。
- 如使用分组交叉拟合，评分类组不得参与该折预处理/模型/校准/策略选择，调参另用内层组，所有拟合计入预算。独立开发集合一旦用于修正，必须登记暴露并换新的独立组。

八个受控活动是替换旧受控部分后补四角色的条件性配额。是否能得到计划 2/2/2/5 攻击组，以真实分组和来源用途为准；不合格时停止准入，不能让 bounded diagnostic 例外授权拟合。

## 5. 连续健康和完整策略可达性

`host-guard-capture-health/1.0.0` 是独立、认证、哈希绑定的采集旁证，字段和恢复算法见 [契约第 9 节](检测与处置契约.md#92-连续健康与预算恢复)。它不进入模型、不替代标签，也不因低分或无观察自动成立。

稳定真实目标的预算跨 boot/capture/keyEpoch/角色/策略保存。P3 先按原始连续目标时间线回放所有开发角色，再按角色/来源汇总；实际分区仍无特征/标签泄漏，只有不用于拟合的安全预算事实连续继承。每个试验臂使用同一初始预算条件和健康时间线、自己的因果检测/动作状态，不把另一臂的检测结论传入本臂。

训练前使用确定性诊断分数检查证据新鲜度、parent、上下文、TTL、累计预算和冷却链是否可达登记门槛；诊断分数不能计为模型结果。受控采集应在隔离期持续健康观察，并等待上下文与到期后冷却两者均满足。公开 PCAP 丢包未知仍可研究，但不能凭文件完整性恢复自动预算。

时效从原始活动起点计算。先测各行为及来源 evidenceAvailableP50/P95，在拟合前冻结研究截止；较长时效的真实自动能力另行批准。修改评价配置后必须验证评价器实际消费该字段，不能继续硬编码每个 30 秒桶起点+10秒。

## 6. 单轮实验与公平对照

| 环节 | 本轮内容 |
|---|---|
| 特征/模型 | LightGBM、XGBoost × base、peer_context，共 4 次；同一 43+3 张量顺序 |
| 修正/消融 | 最多 2 次，基于选型/校准根因，不读取 P6 |
| 稳定性 | 主种子 42 固定，优胜者额外 43/44 两次；不挑最好种子替换主结果 |
| 重跑/折内预留 | 最多 2 次，失败也计数 |
| E5 | rules、model、model_and_policy，同误伤/目标/新鲜度/时效/保护/动作预算，分别选择各自参数 |
| 独立回归 | 固定模型、校准和完整策略后，逐角色、行为与来源评价；独立开发单列 |

完整拟合总计≤10，单次≤300秒，小批冒烟≤3，整轮墙钟及 GPU 占用各≤4小时。阈值/策略选择总计≤256：模型选型及 E5 三臂各 64；具体网格评分前冻结。一次有界实验含上述最多两次修正，不另外解释为可无限开启两轮。MLP、序列网络或新 profile 不列本轮默认投入。

E5 三臂共享硬约束，但不强加只为模型选择的检测参数；“仅模型”只去除待比较的检测组合条件，不去掉目标/质量/授权/预算约束。按独立防泄漏组配对 bootstrap 2000 次、seed=20261004，主收益固定为攻击组等权的自动处置期及时覆盖率差（模型+策略减仅规则）。95% 区间下界>0 才能称收益成立；时效为次指标，不能主指标失败后切换。组数不足或区间跨零为未证明。

策略参数、分数校准、来源范围和时效必须冻结后整体回归。原始分数工作点不替代校准后完整策略成绩，校准集达标不覆盖选型/独立开发失败。规则门槛不得仅因攻击覆盖变高便删去，要与困难良性同时评估。

## 7. 候选、最终评估与交付

本轮采用 Windows 训练仓库的 prefix_runner（check/run），入口兼容条件见 [P3](p3/README.md#6-windows-训练入口与预算)。运行计划、代码、依赖锁与数据/角色/标签/健康/版本哈希保存在实际 run；旧 final 计划及候选不作默认入口。

P3 候选包含 ONNX、manifest、profile、预处理/校准、数据/分区/时间线、决策策略、研究时效、支持来源/行为、E5/回归/运行时报告及逐文件 SHA-256。candidateOnly=true 永久保留在模型本体，P3 policy 为 alert_only；自动资格由单独的 release bundle 和能力证据授予。

ONNX 与框架最大分数差≤1e-4、阈值翻转 0；Windows 与 Mac 按实际推理路径核验。最终报告引用候选 subject，初始 manifest 中 finalEvaluationReportSha256 可为 null，后续由发布包绑定最终报告而非原位补填模型。

P6 未暴露活动须重新通过谱系隔离和访问审计，完整 pipeline 一次最终评价，不能继承 P3 开发成绩。失败数据转作开发后不再称最终盲测；新模型不能复用旧成绩。发布要求与统计边界见 [验证与验收](验证与验收.md)。

自用交付只要求实际模型/配置加载、推理一致性和使用范围核验，不要求发行证书、独立安装包或前端。在线权重冻结；反馈经复核进入 Windows 离线候选，禁止在线伪标签自训练或自动换权重。
