# 验证与验收

版本：host-guard v5。本文替代历史 L1/L2/L3、G3 持续入站影子门禁。没有常驻服务器不阻塞研发；前端不参与验收。下述联合指标仍为预登记目标；P1/P2软件与探针、P3离线候选已有[阶段证据](开发路线.md)，尚无通过的v5独立最终评估或联合自动阻断成绩。

此前[解决方案验证](p1-p3-resolution/README.md)取得八批授权正常任务、稳定目标累计预算42项Windows回归及旧完整包核验。最新[实机验收](p1-p3-completion/README.md)已完成双平台回环/物理接口Go live同轨迹复算，均零丢包；Windows SCM STOP和真实PRESHUTDOWN期限前清零通过；Mac IPv4/TCP回环精确PF动作、TTL、撤销、执行进程崩溃恢复通过。自动启动首次枚举修复后只做SYSTEM手动入口验证，完整G1不标通过；未取得新prefix独立模型成绩或自动资格。原裁决及失败记录保持不变。

验收范围是用户自用运行，不要求对外发行、独立安装包、代码签名证书或签名服务。Windows未签名程序已在SAC=On下实际运行，构建身份项以目标机启动、实际功能、依赖及文件完整性为准。既有可选正式模式的缺证书拒绝记录仅保留为历史验证，不计作当前阻塞。新语料冻结了50,129条prefix，独立核验无跨角色parent/活动/防泄漏组；独立开发角色组数门槛仍未达到，不能用冻结完成替代模型验收。

本机模型交付核对加载、特征/预处理一致性、实际推理结果及错误处理。实际启用自动阻断时，再按对应平台验证范围、到期、撤销和恢复。后文处置命令的签名验证用于内部鉴权，保留该验证不要求购买程序发行证书。

## 1. 验证层次

| ID | 输入和执行环境 | 证明内容 | 不能证明 |
|---|---|---|---|
| V1 数据/标签与因果特征 | 公共 PCAP、透明标签、小型 golden | 输入可复算、无未来信息、标签有依据 | 模型准确或真实阻断 |
| V2 独立模型/策略评估 | 未暴露 final_test、冻结模型/策略 | 特定场景分类、事件覆盖和动作候选精确率 | 任意网络泛化 |
| V3 时间序列回放 | 同提取器、原始事件时钟、已知起点 | 决策时机、目标和窗口行为 | 实时系统墙钟延迟或真实攻击效果 |
| V4 短时良性任务 | 授权主机下载/更新/文件传输/正常重试 | 目标平台采集可用与实际业务误伤 | 无标签背景流都正常 |
| V5 真实动作/故障测试 | 网络层隔离环境、无害 canary 连接 | OS 规则有效、范围正确、恢复可靠 | 攻击流量真实打入系统 |
| V6 联合闭环 | 回放真实模型结论 → 专用测试目标 → 实际适配器 | 模型/策略/执行完整接线 | 未经授权实网生产验证 |

PCAP 只由离线读取器消费，不向网卡注入攻击报文。V5/V6 不运行恶意软件、攻击工具、漏洞利用或凭据攻击。网络隔离须有接口/路由/防火墙证据，应用标签不能代替隔离。V6固定1倍速和一次性时间offset，按[回放隔离契约](检测与处置契约.md#11-回放隔离与版本升级)保持时间间隔与服务语义；真实TTL不得由回放时钟控制。

## 2. 预登记评估计划

P2/P3 在读取 final_test 前冻结 `evaluationPlanId/hash`，至少包含：支持 capability 矩阵、来源和分区哈希、攻击/良性活动定义、排除规则、受保护目标、模型/策略选择预算、事件桶、动作 dedup、TTL、流量配比、指标公式、置信区间算法和失败处理。

每次报告带 plan hash、bundle/model/policy/extractor hashes、平台/捕获域、样本谱系、每类样本量、排除/不适用量、每来源/方向/家族指标。不能仅报告合并平均值。

P3开发回归还须冻结模型、预处理、校准器及完整策略，对所有开发活动输出同一组合的结果。训练角色仅诊断，选型/校准与独立开发评估分列；先按原时序/资产预算回放再汇总各组。当前原始工作点19/28、冻结策略选型回归4/28和校准开发81/84是三种不同口径，均不能替代V2。[来源修复记录](p3/source-repair-20261005.md)已按[后续执行路径](p3/README.md)交付逐观察/机会门槛诊断和统一失败裁决，校准集达标不能覆盖其他声明场景失败。38项 Windows P3 训练/回归测试（`tests/test_host_guard_p3.py`）、4项本机起点因果测试及既有权重 ONNX 对拍通过，仅证明该轮实现正确；上述两组数字与 P2 的 Go 提取器 82 项测试（见[P2 出口](p2/stage-exit.json)）是不同对象、不同轮次，不能互相替代或相加。新来源标签资格已补证，独立数据准入仍 blocked，不授予 P6 或自动执行。

## 3. 统计单位与公式

- connection：完整 parentConnection，prefix/final 不算独立连接。
- attack episode：同一目标/家族的真实攻击活动按预登记 30 秒桶统计；同一活动多个桶有关联，置信区间按原 activity/capture 聚类。
- benign decision opportunity：对正常 peer/service 形成的同样时间桶。没有足够观察的桶记不可评估，不偷偷排除高分正常样本。
- action：合并重试和同一目标 TTL 内重复触发后的唯一实际或候选阻断；续封计入累计影响时间。

`blockPrecision = 正确攻击目标的阻断数 / 全部阻断数`；`blockRecall = 在时效内正确阻断的支持范围攻击 episode / 全部支持范围攻击 episode`；`falseBlockRate = 被错误阻断的正常机会 / 全部正常机会`。零阻断时 precision 未定义，不能写 100%。同时报每 1000 正常机会误伤数、每小时动作数、被影响的正常会话数和累计误伤秒数。

置信区间默认按独立 activity/capture 做分组 bootstrap；组数不足需明确无法可靠估计，不能用几百万相关快照假装置信区间很窄。独立伯努利假设确实成立时，可报 Wilson/Clopper-Pearson；零错误的近似上界 3/n 必须注明独立性假设。

后续独立开发评估以至少5个攻击活动组及5个良性活动组起步，逐声明场景列组数；这是最低计划数，不是区间可靠或99%精确率的证明。组间有关联时合并聚类，方法、重采样单位、次数与随机种子在评分前登记；组数不足明确区间不可可靠估计。按parent/快照随机拆分不能替代独立活动。

final-only研究的“有观察的目标/30秒桶”只作历史诊断；正式攻击episode按有依据的起点及支持范围登记，不以是否输出高分观察决定分母。证据不足、延迟超限和动作无效分别报告；TTL内重复触发被抑制不等于漏阻断，需核对既有动作是否在有效时段覆盖该episode。正式时效须包括起点至证据满足、证据满足至动作生效两个区段，不能仅计算ONNX耗时或从final输出才开始计时。

Precision 随攻击占比变化；报告原始连续场景结果，并在预登记的 10%、1%、0.1% 攻击机会配比上按固定抽样/权重报告敏感性。不能把 1:1 平衡集成绩写成现实精确率；重采样不改变时间窗特征，不将片段拼成虚构抓包。

## 4. 首版联合门槛

| 项目 | lab_auto 首版出口 |
|---|---|
| 模型数据 | 标签、因果、分区/重复审查通过；每个声明家族有未暴露独立活动证据 |
| 自动阻断精确率 | 在预登记支持范围和主评估配比下点估计 ≥99%；必须同时给置信区间和样本量 |
| 自动阻断覆盖率 | 每个声明家族及其预登记支持场景 blockRecall ≥80%，不得用家族均值掩盖失败场景或通过几乎不执行获得高 precision |
| 样本覆盖 | 至少 100 个支持范围攻击 episode、3000 个良性机会；来源活动组数单列；不足不得宣称统计完成 |
| 困难良性集 | 下载、更新、正常并发、重试、连接恢复、管理会话均覆盖，预登记集合零误阻断 |
| 动作误伤预算 | 每资产最多同时 10 条、每分钟 5 次、TTL≤60秒、同对象连续≤120秒 |
| 时效 | 以短窗口家族为首版目标：证据已满足 → 规则确认生效 P95≤2秒；攻击开始 → 首次有效动作 P95≤10秒，超时计漏阻断；逐声明家族按下方家族级时效登记 |
| 平台/恢复 | V5 必需场景全部通过；安装核验、流量效果、到期和撤销均有证据 |
| 模型贡献 | E5 中固定同一误伤预算，模型+策略相对仅规则有覆盖率或时效的正向收益，报告区间 |

上述 99% 是试验点目标，不声称已统计证明真实精确率≥99%。若要作该强声明，需单侧 95% 精确率下界≥99% 且来源代表性成立；约 100 次零误伤不能证明此声明。支持范围过窄、活动组不足或没有净收益，均不得以“99%”发布模型能力。

### 4.1 家族级时效登记（强制）

"攻击开始 → 首次有效动作 P95≤10秒"是**首版短窗口家族的默认目标，不是所有家族的通用要求**。可阻断证据的出现时刻由家族行为与数据本身决定，不由门槛决定：若某家族的可观测证据在物理上不可能早于起点 N 秒出现，则 10 秒目标对该家族**不可达**，把不可达目标写在证书上只会诱导实现去粉饰起点或删除失败场景。

因此每个声明家族在 `evaluation-plan` 中单独登记时效三项，登记值必须在读取 final_test 前冻结：

| 登记项 | 含义 |
|---|---|
| `evidenceAvailableP50s` / `evidenceAvailableP95s` | 该家族攻击起点到"足以支撑自动判定的证据首次出现"的实测分布，来自开发活动 |
| `actionLatencyP95s` | 证据已满足 → 规则确认生效，默认 ≤2 秒，全家族一致（与家族无关，属链路能力） |
| `startToActionP95s` | 起点 → 首次有效动作；**默认家族登记为 `evidenceAvailableP95s + actionLatencyP95s` 向上取整**，短窗口家族取 10 秒 |

- `startToActionP95s` 超过默认 10 秒的家族，**其能力等级上限为 `alert_only`**，除非该家族在 `guard_capability` 中单独登记了经批准的不同时效目标并说明理由。
- 已在开发数据中观察到证据迟现的家族（当前例：CIC2017 慢请求体，首次可用证据通常在 105 秒以后）**不得**沿用 10 秒目标；应登记为 `alert_only` 或登记其真实可达时效，并在报告中说明"该家族不承诺早期自动阻断"。
- 家族级时效目标与第 4 节其它行（精确率、覆盖率、样本量）**并列**：任一未达即该家族不获得 `lab_auto`，不得用其他家族的达标成绩替换。
- 时效超时计**漏阻断**并进入分母；不能因"证据来得晚"把该 episode 从支持范围分母静默删除（与第 3 节一致）。

P3只负责证明开发数据上的模型/完整策略可行性，不要求探索开始时已备齐最终100/3000样本；P3通过也不等于取得P6或自动执行资格。P6按未暴露活动一次性验证上述可由离线数据证明的指标和样本/区间；OS效果、真实P95时延、严格TTL和恢复由P5/P7联合验证。各层未验证项明确列出，不能让P6与P7互相等待同一份尚未产生的真实动作证据。

`authorized_auto` 在 lab_auto 之外，还需明确真实资产/接口/服务授权、目标平台 V4、版本完全一致的 V5、独立批准及运行停止条件。短时 V4 至少两个不同任务时段、覆盖注册业务，不要求持续接收入站或等若干天；样本量和局限随批准记录披露。不具备该范围证据则保持 lab_auto，而不是把实验能力描述为实网验证。

## 5. 因果与特征测试目录

| 场景 | 断言 |
|---|---|
| 1秒/5秒及后续 prefix | 不引用 asOf 后的包、最终时长、EOF 后信息 |
| 入站/出站/无 SYN | 前两者按握手证据定位，unknown 不自动执行 |
| UDP/ICMP | TCP 专属特征为 null + mask，不伪装为已观测零 |
| 冷启动和捕获 gap | 真实 coverage，不凑 100 流；gap 后重新计算连续覆盖 |
| 同一 PCAP 离线/现场夹具 | 相同释放次序、字段、快照，浮点误差按契约 |
| 乱序/同时间/重传 | 有界缓冲与序号确定性；超限缺陷留痕 |
| 片段/截断/卸载/过载 | 质量问题不隐藏；自动候选拒绝 |
| 跨分区连接/窗口 | parentConnection、activity 和上下文隔离带不泄漏 |

## 6. 动作与恢复必需场景

1. 正常目标不触发；受支持攻击模型证据触发同一目标的窄规则。
2. 未登记资产、跨资产引用、错误 executor、错误 boot/captureScope 均拒绝。
3. 过期/撤销授权、新旧 revision、失效目标、重放命令均拒绝。
4. 签名错误、未知/撤销 keyId、篡改 scope/TTL 均拒绝。
5. 管理通道、网关、DNS、受保护 peer/service 不受动作影响。
6. 同键同内容重试只保留一条规则且不延长；同键不同内容拒绝。
7. 规则安装前、安装后回执前、写账本时分别崩溃，恢复后实际规则与账本一致。
8. 控制面/消息队列/代理断连、回执丢失，标 uncertain 并核对，不盲重试。
9. TTL 到期、人工撤销、策略暂停分别删除自身规则；健康状态下到期后1秒内核验不存在，记录实际清理延迟。失败记录 recovery_failed 并停自动；不能把OS未提供的原生TTL当作已经具备。
10. wall clock 回退、时钟不可信、主机重启，不延长阻断时间。
11. 本系统规则与用户已有规则共存，不覆盖/删除其他规则。
12. 已建立连接和新连接分别验证效果；不支持已建连接时限制 capability 声明。
13. 并发命令/续封/撤销竞争不突破预算和连续封禁上限。
14. research、lab、authorized 之间不能复用目标引用、凭据或执行队列。
15. 多个 peer 同时产生告警，证据不会串目标；同流多快照不会增加独立证据数。

每项保存 expected、actual、平台版本、规则标识摘要、前后连接结果与恢复证据；只打印“命令成功”不算通过。实验需要的系统权限仅在已授权资产使用，不为通过测试绕过系统策略。

### 6.1 P5 最小可验收子集（时间风险控制）

第 6 节 15 项覆盖**完整执行器**。契约的完整状态机还包含 `uncertain → applied/rejected/revoked/expired/recovery_failed` 的收敛、`guard_reconciliation` 实态核对和撤销传播窗口管理；这些是正确设计，但会把 P5 工作量推高约 2—3 倍。鉴于代码冻结与答辩时间，**把 P5 拆成本轮必须完成的最小集与后续增量**，避免"全都要"导致已有实测证据无法进入验收叙事。

| 归属 | 内容 | 说明 |
|---|---|---|
| **P5-min（必须，进入本轮联合验收）** | 场景 1、2、4、5、6、9、11、12 | 目标正确性、拒绝条件、签名/篡改拒绝、保护对象、幂等不延长、到期清理与 1 秒内核验、与用户规则共存、新/旧连接效果声明 |
| **P5-min（必须）** | 状态只要求 `pending → dispatched → applied → revoked / expired` 的可证明路径 | 已有实测已达此范围：Windows SCM STOP/PRESHUTDOWN 截止前清零、Mac PF 精确删除与进程崩溃恢复 |
| **P5-ext（增量，允许排在冻结后）** | 场景 3、7、8、10、13、14、15 | 并发竞争、写账本各时点崩溃、断连回执丢失的 reconciliation 收敛全谱、跨环境凭据隔离 |
| **P5-ext（增量）** | `recovery_failed` 的重试与自动收敛策略、全量 `guard_reconciliation` 巡检 | 降级形式：`recovery_failed` 只需**告警并暂停该资产自动能力**，人工介入清理；不要求自动收敛 |

- P5-min 未全部通过时，**该资产不得进入 P7 联合验收**，不得以"已经有了脚本"替代证据。
- P5-ext 未完成时，对应能力在 `guard_capability` 中登记为**受限**：允许 `applied/expired` 的正常路径，**不得声明**"崩溃后自动恢复账本一致"或"撤销传播窗口已覆盖"。报告必须显式列出该项为未验证。
- 此拆分**不降低**任何安全硬约束：目标正确、授权有效、保护对象、TTL 期限、审计完整仍属 P5-min；拆的只是"故障收敛的全谱覆盖"和"自动重试"。
- 拆分不适用于 `authorized_auto`：真实资产自动运行前，P5-ext 同样必须通过。

## 7. 替代影子运行的报告

统一报告为 `evaluation_report`，不新建旧 G3 的改名影子流程。运行健康仅报告采集丢包/过载/拒绝、延迟、模型/策略哈希和规则清理状态。输入漂移提示可暂停能力或进入离线诊断，但不自动改阈值、训练或换权重。

报告末尾列出可声明能力、未支持范围、统计限制和真实平台未验证项。前端尚未适配不影响 CLI/API 交付；现有 shadow-report 端点列为 legacy，不再作为新发布包依据。
