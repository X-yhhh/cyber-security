# 主机流量检测与受控自动阻断平台

面向明确授权的主机（当前为 Mac；Windows 用于训练与受控攻击源，不做自动封禁）：传感器持续采集入站流量并提取特征，自行训练的多分类模型识别端口扫描、暴力破解、洪泛 DoS 和慢速 DoS，后端按来源汇总证据后，由独立执行器实施窄范围、限时、可撤销的本机防火墙封禁。规则引擎并行作为第二条检测来源。系统不依赖外部大模型 API，不训练大语言模型，不宣称全网覆盖或通用 DDoS 清洗能力。

## 本机开发启动

- IDEA 使用项目共享的 `CyberSecurityApplication` 运行配置：JDK 25、`local` profile、工作目录 `backend/`，HTTP 后端固定为 `127.0.0.1:18080`。数据库与登录限流密钥仍由受控环境变量提供，不写入运行配置。该配置关闭消息消费、自动处置与管理员引导。
- 旧 UNSW 模型运行时已删除（2026-10-21，BE-11 后端部分），启动不再恢复历史 active 模型，`cyber.model-artifact.root`/`MODEL_ARTIFACT_ROOT` 不再需要；v5 模型制品根由 `cyber.guard.artifact-root` 配置，推理时按发布组合加载。
- 在 `frontend/` 执行 `npm run dev`，日常开发入口固定为 **http://127.0.0.1:5173**，API 与健康探针转发至 IDEA 后端 18080。端口已占用时直接报错，不再自动递增到 5174。`.claude/launch.json` 的 `frontend-preview` 也使用这一入口。
- 执行 `npm ci` 等重新安装依赖的命令前，先停止 Vite，安装结束再启动；运行中替换 `node_modules` 会使旧进程的预构建依赖缓存失效，出现 `504 Outdated Optimize Dep` 和空白页。发生时重启对应 Vite 实例并刷新页面，不需要更换端口。
- 正式服务的 **https://127.0.0.1:18082** 同时托管已构建前端与后端，无需 Vite；使用现有私有 CA。5191 是历史隔离预演入口，5195 是业务后端的临时源码预览，均不是日常开发入口。后者仍保留现有配置；5173 不能与它们的后端目标混用。

## 实施与交付边界

- 远端长期分支只有 `main`（本机应用、接口及设计）与 `training/windows-cuda`（Windows 离线训练和导出，多分类训练入口在 `src/cyber_training/host_guard/`）；临时分支经 PR 以 merge commit 合并后删除。
- 技术基线为 JDK 25、Spring Boot 模块化单体、MyBatis、MySQL 8、RabbitMQ、Go 传感器；Redis 是可选优化。
- Flyway 是唯一结构来源，新库由 Flyway 从空库迁移到最新（代码最新为 V29，业务库为 V28）；旧初始化脚本已退役。本机管理员由 `LocalAdminBootstrap` 在显式 local profile 下引导，已有 admin 行与口令哈希保持不变。
- 自用交付由 Windows 导出 ONNX 及配置到 Mac 的本地推理入口。无需独立安装包、程序发行证书或持续入站影子运行；内部命令鉴权和完整性核验仍必须完成。
- P7 汇合 P4、Mac 平台 P5 和 P6，已于 2026-10-13 通过 G3；2026-10-14 P0 与部署准备收尾完成；P8 已进行后端分段部署，完整接入仍待授权；真实主机只告警（Q3）。前端不列入阶段门槛，演示最小集已纳入（A9）。
- 原始 PCAP、端点账本、模型、运行结果、密钥和备份保存在受控目录，不进 Git。docs 只保存当前规范、计划与精简执行记录，不堆叠阶段生成报告或临时任务单。
- 真实采集、训练、数据库变更、部署和动作执行依照各次明确授权实施；文档更新本身不启动这些操作。
