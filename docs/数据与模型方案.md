# 数据与模型方案

状态核对于 2026-10-12（当前候选为第二轮去主机上下文模型，见[模型训练与评估记录第 0 节](模型训练与评估记录.md#0-当前模型状态)）。本文规定 P3—P8 的数据、标签、切分、训练和模型交付规则；具体输入文件、数量和执行进度在 [模型训练与评估记录](模型训练与评估记录.md)，验收口径在 [验证与验收](验证与验收.md)。观测格式与模型输入沿用 P2 交接的 `host-guard/5.0.0-rc.2` 和 43+3 特征。

## 1. 任务定义

入站 IPv4/TCP 流量的 5 类分类，类别映射版本 `host-guard-class-map/1`：

| 类别 | 含义 | CIC-IDS2017 来源 | CSE-CIC-IDS2018 来源（L2） |
|---|---|---|---|
| `normal` | 正常业务 | 内部主机访问内部服务器的良性流量；内部用户访问外部网站的流量按服务器视角重算（见 3.1） | 同左 |
| `port_scan` | 端口扫描 | 周五 PortScan；周四 Infiltration 期间内部主机发起的端口扫描（CNS2022 标为 `Infiltration - Portscan`） | 无独立标签，不报告 |
| `brute_force` | 登录暴力破解 | FTP-Patator、SSH-Patator | FTP-BruteForce、SSH-Bruteforce |
| `dos_flood` | 洪泛型 DoS/DDoS | DoS Hulk、DoS GoldenEye、DDoS LOIC | DoS-Hulk、DoS-GoldenEye、DDoS LOIC-HTTP、DDoS-HOIC |
| `dos_slow` | 慢速 DoS | DoS slowloris、DoS Slowhttptest | DoS-Slowloris、DoS-SlowHTTPTest |

L2 日期与类别对应以实际文件和发布说明核对为准，不在核对前写入结论。

**不纳入的类型**及原因：

- Web 攻击（SQL 注入、XSS、Web 暴力破解）：攻击内容在请求正文，流统计特征无法可靠区分，属于 WAF 范畴。
- Bot：方向为本机向外回连，与本系统封禁入站来源的处置方式不同，也无法在不运行恶意软件的前提下演示拦截；列为未来工作。
- Infiltration（除上表纳入的端口扫描外）、Heartbleed：样本过少。
- 各类 `Attempted` 流（CNS2022 标注的未完成攻击，多数只完成握手而无攻击内容）：不作攻击也不作正常，单独计数。
- UDP 类攻击（如 DDoS LOIC-UDP）：超出当前 TCP 范围。

不纳入类型所在的时段和主机**整体排除**，既不作攻击样本，也不作正常样本。

## 3. 特征提取与标签

### 3.1 提取视角

- 以登记的服务主机作为“本机”（`localAddresses`），用 `guardextract` 从原始 PCAP 生成 prefix 与 final 快照；同一 PCAP 对不同本机视角分别提取，输出分开保存。
- CIC2017 的视角：受害服务器 192.168.10.50（全部攻击与 SSH/FTP/SMB 正常访问）、域控制器 192.168.10.3（LDAP/Kerberos/SMB 正常访问）、周四端口扫描的受害内部主机，以及有入站正常访问的其他内部主机。
- **网页正常流量补充**：数据集中正常的入站 80/443 访问每天只有个位数，而两个 DoS 类都针对 80 端口；不补充会使模型学到“入站网页流量即攻击”。补充方式是把内部用户访问外部网站的连接，以外部网站服务器为“本机”重算特征，得到入站网页访问的正常样本。每个外部服务器设样本上限，避免少数网站主导。局限：时间类特征在客户端一侧测得，与真实服务器一侧有偏差，报告中写明；这些样本标 `evidenceTier=analyst_reviewed` 并单列统计。
- 模型输入同时接受 `flow-prefix-v1` 与 `flow-final-v1` 快照：扫描等极短连接在 1 秒前已结束，只有 final 快照；较长连接在 1 秒、5 秒及之后每 5 秒有 prefix。两种快照使用同一 43+3 张量。
- 只保留 `direction=inbound`、`transport=tcp`、IPv4 的快照进入训练与评估；其他快照在线为 `not_applicable`。
- 质量不合格快照（`captureGap`、`offloadSuspected` 等）按契约不进入模型；一条连接只要还有一个合格快照就保留。`offloadSuspected` 的判定是 IP 包长大于 MTU，CIC2017 中服务器返回的 HTTP 响应常被网卡合并成大包，因此 Hulk 只有约 9% 的连接、DDoS 约 30% 的连接可判定。冻结清单记录各类与各场景的**可判定覆盖率**，报告必须列出，G1 成绩只代表可判定的连接。

### 3.2 标签规则 `host-guard-label/2`

CIC2017 的外部攻击在抓包点均显示为同一来源 172.16.0.1（经过 NAT），只按“来源 + 时段”无法逐条区分攻击与同来源的其他流量。因此按以下顺序判定：

| 顺序 | 情况 | 标签 |
|---|---|---|
| 1 | 连接按五元组和首包时间关联到 CNS2022 的攻击流，且该原始标签属于第 1 节纳入类型 | 对应攻击类，作用于该连接全部快照 |
| 2 | 关联到 CNS2022 的 `Attempted` 流，或属于不纳入类型（Web 攻击、Bot、Heartbleed、Infiltration 其余流量） | 排除 |
| 3 | 来源为 172.16.0.1 但未关联到攻击流 | 排除（来源不明） |
| 4 | 两端均为数据集内部主机，非上述情况，且不在不纳入类型的时段内 | `normal` |
| 5 | 内部用户访问外部网站、按 3.1 以服务器视角重算的连接 | `normal`（网页补充，单列） |
| 6 | 其他外部来源的入站流量（如互联网背景扫描）、无法关联或关联冲突的连接 | 排除（`ambiguous`） |

- 关联键：协议、双向端点与端口，首包时间容差在 A3 试提取中实测确定并冻结；一条连接关联到多个不同标签时排除并记录。
- 发布说明的攻击时段用于交叉核对：落在时段外的攻击关联、时段内未关联上的大量连接都要列出原因。
- 每类人工抽查至少 50 条连接，记录结论；规则调整升版本号，不改已冻结数据的标签。

此前阶段三的诊断表明，把“非已知攻击者”一律当正常，会把互联网背景扫描误标为正常，造成大量虚假误报。本版因此只把可确认的流量标为 `normal`。

标签账本至少包含：sourceVersion/sourceHash、labelRuleVersion、parentConnectionId、activityId、类别、原始场景名、start/end、evidenceTier（`publisher_documented / controlled_task / analyst_reviewed / ambiguous`，`controlled_task` 用于 L3 受控采集）、exclusionReason。原始地址只在受控账本中保存。地址、ID、时间戳、文件名和标签辅助列不得进入模型。

## 4. 切分与泄漏控制

L1 采用切分规则 `host-guard-split/2`，同一 parentConnection 的全部快照和续段只属于一个集合：

| 对象 | 切分方式 |
|---|---|
| 攻击：分段 | 按 (日期, 原始场景) 分别处理（如 Slowloris、Slowhttptest、周五 PortScan、周四内部扫描各自独立）；连接起点晚于此前全部连接结束 60 秒以上即为新的运行段。60 秒是上下文窗口的两倍，段间不共享任何 30 秒窗口 |
| 攻击：多次突发 | 至少 3 段且整段分配后每个集合 ≥ 50 条连接时，按规模从大到小把整段交给当前缺口最大的集合（目标 60/20/20），不在一次工具运行内部切开，无保护区损失 |
| 攻击：持续运行 | 其余场景按活跃时长（去掉段间空闲）取 60%/80% 处为初始边界，再在其附近按 5 秒网格搜索，使保留连接最多，并满足 train ≥ 50%、validation 与 test 各 ≥ 15%；搜索只用连接起止时间 |
| 正常流量 | 按天切为 10 分钟时间块，每 100 分钟依次 60 分钟 train、20 分钟 validation、20 分钟 test |
| 边界 | 完整连接区间与实际集合转换边界前后 30 秒保护区相交即整条剔除；同集合相邻块不额外剔除 |
| 出口 | 每个攻击场景在每个集合 ≥ 50 条连接；三个集合都有五类；test 正常连接 ≥ 4,000，且每个集合内部正常连接 ≥ 1,000。任一不满足即冻结失败 |

`host-guard-split/1`（按连接数分位切分）对突发型攻击会把 validation 时间窗压到几秒，被 30 秒保护区吞掉，导致 Slowhttptest、周五主 PortScan 在 validation 中为零；2026-10-07 改为本规则重新冻结，旧冻结结果只留档、不使用。

- 切分清单在训练前冻结并计算哈希。P3-A 准备时允许关联原件、生成标签和封存；冻结后至 P6 前不读取 test 的特征与标签，不做模型评估，访问记录随 run 保存。
- 相同原件、双向五元组及首包时间构成 physicalConnectionId，跨提取视角核对；若该身份对应多个 parent，整组排除，不靠合并 ID 消除冲突。
- L1 test 的受支持入口为 `scripts/p3/access_multiclass_test.py`：绑定 P6 计划、冻结清单和候选哈希，以原子锁登记最多 3 个评价运行。Mac 权限封存及 Windows L3 只读属性只防误读/误写，不能阻止同账户主动绕过或管理员读取；L3 评估入口及日志在 P6 接续。
- 预处理、类别词表、类别权重只用 train 拟合；阈值与模型选择只用 validation。
- L1 内的攻击工具和攻击机跨集合相同，这是同数据集评估的固有局限，由 L2 跨数据集结果弥补，不靠复杂分组规避。

## 5. 训练

| 项目 | 规则 |
|---|---|
| 算法 | XGBoost（主选）与 LightGBM，多分类 softmax；不使用序列模型或 MLP |
| 样本权重 | 每个 parentConnection 的快照权重和为 1；再按类别做有限平衡，避免洪泛类主导 |
| 采样 | 每个活动可设样本上限；默认不使用 SMOTE 或合成流 |
| 校准 | 默认不做额外校准；如需校准只用 validation，并检查校准后分数未退化为常数（各类分数方差、类间差异） |
| 阈值 | 在 validation 上选 `alertThreshold`，使 validation 误报率（按 [验收 3 节](验证与验收.md#3-统计单位与判定规则) 内部/网页等权口径）≤ 1%（给 test 的 2% 留余量）；各类 `autoThreshold`、`minDistinctFlows` 同样在 validation 上选择 |
| 记录 | 每次拟合的配置、种子、代码/依赖哈希、指标和产物保存在 run 目录，并保存原生非 pickle 模型与 train/validation 框架概率；全部运行都要记录，不只保留最好结果。拟合次数上限由每轮计划写明，所有拟合（含 smoke、中断、重跑）计入 run 外只追加台账，超出须负责人书面调整 |
| 捷径检查 | 分别去掉 `serviceClass`、本机上下文特征（`hostFlowStarts`、`hostDistinctPeers`）重新训练对比，并检查特征重要性。网页补充中服务器只看到 1 个访问者，本机上下文系统性偏小，可能让模型学到“本机上下文小即正常”；去掉后性能大幅下降说明存在捷径，须调整数据或特征后再冻结。重训消融只说明换一组特征能否分类，不能证明已冻结模型不依赖这些特征；因此冻结前还须在候选本身上做单对端敏感性检查（[验收第 6 节](验证与验收.md#6-报告指标不设门槛)）。2026-10-07 的 [P6 诊断](模型训练与评估记录.md#7-评价后诊断2026-10-07) 证明，当前候选在主机只有 1 个对端时洪泛、慢速检出归零 |

旧 prefix 路线的教训适用于本版：选型和准入检查必须包含“模型分数是否有区分度”（各类分数分布、与常数分基线的差异），不能只看流程是否机械通过。

## 6. 模型输出与交付

- ONNX 输入沿用 `numeric_values`、`numeric_missing`、`categorical_codes`；输出 `attack_score` `[N,1]` = 1 − P(normal)，`family_scores` `[N,4]` 为 4 个攻击类的概率，列顺序固定为 `familyScoreOrder = [port_scan, brute_force, dos_flood, dos_slow]`。
- 预处理沿用 `p3-preprocess-v2`（可移植的 float64 预处理，避免训练端与 ONNX Runtime 的 `log` 精度差）；ONNX 与训练框架最大分差 ≤ 1e-4。
- 候选包含 ONNX、manifest、预处理、类别映射、切分清单、阈值与策略参数、validation 报告和逐文件 SHA-256。`candidateOnly=true` 永久保留；自动资格由发布组合和 [类别自动资格](验证与验收.md#5-类别自动资格) 授予。
- 在线权重冻结；反馈经复核后进入 Windows 离线候选流程，禁止在线伪标签自训练或自动换权重。

### 6.1 命名与版本迭代规范（2026-10-16）

模型、策略与发布组合的技术键（`modelKey`、`policyKey`、`bundleKey`）是 UUID，已写入 manifest、策略 JCS、subject 与签名报告，**一律不改**。控制台只用**显示名**区分版本；显示名不参与任何摘要、授权或执行判定，修改写审计。列表第一行显示名，第二行短键。

| 对象 | 编号 | 显示名格式 | 递增规则 |
|---|---|---|---|
| 模型 | `M主.次` | `M2.1 · 五分类 LightGBM（第二轮 t37）` | 换训练轮次、特征或标签版本加主号；同一轮重新导出、修复预处理加次号；`version` 字段保留原技术版本串 |
| 决策策略 | `P序号` | `P5 · 真实主机只告警` | 策略正文（阈值、规则、模式、快照类型、能力引用）任一变化即新编号；正文冻结后不复用编号 |
| 发布组合 | `R序号[后缀]` | `R6 · 真实主机 · 只告警` | 模型、策略、环境、能力或协议版本任一变化即新编号；内容不变只为重跑评价/换报告绑定而重建的组合加 `a`、`b`（如 `R5a`、`R5b`） |
| 数据集 | 名称 + 切分版本 | `CIC-IDS2017 L1 · 冻结切分 v2` | 切分或标签规则变化即新版本 |

编号按登记时间单调递增，不回收；退役对象保留原名。备注写来源、与上一版的差异和用途。r1—r6 与现有显示名的对应见[系统实施记录 6.52](系统实施记录.md#652-命名规范与-v28-组合显示名2026-10-16)。

## 7. 规则引擎

规则引擎与模型并行，作为第二条检测来源，规则版本 `host-guard-rules/1`。规则只读观察中已有的字段（例如 `contexts.5.peerDistinctServicePorts`、`contexts.30.peerFlowStarts`），阈值在 L1 validation 上设定，在 L1 test 和 L2 上与模型对比报告。规则默认只告警；标记为可自动的规则同样要在 G3 中完成真实封禁与恢复。旧 v4 窗口规则（`window-rules-v1.json`）只服务 v4 路径，不直接用于 v5 观察。
