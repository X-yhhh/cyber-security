# 前端设计文档

版本：host-guard v5，更新于 2026-10-05，状态核对于 2026-10-12（界面自 `bb8d809` 起未改动，相对后端的缺口见[前端任务](任务/前端.md)）。本文是前端的基本设计文档之一，描述**当前已实现的界面**、
组件库、接入层与交互约定。实施路线见[开发路线](开发路线.md)，后端接口语义以[接口设计](接口设计.md)为准，
模块职责见[功能模块设计](功能模块设计.md)。本文不重复后端契约，只固定前端的表达方式与落位规则。

代码位置：`frontend/`。本文与代码冲突时以代码为准，并修正本文。

## 1. 定位与边界

前端是**本地自用控制台**，用于查看、审核和驱动后端已经实现的事实，不承担检测、判定或执行职责。

| 项 | 约定 |
|---|---|
| 数据来源 | 全部来自后端 API；**不内置演示数据**，数据库无记录时如实显示空态 |
| 授权 | 前端权限判断**只用于隐藏入口**；一切授权、状态迁移、幂等与职责分离由后端重新判定 |
| 动作 | 不提供任意目标地址、命令或 shell 的输入；处置只能引用已登记的决策与稳定预算目标 |
| 阶段声明 | 候选设计、未验收能力不得在界面写成已实现；能力等级按后端返回值原样展示 |
| 敏感值 | 不持久化机器凭据；凭据只在签发响应中出现一次并提示立即保存，不写入本地存储 |

界面上的每一条口径说明都对应一条后端硬约束（例如「批复不等于规则已清理」「202 不代表检测完成」），
改写文案时不得弱化这些含义。

## 2. 技术基线

| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3.5（`<script setup>` + TypeScript） | 稳定版；升级到 Vue 4 需另行评审 |
| 构建 | Vite 6 | 开发服务器将 `/api/v1` 与 `/api/v2` 代理到 `127.0.0.1:18080` |
| 样式 | Tailwind CSS 3.4 | 主题令牌集中在 `tailwind.config.js`，无 CSS-in-JS |
| 路由 | vue-router 4 | 控制台挂在 `/console` 下，未登录跳登录页 |
| 状态 | `reactive` 单例 + composable | 未使用 Pinia（依赖已装但无实际用量），会话与提示为模块级单例 |
| 图标 | lucide-vue-next | 线宽统一 `1.5` |
| 测试 | Vitest 5 + @vue/test-utils + jsdom + msw | 覆盖阈值：行/函数/语句 40%、分支 30% |

## 3. 视觉基线

### 3.1 色彩

单一强调色，不用彩色底徽章；语义靠圆点与文字着色。

| 用途 | Token | 值 |
|---|---|---|
| 页面底色 / 表面 | `paper` | `#FFFFFF` |
| 次级表面（hover 行） | `paper.soft` | `#EFEEE9` |
| 强分隔线（区块顶线） | `ink` | `#14161A` |
| 主要文字 | `ink` | `#14161A` |
| 次级 / 三级 / 四级文字 | `ink-2` `ink-3` `ink-4` | `#3A3D44` `#6B6E75` `#9A9CA1` |
| 分隔线 / 发丝线 | `ink-line` `ink-hair` | `#D9D7D0` `#E4E2DB` |
| 强调（品牌） | `signal` `signal-soft` | `#2438E8` `#E6E8FB` |
| 威胁 / 警示 / 正常 | `threat` `warn` `ok` | `#E0482A` `#B7791F` `#2F7D5B` |

三级线宽体系（`border-ink` / `border-ink-line` / `border-ink-hair`）是版面组织的核心手段。

### 3.2 形状与层级

- **无阴影**。层级只用细线、留白与 `z` 轴（遮罩 `bg-ink/10`）表达。
- **小圆角**：`rounded` = 2px，`rounded-sm` = 1px；`rounded-md/lg/xl` 已从主题移除，写了不产生样式。
  `rounded-full` 仅用于状态圆点 `.dot`。

### 3.3 排版

- 字体：正文 Inter（300/400/500/600），标识符与数值 JetBrains Mono（400/500）。
- 规律：**字号越小越粗、越大越细**。页面标题 `2.25rem font-light`，大指标 `2.5rem font-light`，
  表格单元格 `13.5px`，小标签 `11px`。
- `.num`（等宽 + `tabular-nums`）用于时间、ID、IP、端口、哈希、分数、计数、TTL、版本号。
- `.label`（等宽、大写、`tracking-label`）用于章节号、字段名与表头。

### 3.4 动效

统一使用 `cubic-bezier(0.22, 1, 0.36, 1)`；页面切换 450ms，抽屉 500ms，淡入淡出 300ms。
`prefers-reduced-motion: reduce` 下全部压缩为 0.01ms，`.reveal` 直接显形。

## 4. 信息架构

侧栏模块与路由常量 `modules` 一一对应，编号在页面内硬编码（不由路由生成）。

| # | 路由 | 模块 | 英文 | 主要承载 |
|---|---|---|---|---|
| 01 | `/console/overview` | 态势 | Overview | 事件、传感器、审批、模型部署与漂移概览，运行状态 |
| 02 | `/console/events` | 告警与事件 | Detection | 事件、告警、规则、检测策略 |
| 03 | `/console/response` | 受控响应 | Response | 审批台账、我的申请、响应策略生命周期 |
| 04 | `/console/models` | 模型治理 | Models | 模型候选与校验、发布申请与审批、本机激活、漂移、反馈、训练台账 |
| 05 | `/console/assets` | 资产与传感器 | Assets | 资产台账、授权申请与审批、传感器 |
| 06 | `/console/sources` | 数据源与回放 | Sources | 数据源与接入汇总、回放场景、影子报告、反馈第二人复核 |
| 07 | `/console/audit` | 审计 | Audit | 追加式只读审计查询 |
| 08 | `/console/iam` | 身份与角色 | Identity | 用户、角色与机器客户端台账 |
| 09 | `/console/observation` | 观测与目标 | Observation | **P4 新增**：观察批次、观察记录、推理结论、证据迹 |
| 10 | `/console/release` | 策略与发布 | Release | **P4 新增**：决策策略、发布组合、能力登记、评价运行 |
| 11 | `/console/execution` | 执行与预算 | Execution | **P4 新增**：动作台账与回执、稳定目标预算、自动化停用 |

事件详情为独立路由 `/console/events/:id`（`meta.parent = 'events'`），其余详情一律用抽屉承载。

### 4.1 子视图落位规则

同一模块内的子视图用页内分段（`Segmented`）切换，不再拆分子路由。分段选项按权限动态展开，
因此可见分段数与顺序随身份变化。

### 4.2 P4 三条链路的归属

P4 的 v2 对象按因果顺序落到三个新模块，而不是并入既有页面：观察链路自身是一条连续证据链
（批次 → 观察 → 推理 → 证据迹），与 v1 的同名对象语义不同，混排会误导读数。

- 09 承载检测链路前半段，只读。
- 10 承载「策略与发布组合」的冻结与审批，是能力等级的唯一来源。
- 11 承载动作、回执与预算账本，是唯一涉及真实执行意图的页面。

## 5. 组件库

通用组件位于 `src/components/`。新增页面必须复用这些组件，不另造同类控件。

| 组件 | 用途 | 关键 props / 约定 |
|---|---|---|
| `PageHead` | 页头：编号 + 标题 + 一句口径说明 | `no` `title` `desc`；右侧 slot 放主操作；`#kicker` 放英文名 |
| `Segmented` | 子视图切换（`role="tablist"`） | `defineModel` 双向绑定；指示线用 DOM 实测定位，选项数变化自动重测 |
| `Tag` | 状态标记 | `tone` + `label`；**圆点 + 文字**，不做彩色底 |
| `Metric` | 大指标 | 进场计数动画，尊重 `prefers-reduced-motion`；`tone` 仅影响数字颜色 |
| `Pager` | **页码**分页条 | 用于 v1 的 `page/size` 接口；单页时整条隐藏 |
| `CursorPager` | **游标**分页条 | 用于 v2；后端不返回总数，故只显示「本页 N 条」与进退 |
| `Drawer` | 详情面板 | `Teleport` 到 body；Escape 关闭、Tab 焦点循环、打开时自动聚焦标题、关闭后归还焦点 |
| `LoadState` | 四态占位 | 顺序 `loading → error → empty → slot`；错误带 `role="alert"`；`empty` 由父组件计算 |
| `ToastHost` | 操作结果提示 | 全局唯一，挂载于 `App.vue` |

### 5.1 操作控件阶梯

每个页面只应有一个实心主操作，按语义递降：

1. `.act` — 实心主操作（提交、批准、激活），每页唯一；
2. `.act-ghost` — 边框次操作（起草、停用）；
3. `.link` — 行内文字操作（查看、撤回、取消）；
4. 无样式 `<button>` + 下划线切换 — 筛选器。

输入统一用 `.field`（下划线式，无边框盒）；多行输入追加 `h-auto resize-none py-2`。

## 6. 接入层

### 6.1 两套协议

`src/api/client.ts` 同时支持 v1 与 v2，区别只有信封与错误判定：

| 项 | `/api/v1` | `/api/v2`（P4） |
|---|---|---|
| 信封 | `{success, data, error, requestId}` | `{requestId, data, error}` |
| 成功判定 | `success === true` | HTTP 2xx 且 `error == null` |
| 分页 | `page` + `size`，返回 `totalElements` | `cursor` + `limit`（1—200），返回 `nextCursor` |
| 主键 | 内部数字 ID | 外部 UUID |
| 幂等 | 部分写操作 | **全部写操作**必带 `Idempotency-Key`（UUID 形态） |
| 并发 | 无 | 审批/激活/停用类需 `If-Match: <revision>` |

路径以 `/api/` 开头时视为已含版本前缀，否则自动补 `/api/v1`，因此既有调用点无需改动。

### 6.2 v2 封装

`guard` 对象提供 `list` / `get` / `child` / `create` / `op` 五个方法，只封装后端路由中真实存在的组合，
不在前端做兜底猜测；未知组合由后端返回 404。

- 写入的幂等键默认由 `idempotencyKey()` 生成 UUID；
- `op` 的 `revision` 参数生成 `If-Match`。注意同一幂等键配不同 `If-Match` 会被后端视为不同请求，
  因此键必须随每次提交生成，不能跨提交复用。

### 6.3 会话与错误

- 会话状态只来自 `GET /auth/me`；`can(permission)` 用于隐藏入口。
- CSRF 头名由后端 `/auth/csrf` 下发，前端不硬编码；写请求 403 时自动作废本地令牌，下次重取。
- 401 自动跳登录页（`/auth/*` 自身的失败除外）。
- 错误文案统一由 `errText` 生成并附带 `request-id`，页面不得自行拼接错误信息。

## 7. 权限与职责分离

- 导航**不过滤权限**，11 个模块恒常显示；过滤发生在分段选项、操作入口与请求三处。
- 审批类入口在无权限时不显示原因文案（避免泄露他人对象的处理状态）。
- 后端职责分离规则在前端只做提示：自批返回 403 `APPROVAL_SEPARATION_REQUIRED`，
  本人起草的版本不显示审批按钮，`If-Match` 不匹配返回 409 `REVISION_CONFLICT`。
- 页面不得依据前端推断「已批准」「已清理」等终态；终态一律读自后端返回值。

## 8. 状态与语义

后端状态值到颜色的映射**集中在 `src/data/tones.ts`**，用 `Proxy` 对未知值回退为中性 `mute`，
页面不各自判色。新增集合必须在此登记，不允许在页面里内联三元表达式选颜色。

要点：

- `signal`（钴蓝）表示「进行中 / 需关注但非威胁」，不是装饰色；
- 威胁语义只用 `threat`，且「模型分数」与「展示风险」分开着色，不合并为一个高亮；
- **期望状态与观测状态分开显示**：动作的 desired 与 observed 各自成列，制定不等于执行；
- 不成功的推理不带分数，`null` 显示为 `—` 而不是 `0`。

## 9. 交互与实现约定

1. **不本地推断终态**：写操作成功后 `await reload()` 重新读取；不做乐观更新。
2. **竞态防护**：切换实体或翻页时用请求序号作废旧响应（`let seq` + `mine !== seq` 早退）。
3. **分页**：v1 用 `Pager`（页码从 0 开始）；v2 用 `CursorPager`（游标栈支持回退，栈空时禁用「上一页」）。
4. **可点击行**：`tr.row-link` 必须配 `tabindex="0"` 与 `@keydown.enter`。
5. **空态文案**：带范围限定的句子（如「数据库中暂无你审计范围内的记录。」），不使用「暂无数据」。
6. **表单**：字段名集中在常量对象中定义，避免同一请求体在两处写字面量。
7. **无障碍**：抽屉焦点循环与 Escape 由 `Drawer` 统一处理；错误区 `role="alert"`；
   切换类控件 `role="tab"` + `aria-selected`，分页区 `aria-label`。

## 10. 页面清单

### 10.1 既有页面（01—08）

v1 接口为主。明细见 `frontend/README.md` 第 2 节的接口对照表。

### 10.2 观测与目标（09）

| 分段 | 数据 | 读权限 |
|---|---|---|
| 观察批次 | `observation-batches` | `detection.read` |
| 观察记录 | `observations` | `detection.read` |
| 推理结论 | `detections` | `detection.read` |
| 证据迹 | `evidence-episodes` + `evidence` 子资源 | `detection.read` |

表达重点：批次受理是局部接收（接受/拒绝/去重三态并存）；202 只表示持久化受理；
快照只含 `asOf` 之前的报文；证据迹按 30 秒桶归并并按父流去重。

### 10.3 策略与发布（10）

| 分段 | 数据 | 读权限 | 写操作 |
|---|---|---|---|
| 决策策略 | `decision-policies` | `resource.read` | 复核（`policy.approve`，需 `If-Match`） |
| 发布组合 | `release-bundles` | `resource.read` | 登记报告 / 封存 / 审批 / 激活 / 停用 |
| 能力登记 | `capabilities` | `resource.read` | 无（只读） |
| 评价运行 | `evaluations` | `evaluation.read` | 无（只读） |

表达重点：策略复核不等于激活；封存必须含一次 `final` 运行；报告不反向写入被评估的 subject；
能力等级按平台分别取得，不复制另一平台成绩。

### 10.4 执行与预算（11）

| 分段 | 数据 | 读权限 | 写操作 |
|---|---|---|---|
| 动作台账 | `actions` + `receipts` 子资源 | `action.read` | 申请（`action.request`）、审批（`authorization.approve`）、撤销（`action.revoke`） |
| 预算目标 | `budget-targets` | `action.read` | 无（只读） |

页头另有「停用自动化」（`automation.stop`，202 受理）。

表达重点：期望与观测状态分列；无回执时显示「命令未下发」，不显示「执行成功」；
预算账本只读，界面不提供任何清零入口，额度恢复条件如实写出；
人工申请必须引用决策绑定的稳定预算目标，不接受原始地址。

## 11. 测试

- 单元与组件测试位于 `src/**/*.test.ts`，用 msw 拦截请求，断言落到可见文案与 `role`。
- 页面级测试覆盖权限门控（无权限不显示入口）与四态渲染。
- `npm run lint` 警告即失败；`npm run typecheck` 与 `npm run build` 必须通过。
- 覆盖率阈值由 `vite.config.ts` 强制，新增页面应同步补测试，不通过降低阈值来达标。

## 12. 待办与约束

- 现有 README 的历史描述曾与实际实现不一致（浅色调色板、彩色徽章、多层阴影），已按代码修正；
  后续修改视觉基线必须同时更新本文、`tailwind.config.js` 与 README。
- 后台任务未接入 `event-sources` / `heartbeats` / `health-windows` / `target-bindings` / `command-claims` /
  `reconciliations` 等**机器侧**路由：这些由采集器与执行器以机器凭据调用，浏览器会话不可用
  （机器路由会清空会话上下文，且要求 `Bearer mch_*` 身份），因此不属于控制台前端范围。
- 稳定目标预算的「未核验标识冲突」「跨 boot 续期」等异常分支只按后端返回值展示，
  前端不自行推断连续性。
- 回放与真实执行器仍按后端能力开放；前端不提供绕过签名、TTL 与范围约束的入口。
