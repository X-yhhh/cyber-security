# 接口设计

版本：host-guard v5 目标 API，尚未实现。新协议统一 `/api/v2`；旧 `/api/v1` 不静默改语义。现有身份登录会话可以复用 v1，业务 v2 由 P4 新增；前端适配不在本路线内。

## 1. 通用约定

- HTTPS；本机回环开发可 HTTP，非回环不得明文。人工请求使用服务端 session，所有人工写入校验 CSRF；机器使用专用 bearer 凭据，不接受浏览器 session 冒充。
- 外部 ID 为 UUID，映射数据库内部 BIGINT。时间为 UTC RFC3339 Z。列表 `cursor` + `limit`（默认50，1—200），按 `(createdAt,id)` 稳定倒序；返回 nextCursor，不让跨范围记录影响可见分页。
- 所有资源先权限再范围校验；跨范围单对象返回404，功能权限不足403。请求 trace 使用服务器生成/校验的 `X-Request-Id`，日志脱敏。
- 人工/机器写入均需 `Idempotency-Key` UUID，范围为主体+方法+路由模板+资源+键；保存 JCS 请求 SHA-256。相同键内容不同409，相同内容返回原结果。幂等记录至少覆盖重试期，动作幂等事实永不按短缓存到期删除。
- JSON 未知字段拒绝；Content-Type固定 application/json，默认请求≤1MiB。观察批次≤100条，拒绝超大批次；不接受原始 PCAP/权重/任意文件路径上传到通用接口。
- 人工更新需 `If-Match: revision`，并发冲突409；批准的不可变版本不能原位 PATCH。

统一响应：`{requestId, data, error}`；成功 error=null；失败 data=null，error 为 `{code,message,retryable,details}`。details 只含脱敏字段名/原因码。异步接收202意味着持久化受理，不代表检测、部署或阻断已完成。

## 2. 权限与资源映射

人工共同查询需要 `resource.read` 和该资源范围；报告另需 evaluation.read，安全数据另需 detection.read，动作另需 action.read。写权限见下表和[功能模块](功能模块设计.md)。机器权限精确绑定 sensor/executor→asset，不接受独立范围笛卡尔积。人工管理员不能用普通业务请求指定机器已批准标志。

| PATCH /assets/{id} | status,criticality,owner | asset.manage+If-Match；200；停用同时暂停该资产新命令 |

接口不返回凭据明文/摘要、HMAC密钥、私钥或原始端点映射。授权修改不能追溯使旧动作合法。

## 4. 机器观察与健康

### 4.1 提交观察

`POST /machine/sensors/{id}/observation-batches`，权限 machine.observation.write。

请求 `{batchId,bootId,sequence,configId,contractVersion,profileSha256,observations}`，observations 中每条遵循 [Observation Schema](contracts/observation.schema.json)。最大100条。batchId固定，sequence按boot从1单调递增；重试同键复用原序号。允许接收乱序到达批次但记录缺口，缺口未恢复期间相应上下文不得用于自动动作。

服务端从身份读取asset/sensor/environment，不信任请求扩大范围；逐条核对boot/config/profileSha256和结构，整批身份/版本/幂等冲突拒绝。业务记录可部分接收，202返回 `{batchId,status,acceptedCount,rejectedCount,duplicateCount,rejections:[{observationId,code}]}`。拒绝明细上限100。

同事务写观察/拒绝事实和outbox；随后返回。查询 `GET /observation-batches/{id}`、`GET /observations/{id}` 返回接入与推理独立状态，不把202当作执行成功。查询需要 detection.read 与全部来源/资产范围。

### 4.2 配置和健康

| 方法/路径 | 机器权限 | 请求 / 响应 |
|---|---|---|
| GET /machine/sensors/{id}/config | machine.sensor.read | 批准配置、契约/profile哈希、采集范围、资源上限、serverTime |
| POST /machine/sensors/{id}/heartbeats | machine.sensor.health | bootId,version,configHash,lastSequence,clockSkewMs；返回serverTime，不下发秘密 |
| POST /machine/sensors/{id}/health-windows | machine.sensor.health | windowStart/end,packetsSeen/dropped,lateCount,queueMax,memoryBytes,cpuPercent,qualityCounts |
| POST /machine/executors/{id}/heartbeats | machine.executor.health | bootId,adapterVersion,capabilityHash,pendingRecovery,activeRuleCount,clockSkewMs |

drop counter未知使用null，不能填0。健康窗口按机器+起止时间去重；监控到缺陷暂停对应自动能力，不影响无关已验证平台。

## 5. 模型、数据和评估

| 方法/路径 | 请求核心 | 权限 / 语义 |
|---|---|---|
| GET/POST /datasets | manifestRef,manifestSha256 | resource.read / dataset.manage；只登记受控对象，不抓取任意URL |
| GET/POST /models | manifestRef,manifestSha256 | resource.read / model.manage；不可变候选，Schema为[ModelManifest](contracts/model-manifest.schema.json) |
| POST /models/{id}/validations | validationProfileId | model.validate；202，哈希、ONNX和golden校验，GET /models/{id}/validations 查询结果 |
| POST /evaluation-plans | scope,datasetRefs,splitHashes,metrics,scenarioRefs | evaluation.run；201，读取final_test前冻结不可变计划 |
| POST /evaluations | planId,bundleCandidateId,runnerRef | evaluation.run；202，仅允许预登记本地/离线runner，不能执行任意命令 |
| GET /evaluations、/evaluations/{id} | filters,cursor,limit | evaluation.read；返回结果、范围、状态、排除原因、统计局限 |
| POST /evaluations/{id}/imports | reportRef,sha256,runnerIdentity | evaluation.run；导入Windows签发/可核验报告，不导入任意序列化执行对象 |
| POST /replay-runs | scenarioId,modelId,policyId,speed | evaluation.run；202，研究环境，永不获取真实目标引用 |
| GET /replay-runs/{id} | — | evaluation.read；进度、结果引用、原事件时间与墙钟分开 |
| POST /lab-validation-runs | scenarioId,scenarioSha256,mappingId,mappingSha256,bundleId,assetId,authorizationId | evaluation.run；202；仅经批准的lab试验计划/范围和登记runner，可产生真实canary动作；固定1倍速 |
| GET /lab-validation-runs/{id} | — | evaluation.read；固定时间offset、隔离/映射证据、动作与恢复结果 |

lab-validation-runs须另外校验对应lab执行授权、隔离证明和映射，evaluation.run本身不授予真实动作权。首次V6以P5适配器证据和P6模型/策略证据申请lab试验授权，不要求预先取得本次试验要证明的lab_auto等级；通过后才登记该等级。时间平移及映射不变量见[回放隔离契约](检测与处置契约.md#11-回放隔离与版本升级)，research接口不得设置此运行类型。

外部训练由Windows离线CLI执行；后端不提供“立即训练”或远端shell接口。报告上传不等于内容真实，需校验来源、哈希、计划一致性和runner权限。

## 6. 策略和发布

| 方法/路径 | 请求核心 | 权限 / 语义 |
|---|---|---|
| GET/POST /decision-policies | [DecisionPolicy](contracts/decision-policy.schema.json) | resource.read / policy.draft；201 draft |
| POST /decision-policies/{id}/reviews | decision,reason | policy.approve；不同主体批准为reviewed，不自动激活 |
| POST /release-bundles | modelId,policyId,featureProfileSha256,extractorSha256,evaluationPlanId,capabilityIds,environment | bundle.request；201 candidate，不可变组合 |
| POST /release-bundles/{id}/sealings | evaluationIds | bundle.request；201，核验完整计划及同subject报告，封存manifest，成功才进入evaluated |
| GET /release-bundles、/release-bundles/{id} | cursor/limit | resource.read；候选subject、封存manifest与状态，报告内容另需evaluation.read |
| POST /release-bundles/{id}/decisions | decision,reason | bundle.approve；仅evaluated可批准；自批拒绝 |
| POST /release-bundles/{id}/activations | assetIds,authorizationIds | bundle.approve；202，逐资产核验范围，激活模型/策略组合与能力 |
| POST /release-bundles/{id}/suspensions | reason,revokeExisting | automation.stop；202，立即停新命令，可请求清理现有规则 |
| GET /capabilities | platform,scope | resource.read；实验/平台证据及research/alert_only/lab_auto/authorized_auto/suspended |

candidate 的模型/策略/契约/能力声明形成不可变 subjectSha256，评估报告引用该 subject；报告完成后另封存发布 manifest（含 subject 和报告哈希），再进入 evaluated/approved。报告不反向写入被评估的 subject，避免哈希循环。评估失败保留candidate及失败报告，不伪造evaluated。

自动发布不是逐动作人工审批。政策内证据通过后领域服务自动创建action；任何人工API不得直接传入score或autoApproved覆盖该判定。

## 8. 执行机器协议

`POST /machine/executors/{id}/command-claims`，machine.command.claim，body为 `{bootId,capabilityHash,maxItems,waitSeconds}`，maxItems为1—10、waitSeconds为0—5。控制面复核当下授权和目标新鲜度，返回200 `{commands:[SignedActionCommand],revocations:[RevocationRequest],serverTime}`，无任务相应数组为空。总任务数不超过maxItems，撤销优先。领取有副作用，不能用GET实现。

命令包结构见 [ActionCommand](contracts/action-command.schema.json)，签名算法和所有绑定见[检测与处置契约](检测与处置契约.md)。同一命令重领不更新TTL；应用期限过后不再返回可执行命令；从未领取可证明未执行的记expired，已领取但无终结证明的记uncertain并核对，不能仅按时间写已清理。命令payload的bootId绑定采集器，executorBootId绑定当前领取代理；两者分别核验。

RevocationRequest固定字段为 `{revocationId,actionId,commandId,executorId,assetId,environment,desiredRevision,issuedAt,reasonCode}`；ID均UUID，desiredRevision为正整数，issuedAt为UTC时间，未知字段拒绝。控制面仅返回该executor名下任务，HTTPS校验服务端身份；恢复撤销不依赖已经过期的执行授权。pending从未签发命令的撤销由控制面锁行终止并审计，不生成代理任务；已签发才生成绑定commandId的RevocationRequest。代理先匹配自己的命令账本或已持久化领取记录，未知绑定拒绝并启动核对，不能执行任意规则删除。相同revocationId重领内容不变，旧revision不能覆盖新意图；代理先持久化撤销墓碑，再取消待应用命令、删除自身规则并回执revocationId。未收到清理证明会持续返回该任务，不以已领取代表成功。此通道没有任意ruleHandle/地址输入；撤销消息不另作离线签名，不能脱离受认证通道受理。

`POST /machine/executors/{id}/receipts`，machine.receipt.write，body遵循 [ActionReceipt](contracts/action-receipt.schema.json)。200表示回执已追加持久化；迟到回执不能逆转终态。同一receiptId不同哈希409。

`POST /machine/executors/{id}/reconciliations`，machine.receipt.write，body为 `{bootId,observedAt,ownedRules:[{actionId,ruleHandle,blockUntil,stateDigest}],recoveryErrors}`；上限1000条/1MiB。只核对本系统规则；发生不一致先暂停、追加证据，不按控制面旧状态盲目覆盖系统。

## 9. 错误目录

| HTTP | 稳定错误码示例 | 处理 |
|---|---|---|
| 400 | INVALID_REQUEST, UNKNOWN_FIELD, INVALID_TIMESTAMP | 修正输入，不重试相同错误 |
| 401/403/404 | UNAUTHENTICATED, SCOPE_DENIED, RESOURCE_NOT_FOUND | 不泄露目标存在性 |
| 409 | IDEMPOTENCY_CONFLICT, REVISION_CONFLICT, STATE_CONFLICT | 读取当前状态，不换键强行重试 |
| 413/429 | PAYLOAD_TOO_LARGE, CAPACITY_EXCEEDED | 分批/退避；证据过期就不执行 |
| 422 | CONTRACT_UNSUPPORTED, PROFILE_HASH_MISMATCH, TARGET_STALE, MODEL_NOT_APPLICABLE, QUALITY_INSUFFICIENT | 记录并转观察/诊断 |
| 422 | AUTHORIZATION_EXPIRED, PROTECTED_TARGET, CAPABILITY_UNVERIFIED, SIGNATURE_INVALID, COMMAND_EXPIRED | 拒绝动作，不降级绕过 |
| 503 | MODEL_UNAVAILABLE, EXECUTOR_UNAVAILABLE, RECOVERY_PENDING | 明确失败，暂停对应自动能力 |

同一稳定码在API/日志/审计/回执含义一致。系统异常只返回脱敏说明和requestId。

## 10. 迁移与验证

P4新增 v2，不重写已发布 v1 的返回语义。旧 shadow-report、资产级自动关联和原始目标参数只作为历史兼容，不能驱动 v5 动作。按[现状与迁移](现状与迁移.md)切换后再另行评估退役；不要求用户先改前端才完成后端。

必测权限、CSRF/机器身份隔离、资源范围、未知字段、批次局部拒绝、幂等重试、过期消息、并发批准/撤销、回执乱序与实际清理确认。契约Schema校验只是其中一部分。
