## 2. 统一契约与交付规则

- 机器结构维持 `host-guard/5.0.0-rc.2`；P3 新计划为 `p3-prefix-cde-20261005-v4`。新决策 `host-guard-decision/2026-10-05.2`、评价 `host-guard-evaluation/2026-10-05.2` 和健康旁证 `host-guard-capture-health/1.0.0` 的定义统一在 [检测与处置契约](检测与处置契约.md)。
- 修改角色/行为映射、时效、预算或阈值时生成新计划或策略版本，绑定实际哈希；不改旧清单冒充已验证，也不为文档改版重开已收口阶段。
- 先验证结构可达性，再训练；先冻结完整模型/校准/策略，再读取独立评价数据。模型分数、离线候选、实际 OS 动作分别报告。
- 旧源码、运行资源和数据不因文档清理自动迁移；后续按阶段接入，数据库仅向前迁移，保留 admin 行和已执行 Flyway 校验和。
- docs 保存当前规范、交接和设计计划；实际 run 清单、结果、模型与报告放受控产物目录。闭阶段复现使用对应 Git 基线或完整备份，不保留旧报告供日常开发误读。

### P3 出口

选型、校准和独立开发三个角色分别对两个声明行为进行完整策略回归：自动处置期及时覆盖≥80%、人工移交连续性≥80%，登记困难良性零错误机会/错误候选；支持来源不能被总体均值掩盖。train 只作诊断。独立组配对 E5 的预登记收益 95% 区间下界>0，才算证明模型贡献；最低 5+5 组不保证区间可靠。ONNX 最大分差≤1e-4、阈值翻转 0。统计公式及分母以 [验证与验收](验证与验收.md) 为准。

起点截止按行为及来源在拟合前登记，10 秒证据新鲜度与攻击起点时效分开。较长时效研究不自动成为已批准自动能力；缺乏对应批准保持 alert_only。回放先按连续真实目标预算域执行再分角色汇总，不能每组清空预算。

本轮只有一次有界实验，最多两次修正拟合包含在十次总额内。任何结构不可达、数据不足、误伤、收益不成立或预算耗尽均停止移交并按根因修正；独立开发数据一旦用于修正即登记暴露，需要新的独立组。P3 不读取 P6 锁定特征/标签/分数，不用 P6 的最终 100/3000 样本要求阻塞正常开发起步。

## P4 后端、数据库与事件关联

### 已完成范围

已在 JDK 25 下实现 v2 控制面和机器接口、机器身份与资源范围校验、不可变观察/推理/episode/案件事实、候选 ONNX 运行时校验、策略和发布组合、稳定目标预算、撤销、命令领取与回执/核对台账。`V19__host_guard_v5_foundation.sql` 与 `V20__host_guard_case_and_trial.sql` 只向前追加 schema；隔离 MySQL schema 已从 V1 迁移至 V20。guard outbox 消费、重试和死信队列配置已在代码中具备，但未连接真实 RabbitMQ broker 验证。本次没有迁移 `cyber_security` 业务库、重启服务或执行真实防火墙动作。

### 实施任务

1. 在 JDK 25 下新增 v2 观察接入、机器身份、范围鉴权和不可变记录；保留 v1 兼容。MySQL 8 实例和现有迁移核验后向前追加 guard 逻辑模型，RabbitMQ 通过 outbox 至少一次发布。
2. 接入 ONNX/profile、候选登记、超时和不适用处理；显式绑定 `contractVersion` 与决策/评价/健康版本，拒绝混用旧候选。
3. 对象/服务级 episode 按 parent 去重，记录最新证据、拒绝次序及完整证据摘要；案件汇总不扩大动作范围。
4. 实现认证健康窗口与稳定 budgetTargetId 的持久事实，跨 boot/keyEpoch/角色/策略连续关联；目标预算、资产额度、动作和 outbox 原子预留。
5. 按契约在实际规则清零、连续健康与 120 秒冷却均满足时事务恢复额度；缺口/未知/uncertain 不自动重置。预算快照、健康证明和每次恢复进入追加审计。
6. 完成策略/发布组合/资产绑定、审批分离、能力暂停、撤销、回执和核对 API。真实清理状态来自执行器，不由后端时间推断。

### 出口

已完成定向代码/事务验证和独立 MySQL 8 迁移验证，覆盖机器身份隔离、跨范围拒绝、重复写、审批分离、回执乱序及固定夹具的接入到撤销闭环。RabbitMQ broker 的发布确认、延迟重试和死信流转仍是部署前验证项。无默认真实动作启用；固定夹具只证明后端行为，P7 再接真实模型和实际适配器。

## P5 本机执行与恢复适配器

### 当前实现

已新增独立 Python 执行/恢复入口、PF/WFP 适配代码、本地密钥与 IPC 身份工具、Go guardtargets 服务、命令/回执/实态对接。P4 新增执行器范围内的预算证明查询与历史清零证据审计；查询不清零，历史补报不提前恢复额度。初版范围限 IPv4/TCP 入站，其他范围明确拒绝。

已完成固定命令故障回归、真实 TLS/Go IPC、Java/Python 签名摘要一致性和隔离 MySQL API 验证。尚未安装常驻服务或完成两平台实机故障矩阵；用户本轮要求不重启，主机重启验收暂缓。P5 仍为进行中，不能用 P1 探针或本次替身测试授予自动资格。

### 实施任务

1. 复用 P1 已确认的平台路径，将窄范围 peer_service 阻断实现为最小权限、独立身份的长期适配器；保护现有用户规则和管理连接。
2. 实现命令签名、授权 revision/租约、目标新鲜度、采集器/执行器 boot 和环境绑定；拒绝过期、串目标、重放与篡改。
3. 写规则前持久化命令与恢复账本，独立恢复器按可信截止清理，核验真实规则和新/已建连接效果；回执采用明确状态与 stateDigest。
4. 验证 TTL、撤销、断连、回执丢失、进程崩溃、时钟回退、重启及并发竞争。未证明规则不存在时保留 uncertain/recovery_failed 和预算，不接受新 ID 盲重试。
5. 输出实际清零时刻供 P4 的目标预算恢复核验。恢复器故障时暂停对应资产自动能力并提供可用的人工清理路径。

### 出口

[动作与恢复必需场景](验证与验收.md#6-动作与恢复必需场景) 全部按声明能力通过；P1 探针通过不替代生产 P5。只能延后自动修复便利功能和未声明平台能力，不能延后有效授权、环境隔离、崩溃/重启时不延长 TTL、并发预算和核对事实等硬约束。Mac/Windows 分别记录；不支持的平台保持不可自动。

## P6 冻结独立评估与候选导出

### 入口

P3-E 通过，完整 pipeline 与支持来源/行为/时效/规则版本已锁定；新评价活动的 parent、来源上下文和近重复与开发数据隔离，访问记录证明未用于选型。P3 独立开发评价和 P6 最终评价不是同一集合。

### 实施与出口

- 在读取最终特征、标签和分数前冻结评估计划、分母、攻击/良性配比、各来源范围、健康/预算处理和排除规则。相关组归并；无观察和超时保留在分母。
- 对完整模型、校准和策略做一次独立评估。按 [验收门槛](验证与验收.md#4-首版联合门槛) 检查两行为及支持来源的覆盖/精确率/误伤、至少 100 个攻击 episode 和 3000 个良性机会，并报告独立组数和区间。
- 冻结 ONNX 及必要配置，在 Windows/Mac 核验实际加载和推理一致性。final 报告引用不可变候选 subject，由发布组合绑定，不回填模型清单造成哈希循环。
- 输出离线可证明范围和 alert_only/candidateOnly 移交状态；真实 OS 生效时延与恢复留给 P5/P7。P6 不因这些尚未联合的证据与 P7 循环等待。

失败保存完整 run；若据此调整模型/阈值/范围，原集合降级为已暴露开发数据，另用未暴露集合重新申请最终评价。不得删失败来源、挑 seed 后继续复用旧最终成绩。

## P7 联合闭环与隔离验收

### 入口与实施

P4、相应平台 P5、该能力 P6 通过；登记网络层隔离、canary 映射、目标/接口、期限和试验授权。首次联合试验基于 P5/P6 申请 lab 试验资格，不要求先取得本阶段要证明的 lab_auto。

1. 冻结 PCAP 作为文件输入，经真实模型、同一策略和预算路径产生候选；只向登记的无害 canary 应用实际规则，不向网卡注入攻击报文。
2. 使用固定 1 倍速、一次性时间 offset，保留原始起点、前缀间隔、质量、目标和新鲜度；命令与 TTL 使用真实墙钟及单调计时。
3. 同时核验目标连接受控、其他连接正常、已建/新建连接范围、原始起点到首次动作、证据到 OS 生效和实际恢复。
4. 健康观察器跨活动持续，预算从实际清零证据恢复；断连、并发、时钟及恢复异常不因联合试验而豁免。

### 出口

声明能力的全部安全硬约束与联合门槛通过后取得 lab_auto；模型须有量化贡献。按平台分别验收，不能复制另一平台成绩。错误目标或恢复失败立即暂停对应资产；分类/数据问题回 P3 修正，后端问题在 P4、执行问题在 P5 处理。若需改观测语义，以新版本变更处理，不重新打开 P1/P2 历史待办。

## P8 自用部署与交付

把冻结模型与配置导入 Mac 的现有后端/本地入口，核对运行程序、模型/profile/policy/bundle 哈希、真实加载与拒绝行为。采集器、执行器、恢复器和控制面按实际部署方式配置最小权限、起停、日志、健康和恢复路径。

自动启用只绑定明确授权的资产、接口、服务、期限和已经联合验收的能力；authorized_auto 还需目标平台短时良性任务、运行停止条件及独立批准。单人测试身份隔离不等于实际第二人批准。不能满足该级别时交付模型/告警或 lab 能力，明确剩余项，不改写等级。

完成前验证启用/停用、授权撤销、模型不可用、重启/断连、规则清理和回退。保留当前必要的 v4 兼容路径，待代码与历史制品校验依赖迁移后再独立退役。交付使用现有运行方式、API/CLI 与报告；不增加前端或程序发行签名任务。

## 3. 阶段完成记录

每阶段 run 必须记录输入与版本哈希、实际操作、验证结果、未支持范围、失败原因及恢复证据。生成记录在受控产物目录保存，当前状态回写本路线与对应既有入口。用户未要求 Git 提交/推送时只交付工作区修改；计划能力不得写成已部署能力。
