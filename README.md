# 主机流量检测与受控自动阻断平台

本项目面向明确授权的 Mac/Windows 主机，通过自行训练的流量模型识别可观测攻击行为，经策略校验执行窄范围、限时、可撤销的本机防火墙阻断。模型必须对自动阻断产生可量化的贡献；不调用外部大模型 API，不训练大语言模型，不宣称全网可见或通用 DDoS 清洗能力。

## 当前状态与本轮范围

2026-10-03 起采用新的设计基线 **host-guard v5**。P0 文档与声明式契约重构已完成，基线提交为 `f4429f5`。截至 2026-10-04，[P1 后续补证](docs/p1/README.md)已取得两个完整 CIC 工作日原件，111/111 条关联匹配，20 条起点审查中有 5 条结构候选；正常 HTTP 任务与 Windows 窄阻断/恢复证据均已归档。[WFP动态探针](docs/p1/wfp-dynamic-probe.md)六项非重启场景通过，一次明确授权的重启后无残留。**数据可行性出口通过，P1整体blocked**：缺少跨重启期限内清零观察，自动启动观察任务退出1，严格TTL仍未验证；Mac暂缓实测、无自动能力。完整裁决见[阶段出口](docs/p1/stage-exit.json)。

活动业务路径仍为旧 v4 实现。[P2 因果提取与契约冻结](docs/p2/README.md)已通过研究软件验收；随后完成[数据补齐与重新冻结](docs/p2/data-readiness/README.md)，final研究集保留23020条观察，具备互斥训练、选型验证和独立校准角色。新增六批授权Windows回环良性任务共1008条连接，结束后监听释放。2026-10-04已完成[P3有界研究](docs/p3/README.md)：10次完整拟合，生成LightGBM基础特征候选，Windows/Mac全量ONNX对拍通过；**P3出口仍blocked**，选型覆盖19/28，早期证据、独立活动与正常机会不足。prefix研究、最终验收及自动执行资格仍未通过。候选未接入活动运行时，未迁移数据库或改变部署。

新的研发目标是证明“识别有效、目标准确、动作及时、恢复可靠”。取消持续入站影子运行作为研发或验收前置条件，采用独立离线评估、因果 PCAP 回放、短时良性任务、隔离环境真实阻断和故障恢复联合验收。模型分数不是阻断正确率，发布批准也不自动授予执行权限。

前端页面、视觉设计和前端适配均不安排在本开发路线内，由用户在后端及平台能力完成后自行处理。保留现有前端目录；文档中的 API 是无前端依赖的后端契约。

## 技术与环境

- 应用仓库 `main`：JDK 25、Spring Boot 模块化单体、MyBatis、MySQL 8、RabbitMQ、Go 传感器。Redis 为可选优化，不是实施前提。
- 训练仓库 `training/windows-cuda`：Windows CUDA 离线数据处理、模型实验和 ONNX 导出，不合并训练资产到业务主干。
- 默认由 Mac 运行控制面，Mac/Windows 传感器只观测各自授权接口。控制面断开时不执行新阻断；本地恢复器仍负责已有临时规则到期清理。
- 原始 PCAP、端点账本、模型、训练输出、密钥、日志和备份不进 Git。配置与数据位于受控服务目录，仓库只保存实现、设计及小型去敏验收材料。
- 新方案允许检测入站与出站，按平台、协议、地址族、方向、攻击家族分别声明实测范围。首个自动动作候选为 IPv4/TCP 的对端服务级临时阻断；其他能力不得由解析成功推定。

## 实施起点

当前实现进度见 [P3 报告](docs/p3/README.md)和[出口裁决](docs/p3/stage-exit.json)。final特征的有界研究已完成，校准开发对照中模型＋策略覆盖81/84、规则2/84，两者正常机会误伤均0/18；该数据参与校准/策略搜索且样本不足，不能授予P6准入或自动资格。下一步补独立早期证据及正常机会，475条prefix候选尚不足以支持独立prefix选型/校准；final_test未分配，P1平台恢复缺口继续保留。

P3训练代码和候选在Windows独立训练仓库，主干仅保存报告与设计。P1/P2基线为`efcbd12`，P3按`main`报告与`training/windows-cuda`训练实现分别交付，历史验证JSON保留生成时状态。Windows入口被系统策略阻断时保持现有防护，不扩大到其他资产或改变系统策略。后续实现按阶段推进；新增真实采集、资产操作、部署或Git发布必须落在明确授权范围内。
