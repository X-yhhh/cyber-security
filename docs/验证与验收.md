# 验证与验收

版本：host-guard v5。本文替代历史 L1/L2/L3、G3 持续入站影子门禁。没有常驻服务器不阻塞研发；前端不参与验收。指标为预登记目标，当前没有 v5 实测成绩。

## 1. 验证层次

| ID | 输入和执行环境 | 证明内容 | 不能证明 |
|---|---|---|---|
| V1 数据/标签与因果特征 | 公共 PCAP、透明标签、小型 golden | 输入可复算、无未来信息、标签有依据 | 模型准确或真实阻断 |
| V2 独立模型/策略评估 | 未暴露 final_test、冻结模型/策略 | 特定场景分类、事件覆盖和动作候选精确率 | 任意网络泛化 |
| V3 时间序列回放 | 同提取器、原始事件时钟、已知起点 | 决策时机、目标和窗口行为 | 实时系统墙钟延迟或真实攻击效果 |
| V4 短时良性任务 | 授权主机下载/更新/文件传输/正常重试 | 目标平台采集可用与实际业务误伤 | 无标签背景流都正常 |
| V5 真实动作/故障测试 | 网络层隔离环境、无害 canary 连接 | OS 规则有效、范围正确、恢复可靠 | 攻击流量真实打入系统 |
| V6 联合闭环 | 回放真实模型结论 → 专用测试目标 → 实际适配器 | 模型/策略/执行完整接线 | 未经授权实网生产验证 |

PCAP 只由离线读取器消费，不向网卡注入攻击报文。V5/V6 不运行恶意软件、攻击工具、漏洞利用或凭据攻击。网络隔离须有接口/路由/防火墙证据，应用标签不能代替隔离。V6固定1倍速和一次性时间offset，按[回放隔离契约](检测与处置契约.md#11-回放隔离与版本升级)保持时间间隔与服务语义；真实TTL不得由回放时钟控制。

## 2. 预登记评估计划

P2/P3 在读取 final_test 前冻结 `evaluationPlanId/hash`，至少包含：支持 capability 矩阵、来源和分区哈希、攻击/良性活动定义、排除规则、受保护目标、模型/策略选择预算、事件桶、动作 dedup、TTL、流量配比、指标公式、置信区间算法和失败处理。

每次报告带 plan hash、bundle/model/policy/extractor hashes、平台/捕获域、样本谱系、每类样本量、排除/不适用量、每来源/方向/家族指标。不能仅报告合并平均值。

## 3. 统计单位与公式

- connection：完整 parentConnection，prefix/final 不算独立连接。
- attack episode：同一目标/家族的真实攻击活动按预登记 30 秒桶统计；同一活动多个桶有关联，置信区间按原 activity/capture 聚类。
- benign decision opportunity：对正常 peer/service 形成的同样时间桶。没有足够观察的桶记不可评估，不偷偷排除高分正常样本。
- action：合并重试和同一目标 TTL 内重复触发后的唯一实际或候选阻断；续封计入累计影响时间。

`blockPrecision = 正确攻击目标的阻断数 / 全部阻断数`；`blockRecall = 在时效内正确阻断的支持范围攻击 episode / 全部支持范围攻击 episode`；`falseBlockRate = 被错误阻断的正常机会 / 全部正常机会`。零阻断时 precision 未定义，不能写 100%。同时报每 1000 正常机会误伤数、每小时动作数、被影响的正常会话数和累计误伤秒数。

置信区间默认按独立 activity/capture 做分组 bootstrap；组数不足需明确无法可靠估计，不能用几百万相关快照假装置信区间很窄。独立伯努利假设确实成立时，可报 Wilson/Clopper-Pearson；零错误的近似上界 3/n 必须注明独立性假设。

Precision 随攻击占比变化；报告原始连续场景结果，并在预登记的 10%、1%、0.1% 攻击机会配比上按固定抽样/权重报告敏感性。不能把 1:1 平衡集成绩写成现实精确率；重采样不改变时间窗特征，不将片段拼成虚构抓包。

## 4. 首版联合门槛

| 项目 | lab_auto 首版出口 |
|---|---|
| 模型数据 | 标签、因果、分区/重复审查通过；每个声明家族有未暴露独立活动证据 |
| 自动阻断精确率 | 在预登记支持范围和主评估配比下点估计 ≥99%；必须同时给置信区间和样本量 |
| 自动阻断覆盖率 | 每个声明家族 blockRecall ≥80%，不得通过几乎不执行获得高 precision |
| 样本覆盖 | 至少 100 个支持范围攻击 episode、3000 个良性机会；来源活动组数单列；不足不得宣称统计完成 |
| 困难良性集 | 下载、更新、正常并发、重试、连接恢复、管理会话均覆盖，预登记集合零误阻断 |
| 动作误伤预算 | 每资产最多同时 10 条、每分钟 5 次、TTL≤60秒、同对象连续≤120秒 |
| 时效 | 以短窗口家族为首版目标：证据已满足 → 规则确认生效 P95≤2秒；攻击开始 → 首次有效动作 P95≤10秒，超时计漏阻断 |
| 平台/恢复 | V5 必需场景全部通过；安装核验、流量效果、到期和撤销均有证据 |
| 模型贡献 | E5 中固定同一误伤预算，模型+策略相对仅规则有覆盖率或时效的正向收益，报告区间 |

上述 99% 是试验点目标，不声称已统计证明真实精确率≥99%。若要作该强声明，需单侧 95% 精确率下界≥99% 且来源代表性成立；约 100 次零误伤不能证明此声明。支持范围过窄、活动组不足或没有净收益，均不得以“99%”发布模型能力。

`authorized_auto` 在 lab_auto 之外，还需明确真实资产/接口/服务授权、目标平台 V4、版本完全一致的 V5、独立批准及运行停止条件。短时 V4 至少两个不同任务时段、覆盖注册业务，不要求持续接收入站或等若干天；样本量和局限随批准记录披露。不具备该范围证据则保持 lab_auto，而不是把实验能力描述为实网验证。

## 5. 因果与特征测试目录

| 场景 | 断言 |
|---|---|
| 1秒/5秒及后续 prefix | 不引用 asOf 后的包、最终时长、EOF 后信息 |
| 入站/出站/无 SYN | 前两者按握手证据定位，unknown 不自动执行 |
| UDP/ICMP | TCP 专属特征为 null + mask，不伪装为已观测零 |
| 冷启动和捕获 gap | 真实 coverage，不凑 100 流；gap 后重新计算连续覆盖 |
| 同一 PCAP 离线/现场夹具 | 相同释放次序、字段、快照，浮点误差按契约 |
| 乱序/同时间/重传 | 有界缓冲与序号确定性；超限缺陷留痕 |
| 片段/截断/卸载/过载 | 质量问题不隐藏；自动候选拒绝 |
| 跨分区连接/窗口 | parentConnection、activity 和上下文隔离带不泄漏 |

## 6. 动作与恢复必需场景

1. 正常目标不触发；受支持攻击模型证据触发同一目标的窄规则。
2. 未登记资产、跨资产引用、错误 executor、错误 boot/captureScope 均拒绝。
3. 过期/撤销授权、新旧 revision、失效目标、重放命令均拒绝。
4. 签名错误、未知/撤销 keyId、篡改 scope/TTL 均拒绝。
5. 管理通道、网关、DNS、受保护 peer/service 不受动作影响。
6. 同键同内容重试只保留一条规则且不延长；同键不同内容拒绝。
7. 规则安装前、安装后回执前、写账本时分别崩溃，恢复后实际规则与账本一致。
8. 控制面/消息队列/代理断连、回执丢失，标 uncertain 并核对，不盲重试。
9. TTL 到期、人工撤销、策略暂停分别删除自身规则；健康状态下到期后1秒内核验不存在，记录实际清理延迟。失败记录 recovery_failed 并停自动；不能把OS未提供的原生TTL当作已经具备。
10. wall clock 回退、时钟不可信、主机重启，不延长阻断时间。
11. 本系统规则与用户已有规则共存，不覆盖/删除其他规则。
12. 已建立连接和新连接分别验证效果；不支持已建连接时限制 capability 声明。
13. 并发命令/续封/撤销竞争不突破预算和连续封禁上限。
14. research、lab、authorized 之间不能复用目标引用、凭据或执行队列。
15. 多个 peer 同时产生告警，证据不会串目标；同流多快照不会增加独立证据数。

每项保存 expected、actual、平台版本、规则标识摘要、前后连接结果与恢复证据；只打印“命令成功”不算通过。实验需要的系统权限仅在已授权资产使用，不为通过测试绕过系统策略。

## 7. 替代影子运行的报告

统一报告为 `evaluation_report`，不新建旧 G3 的改名影子流程。运行健康仅报告采集丢包/过载/拒绝、延迟、模型/策略哈希和规则清理状态。输入漂移提示可暂停能力或进入离线诊断，但不自动改阈值、训练或换权重。

报告末尾列出可声明能力、未支持范围、统计限制和真实平台未验证项。前端尚未适配不影响 CLI/API 交付；现有 shadow-report 端点列为 legacy，不再作为新发布包依据。
