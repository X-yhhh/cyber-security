# 数据与模型方案

版本：host-guard v5；对应[检测契约](检测与处置契约.md)、[验收](验证与验收.md)和[开发路线](开发路线.md)。训练只在明确授权的 Windows 训练仓库离线执行，本次未开始训练。

## 1. 任务与实验对象

基本任务是从当前可观测流量区分正常与可疑攻击行为，并为特定家族的自动阻断提供证据。优先尝试 connection_abuse（连接扫描/异常连接聚集）和 sustained_flood（持续流量滥用），并用下载、更新、合法并发、重试等困难负样本检验。类别命名不能超过标签与观测支持范围。跨多端口的一次性扫描未必能满足单服务证据或由窄规则有效遏制；没有可证明的阻断覆盖时只能告警，不能为通过指标扩大到对端全端口封禁。P1/P3须对此做任务级裁决。

同一模型可覆盖多个经评估场景，也可按方向/协议拆分候选；拆分决定基于开发数据，不为躲避最终测试失败临时排除类别。每个 `(profile,direction,protocol,family)` 都有样本量和能力状态。没有支持数据的 IPv6/UDP 只做规范观测，不能声明模型检测已通过。

研究、候选、自动发布是三种不同资格。已批准来源及 train/validation 可以开展实验，不等待主机日志、动作适配器、全部类别或持续影子观测。自动发布仍须整链验收。

## 2. 来源与角色

| 来源 | 角色及选择依据 | 使用前仍需核实 |
|---|---|---|
| CIC-IDS2017 研究修正版及对应 PCAP | 优先开发候选，复用公开的修正标注逻辑，不重新把背景全部猜成正常 | 修正版本、许可、对应原始包、时间/方向/连接关联、已有切分暴露情况 |
| 现有 UNSW-NB15 | 历史对照；只有新提取器可复算的原始包才能训练早期快照模型 | 数据角色不能按文件名猜测；旧完整流 CSV 不能替代 prefix |
| IoT-23 官方有界场景 | 出站扫描/恶意通信覆盖，允许发起端；IoT 正常不代表桌面正常 | 场景/家族差异、完整标签连接、公开许可及重复关系 |
| 受控本机良性任务 | 面向实际终端的困难负样本及独立实机验收 | 用户授权的主机/接口/时段、任务脚本/记录、业务连接可对应性 |
| 独立来源或独立活动 | 留作泛化与锁定评估 | 不得把同 PCAP 的镜像、重新切段或排序副本当新来源 |

2026-10-03 查阅来源：[CIC 官方说明](https://www.unb.ca/cic/datasets/ids-2017.html)、[CNS2022 修正研究](https://intrusion-detection.distrinet-research.be/CNS2022/index.html)、[修正数据目录](https://intrusion-detection.distrinet-research.be/CNS2022/Datasets/)、[标注及工具说明](https://intrusion-detection.distrinet-research.be/CNS2022/Tools_Documentation.html)、[IoT-23 官方说明](https://www.stratosphereips.org/datasets-iot23)。修正目录列出的 CICIDS2017 包约 328M，只是修正表格包，不是原始 PCAP 大小。本轮只核实网页，不代表已下载、许可审查或接入成功。

P1 每来源先做有界样本，原始试点总预算 2 GiB，确需增大时先记录缺失证据与预期收益并在现有授权范围内执行；不得用截断文件产生完整样本结论。优先完整连接/活动，不以最小字节数牺牲可关联性。候选最多先审查两个来源；失败给出具体原因和下一项修正，不循环扩大来源清单。

## 3. 标签证据模型

每条标签包含 sourceVersion、sourceHash、labelRuleVersion/hash、connectionId、activityId、start/end、label、family、evidenceTier、reviewStatus、exclusionReason。endpoint 关联账本仅保留在受控离线目录，Git 只存统计和哈希。

| evidenceTier | 可用范围 | 要求 |
|---|---|---|
| publisher_documented | 基准训练及对应基准评估 | 可信发布来源、明确标签定义、连接可追溯、抽样复算；不强制额外主机日志 |
| controlled_task | 本机良性/测试任务 | 已登记正常任务与时间/连接证据；不把整个主机同时段都当正常 |
| analyst_reviewed | 人工确认样本 | 明确证据与第二人复核后可加入训练 |
| ambiguous | Unknown，仅诊断 | 不参与监督标签、正式分母或自动验收 |

标签台账保留旧结论；新证据使旧 Unknown 可升级时生成新标签版本并给出依据，不能直接批量改旧审查 JSON。公开正常日标签可作为 publisher_documented 来源，必须注明受控基准局限；“未匹配攻击规则”本身不构成正常证据。

修正版的 Attempted 是标注语义，不得作为模型输入或机械新攻击类。按研究者定义和本任务观测记录处理：无法确认出现可观察恶意行为时不作为自动阻断正例；是否并入 benign 或排除需按活动证据预登记。不能因某主机曾攻击就给该主机全部连接标 Attack。

## 4. 样本生成与因果标签

1. 原件只读，记录来源/许可/大小/SHA-256；保存提取器 build SHA、配置、时钟和捕获域。
2. 同一 Go 引擎处理 PCAP 与现场采集，输出 prefix/final 及旁路连接索引；不使用第三方完整流 CSV 列直接冒充新特征。
3. 关联完整连接及活动区间，方向、时间和包来源可核验；分段共享 parentConnectionId。歧义不传播标签。
4. 为每个 asOf 只使用已发生的信息。知道整条流属于攻击，不代表攻击发生前的 prefix 已可判攻击。无攻击起点证据时可做 final 研究，但不能用于声称提前识别的验收。
5. 不支持/缺失字段按契约质量区分，只有结构性缺失进入模型 mask；采集故障样本单列鲁棒性试验，不悄悄变良性。
6. 输出每来源、方向、profile、服务、家族、质量、排除原因及保留量。低保留率先诊断关联/任务定义，而非直接训练或换源。

训练样本 snapshot 多的长连接不能主导损失：每个 parentConnection 的样本权重总和为 1，再按活动/来源作有限平衡；权重策略须在验证前登记。SMOTE 不作为默认，禁止跨 split 或打乱序列后插值伪造时间流。

## 5. 分区与泄漏控制

- 先建立原始 capture/host/activity/parentConnection/duplicate group，再按组划分 train、validation、final_test。默认目标比例 60/20/20，样本不足时按组实际分配并报告，不追求机械比例。
- 同一攻击活动、完整连接、重放副本、近重复内容必须属于同一分区。优先时间/活动/主机隔离；若某类别只有单次活动，不能宣称该类别独立泛化已验证。
- 30 秒上下文加最长 120 秒流状态可能共享历史，时间边界留至少 150 秒隔离带并重置引擎；跨边界长连接整体归组或排除，不让测试上下文读 train 的流量。
- 源地址、标签辅助列、Attempted Category、日期、CSV 行号、原文件名与环境 ID 不进模型。做来源分类诊断/特征消融，检查是否主要学会辨认实验场景。
- 编码、插补、标准化、采样权重只拟合 train。超参、校准、策略阈值在 validation 的独立组子分区或组内交叉验证完成；同一组不能兼作校准与无偏报告。
- final_test 冻结哈希和访问记录，仅在模型及完整策略冻结后一次正式评估。失败保留全部报告；继续开发可将该集合明确降级为开发诊断，但不得继续称其独立最终测试，另需未暴露数据。
- 不能把攻击仅来自 A、正常仅来自 B 的来源组合当可靠分类基线；各主来源应有正负对照，来源/类别混淆需在 P1 明确揭示。

## 6. 有界实验矩阵

| 实验 | 对比 | 回答问题 |
|---|---|---|
| E1 因果特征 | 基础流 vs 基础+上下文；prefix 1s/5s vs final | 信息是否足以早期识别，增益来自哪里 |
| E2 模型 | XGBoost、LightGBM、MLP；相同分区与特征 | 表格/神经模型哪个在误伤约束下覆盖更好 |
| E3 困难负样本 | 加入下载、更新、重试、正常并发前后 | 是否解决目标终端的具体误报 |
| E4 时序增益 | 仅当 E1 暴露时序不足，比较小型 TCN/GRU 与最佳基线 | 序列是否提供额外信号；须先回P2新增序列profile和输入契约，禁止为“深度”堆结构 |
| E5 决策消融 | 仅规则、仅模型、模型+策略 | 相同误阻断预算下模型是否真正贡献 |
| E6 泛化 | 按独立活动/主机/来源留出 | 哪些能力可发布，哪些只能研究 |

首轮每来源最多 100,000 个 parentConnection、最多 2 个来源；先做 3 个基线各 1 个种子，优胜者再 3 种子和最多 20 次搜索，总 GPU 预算先设 4 小时。开发预算与来源/平台按 P1 实际资源登记，可有理由扩大；不以旧 30 分钟矩阵限制所有研究。显存/内存上限按远端真实设备核验后配置，不从本机推断。

每轮产物含配置、代码 SHA、数据/切分哈希、耗时、失败、错误样本分组、逐源 PR/ROC、校准和资源。两轮没有降低关键误伤或提高有效覆盖时停止盲调，给出标签问题/特征不足/样本不足/不可观察任务四选一或组合诊断，再验证最小修正。

## 7. 阈值与能力选择

告警阈值用于发现；自动阈值与 minDistinctFlows、minEvidenceSpan、上下文条件一起在 validation 上选。以误阻断约束下的事件级覆盖最大化为目标，不单选 Macro-F1 最大。

所有待发布来源分别报告结果；未列为支持范围的外部数据可作挑战集，不要求一个通用分类器在所有历史来源达到同一 ROC-AUC。不得在最终成绩出来后临时删掉失败来源来保持“全部通过”。

校准只描述与验证分布接近条件下的分数可靠性，不保证分布外安全。输入缺陷、协议不支持、超出能力范围必须停止自动升级；OOD 检测只能增加证据，不能证明能识别所有未知攻击。

## 8. 交付与不可变追溯

候选包含 ONNX、manifest、feature-profile、编码/插补/校准参数、数据 manifest、split manifest、validation 报告及文件 SHA-256 清单。初次manifest的finalEvaluationReportSha256可以为null，此后不得原位补填；最终报告独立引用冻结的评估subject，发布包绑定该报告，无须改写模型本体。所有示例哈希不是真制品，不得导入。

manifest 始终标 candidateOnly=true，发布资格单独由 release bundle 记录，不修改模型本体来假装批准。bundle 绑定模型哈希、特征与提取器哈希、策略哈希、评估计划/结果、平台能力、授权环境和批准记录。新权重绝不能复用历史锁定测试成绩。

ONNX 与训练框架最大分数差 ≤1e-4，阈值附近决策逐条一致；不一致必须解释/修复，不以均值误差掩盖决策翻转。在线权重冻结，反馈经复核进入下轮 Windows 离线候选。
