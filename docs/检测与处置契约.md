## 2. 观测范围、组流与时钟

- 本地网络命名空间/接口授权 ID 属于流键。同资产多个接口可能看到同一个包，首版每个地址族只允许一个捕获域；多域合并前必须另验去重，不能靠五元组假定无重复。
- 双向流键为 `(captureScopeId, addressFamily, transport, unordered endpoints)`。TCP 纯 SYN 判定发起端；无首包 SYN 时 `direction=unknown`，不能用首个响应包推断为入站/出站自动执行。
- 首版 UDP 以捕获域内首个报文确定观察方向，只作为研究特征，不证明看到了真正首包；ICMP/other或不能可靠确定服务端时direction=unknown、servicePort=null、serviceClass=other，不生成targetRef。TCP无SYN也采用这组unknown值。
- TCP 相同五元组观察到新 SYN 且不属于当前握手重传，以 new_syn 关闭旧 epoch，新建 flowId 和 parentConnectionId；只有未完成握手的同发起端、同 ISN 的 SYN 才视为重传。FIN 双向完成或 RST 结束，保留 5 秒墓碑吸收非 SYN 尾随包，新 SYN 不被吞掉。TCP 空闲 30 秒、UDP/其他协议空闲 10 秒、最长 120 秒导出 final；同一 TCP 连接的续段保留 parentConnectionId、方向、服务和握手状态，单段统计重置，无新包不建续段。
- 连接身份保留在有界表中直至新 SYN 或新 boot；满表拒收并标 capacityDrop，不遗忘后冒充独立连接。FIN/RST 墓碑过后仍无新 SYN 的段保留 parent，但方向降为 unknown；UDP 空闲后的首包是新的观察 epoch。捕获帧副本/重传按实际包计数，不折算去重，读取序号重复/倒退直接拒绝。
- 已交接输入适配支持单接口/单 section 的 Ethernet、RAW IP（12/101）及原生 DLT_NULL/DLT_LOOP 回环输入。链路适配只解析头，不改变 IP 字节量；DLT_NULL 校验捕获平台字节序和地址族，DLT_LOOP 使用网络字节序，地址族与IP版本不符拒绝。其他链路、混接口/多 section 容器拒绝。分片、缺失必要头、容量丢弃记录质量问题，不造完整流。合法协议缺某特征可为 null；解析失败不能伪装成协议正常缺省。
- timestamp 取捕获时间，captureSeq 为同接口原始读取序号；计算次序为 `(timestamp,captureSeq)`。首版乱序容忍 100 毫秒，超出时标记 latePacket，不修改已发布快照；在线和离线执行同一有界缓冲，不离线全局排序美化结果。
- 在线捕获时钟和离线原始事件时钟都驱动相同Tick。候选水位=单调推进的当前事件时钟−100ms，先按序释放不晚于水位的包，再导出不晚于水位的快照；同一时刻先包后Tick。没有新包的在线空闲也推进Tick；离线在相邻包间模拟同样定时点。决策只用已经释放且 timestamp ≤ asOf 的数据。训练样本同样不能读取未来；EOF 仅结束离线输入，不能伪造连接已经正常结束。

## 3. 快照与幂等

同一 flowId 在 `firstSeenAt+1s`、`+5s`，随后每 5 秒（10、15…秒）输出 prefix，直至结束或 120 秒切段。仅当上次快照之后有新接纳报文时输出；首个快照只需至少一个报文。提前结束输出 final，已经发出的 prefix 不删除；结束时刻与周期重合只发 final。没有新包的定时器不能续证目标或制造新证据。续段保留 parentConnectionId，按新 flowId 的 firstSeenAt 重新调度。

`snapshotIndex` 从 0 单调递增；`observationId` 为该快照固定 UUID，重试不能重建。逻辑唯一键为 `(sensorId,bootId,flowId,snapshotIndex)`；相同键不同 content hash 拒绝。prefix/final 一起分区，不能把一个连接的不同快照分别放入 train 和 test。

续段的新 flowId 从 snapshotIndex=0 重新计数，elapsedMs 与段内统计重新起算；parentConnectionId 不变。去重按 parent，证据新鲜度按各自 asOf，不跨段保留过期高分。统计桶、续段、boot 或角色切换均不得重置评估旁路中的原始攻击起点。

`profile` 为 `flow-prefix-v1` 或 `flow-final-v1`。final 不得输入只验收 prefix 的模型，prefix 不得用完整流统计代替。`firstSeenAt ≤ lastPacketAt ≤ asOf ≤ emittedAt`；`elapsedMs = (asOf-firstSeenAt)`，用于可观测年龄，不是完整连接最终时长。lastPacketAt 是已接纳的最新报文时间，不随定时器推进。prefix 的 closeReason=null；final 为 fin/rst/idle/max_lifetime/eof/new_syn。EOF 只将缓冲释放到已经观测的最大事件时刻，不补未来空闲 Tick；仍活动的流导出 eof。EOF 不证明握手/连接正常完成；没有活动结束真值的 eof final 不能用于证明攻击结束。研究提取器的 emittedAt 为释放所用事件时钟，不能当现场处理延迟；现场为实际调用 Tick 的采集时钟。

## 4. 基础特征定义

所有方向以本机为锚：outbound 表示本机发送的数据，inbound 表示本机接收的数据；连接 direction 表示谁发起，两者不得混淆。

| 字段 | 单位/定义 | 缺失规则 |
|---|---|---|
| elapsedMs | asOf 减 firstSeenAt，毫秒 | 非负，必填 |
| bytesOutbound / bytesInbound | 到 asOf 的双向 IP 总长度累计（含 IP/传输层头，不含链路头） | 未看到反向包是 0 |
| packetsOutbound / packetsInbound | 捕获点实际看到的 IP 包数，不按 MSS 猜测重建线路包 | 非负，总和至少 1 |
| lengthMin / lengthMax / lengthMean / lengthStd | 双向 IP 包总长度的最小/最大/均值/总体标准差，字节 | 单包 std=0，不可空 |
| iatMeanUs / iatStdUs | 相邻已接纳报文时间间隔均值/总体标准差，微秒，同时间间隔为 0 | 总包数<2 时均为 null |
| synCount / synAckCount / rstCount / finCount | 各 TCP 标志计数，synCount 只数 SYN 且非 ACK | 非 TCP 全为 null；没有某标志为 0 |
| handshakeSeen | 同 epoch 按顺序观察到 SYN、SYN-ACK、ACK | TCP 未见完整握手=false，非 TCP=null |
| transport / direction / serviceClass | tcp/udp/icmp/other；inbound/outbound/unknown；服务端口分桶 | unknown 是显式类别，不猜应用内容 |

serviceClass 固定为 `dns`(53)、`web`(TCP 80/443/8080 或 UDP 443)、`remote_admin`(22/3389)、`mail`(25/110/143/465/587/993/995)、`other`。只是端口分桶，不证明实际应用。servicePort 作为目标元数据不直接入模型，避免记住数据集固定攻击端口；后续消融确证有用时换 profile。

捕获点若出现卸载合并大包，记录 `offloadSuspected=true`；首版该快照不进入自动处置模型，不采用旧 MSS 折算推断其等价性。新增平台或捕获模式须比较现场与 PCAP 的可观测差异；无法统一时明确不支持该模式。已完成的 P1/P2 不因文档修订重新验收。

rc.2 采用 float64 Welford 在线总体方差；乘积显式舍入后再累加，禁止 ARM 编译器融合乘加而改变跨架构内容哈希。模型边界再转 float32，缺失 mask 独立；Java 两遍统计参考允许相对 `1e-8` 算法误差，Go 同版本跨平台观察要求逐字节一致。

## 5. 因果上下文与冷启动

每个快照包含 1、5、30 秒三个窗口，数组顺序固定。区间为 `(asOf-windowSeconds, asOf]`，同时间只含已接纳序号；新连接按首包计一次，不按 snapshot 次数计数。窗口从新 boot、捕获 gap 后重新预热，但不要求达到固定连接数。

| 字段 | 计算范围/语义 |
|---|---|
| coverageMs | 捕获开始或最后一次 gap 至 asOf 的连续可观测时长，截断到窗口长度 |
| peerFlowStarts | 相同资产内 peer 的新连接数 |
| peerSynCount / peerRstCount | 相同 peer 的 TCP 标志计数 |
| peerDistinctServicePorts | 相同 peer 在窗口内有包的不同已知服务端口数；未知端口不计 |
| hostFlowStarts / hostDistinctPeers | 本捕获域的新连接数/窗口内有包的不同 peer 数，仅作上下文，不能单独归罪于某个 peer |
| peerBytesOutbound / peerBytesInbound | 窗口中相同 peer 双向 IP 字节量（计包发生时间，不按完成流回填） |

窗口不足时记录真实计数及 coverageMs；“在已观测 300ms 内零连接”是零，“未观测到时间段”由覆盖率表达。训练包含冷启动样本；manifest 每个 supportedScope 给出 coverageWindowSeconds 和 minimumCoverageMs，针对该窗口校验覆盖，且 minimumCoverageMs 不得超过窗口长度。自动策略另检查其 contextWindowSeconds 已完整覆盖；不能要求所有 30 秒窗口暖机后才允许 1 秒模型推理。特征仅用本捕获域，不把几台主机拼成一个窗口。

truncated仅表示计算必需的链路/IP/传输层头被截断或必要长度不可验证；按既定snaplen省略不需要的载荷本身不算质量失败。IP长度可从完整头读取，不能按已捕获字节数冒充原始IP长度。

质量字段：`captureGap`、`latePacket`、`truncated`、`offloadSuspected`、`capacityDrop`、`clockSkewMs`。captureGap/latePacket/truncated/capacityDrop/offloadSuspected任一为true时，首版只允许诊断/告警；`abs(clockSkewMs)>1000` 或 null 时禁止新自动执行。真实缺陷不因模型高分而被忽略。现场健康丢包计数未知时使用null，由平台探针评估可观测限制；公开PCAP缺少历史内核丢包统计不阻塞研究，报告该局限，文件读取完整不等于历史捕获零丢包。

rc.2 的 gap、超水位迟到、本域分片/必要头错误、容量丢弃清空上下文并重置 coverage；已有活动流保留缺陷至关闭，随后30秒新流继承缺陷。可确认不属于本机的坏帧不污染本域；地址头也不可解析时保守处理。卸载嫌疑保留原 IP 长度与实测包数，不采用 MSS 估算。

`clockSkewMs` 由传感器在当前心跳窗口的已认证交互中计算：本机时钟减控制面 `serverTime`。窗口内交互失败、偏差不可测或响应缺少 serverTime 时为 null；不得沿用过期偏差冒充新测量。时钟恢复后使用新观测重新判定，不恢复已过期证据。

观察中的质量位与 context coverage 只证明该快照的可用性，不能单独证明两次活动间持续健康。预算恢复所需连续健康旁证见第 9 节；停止捕获后等待不构成此证明。

## 6. 目标引用与权限

`peerKey` 为资产/传感器作用域内 HMAC-SHA256 假名键，带 keyEpoch，不能跨 epoch 合并证据。密钥保存在本机安全存储，不入模型或业务库。`targetRef` 是随机不可猜引用，绑定 `(assetId,sensorId,bootId,captureScopeId,peerKey,keyEpoch,direction,transport,servicePort,addressFamily)` 与本机具体端点。

引用本地租约最晚到 lastPacketAt+15秒，只有新接纳报文可以续证；boot 改变、接口/地址变更或方向不明确使引用失效。后端不能仅凭 peerKey 构造新目标；目标引用不能被跨资产/跨环境使用。中央数据库不保存可反查原始地址的映射。

P2 的易失 IPC 原型只接本机回环上的 TLS1.3 双向认证，固定 collector/executor 证书摘要分别允许登记/解析；绑定 executorBootId。进程重启、地址/接口失效和时钟回退会拒绝旧引用，研究环境永远没有引用。该原型不持有 OS 防火墙权限，也未实现 P5 的命令签名、持久恢复与生产密钥部署。

自动命令必须采用明确的 `peer_service` 范围：入站限定远端地址、本地服务端口和协议；出站限定远端地址、远端服务端口和协议。不能由单流高分升级为整机隔离或全端口阻断。IPv6、UDP、未知方向可以保留观测，未验收不得自动执行。

## 7. 模型与输出

训练端按 [feature-profile.json](contracts/feature-profile.json) 生成有序输入。ONNX 输入为 `numeric_values` float32 `[N,K]`、`numeric_missing` float32 `[N,K]`、`categorical_codes` int64 `[N,C]`；K/C 从已冻结 manifest 与 profile 导出。缺失数值占位 0 必须同时置 mask=1；图内使用 train 拟合的插补/缩放，不能把占位当真实零。图内包含冻结校准转换，attack_score为校准后分数；校准拟合只用validation，不改变train预处理。当前固定张量仅适用于树模型/MLP；序列模型必须先新增有序序列与mask契约、profile和版本并对拍，不得把TCN/GRU塞入同一二维输入后宣称兼容。类别词表只拟合 train，unknown 单独编码。

输出 `attack_score` float32 `[N,1]`，二分类标签映射固定benign=0、attack=1。可选 `family_scores` `[N,F]` 的列严格对应manifest.outputContract.familyScoreOrder，空数组表示不输出家族分数。二分类推理的family=null；策略的family是已验收任务范围（例如connection_abuse），并非模型证明了具体攻击类型。非空family必须来自已验收的家族输出，不凭二分类高分填具体攻击名。策略及episode携带自己的任务family，并绑定相应模型支持范围。校准器、编码器及默认推理资料绑定manifest，告警/自动阈值绑定独立policy；模型分数不是逐样本真实正确概率。

推理响应固定包含 observationId、modelId、manifestSha256、applicability、score、family、reasonCodes、completedAt。applicability 非 supported 时 score=null，不得输出零风险；未知模型、哈希不符、ONNX 超时明确失败，不无声切换候选。

本轮 K=43、C=3；基础/上下文消融在同一张量契约内采用冻结的特征选择，不改变向量顺序。当前 P3 的 family 为 `connection_abuse`，行为场景为 `slowloris`、`slowhttptest`；它们是评估标签，不表示二分类模型输出了具体行为名称。场景归一化映射及 sourceId/sourceDomainId/contextSourceId/cohortId 保留在旁路索引，均不得加入模型输入。

## 8. 证据与策略判定

episode 键及 30 秒桶见[功能模块](功能模块设计.md)。策略仅使用截至决策时已到达、且 asOf 未过期的证据，不读取未来回放标签。模型版本、策略版本、方向、peer、服务与契约不同不得共同计数。

自动候选需同时满足：已验收的 supported capability；score≥autoThreshold；minDistinctFlows 和 minEvidenceSpanMs 满足；同目标上下文条件满足；数据质量合格；引用新鲜；资产授权/自动发布包 active；保护目标和动作预算检查通过。参数在 validation 上选取并冻结，不写死“三次告警必定攻击”。同 parentConnection 的多个 prefix/final 和续段只能贡献一次，选择截至决策时最新的合格快照，不能保留已经失效的历史最高分。参与计数的每条快照都须达到 autoThreshold，证据跨度取它们 asOf 的最大差；单连接模式跨度为0。minPeerFlowStarts=0表示不要求窗口内新建连接，供持续长流模式使用，不能靠重复快照补足连接数。autoThreshold必须不低于alertThreshold，minEvidenceSpanMs不得大于maxEvidenceAgeMs。

首次lab联合试验的能力前提是P5适配器及P6离线范围均已通过，并持有效lab试验计划授权；不先要求尚待V6证明的lab_auto。其余质量、模型阈值、证据、目标、预算、签名和恢复检查完全相同，通过联合报告后才授予lab_auto。该试验资格不能用于authorized环境。

若只有一条流足以自动处理，必须以该特定模式单独验证并将 minDistinctFlows=1；默认不能从多流模式推出。仅规则模式可以单独支持已验证规则能力，但不计为模型自动阻断成果。

### 8.1 判定次序与发布绑定

新决策规则固定按下表检查，首个不通过项为主 reasonCode；诊断可以附完整检查轨迹，但不能因调换次序改变主结论。参与决策的每条证据还须满足 `0 ≤ decisionAt-asOf ≤ maxEvidenceAgeMs ≤ 10000`，未来或过期证据不得计数。

| 顺序 | 检查 | 主拒绝代码 |
|---|---|---|
| T1 | 已验收能力、范围及模型/策略/契约版本一致 | `CAPABILITY_NOT_SUPPORTED` |
| T2 | 数据质量合格 | `QUALITY_UNSUPPORTED` |
| T3 | 时钟可测且绝对偏差不超过 1000ms | `CLOCK_UNTRUSTED` |
| T4 | 目标引用绑定有效、lastPacketAt 租约未过期 | `TARGET_REF_STALE` |
| T5 | 证据未超 10 秒且各选定 parent 最新快照 score 达阈值 | `EVIDENCE_STALE` 或 `SCORE_BELOW_AUTO`（先检查时效） |
| T6 | 独立 parent 数与证据跨度满足 | `EVIDENCE_INSUFFICIENT` |
| T7 | 同目标上下文完整覆盖并满足登记条件 | `CONTEXT_CONDITION_UNMET` |
| T8 | 资产授权、revision、发布包及环境有效 | `AUTHORIZATION_INACTIVE` |
| T9 | 保护对象、目标累计预算和资产总额度通过 | `PROTECTION_OR_BUDGET_BLOCKED` |

T9 细分原因必须记录保护命中、TTL 去重、连续预算、资产并发或速率限制；多项同时失败按上述列举顺序记录首项。目标首次因连续预算被拒时，同一预算 generation 输出一次 `escalate_manual`（含目标、时刻、已累计阻断时长和触发证据），之后的合格证据只形成人工移交告警，不签发自动动作；额度恢复后才可能再次转人工。符合阈值、新鲜度、parent 和上下文条件的合格攻击证据，即使被 TTL/预算抑制，也推进目标的 lastEvidenceAt。

自动资格唯一由 `guard_release_bundle → guard_bundle_capability → guard_asset_binding` 绑定；`DecisionPolicy.supportedCapabilityIds` 必须与该组合一致。draft 策略不能随 active bundle 执行。研究回放只计算 block_candidate：以冻结支持范围和旁路目标身份模拟检查，不伪造 live targetRef、已批准能力或 ActionCommand；报告明确哪些检查为离线模拟。

`evidenceSha256` 采用 `guard-evidence/1`：对含决策版本、decisionId/decisionAt、environment、model/manifest/policy/bundle/capability 哈希引用、授权 ID/revision、完整目标绑定、budgetTargetId/预算 revision/健康证明哈希、lab session 摘要（无则 null）及选定观察引用的对象做 RFC8785 JCS 后 SHA-256。观察引用含 observationId、原始不可变 contentSha256、parentConnectionId、asOf，按 observationId 排序；不重新序列化观察文件来改其哈希。该证据对象由服务端持久化，不能只保存最终摘要。

## 9. 命令、签名、租约与去重

ActionCommand 是固定结构的载荷；传输为 `{payload, keyId, algorithm:"Ed25519", signature}`，signature 为对 RFC8785 JCS 规范化 payload UTF-8 的 Ed25519 签名（base64url 无填充）。签名、公钥信任、轮换和吊销在 P5 独立测试；私钥在控制面密钥存储，代理只持受信任公钥。

载荷绑定 commandId、actionId、executorId、executorBootId、assetId、sensorId、bootId（采集器启动标识）、captureScopeId、targetRef、peerKey、keyEpoch、environment、scope、direction、transport、servicePort、capabilityId、bundleId、policySha256、evidenceSha256、authorizationId/revision、issuedAt、applyBy、leaseExpiresAt、blockUntil、idempotencyKey。客户端无权覆盖这些字段。

首版 TTL 30 秒，策略可在 5—60 秒内选择，系统硬上限 60 秒；连续续封最大累计 120 秒，超过即按 8.1 节输出 `escalate_manual` 转人工，不放宽上限、不换预算身份续期。每资产同时最多 10 条自动规则，每分钟最多 5 个新动作；这些是误伤约束，不是准确率证明。续期是新的经批准动作/证据，重试不得重置 blockUntil。

必须满足 `issuedAt ≤ applyBy < blockUntil`、`applyBy-issuedAt ≤ 5秒`、`applyBy ≤ leaseExpiresAt`、`blockUntil ≤ leaseExpiresAt ≤ authorization.validUntil`，并且 `blockUntil-issuedAt ≤ maxTtlSeconds`。领取前控制面重新核验授权，签发短期授权租约；应用前代理验证签名和所有绑定，本地读取目标与保护清单。未知 keyId、过期、boot 不符均拒绝。撤销请求按[执行机器协议](接口设计.md#8-执行机器协议)通过带服务端认证的 TLS 通道及 executor 专用身份领取，绑定本机账本里的 actionId/commandId 与单调 desiredRevision，只允许删除自身规则，不接受远端任意句柄。它不创建或续期规则；代理持久化撤销意图后不再应用该 action 的迟到命令。断网时无法保证瞬时撤销，最迟按已签发租约到期清理，最大暴露时间必须在报告中说明。

幂等键由控制面按 actionId 固定；相同键/相同哈希返回已有结果，不延长 TTL；相同键/不同哈希拒绝。代理在改规则前 fsync 命令与恢复账本，规则 ID 确定性生成。崩溃恢复先核对操作系统实际规则再决定重试，不能把传输超时当作未执行。

### 9.1 稳定目标与累计预算

可信本机解析器为 `(assetId,environment,真实对端,方向,协议,服务端口,地址族)` 用持久预算密钥生成不可反查的 stableTargetToken，控制面据此登记稳定预算身份 `budgetTargetId`，经executor专用目标绑定接口关联targetRef。它与用于证据隔离的 peerKey/keyEpoch 分开：boot、capture、活动、分区角色、keyEpoch、policy 或 bundle 变化均不建立新额度。真实对端映射与密钥只在本机受控存储，密钥迁移须证明旧新身份连续性；身份无法关联时拒绝新自动动作，不默认清零。

同一目标将已发生及尚未确认终结的预留阻断区间取并集累计，硬上限为 120 秒；重叠重试不重复计费，但不能通过新 actionId 延长期限。到期、换组或撤销不自动清除已消耗时长。规则状态 uncertain 时保守保留预留；只有可信核对才能释放未发生的预留。每资产同时最多 10 个未确认终结动作、数据库单调推进时间上的滚动 60 秒最多 5 个新动作，所有能力/发布包/方向共享；幂等重试不算新动作。

预算预留、动作创建与 outbox 发布同事务完成，并发串行核验；代理按本地账本再次防止超限。每次拟议动作须满足策略更严格的限制和系统硬上限，不允许运行时放宽参数。

### 9.2 连续健康与预算恢复

连续健康旁证是独立记录，不是新的模型特征、标签或“模型分低”的推断。每个记录含 healthVersion=`host-guard-capture-health/1.0.0`、healthWindowId、assetId/sensorId/captureScopeId、observerSessionId、sequence、intervalStart/End、previousSha256、counterStart/End、captureGap、clockSkewMs、configSha256、buildSha256，可附接口列举的metrics。身份字段必须与机器凭据一致。每条内容摘要为完整payload的RFC8785 JCS SHA-256，链首previousSha256=null，其余引用前条摘要，不在payload放自引用哈希。

counterStart/End的键固定为packetsSeen、kernelDrops、capacityDrops，值为非负累计整数或null。不可测为null；区间间断、重复序号冲突、进程中断、计数回退、丢包/丢弃、时钟不可信或身份不符均不能证明健康。记录最多覆盖5秒、连续拼接，实时接收延迟上限10秒，超限暂停新动作并核对。

现场由独立采集健康观察器连续输出，经传感器专用机器身份认证并保存哈希链；离线 run 绑定原始旁证、来源身份、提取代码和文件清单哈希。文件哈希只证明完整性，不能代替来源认证。公开 PCAP 的历史丢包未知不妨碍诊断，但不能被当作连续健康并用于恢复额度。

自动恢复累计预算仅在以下条件同时成立时发生：

1. 可信执行回执/核对已证明该目标没有活动或 uncertain 规则，得到 lastBlockEnd；离线只能使用明确标注的模拟区间。
2. 认证健康链完整覆盖 lastBlockEnd 至当前时刻，首条有效区间不晚于 lastBlockEnd；无未知计数、gap 或身份缺口。
3. 从 `max(lastBlockEnd,lastEvidenceAt)` 起已连续健康且无新的合格攻击证据至少 **120 秒**。在没有新流量时由健康观察器证明仍在捕获；低分或无观察本身不证明健康。
4. 在同一预算事务中登记健康证明、旧累计值、恢复时点、revision 及审计，再清零。历史规则未核实或健康链缺失时保持原预算；需要人工恢复时走明确的核对与审计流程，不伪造自动冷却成功。

研究活动间可重置逻辑特征引擎来隔离上下文，但健康观察器与预算账本连续运行。下一组开始必须同时满足上下文隔离至少 150 秒加登记余量（本轮最低 155 秒）和上述到期后冷却条件，取较晚时点；固定 sleep 155 秒不是预算恢复证据。P3 回放、P4 持久状态、P5 实际清理和 P6/P7 评价采用相同口径。

## 10. 动作状态与恢复

```text
pending → dispatched → applied → revoked | expired
pending → rejected | revoked | expired
dispatched → rejected | revoked | expired | uncertain
applied → uncertain
uncertain → applied | rejected | revoked | expired | recovery_failed
applied → recovery_failed
recovery_failed → revoked | expired
```

pending从未生成可执行命令时，可由控制面事务证明未执行并终止；已经签发命令的状态只能据代理/规则核对证明终止。dispatched可在应用回执丢失后直接接收已清理的revoked/expired证明，不强造中间applied记录。

`dispatched` 仅表已领取；`applied` 必须有 OS 规则安装核验回执，流量效果由独立测试证明。`uncertain` 禁止盲目重发新 ID；`expired` 必须已证明规则不存在/已清理，不能仅因墙钟超过 blockUntil 写成功。清理失败为 recovery_failed，告警并暂停该资产自动能力。TTL是清理截止时点，不是操作系统自动提供的保证；健康状态下以blockUntil后1秒内核验规则已不存在为恢复验收目标，若要求更严需单独能力测试。恢复器停摆无法核对时明确uncertain/recovery_failed及实际超时，不能继续宣称TTL已兑现。

本地恢复器与检测进程分离。重启后先清理到期规则、复核未到期账本，再接受新命令。wall clock 后退不能延长规则寿命，运行内使用单调时钟；重启按签名绝对到期值和可信时间核对，无可信时间则清理本系统临时规则并拒绝新动作。只删除本系统管理且能以账本证明归属的规则。

回执含固定 receiptId、commandId、revocationId（无撤销任务时为null）、executorId、status、observedAt、ruleHandle、effectiveBlockUntil、errorCode、stateDigest。由独立 executor 机器凭据认证；只能回报自己的命令。追加保存全部回执，状态投影按允许迁移更新；迟到回执不得把 revoked/expired 重新写成 applied。代理确认未安装且没有待执行命令才可回 rejected；撤销/过期成功须证明其管理规则已不存在。executorBootId改变使旧待应用命令失效，但不改变已有规则的清理责任；恢复完成后只能用新鲜决策申请新动作。

`stateDigest` 采用 `guard-state/1`：对 `{digestVersion,assetId,executorId,executorBootId,rules,pendingRevocations}` 做 RFC8785 JCS 后 SHA-256。rules 保存实际枚举到的本系统规则 actionId/commandId/ruleHandle/effectiveBlockUntil/normalizedScopeSha256，按 ruleHandle 排序；pendingRevocations 保存 revocationId/actionId/desiredRevision，按 revocationId 排序。无规则时是空数组，不是未经枚举就填零哈希。摘要不包含读取时间，读取时刻由 observedAt 单独记录；发现归属异常须返回 uncertain/recovery_failed 并保存核对详情，不能只比摘要判成功。

## 11. 回放隔离与版本升级

environment 固定 `research / lab / authorized`。research 观察 targetRef=null，任何 research 结果都不能签发 ActionCommand。lab 联合测试需要批准的 canary 映射、独立执行身份和网络层外联隔离证据；不能仅改 environment 字符串获得权限。

V6使用独立lab validation session，不把research结果直接改标。session预登记scenarioHash、mappingSha256、bundleId、授权及原始/测试起点；只允许1倍速。对原始时间施加一个固定offset：labTime=sourceTime+offset，所有报文、firstSeenAt/lastPacketAt/asOf一致平移，窗口间隔和特征值不变；emittedAt/接收/动作采用真实墙钟，标签起点只在评估旁路同样平移。延迟或积压仍按同一10秒证据期限拒绝，不能每个快照重新取now来消除延迟。命令issuedAt/applyBy/blockUntil及恢复器始终使用真实时间，不使用加速时钟。

lab目标映射由已授权runner和隔离代理共同核验，只替换公开原始地址为登记canary地址；方向、协议、地址族和服务端口必须保持一致。不能满足的场景不能进入该canary试验。不同源peer需要分开的canary身份或分次运行，不能把正常/攻击目标混映为一个执行对象。映射摘要绑定validation session并进入evidenceSha256；原始地址和lab实际端点都不作为模型输入。研究回放支持倍速，V6的真实动作时间不能沿用倍速规则。

v5 契约候选不是旧 v4 的原位修改。运行时 schema/validator/模型/代理必须按同一发布组合接入，旧数据和权重不能重新贴 v5 标签。P1/P2 交接保持收口；后续字段/公式或结构状态含义变化时，在所属阶段登记新的兼容性版本、复算受影响样本并重跑对拍。仅文字整理不升级机器结构；决策预算、评价时钟或健康证明规则变化必须升级各自协议版本，生成新 policyVersion/评估计划与发布组合，不能复用旧成绩。

原始冻结包保持不可变，新 run 单独绑定实际制品，不改历史哈希。运行报告、候选及冻结清单写入受控 artifacts/run 目录，docs 仅维护当前设计与计划。未来增加序列模型或 family_scores 族名时先冻结相应输入/输出注册表；当前 P3 为二分类、familyScoreOrder 空数组，不把未设计能力列为本轮待实现。
